# Работа по TODO BecqMoni

Цель — выполнить порученные задачи и уменьшить остаток, сохранив решения пользователя, чужие правки и доказательства приёмки. Нельзя добиваться уменьшения числа строк фиктивным закрытием, удалением или расширением задания.

## Подготовка

- Прочитать `AGENTS.md`. Для новой постановки сначала использовать соседний навык [becqmoni-analyst](../becqmoni-analyst/SKILL.md).
- Найти порученные строки в TODO.md и DONE.md. Названы номера — работать по ним. Названа серия или весь TODO — выбрать группу по общей причине или приёму, обычно 2–4 строки на исполнителя. Не брать соседние номера автоматически.
- Снять побайтовый снимок TODO вне репозитория. Зафиксировать исходные `git status`, ветку и незавершённое слияние. Посчитать открытые строки всех серий скриптом `scripts/todo_check.py`.
- Неизвестные решения задать доступным вопросником в начале; независимую работу продолжать. Не спрашивать то, что определяется чтением дерева.

## Выполнение и делегирование

Сначала определить доступность и разрешённость делегирования в текущей сессии. Этот навык описывает работу с агентами, но не отменяет ограничений среды. При разрешённом делегировании пользоваться `collaboration.spawn_agent`, сообщениями и ожиданием; при недоступности или запрете выполнять группы последовательно самостоятельно. Не заявлять о независимом ревью, если его не было.

Одновременно — не более трёх исполнителей и не больше доступных слотов. Разводить файлы, исходники проб, каталоги сборки и данные измерений. Модель наследовать по умолчанию; менять её только по явному выбору пользователя или действующим правилам среды, используя доступные модели Codex. Названия моделей прежнего приложения не являются конфигурацией Codex.

Каждому исполнителю передать:

- корень и ветку, требование прочитать `AGENTS.md`, русский язык;
- точную постановку каждой строки, решения пользователя и границы полномочий;
- свои и занятые файлы; TODO/DONE правит только координатор;
- собственные OutputPath и IntermediateOutputPath и каталог в уже установленном `D:\BqMoni_Claude\<полоса>`; существующий путь данных не переименовывать ради имени продукта;
- проверяемую приёмку, положительный контроль и пути к артефактам;
- запрет коммитов, `git add` и `git rm`, если это не поручено отдельно;
- журнал в своём файле handover; скриншоты — вне git, без личных данных в публичном журнале;
- требование сообщать результат по каждой строке сразу и отдельно называть непроверенное.

Подробные ограничения сборки, корпуса, складов и приёмки — в [references/operations.md](references/operations.md); читать перед соответствующей работой.

## Реестр и приёмка

- Для правки применять `scripts/todo_edit.py` с JSON-заданием. Он сохраняет внутренние `|` и переводы строк. Повтор `append` не идемпотентен: после обрыва сначала проверить фактический файл.
- После каждой правки запускать `scripts/todo_check.py`; перед сдачей использовать `--strict` и явно перечислять свои изменённые и новые номера. При потере, задвоении или чужом изменении строк остановить зависимую запись и разобраться.
- Проверять реальные файлы, сборку и измерения. Отчёт оборвавшегося исполнителя не доказывает завершение. При разрешённом делегировании требовать независимого критика; он возвращает по пунктам «принято», «не принято» или «не доказано» с командой и артефактом. При недоступном независимом ревью прямо назвать ограничение.
- Проверка приложения — запуском на копии пользовательского конфига и осмотром нужного экрана. Для приёмки коммита требуется `python tools/check_all.py` с кодом 0. Не отключать сторожа ради зелёного результата.
- Подтверждённое закрытие отметить в TODO и журнале. В DONE переносить только по прямому указанию пользователя. AMBER закрывает пользователь либо даёт на это явное разрешение.

Находку сначала исправить в объёме порученной задачи либо дописать в существующую строку с той же причиной. Факт без действия — в журнал; решение пользователя — в вопросник; отказ — в таблицу отказов. Новый номер — последнее средство после поиска дублей в обоих реестрах. Новые работы за пределами поручения не запускать автоматически ради баланса.

В отчёте — проверенные результаты по строкам, ограничения приёмки и измеренный счёт открытых строк до/после. Неподтверждённое не закрывать.
