# Работа по TODO.md чужими руками

Твоя роль — **распорядитель, а не исполнитель**. Работу делают сабагенты
(«полосы»). Твой контекст — общий ресурс всего захода: истратишь его на чтение
кода и сборки — заход кончится на середине, и незакрытые полосы придётся
принимать вслепую.

## Порядок

### 1. Взять ровно то, что названо

Amber называет строки или серию. Прочитай **только их**:

```bash
grep -n '^| \*\*A37\*\* \|^| \*\*A40\*\* ' TODO.md
```

Список открытых строк серии — одной командой, статусами, а не текстом:

```bash
awk -F'|' '/^\| \*\*A[0-9]+\*\* \|/ {print $2" :: "substr($3,1,60)}' TODO.md
```

⛔ Не расширяй задание. Соседняя строка, которая «тоже надо бы», — это отдельная
строка реестра, а не твоя работа сегодня.

### 2. Спросить всё сразу, вопросником

Решения, которых нет в строке, спрашиваются `AskUserQuestion` **в начале
захода**, а не копятся к отчёту: вопрос словами в тексте ответа не задан и
решения не получит. Всё, что можно делать без ответа, — запускай, не дожидаясь.

Собери по строкам всё, что держит решение (текст на экране, снимать или чинить,
что делать со складом), и задай одним вопросником: короткий вопрос, 2–4
варианта, у каждого цена и следствие, рекомендуемый первым.

### 3. Развести файлы, потом запускать

**Не больше трёх полос разом.** Ограничение не про машину, а про столкновения:
две полосы в одном файле дают потерянную правку, которую никто не заметит.

Перед запуском выпиши, какие файлы трогает каждая строка, и раздай их **без
пересечений**. Одна строка — одна полоса; две смежные строки в одних файлах —
одна полоса, а не две. Каждой полосе в задании перечисли явно: «ТВОИ файлы …»
и «⛔ НЕ трогай … — заняты другими полосами».

Освободился файл — следующая полоса берёт его. Полосы запускай **в одном
сообщении**, чтобы шли разом.

### 4. Что писать в задание полосе

Полоса не видит этого разговора. В задании должно быть всё:

- корень дерева, ветка, «прочитай `CLAUDE.md`», «пиши по-русски»;
- **дословная постановка строки** — полоса не обязана её искать, но пусть
  сверит: посылка строки часто уже или шире реальности, и это сама по себе
  находка;
- принятое решение Amber, если оно есть, — и что именно им **не** покрыто;
- ⛔ **свой каталог сборки** (`OutputPath` и `IntermediateOutputPath`), иначе
  полосы затирают сборки друг друга;
- как выглядит приёмка **числом**, и требование положительного контроля;
- запреты: `TODO.md` и `DONE.md` не править, коммитов не делать, чужие файлы
  не трогать;
- куда писать разбор — **свой новый файл** в `handover/`, не чужой;
- что вернуть в отчёте: измеренные числа, готовый текст для закрытия строки,
  отдельным списком — новые найденные проблемы готовым текстом строки;
- порядок разбора находок по §9: сперва починить самой, потом искать родителя
  в реестре, строкой возвращать только дороже часа или не своё — и у каждой
  назвать, почему не сделала.

### 5. Реестр ведёшь ты, и только ты

⛔ **Полосам `TODO.md` править запрещено.** Три сабагента, дописывающие один
файл, теряют строки друг друга молча. Полоса возвращает готовый текст — строку
правишь ты, скриптом `scripts/todo_edit.py` (он знает про внутренние `|` в
описаниях, про одиночный CR и про строки из трёх клеток).

```bash
python .claude/skills/todo-work/scripts/todo_edit.py задание.json
```

После каждой правки — сверка целости, она дешёвая и ловит потерю строк:

```bash
python .claude/skills/todo-work/scripts/todo_check.py TODO.md.snapshot
```

Снимок делай **один раз в начале захода** (`cp TODO.md <scratch>/TODO.md.bak`).

⛔ Скрипт не идемпотентен: `append` дописывает при каждом запуске. Если запуск
оборвался на выводе — сперва проверь, записался ли файл, и только потом
повторяй. Откатывать `TODO.md` целиком **нельзя** — снесёшь чужие строки.

### 6. Принимать по замеру, а не по словам

- **Полоса дошла до конца** — прочитай отчёт, возьми числа. Одну дешёвую
  проверку сделай сам, если она в один вызов (запустить пробу, прочитать
  вердикт). Дорогую — отдай отдельной полосе.
- ⛔ **Полоса оборвалась** (предел сессии, зависание) — её слова ничего не
  значат: оборванный агент отчитывается о том, что собирался сделать.
  Что она успела, устанавливай **замером состояния дерева**, и лучше — руками
  отдельной полосы с заданием «проверь, сделано ли X, и доделай остаток».
- ⛔ Приёмка, которая проходит всегда, ничего не меряет. Если полоса не
  показала **положительного контроля** — заведомо плохой вход, на котором
  проверка ОТКАЗЫВАЕТ, — работа не принята. Требуй его в задании заранее.
- ⛔ **Формат `.resx` — в приёмке каждой полосы** (решение Amber 05.09.2026,
  `T235`): git его не хранит (`eol=crlf` в `.gitattributes`, в индексе LF), и
  сломанные переводы строк `git diff` не покажет. Полоса, трогавшая любой
  `*.resx`, перед отчётом гонит `python tools/check_resx.py` (и остальные три
  `check_resx_*.py`) и показывает код 0 по формату; сломала — чинит сама
  (`tools/resx_format.py`). Переводы строк считать только байтами.

### 7. Новая проблема — строка, но ПОСЛЕ разбора по §9

Всё, что полосы нашли попутно, разбирается **сразу**, вместе с закрытием, — но
строкой становится только то, что прошло порядок §9 (не починено на месте, не
дописано в родителя, не факт для журнала, не вопрос для сегодняшнего
вопросника). Полосы предлагают номера вслепую и **сталкиваются** — номера
раздавай сам, проверив свободные ОБЕИМИ формами записи (закрытые строки в
`DONE.md` теряют жирность: `~~T3~~`):

```bash
for id in A150 A151 T160; do echo -n "$id=$(grep -c "^| \*\*$id\*\* " TODO.md)/$(grep -c "^| \*\*$id\*\* " DONE.md) "; done
```

Часть находок окажется решениями для Amber — не решай их за неё, спрашивай
вопросником следующей же пачкой.

### 8. Отчитываться коротко

Пиши мало. Таблица «строка — чем закрыта», два-три предложения о том, что
оказалось не так, как думали, и счёт: открытых было / стало, закрыто /
заведено / из заведённых закрыто в тот же день (§9). Пересказ
отчётов полос не нужен — они лежат в `handover/`.

Числа в отчёте — **счётом по файлу**, а не по памяти:

```bash
python .claude/skills/todo-work/scripts/todo_check.py TODO.md.snapshot --tally
```

### 9. Баланс: заход обязан УМЕНЬШАТЬ число открытых строк

Мера захода — не «сколько закрыто», а разность: открытых строк стало меньше
или больше. Считать до и после, по ВСЕМ сериям (`todo_check.py --tally` видит
только `A` и `T` — `T206`; пока не починен, считать своим счётом по образцу
`\| (~~)?\*\*([A-Z]+\d+)\*\*`).

Цифра, ради которой этот раздел: **05.09.2026 девять добросовестных полос
закрыли 18 строк и завели 76 — открытых стало 220 → 266.** Каждая полоса
приносила по три-пять находок, каждая находка становилась строкой, и реестр рос
быстрее, чем чистился. Реестр, растущий на каждом заходе, перестаёт быть
списком дел и становится журналом: строки в нём уже не прочтёт никто.

**Правило: находка становится строкой В ПОСЛЕДНЮЮ очередь.** Каждая находка
проходит порядок сверху вниз, берётся первое подошедшее:

1. **Дешевле часа и в своих файлах — доделать в той же полосе.** Полоса,
   нашедшая дыру в собственном стороже, обрезанную подпись рядом, мёртвый
   номер в шапке, чинит это сама и показывает контролем. Строкой заводится
   только остаток дороже часа, либо упирающийся в чужой файл или в решение Amber.
2. **Уже есть строка о том же — дописать в неё** (`append`), а не заводить
   соседку. Перед номером — grep по ключевым словам в ОБОИХ реестрах. Признак
   двойника: та же причина в другом месте. (05.09.2026 об одном — «сторож судит
   всё дерево, а не то, от чего зависит сборка» — заведено три строки:
   `T194`, `T199`, `T226`.)
3. **Это запись факта, а не дело** («дата в шапке DLL — константа», «правило
   края при умолчаниях почти недостижимо») — место ему в журнале полосы и, если
   нужно, одной фразой в родительской строке. Строка без «Сделать», которое
   кто-то исполнит, — не строка.
4. **Это решение Amber** — не строка «Решить (Amber)» на потом, а вопросник
   СЕГОДНЯ, пачкой по четыре. Решение часто закрывает вопрос сразу (`T190`,
   `A226` — закрыты в день заведения). Строка заводится, только если вопрос не
   влез в вопросник дня — и тогда с пометкой, что он уже задан.
5. **Это отказ делать** — таблица «Чего делать НЕ надо» с причиной, а не
   открытая строка.
6. Остальное — строка с приоритетом, и в ней сказано, **почему её нельзя было
   закрыть на месте**.

Полосе это говорится в задании, дословно: «находки — сперва чини сам, потом
ищи родителя в реестре, строкой возвращай только то, что дороже часа или не
твоё; у каждой возвращённой строки назови, почему не сделал». Ожидание —
ноль-две новых строки на полосу; больше — распорядитель просит обосновать
каждую и половину обычно дописывает в родителей.

**Вторая половина правила — откуда брать работу.** Заход не кончается
закрытием строк, которые назвала Amber. Если волна породила строк больше, чем
закрыла, следующие полосы того же захода идут по ПОРОЖДЁННЫМ, начиная с
дешёвых, пока баланс не сойдётся хотя бы в ноль. И в каждый заход — одна
полоса-чистильщик по старым строкам: чья посылка протухла (`T71`, `T149` —
закрылись сверкой с деревом), что уже сделано по факту (`V12`/`V13`), что
держится только словом Amber (в вопросник).

В отчёте — баланс числом: «открытых было N, стало M; закрыто k, заведено n, из
них закрыто в тот же день j». Отрицательный баланс — норма захода;
положительный — объяснить по строкам, почему каждая не закрылась на месте.

## Чего не делать

⛔ **Не читай исходники, чтобы «разобраться».** Разбирается полоса. Исключение —
беглый `grep`, отвечающий на вопрос «кому отдать эту строку и не столкнутся ли
они»; на это хватает пары вызовов.

⛔ **Не собирай и не мерь сам**, пока это не одна команда с готовым ответом.
Сборка, прогон корпуса, профилирование — работа полосы.

⛔ **Не запускай четвёртую полосу**, пока не освободилась одна из трёх. Соблазн
велик, цена — столкновение в файле, которое всплывёт через час.

⛔ **Не переноси строки в `DONE.md`.** Закрытая строка **вычёркивается и
остаётся** в `TODO.md`; переносит только Amber, руками.

## Почему именно так

Каждое ограничение оплачено:

- **Три полосы.** На шести ломается сторож свежести оснастки: сборка не
  успевает доехать до каталога проб между чужими правками, и прогон идёт старым
  двоичным файлом с новыми ключами — молча.
- **Свой каталог сборки каждой полосе.** Общий `OutputPath` даёт пробы,
  собранные с чужим приложением; побитовая приёмка это не ловит.
- **Реестр одной рукой.** Параллельная дописка `TODO.md` уже сносила чужие
  строки.
- **Приёмка с положительным контролем.** Сторож, описанный, но не написанный,
  выглядит как работающий: код 0, находок 0. Отличает их только подброшенный
  плохой вход.
- **Оборванная полоса — по замеру.** Она пишет «сделано» о том, к чему только
  приступала.
- **Баланс строк.** Заход 05.09.2026 при добросовестных полосах закрыл 18 и
  завёл 76: правило «каждая находка — строка» без порядка разбора превращает
  реестр в журнал, а каждая лишняя строка стоит будущего захода. Сокращать
  реестр — цель захода, заводить строки — его побочный расход.
