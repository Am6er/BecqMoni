# AGENTS.md — BecqMoni

Инструкции для Codex в этом проекте.

BecquerelMonitor — WinForms-приложение гамма-спектрометрии, C#, .NET Framework 4.8.

## Общение и постановка

- Всегда по-русски; пользователь — мужчина. Сначала ответить на заданное «почему», затем при необходимости задать вопросник.
- Новая постановка: до первой правки читать .agents/skills/becqmoni-analyst/SKILL.md. Не повторять разбор на «продолжай», ответ пользователя, запрос статуса или команду коммита. Пустой вопросник не нужен.
- Дефекты приложения идут перед корпусом и обслуживающей оснасткой. Не расширять поручение ради соседних проблем.
- После исправления каждого дефекта передавать сабагенту-критику описание исходного сценария, изменения и результаты проверок. До завершения работы получить его отзыв и устранить подтверждённые замечания.
- Перед работой искать в TODO.md и DONE.md, включая таблицу отказов. По выбранным строкам или серии использовать .agents/skills/becqmoni-todo-work/SKILL.md.

## Реестр и полномочия

- TODO — корень незавершённой работы. Подробности, решения и измерения — в связанном журнале; в строке краткая задача и ссылка. Фиксировать найденное в рамках существующей задачи; новую строку заводить после поиска родительской и дублей. Не создавать искусственные задачи для фактов без действия.
- Закрытие подтверждать измерением; строки не удалять. В DONE переносить только по прямому поручению пользователя. Серию AMBER не закрывать за него. Реестр правит координатор, а не несколько исполнителей одновременно.
- Не редактировать пользовательский конфиг BecqMoni; GUI запускать на копии. Поставочные NuclideDefinition.xml и config/device защищены. Для config/ROI есть расхождение старого запрета и позднего решения: перед такой задачей проверить конкретное датированное решение пользователя, не выбирать молча.
- Изменение баз и объявленной базы — отдельное решение пользователя; разрешение на метод не разрешает запись. Не подменять существующие данные или паспорт под новую модель. Не трогать NonlinearEnergyCalibration и не заводить новых задач по германию.
- Готовые совместимые матрицы переиспользовать. Перед пересчётом — опись сцен, частей, клейм и DLL. Единственные результаты плеч сохранять до принятия либо отклонения опции.

## Сборка и проверка

- MSBuild запускать через PowerShell. Для диагностики обязательны SignManifests=false, GenerateManifests=false и собственные OutputPath **и** IntermediateOutputPath (Debug_Codex / Release_Codex либо свои каталоги). Для настоящей ClickOnce-публикации GenerateManifests=false не подходит.
- Матрицы и измерение скорости — оптимизированной Release-сборкой. Перед долгим расчётом пересобрать целевые пробы, проверить код возврата и первые две единицы работы. Не обходить сторожа подменой бинарника.
- Подробный рецепт сборки и профилирования — в тематических правилах ниже; читать перед соответствующей работой.
- Для приёмки коммита требуется python tools/check_all.py с кодом 0. Существующее красное состояние не прятать новым исключением.
- Для корпуса выбирать достаточную малую базу и свой -Out; при доборе спектров оба плеча и scorer получают один -List. Полный прогон — по поручению или когда малая база не покрывает эффект. Старые численности корпусов не подставлять без проверки. Каждое число называет точную часть корпуса, сборку, вход и артефакт.
- Изменения UI проверять запуском приложения на копии конфига и нужным экраном. Положительный контроль обязателен там, где проверяется отказ или сторож.

## Файлы и соглашения

- Временные расчёты и worktree — в установленном D:\BqMoni_Claude\<полоса>; чужие или существующие каталоги не занимать без проверки. Канонические сборки и склады не удалять. Переименование продукта не меняет эти пути данных.
- В shared-дереве сохранять чужой индекс и правки; коммиты, если разрешены, делать своими поимёнными путями. Скриншоты и личные данные в публичный git не помещать.
- Перед исправлением искать все вызовы, включая callbacks, overrides, сериализацию и отражение.
- Английские ресурсы первичны; русский перевод обновлять в парном .ru.resx. Числа читать и писать InvariantCulture: десятичная точка, без группировки разрядов.
- В новых русских текстах: импорт/экспорт, FSA, FWHM, гид. Старые журналы и цитаты не переписывать. Сохранять кодировку и фактические переводы строк по байтам.
- Делегирование и выбор моделей подчиняются возможностям и правилам текущей сессии. При разрешении разводить файлы и выходные каталоги; не больше трёх исполнителей разом.

## Работа в Codex

- Для поиска использовать rg и rg --files; файлы менять доступными средствами Codex. PowerShell запускать через exec_command, а не отсутствующий MCP прежнего приложения. При отказе доступа пользоваться штатным согласованием операции, не обходить его.
- Если требуется решение пользователя, пользоваться доступным вопросником Codex, например request_user_input_async; не запускать Plan-only инструмент в Default mode. Сначала находить ответы в проекте, спрашивать только оставшееся существенное.
- Для GUI использовать доступное управление компьютером и его инструкции. Старые имена MCP-инструментов не означают, что такой инструмент подключён.
- Прежние списки permissions.allow не переносились в настройки Codex. Не менять режим разрешений или доверия проекту ради миграции. Нынешнее поручение и ограничения среды определяют допустимые действия.
- Перед правкой проверять состояние дерева и сохранять чужие изменения. Пользоваться выбранным в проекте gh через PowerShell для GitHub; отправка сообщений, публикация и развёртывание требуют полномочий на соответствующее действие.
