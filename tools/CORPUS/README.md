### 1.2 Части: цифра называет свою

Матрица отклика считается **из геометрии** и **своя на каждую сцену**: один кристалл в
трёх расположениях источника даёт долю пика 0.848 / 0.822 / 0.815 и до четверти
разброса в континууме. Спектр с матрицей и спектр без неё разбираются РАЗНЫМИ
моделями, и сводка, смешавшая их, даёт среднее по двум моделям незаметно. Поэтому
корпус разделён (`scripts/split_corpus.py` → `corpus/parts.csv`), и **числа частей не
складываются никогда**.

**Решение Amber 09.08.2026: геометрия задаётся там, где сосуд и расстояние НАЗВАНЫ, и
нигде больше.** Выдумывать постановку по догадке нельзя.

| часть | сколько | что это |
|---|---|---|
| `known` — понятные | **92** | геометрия есть, матрица посчитана, образ полный (пик с континуумом, краем и пиками вылета) |
| `unknown` — непонятные | **36** | форма и положение пробы не записаны нигде; матрицы нет по построению |

`corpus/parts.csv` при каждой приёмке; форма строк — машинная.

Состав по группам: понятная — `G1S24` 43, `G1S16` 36, `AS80x80` 5, `RC103` 4,
`ASN16` 4; непонятная — `ASN16` 8, `AS80x80` 6, `GS4000` 4, `RC103` 4,
`ASN8_8192` 3, `LABR_BRIL` 2, по одному `ASN3`, `ASN8_1024`, `ASN8_2048`,
`ASN8_3000`, `ASN8_4096`, `OBS`, `RC101`, `AS1PRO`, `G1S16`.

Три правила раздела, каждое оплачено измерением:

* **Спектр без геометрии держится в корпусе НАРОЧНО** — как опора модели разрешения
  своей группы (решение Amber 16.08.2026). Он не «недоделанный понятный»; задачи
  «построить ему геометрию» по нему НЕ ЗАВОДЯТСЯ. Измерено: группа `AS80x80`,
  оставшись вдвоём вместо девяти, сдвинула модель разрешения, и у `AS80_Lu176`
  пропало опознание Lu-176 при живой геометрии, матрице и кривой.
* **Части НЕ независимы: они связаны через группу** — моделью разрешения и
  энергокалибровкой (`S48`). Подсказка разрешения стадии 2а берётся медианой по ВСЕЙ
  группе, и новый спектр любой части двигает калибровки всех спектров группы. Отсюда:
  **после любого изменения состава корпуса — хоть в непонятной части, хоть в
  исключённой — база понятной части снимается заново**, а не переносится.
* **Непонятная часть разбирается только там, где есть кривая.** Гейт `A277` «нет
  геометрии — нет FSA» (цена принята Amber 10.09.2026) оставляет разбор трём спектрам
  из 36 — тем, у кого узел кривой пришёл из исходного файла библиотеки
  (`AS80_Th232WT20`, `RC103_Th232WT20`; до 18.09.2026 третьим был `ASN16_Cs137`,
  ставший понятным по `B30`); остальные печатают
  `нет геометрии — разбора не было`. Σχ² и медиана непонятной части считаны ПО
  РАЗОБРАННЫМ, recall — по всем.

### 1.3 Группы детекторов (`corpus/detectors.csv`)

Группа = конфигурация устройства = одна модель разрешения. Модель живёт в кэвах
(`res_c0`, `res_c1`, `res_c2`, `ПШПВ² = c0 + c1·E + c2·E²`, свободный член нулевой
намеренно), спектр хранит её в каналах узлом `<PowerFwhmCalibration>` (степенная
форма `ПШПВ = a·E^p`, 114 спектров восьми групп: `AS80x80`, `ASN16`, `ASN8_8192`,
`G1S16`, `G1S24`, `GS4000`, `HPGE`, `RC103`) либо `<SqrtFwhmCalibration>` (17 спектров
остальных одиннадцати групп). Перенос в каналы — `corpus_calib.fwhm_channel_coef`
весом 1/ПШПВ² на линейной сетке от физичной энергии (`V11`); форма — по правилу
`res_apply.plan()` «низ лучше, верх не хуже, 0 < p < 1» (`V2`), и тем же планом
сторож `check_corpus.check_fwhm_node` судит, что узел ТОТ.

  год» 2024 шире у 11 пар из 12 (p = 0.0063). Группы делятся по ЭПОХЕ поверки, а не
  по экземпляру; читать их как годы, а не как номера приборов. Двенадцать прежних
  спектров `G1S_*` из внешней конверсии оказались побайтными дубликатами эталонов и

* **Германий (8 спектров, 3 группы) — вне работы** по приказу Amber 08.08.2026: в

* Рабочий диапазон групп — `e_lo` 20…30 кэВ, `e_hi` 2700…2800 кэВ.

**Решение Amber 04.09.2026: «прогоны корпуса по много часов на каждой задаче —
неправильный путь».** Частые замеры идут по малой базе; полный корпус — когда список

**Дорог не прогон, а СЦЕНЫ.** Разбор всего корпуса — секунды; часы съедает пересчёт
матриц, а матрица считается на сцену. Поэтому база собрана «поменьше сцен», а не
«поменьше спектров»: **59 спектров (понятных 45, непонятных 14) на 8 сценах** —
`ASN16_lu_side`, `ASN16_point0_house`, `ASN16_point10_house` (с 18.09.2026, `B30`),

G1S дают 38 понятных спектров ценой двух матриц. Состав построчно с причиной — в

### Как переобъявлять базу

Объявление — ЕДИНСТВЕННОЕ место, где база названа; шапка `TODO.md` и памятка —
дословные копии этой таблицы (`tools/check_registry.py` требует, чтобы все три
называли одну базу, ту же дату и пометку). Сторож `check_corpus_readme.py` берёт
действующие базы ТОЛЬКО из строк этой таблицы; любое другое имя `out_*` в документе —
снятая база по построению, и раздел с ней обязан нести пометку о снятии. Проще не
называть снятых вовсе.

Порядок (форма строки отпечатка — `T249`, грамматика заголовка — `check_registry.py`):

1. Прогон — только через `run_appwd.ps1` / `run_mini.ps1` (оператором вызова `&`), в
   свой `-Out`. В каталоге появится клеймо `.run.json`: `corpus`, `sources`, `head`,
   грязные файлы дерева, ключи пробы, sha256 `BecquerelMonitor.exe` и
   `CorpusFsaProbe.exe`. Старое клеймо снимается ДО запуска пробы, новое пишется только
   при коде 0 — отказавший прогон клейма не оставляет.
2. Открыть `.run.json` полной и малой — они обязаны совпасть по `corpus` и `sources`
   (иначе прогоны сняты с разных деревьев) — и переписать `corpus=…` и `sources=…` в
   строку отпечатка: одна строка сразу под таблицей, пары в обратных кавычках, вторая
   строка с `corpus=` в разделе запрещена (сторож отказывает как двусмысленное).
   `python tools/check_declared_base.py --fingerprints` печатает то же с ДЕРЕВА —
   годится, только пока дерево то самое.
3. `head=<коммит>` — только если стенд был чист (`dirty` в `.run.json` пуст); иначе не
   писать и закоммитить правки разбора ОДНИМ коммитом с объявлением. `run=none` не
   писать: это для каталогов, снятых до заведения клейма.
4. Заголовок раздела: `## ✅ ДЕЙСТВУЮЩАЯ БАЗА: DD.MM.YYYY (пометка) — …`; в шапке
   `TODO.md` — `⛔ **ДЕЙСТВУЮЩАЯ БАЗА КОРПУСА — DD.MM.YYYY (пометка): …**` с той же
   таблицей; памятку `corpus-base-current.md` — той же таблицей.
5. `python tools/check_declared_base.py`, `python tools/check_corpus_readme.py`,
   `python tools/check_registry.py` — код 0 до коммита; положительный контроль —
   `check_declared_base.py --corpus=<копия корпуса с одним подменённым спектром>`
   обязан дать 1.

Признаки годности объявления: recall 100 % и фантомов 0 на понятных частях обеих баз;
матрица найдена и применена у всех понятных; состав нуклидов назван поимённо, если
сменился; непонятная часть не сдвинулась там, где правка её не касается (у неё нет
матрицы — это отрицательный контроль всякой правки склада).

## 2. Как гонять

### 2.1 Полный корпус — кодом приложения

Прогонов два, и они меряют разное: **полноспектральный разбор** (`CorpusFsaProbe` из
оснастки `scripts/wd_<имя>`, один каталог на весь корпус) — основной; **поиск пиков**
(`scripts/wd_<группа>` по `mkconfig.py`, рабочий каталог на группу) — прогонялки по
всему корпусу у него сегодня нет, `probes/PeakFinderProbe.cs` разбирает один спектр.

Оснастка — изолированный каталог: приложение, пробы, поставочный `BecquerelMonitor.xml`,
приборы КОРПУСА (не `%AppData%\BecqMoni` — живой конфиг только на чтение), матрицы
склада по guid — и ⛔ **БЕЗ `NuclideDefinition.xml`** (`AMBER19`, §3.3). Список «что
откуда кладётся» живёт в ОДНОМ месте — `appwd_plan.ps1` (`Get-AppWdPlan`): по нему
`mk_appwd.ps1` копирует, по нему же сторож сверяет (sha256 всей оснастки, ~0.3 с;
время правки не годится — `Copy-Item` его сохраняет). Порядок: собрать приложение →
`build_all.ps1` → `mk_appwd.ps1` → `run_appwd.ps1`.

`run_appwd.ps1` сам добавляет пробе два ключа (видны в клейме прогона, `keys=`):
`--fit-floor-by=<Out>\xray_rule.csv` — правило корпуса §3.10 (список пишет
`scripts/xray_rule.py` в каталог прогона; плечо без правила — `-NoCorpusRules`, базой не
объявляется) — и `--audit` — сверка линий `lines_spline.csv` для мерки паспорта §3.11
(разбор от него не меняется ни в одном бите).

```powershell
& 'tools\CORPUS\scripts\mk_appwd.ps1'  -Bin '<абс>\BecquerelMonitor\bin\<сборка>' `
     -ProbeBuild '<абс>\tools\effmaker\probes\<каталог проб>' -Wd '<абс>\tools\CORPUS\scripts\wd_<имя>'
& 'tools\CORPUS\scripts\check_appwd.ps1' -Wd '<абс>\tools\CORPUS\scripts\wd_<имя>'   # приёмка оснастки отдельно
& 'tools\CORPUS\scripts\run_appwd.ps1'  -Out '<абс>\tools\pie\out_<имя>' -Wd '<абс>\tools\CORPUS\scripts\wd_<имя>'
# ключи пробы — массивом: -Extra '--weights=data','--only=ASN16_Cs137'
python tools/pie/score.py --mode=spline --out-dir=tools/pie/out_<имя> --part=known   --members
python tools/pie/score.py --mode=spline --out-dir=tools/pie/out_<имя> --part=unknown --members
```

* ⛔ **Обёртка, а не прямой запуск пробы** (`T68`): `cd wd_app; .\CorpusFsaProbe.exe`
  идёт МИМО сторожа оснастки и протухшую сборку не заметит. `run_appwd.ps1` — читатель
  отказа: сторож остановил — проба не запускается, код 2, в `-Out` ни одного файла;
  код 6 — план оснастки не строится, 64 — лишние аргументы, 65 — склеенный ключ.
* ⛔ **Звать оператором вызова `&`**, не `pwsh <файл>.ps1` и не `pwsh -File` (`T84`):
  при запуске файлом аргументы разбирает командная строка, и массив `-Extra`
  схлопывается в один элемент — молча, начиная со второго ключа. Приёмка числом —
  `check_appwd.ps1 -SelfTest`.
* ⛔ **`-Wd` принимается ТОЛЬКО вида `tools\CORPUS\scripts\wd_<имя>`** (`T91`), иначе
  отказ кодом 7: этот образец ждут `.gitignore` и умолчания сторожей.
* ⛔ **Пути — абсолютные** (`T136`): на относительных `mk_appwd.ps1` собирает ПУСТУЮ
  оснастку и отказывает лишь на самопроверке; `run_appwd.ps1` достраивает
  относительный `-Out` от каталога PowerShell сам, но проба запускается из оснастки.
* Умолчания разбора — умолчания приложения: режим `spline`, `--lib=sample`, веса по
  модели, равновесие ряда ВКЛ, перекладка фона ВКЛ, пол полосы по порогу АЦП;
  база снята без единого ключа (`keys` в клейме прогона пуст). Ключей `--sthr`/`--zthr`
  у пробы нет — это ключи `score.py`; `--share-thr=` — порог доли континуума
  развёртки полосы, не порог отбора.
* Полезные ключи пробы: `--only=<список>` — подмножество; `--weights=data|model`,
  `--no-matrix`, `--no-room`, `--no-atomic`, `--no-equilibrium`, `--no-background`,
  `--fit-floor=off`, `--anchor-zero=`, `--sum-light=`, `--loss-joint=`, `--refit-z-rel=`,
  `--angcorr=` — плечи A/B к умолчаниям; `--audit` — кросс-проверка по линиям, которые
  обязаны быть (`S60`, файл `lines_<режим>.csv`, итог полосами энергии);
  `--dump-curves=` — дампы модель/измерение для `wave_shape.py`; `--print-settings` —
  отражением из сборки, что именно включено; `--spoil=manager` — положительный
  контроль гейта библиотеки, обязан кончиться кодом 12.

**`score.py`** (`tools/pie/score.py`) считает по `manifest.csv` и `*_spline_components.csv`
попадания, фантомы и подавленные; печатает часть в шапке и в итоге ВСЕГДА.
Критерий «найден»: доля ≥ 0.30 % (`S90`, решение Amber: самый высокий порог, который
не стоит recall ни одной части) и z ≥ 4; **решение одно на цепочку** (`A280`, Amber
10.09.2026: цепочка принимается или отсеивается целиком по сумме долей и общему z);
промахи двух разрядов — `MISS` и `НИЖЕ-ПРЕДЕЛА` (`A279`, Amber 07.09.2026). Ключ
`--members` **обязателен**: разбор раскладывает цепочку на дочерние, и без разворота
Ac-228 / Pb-212 / Tl-208 идут фантомами, а «thorium» — промахом (recall вдвое ниже,
фантомов втрое больше). Колонка «подавлен» читается вместе с recall (`S95`): приборный
образ пересилил весь нуклидный состав. Колонка «комнатных» — вездесущие K-40 / Th-232 /
Ra-226, найденные там, где не объявлены: не фантомы, но сигнал про фон и пробу.

### 2.2 Малая база


Скрипт зовёт сторожа оснастки, гонит пробу по списку `corpus/mini.csv` и следом
`score.py --only=<тот же файл>` по обеим частям — двум спискам разойтись нечем
(`S137`: без `--only` recall считается против ВСЕГО манифеста и для подмножества
ложен по построению — спектр, который не гоняли, идёт промахом). Сторож покрытия при
этом не отключён: упавший спектр без строк выходит «НЕТ РЕЗУЛЬТАТА».

* `-List <свой>.csv` (уточнение Amber 10.09.2026) — свой список тем же форматом:
  **третья выборка**, не «малая база плюс спектр». Её числа не сравнимы ни с малой
  базой, ни с полным корпусом, переобъявлять ею базу нельзя; требует своего `-Out`.
  Матриц скрипт не считает: добранная сцена понятной части требует своей матрицы в
  складе, иначе разбор напечатает «БЕЗ МАТРИЦЫ» строкой, которую легко принять за
  норму непонятной части.
* Отдельного склада у малой базы НЕТ: матрицы берутся из штатного склада корпуса;
  плечо с другим складом — ключи `-Store`/`-Wd`/`-Bin`/`-ProbeBuild` (§2.3).
* Плечо считается в СВОЙ `-Out`: подменить им объявленный каталог — та самая смесь
  поколений, ради которой написан `check_declared_base.py` (`T248`).

### 2.3 Плечо A/B по ключу физики склада

⛔ **Оба конца обязаны идти ОДНИМИ двоичными файлами и различаться ТОЛЬКО складом.**
Плечо, собранное другой сборкой, отличается от контроля двумя вещами сразу, и разность
приписывается ключу.

```powershell
$r = (Get-Location).Path
$arm = "$r\tools\effmaker\out\<склад плеча>"
# 1. матрицы сцен плеча — в СВОЙ склад; базовый не трогается вовсе
Push-Location "$r\tools\effmaker\probes\<каталог проб>"
.\CorpusMatrixProbe.exe "--dir=$arm" --only=<сцены через запятую> --<ключ>=<значение>
Pop-Location
# 2. разложить их по guid ВНУТРИ своего склада
python tools/CORPUS/scripts/mx_swap.py "--from=$arm" "--into=$arm"
# 3. оснастка плеча — те же двоичные файлы, склад свой
& 'tools\CORPUS\scripts\mk_appwd.ps1' -Bin "$r\BecquerelMonitor\bin\<сборка>" `
     -ProbeBuild "$r\tools\effmaker\probes\<каталог проб>" -Wd "$r\tools\CORPUS\scripts\wd_<имя>" -Store "$arm"
# 4. прогон
& 'tools\CORPUS\scripts\run_mini.ps1' -Out "$r\tools\pie\out_<имя>" -Wd "$r\tools\CORPUS\scripts\wd_<имя>" `
     -Bin "$r\BecquerelMonitor\bin\<сборка>" -ProbeBuild "$r\tools\effmaker\probes\<каталог проб>" -Store "$arm"
```

* Плечо по ключу РАЗБОРА (не склада) проще: тот же `run_mini.ps1`/`run_appwd.ps1` с
  `-Extra '--<ключ>=…'` в свой `-Out`, оснастка та же.
* Настройку проверять на ПЕРВЫХ ДВУХ сценах, а не на всех: на второй матрице видно то
  же, что на сорок четвёртой, а цена узнать различается на часы (`A77`).
* Плечо в полном качестве стоит ~8 минут на сцену; дешевле считать ОБА конца
  облегчённо — меряется разность, — но числа такого плеча ставятся только рядом со
  своим контролем, не рядом с базой.
* Матрица, посчитанная абляционным ключом, у которого нет пары в `CorpusFsaProbe`,
  разбором ОТВЕРГАЕТСЯ по клейму: абляциями сравнивают матрицы (`MatrixDiffProbe`), а
  не гоняют по ним спектры.
* Сверять плечи по ключу спектр/компонент, не по заглавным числам; побитовое
  совпадение `components`/`limits` при расхождении только `ms`/`cpu_ms` — норма.

### 2.4 Пересборка корпуса — четыре шага одной командой

```
python tools/CORPUS/scripts/rebuild_corpus.py --from-library
python tools/CORPUS/scripts/rebuild_corpus.py --dry     # показать шаги, не запуская
```

⛔ **Пересборка — ЧЕТЫРЕ шага, а не один** (`T61`), и они гонятся одной командой,
которая останавливается на первом отказе — недособранный корпус хуже
непересобранного, потому что выглядит целым:

1. `build_corpus.py --from-library` — копии спектров, устройства, манифест, узел ПШПВ
   КОРНЕВОЙ формы всем; без рабочих копий девятки в `scripts/spectra` (каталога нет в
   git — в worktree скопировать из основного дерева и сверить sha256 со строками
   `scope=legacy` в `corpus/inputs.csv`) — ОТКАЗ кодом 3 до первой записи (`S196`);
2. `restore_eff_nodes.py --apply` — вернуть узлы `<Efficiency>` из git (сборщик о них
   не знает и стирает, `T30`); узел сверяется с git ДОСЛОВНО, а не по имени геометрии;
   кому положено — всем с геометрией (`W29`, решение Amber 24.08.2026); ключ `--scope=`;
3. `res_apply.py --mode=power-node --apply` — степенной узел ПШПВ (`V2`); без него Σχ²
   хуже на треть;
4. `check_corpus.py` — приёмка.

Правила пересборки:

* **Корпус держит свои копии сам и в чужую папку не лезет** (правило Amber 16.08.2026,
  дословно: «корпус должен хранить СВОИ копии у себя и не лезть в мою папку, если я
  этого не разрешил», `B8`). Без `--from-library` `build_corpus.py` ничего не читает и
  не пишет (код 2); всё остальное — приёмка, раздел, сводка, прогон — читает копии из
  `corpus/spectra`. Сырьё (~145 МБ) в репозитории не хранится: корпус самодостаточен
  для чтения, а не для пересборки.
* **Сторож входа — `corpus/inputs.csv`** (`B10`): при полной пересборке пишется
  отпечаток входа и сверяется с прежним ТРЕМЯ слоями — «ФАЙЛ ПОЕХАЛ» (sha исходника),
  «ОТБОР ПОЕХАЛ» (точки модели при том же файле), «МОДЕЛЬ ПОЕХАЛА» (сами `res_c`).
  Одна пересохранённая в приложении шапка исходника двигает калибровку фона, отбор
  линий, модель разрешения группы и правило `same_setting` соседей — девять спектров
  от одного файла; сторож называет виновника, решение — за человеком.
* Пересборка и приёмка держат взаимный замок (`corpus_lock.py`, `A75`): пересборка
  переписывает те же файлы, что приёмка читает.
* `bg_from_spe.py --apply` — не питон-шаг конвейера, зовётся отдельно: возвращает
  спектрам G1S ПОЛНЫЙ фон из оригинального `.spe` (сторонний конвертер обрезал
  верхние каналы, и анализатор такой фон молча отбрасывал, `S44`). Серии поверки
  накопительные — берётся последний файл, складывать их нельзя.
* Полный порядок всего конвейера, сверху вниз:

```
python scripts/library_inventory.py     # опись исходной библиотеки спектров
python scripts/library_screen.py        # отбор кандидатов
python scripts/rebuild_corpus.py --from-library   # четыре шага выше
python scripts/bg_from_spe.py --apply   # полный фон из оригиналов поверки (S44)
corpusgeomprobe                         # геометрии понятной части -> corpus/geometries/*.in + index.csv
corpusmatrixprobe                       # матрица на каждую -> corpus/geometries/*.rmx
corpuseffprobe                          # кривые + узлы Efficiency в спектры + response/<guid>.rmx
python scripts/split_corpus.py          # раздел -> corpus/parts.csv
python scripts/mk_materials.py          # вещества -> corpus/materials.csv
python scripts/check_corpus.py          # приёмка
python scripts/corpus_summary.py        # сводка -> corpus/SUMMARY.md + summary.csv
python scripts/corpus_stamp.py          # клеймо генератора (пишет сборка) против дерева
```

Порядок проб — **Geom → Matrix → Eff**, и он важен: `CorpusEffProbe` кладёт
`response/<guid>.rmx` копированием уже посчитанных матриц, до `CorpusMatrixProbe`
копировать нечего. `check_corpus.py` — приёмка с кодом возврата: калибровки (медиана
промаха в долях ПШПВ ниже 0.25), узел ПШПВ той формы, что положено (`check_fwhm_node`,
ОТКАЗ), матрица ИМЕННО в том файле, который грузит разбор (`check_response_store`, по
guid узла, ОТКАЗ), состав сцены против заголовка спектра (`check_composition`,
напоминание), вещества (`check_materials`), покрытие раздела (`check_parts`),
строки `manifest.csv` против `parts.csv` и `corpus_def` (`check_manifest`, `S196`, ОТКАЗ),
клеймо генератора.

### 2.5 Склад матриц: считать только изменившееся

Указание Amber 16.08.2026 (`B16`): «пересчитывать только то, что изменилось.
ГЛОБАЛЬНЫЙ пересчёт нужен только когда изменилась картина ЦЕЛИКОМ — например новая
версия физики». `CorpusMatrixProbe` и `CorpusEffProbe` сверяют клеймо и пропускают
готовое; отдельного ключа «пересчитать всё» НЕТ нарочно — поднялась физика, клеймо не
сойдётся у всех, и пересчёт станет глобальным сам. `--force` — пересчитать вопреки
сошедшемуся клейму. Гвард не понижает качество: матрица, посчитанная гуще требуемого,
пропускается с прямым сообщением.

* Единый счёт склада при смене физики: `CorpusMatrixProbe --dir=<склад> --threads=10
  --target=0 <ключи физики>` в СВОЙ каталог (worktree или `D:\BqMoni_Claude\<полоса>\`),
  приёмка `MatrixAuditProbe --phys=<N>` обеими половинами (склад и `response/`),
  перенос в живой склад по sha256 с обеих сторон, снимок прежнего склада — вне git.
  ⛔ Перед счётом дольше получаса — пересобрать каталог проб и убедиться, что сборка
  ПРОШЛА (`A77`): старый двоичный файл ест новый ключ по-старому и молча.
* `scripts/mx_swap.py --from=<склад> --into=<каталог>` — разложить матрицы по guid;
  `--store` — в `response/` склада, `--wd` — в оснастку. `scripts/store_vs_wd.py`
  (`A79`) — сторож перекладки: склад против каталога прогона ПО КЛЕЙМУ;
  `scripts/audit_wd.py` — приёмка каталога прогона именами guid. Правило: приёмку
  звать ДВАЖДЫ — по складу и по тому каталогу, откуда читает разбор.
* Порог шума матрицы 5 % назначен, безопасная цель по измерению — 3 % (`T35`,
  `scripts/mx_noise.py`): ниже 3 % разбор шума не замечает, сразу за 5 % платит.
  ⛔ **Рецепт склада: `--threads=10 --target=0 --n=3000000`; ДАЛЬНИМ ТОЧКАМ — ×2
  (`--n=6000000`)** — решение Amber 18.09.2026, вопросником, дословно: **«Добить
  историями ночью: дальним точкам ×2»** (прежнее «историями не добивать» этим снято);
  исполнено П103 единым счётом физики 20, П107 — физики 21, П114 — физики 22, П140 — физики 23, П161 — физики 24, П180 — физики 25 и П185 — физики 26. Густые сцены — `RC103_point50`,
  `ASN16_point10_house`, `G1S_point25` (дальняя точка у малого кристалла: шум худшего
  узла 11…12 % при 3 000 000, при 6 000 000 — в √2 ниже); реестр — `DENSE_SCENES` в
  `tools/check_corpus_scenes.py` (одно место; сторож принимает матрицу густой сцены
  РАВЕНСТВОМ клейма с клеймом сцены при `MatrixStampProbe --hist=x2`, а не «историй
  больше»). Считать их отдельным вызовом `--only=<три сцены> --n=6000000` ПЕРВЫМ, затем
  остальные без `--only` и без `--force` — гвард `T36` густые пропустит как «ГУЩЕ
  штатной»; `--force` во втором вызове затёр бы их штатной густотой. Четвёртая шумная —
  `RC103_marinelli05_kcl` (8.8 %, маринелли без зазора у торца) — не дальняя точка,
  правило её не касается.
* Две страховки перед любым пересчётом склада: копия файлов с sha256 (`.rmx` вне git,
  из истории их не вернуть) и карта «сцена → guid» (`scripts/wd_key_guid.csv`,
  побайтовым совпадением `<ключ>.rmx` с `response/<guid>.rmx`).
* Разбор берёт матрицу из `config/device/response` РАБОЧЕГО каталога по guid кривой, а
  не из корпуса по ключу сцены; `mx_swap.py --wd` подменяет её в оснастке, корпус не
  трогая.

### 3.1 ⛔ Первый постулат: у каждого спектра — СВОЯ база пиков, привязанная к снятому нуклиду (Amber 17.08.2026, `S56`)

первому подходящему кандидату. Цена измерена (`N18`): `ASN16_Lu176` получал Pu-238
долей 1.7 % при z = 31.77 на единственной линии 152 кэВ в 0.0009 %, севшей в полосу
обратного рассеяния линии 306.78 самого лютеция.

Что предъявляется спектру (сборщик — `FsaSampleLibrary`, источник — базы, не конфиг;
ни `NuclideDefinition.xml`, ни `NuclideSet` не участвуют):

| откуда | что берётся | куда |
|---|---|---|
| `manifest.csv`, колонка `chains` | весь равновесный ряд родителя обходом `nucdb.decay_chain` от корня с накопленным ветвлением; хвосты ветвей ниже 10⁻³ отсекаются | один образ на ряд |
| `manifest.csv`, колонка `nuclides` | одиночный нуклид поверх рядов | свой образ |
| `nucdb.decay_radiations`, типы `G` и `X` | гаммы И рентген распада, K- и L-серия — **база собирается из ВСЕХ излучений, а не из гамма-линий** (у Lu-176 низ спектра держится на K-рентгене гафния 54…65 кэВ) | линии образа |
| всегда | вездесущие K-40 / Th-232 / Ra-226 — NORM обходом `decay_chain` от 232TH и 226RA | свои образы (плечо `--no-room`) |
| `materials.csv` + геометрия спектра | K-серия пробы, кристалла и защиты; L-серия тяжёлых элементов пробы и защиты отдельным образом `Xray-<эл>-L` со своей амплитудой (`AMBER10`; у кристалла L-вылет считает перенос) | мешающие образы `Xray-*` |

* **«Везде, где не знаешь, суй NORM — не из `NuclideDefinition`, а из базы»** (Amber
  18.08.2026). Найденный после вычитания фона природный ряд — не выдумка разбора, а
  NORM пробы либо недовычтенный фон («по сути да, там NORM»); мерка считает такие
  компоненты колонкой «комнатных», не фантомами.
* **Изомеры в состав не идут — кроме ряда U-238** (Amber 18.08.2026): Pa-234m несёт
  линию 1001.03 кэВ, без него ряд остался бы без сильной линии.
* **Атомные образы кладутся ВСЕМ спектрам** (Amber 18.08.2026), включая те, у кого
  матрица считает ту же физику сама: это сознательное второе счетоводство и опора
  кросс-проверки по линиям, которые обязаны быть (`S60`, `--audit`).
* Метку изомера от символа отделяет РЕГИСТР, а не буква: «241AM» — америций,
  «234PAm1» — изомер; правило «хвост m — изомер» ломает 176 нуклидов базы.
* ⚠ **Мерки меняют смысл:** recall и фантомы считаются относительно предъявленного
  списка, и сужение списка улучшает их само по себе; сравнивать прогон с иным списком
  напрямую нельзя. Узкая база (семь линий) уводит подгонку усиления на край сетки —
  при узкой базе сетку расширять или закреплять калибровку.
* На фон `AS80_Lu176` не ориентироваться — он плохой (решение Amber 18.08.2026,
  пересъёмка `S52`); чинить съёмкой, а не подбором.

### 3.2 Части не смешивать; цифра называет часть (Amber 09.08.2026)

§1.2 целиком: числа частей не складываются; сводка без названной части
недействительна — не потому что неточна, а потому что неизвестно, что в ней смешано;

### 3.4 ⛔ Опора НИЗА шкалы — рентген (`B25`, решение Amber 10.09.2026)

Ниже ~45 кэВ у образцов корпуса нет ни одной гамма-опоры (самые нижние: Ba-133 53.16,
Am-241 59.54, Cd-109 88.03, Lu-176 88.34), и без опоры низ шкалы продолжается прямой
(`B24`). Решения Amber 10.09.2026, вопросником, дословно: «Рентген в опоры — только
как опора НИЗА», «Все спектры корпуса с рентгеном внизу», «Пересобрать корпус и сразу
прогнать базу целиком». Это точечное снятие запрета `V27`: наверху шкалы рентген
опорой по-прежнему не бывает. Опору низа получили 33 спектра (метка `/xlow` в
`ecal_mode`).

Правило `build_corpus.add_low_anchor`:

| постоянная | значение | чем держится |
|---|---|---|
| `LOW_ANCHOR_KEV` | 45.0 | нет гамма-опоры ниже; порог 60 резал бы Am-241 по касательной |
| `LOW_ANCHOR_MIN_KEV` | 15.0 | ниже — порог АЦП: максимум есть, энергии нет; то же число, что `corpus_calib.E_MIN_PHYSICAL` |
| `LOW_ANCHOR_MIN_PURITY` | 0.80 | доля рентгена в группе; K-серия одного элемента — одна структура, не загрязнение |
| `LOW_ANCHOR_MIN_INTENSITY` | 3.0 | выход линии, % |
| `LOW_ANCHOR_MIN_SIG` | 8.0 | выше штатной 5.0: опора ищется широким окном, ложная находка дороже |
| `LOW_ANCHOR_TOL_FWHM`, `LOW_ANCHOR_WIDTH` | 3.0; 0.30…3.0 | допуск положения и ширины |

Рентген ищется по ЛОКАЛЬНОМУ МАКСИМУМУ, а не по шкале (`match_low_anchor`): штатный
поиск его не находит — гауссиана садится на монотонный спад. Структура внизу
принадлежит ОБРАЗЦУ, а не прибору: у всех спектров G1S16 первый ненулевой канал один и
тот же, а максимум внизу движется с энергией рентгена образца. Плата за правило есть,
и она в положении линий выше 200 кэВ (+13 % Σ|промах| по независимой мерке
`ecal_compare.py`), а не в разборе.

⛔ **K-серия опоры — правилом приложения, Kβ ОДИН раз** (`S209`, П205 01.10.2026). `KB` в
`decay_radiations` — итог Kβ, рядом лежит его разложение `KpB1` + `KpB2`; до 01.10.2026
генератор складывал оба, и центр K-опоры стоял выше на 1.7…2.2 % (Ba-133 32.29 кэВ вместо
31.67, Cs-137 33.45 вместо 32.92, Cd-109 23.01 вместо 22.61). Теперь `chains.k_series_rule`
(зовут `chain_lines` и `build_corpus.xray_lines`) повторяет `KSeriesRule.cs`: разложение,
если оно полное, иначе итог; строка K-M — на центре тяжести `matdb.fluorescence_k.kb_ev`
(`AMBER120`); константы правила ЧИТАЮТСЯ из `KSeriesRule.cs`, клеймо генератора держит
этот файл и таблицу `matdb.sqlite#fluorescence_k` (не весь `matdb`). Порог выхода 0.5 %
у одиночного нуклида — на линию, у K-серии — на её сумму (группа идёт в опору целиком).

⛔ **Подсказка разрешения группы — с гистерезисом** (`S209`). Подсказка стадии 2а (медиана
FWHM/√E опор группы) записана в `data/res_hint.csv` и держится, пока новая медиана в
полосе ±`RES_HINT_HYSTERESIS` (2 %); дальше берётся новая и записывается (только полной
пересборкой). Без этого набор опор зависел от сотых долей модели группы: при подсказке
×(1 ± 0.0005) сменился у 21 спектра из 129 (`ASN16_Lu176_P0` — 166 кэВ шкалы). Приёмка —
`python scripts/stability_probe.py` (код 0: ±0.05 % не меняет набор опор ни у одного
спектра; `--scales=0.97,1.03` — положительный контроль, `--no-hysteresis` — прежнее
поведение). Сглаживать пороги по одному не выход, и это измерено: дробные края окна
гауссова фита сдвинули шкалу у 119 спектров из 129 и оставили неустойчивыми 37.

### 3.5 Связка ряда одной амплитудой (`S70`, Amber 18.08.2026)

Галка «Равновесие» — умолчанием ВКЛЮЧЕНА: ряд идёт в разбор ОДНОЙ колонкой с одной
свободной амплитудой, относительные веса закреплены ветвлением; выключена
(`--no-equilibrium`) — у каждого члена своя амплитуда, чем и видно неравновесие. Связка
снимает вранье по построению (свободные амплитуды на чистом ториевом источнике давали
Ra-224 30 % при положенном ≈1 %) и стоит невязки там, где модель плоха: свободные
амплитуды членов ряда прячут ошибку модели, выдавая её за неравновесие.

### 3.6 Фон

* **Фон вычитается с β = 1:** нормирован по живому времени, свободной амплитуды у фона
  нет (иначе NNLS, взяв фон первым, объясняет им K-40 пробы).
* **Фон перекладывается в шкалу спектра** (`FsaAnalyzer.RebinBackgroundToSpectrum`,
  `S45`): отсчёты распределяются по перекрытию энергетических окон, границы — из
  центров каналов. Фон, снятый в той же настройке (расхождение шкал ≤ 0.30 ПШПВ,
  `build_corpus.same_setting`), получает калибровку ПЕРЕДНЕГО ПЛАНА («как передний
  план/S45» в манифесте, 79 спектров): у бедного линиями фона своя калибровка хуже, и
  перекладка по ней вносила сдвиг, а не снимала.
* **Спектров без фона не держим** (Amber 15.08.2026): сперва привязывается фон своей
  группы, если он есть; фоновые спектры — доноры фона, а не самостоятельные образцы.
* Сигнал «фон не взят» имеет читателя: `FsaResult.BackgroundRejected`, колонка
  `bg_rejected` и строка «ФОН НЕ ВЗЯТ» у `CorpusFsaProbe`.

### 3.7 Оснастка и прогоны

* Обёртки вместо прямого запуска пробы (`T68`), оператор `&` (`T84`), `-Wd` только
  `scripts\wd_<имя>` (`T91`), пути абсолютные (`T136`) — §2.1.
* Оснастка сверяется по sha256, не по времени; «оснастка свежая» — вердикт сторожа,
  а не дата файла.
* Копировать файл в оснастку мимо `mk_appwd.ps1` нельзя: состояние «приложение свежее,
  пробы старые» никакой сторож не видит; отказал сторож — собирать в ДРУГОЙ каталог.
* Числа считаются оптимизированной сборкой (Release), отладочная — вдвое дольше при
  побитово равном результате; свой каталог сборки полоса снимает после приёмки.
* Мерить ЦП-временем на историю, а не часами: `CorpusMatrixProbe` печатает время на
  часах, долю ядер («МАШИНУ ДЕЛИМ») и ЦП на историю — сравнивать между прогонами
  надо последнее.
* Замер посреди чужого счёта мерит смесь: полный корпус и склад — не тогда, когда
  машина занята другой полосой.

### 3.8 Полный корпус — только по слову Amber

Малая база — умолчание для каждой задачи (Amber 04.09.2026, 10.09.2026, §1.8); полный
корпус и единый счёт склада запускаются словом Amber — как ночные полосы, с журналом и

### 3.9 Харнесс `tools/pie` — независим

Полноспектральный харнесс `tools/pie` (доматричный, свой решатель) — законная
независимость отдельного инструмента (решение Amber 05.09.2026, `T71`): его сетка

### 3.10 ⛔ Рентген точечных источников ЛСРМ ниже ~30 кэВ в амплитуду не идёт (`AMBER153` (б), Amber 01.10.2026)

Решение Amber 01.10.2026 вопросником, дословно: **«Правило корпуса: рентген не в
амплитуду (Рекомендую)»**; капсулу источника НЕ моделировать, множителя рентгена в
разборе НЕ вводить.

**Почему.** Источник ОСГИ сидит в капсуле, а сцена корпуса (`G1S_point5`,
`G1S_point25`) описывает его точкой в воздухе. Капсула гасит мягкий рентген: 22 кэВ Ag K у
Cd-109 в данных 0.22…0.49 паспортного ожидания при 88 кэВ на месте — подпись 0.05…0.1 мм
стали (П191, прямой счёт `AS80_point5.in`). Разбор ведёт амплитуду за самым сильным
пиком, то есть за рентгеном, и активность Cd-109 выходила 0.62…0.82 паспорта. Участок
ниже 30 кэВ у этих спектров мерит СЦЕНУ (неописанную капсулу), а не разбор.

**Как.** Полоса ФИТА такого спектра начинается с 30 кэВ: каналы ниже в χ² не входят,
амплитуду держат линии выше. Ставится ключом пробы `--fit-floor-by=` (пол на время
разбора ЭТОГО спектра, прочие — побитово как без ключа); список кладёт `run_appwd.ps1` в
каталог прогона (`xray_rule.csv`), его пишет `scripts/xray_rule.py`. Пустой список —
отказ прогона (код 67): правилу некому — значит, манифест или база потеряли паспорта.

**Кому** — спектру с ОБОИМИ признаками: (1) точечный ЛСРМ — паспорт «паспорт: Xx-NNN A=…
Бк dA=…% дата» в `manifest.why` и `SourceType` = Point в геометрии файла; (2) у
объявленного состава есть фотоны (γ или рентген `nucdb`, выход ≥ 1 %) в полосе 18…30 кэВ —
правилу есть что убирать. 18 кэВ — пол библиотеки по кривой у этих сцен (18.2…18.4 кэВ,
`--band-audit=`): ниже линий в образах нет вовсе. Сегодня это 6 спектров: Cd-109
(`G1S16_Cd109_P5`, `_P25`, `G1S24_Cd109_P5`; Ag K 22.0…25.5 кэВ) и Am-241
(`G1S16_Am241_P5`, `_P25`, `G1S24_Am241_P5`; Np L 18.0/20.9 кэВ, γ 26.3 кэВ). Имён
нуклидов в правиле нет — состав из манифеста, линии из базы.

| признак | цена, которой держится (малая база, П214 02.10.2026) |
|---|---|
| пол 30 кэВ, а не 60 (полоса П191 «по одной γ 88 кэВ») | число из решения; Cd-109 к паспорту 0.618 / 0.819 / 0.798 → **0.907 / 0.963 / 0.992** (G1S24 P5 / G1S16 P5 / G1S16 P25), хвост Ag Kβ выше 30 кэВ ещё держит G1S24 на −9 % (полоса от 60 давала 0.944) |

| Am-241 в правиле | +0.8…+1.9 % к паспорту (0.954 → 0.961, 1.048 → 1.067, 0.980 → 0.994) — L-рентген Np в амплитуде почти не весит, но признак (2) у него есть |

recall, фантомы, подавленные — без перемен; непонятная часть не тронута.

### 3.11 Мерка паспорта: активность против паспорта (`AMBER153` (а), П214 02.10.2026)

Recall и χ² спрашивают «назван ли нуклид» и «как легла модель», но не «СКОЛЬКО его».
`tools/pie/score.py` с П214 печатает после всех итогов **таблицу «разбор / паспорт»**
(счёт — `tools/pie/passport.py`, запускается и отдельно): у каждого спектра с опорой в
`manifest.why` — `decay_s` компонента против паспорта, приведённого распадом на начало
набора (`StartTime` файла; период — `nucdb`); объёмные эталоны (Бк/кг) — × масса = ρ ×
объём сосуда ПО ГЕОМЕТРИИ ФАЙЛА (масса сценная, не взвешенная). Опоры трёх видов:
паспорт точечного ЛСРМ (Бк), объёмного ЛСРМ (Бк/кг), чек-источник Amber («на дату
съёмки … — … Бк»). Порог — **±(dA + 3 %)**; итог — сколько вне порога и медиана по
группам «прибор · сосуд». Ниже — **верх шкалы**: отношение «изм./ожид.» верхней линии к
опорной у одного компонента по сверке линий (`lines_spline.csv`, ключ `--audit`):
2614/239 у ряда тория, 1836/898 у Y-88, 1770/570 у Bi-207 — мерка прибора/сцены, от
паспорта не зависит. Метрика — МЕТКА: ни одна графа итога от неё не меняется.

⚠ Читать её по группам, а не одним числом: на rev39 (полная понятная, 80 нуклидо-спектров,
вне порога 38) занижение у точек 5 см −4…−5 % у всех нуклидов (геометрия сцены, 2…3 мм по
1/(d + d₀)², П191), у маринелли медианой −7…−10 % (Cs-137 до −16 %), у цилиндров (Дента, Петри) медианой −12 % (G1S16) и −22 % (G1S24);
контактные сцены приборов Amber (`ASN16_Cs137` 1.164, `RC103_Cs137_50mm` 1.234) — торец
и опорная плоскость сцены (`AMBER153`, дописки). Паспорт первичен (§1.4): расхождение —
свойство сцены или разбора, не повод сомневаться в паспорте.

| `score.py` всегда с `--members` | без разворота цепочек recall вдвое ниже, фантомов втрое больше — выглядит как обвал физики |
| `score.py` на подмножестве — с `--only=<тот же список>` | recall против всего манифеста: «итого 79, recall 48 %» на 42 спектрах |
| различие плеча < 0.3 Σχ² — шум | два прогона одной настройки расходятся на 0.3 |
| матрица считается на сцену: новые сцены — `--only=`, плечо — в свой склад | `CorpusMatrixProbe` без `--only` трогает ВСЕ сцены и молча вернул густую матрицу к штатной густоте (`T36`) |
| `CorpusEffProbe` — только когда узлы надо пересчитать; вернуть узлы — `restore_eff_nodes.py` | проба переписывает `<Efficiency>` ВСЕМ спектрам сцены и трогает данные корпуса; 35 минут на кривые, которые не менялись |
| приёмку склада звать по складу И по каталогу прогона | 37 спектров считались без матрицы при «СОШЛОСЬ»: проверялся `<ключ>.rmx`, разбор читал `response/<guid>.rmx` (`B14`) |
| «узел есть» и «узел ТОТ» — разное: сверять с git дословно | закреплённые спектры несли узел прежней эпохи под тем же именем геометрии; понятная часть 83 из 84 |
| узел `<Efficiency>` снимать разбором XML, не регэкспом | внутри узла каждая точка кривой записана тем же тегом (35 вхождений на файл): первый закрывающий — у точки, файл битый |
| набивка сосуда — из заголовка спектра, эпоха в ключе сцены | одно имя вещества на две поверки: 24 спектра G1S24 считались чужим составом, семь сцен были общими у двух эпох (`B13`) |
| одна геометрия — одна кривая; узлы новым спектрам — копией от соседа по сцене | узлы, поставленные копией, матрицы не приносят — `response/` кладёт только `CorpusEffProbe` |
| приёмка — по клейму и содержимому, не по mtime | `Copy-Item` сохраняет `LastWriteTime`; подмена при равном времени временем не видна; все 44 матрицы лежали свежие и все были негодны (`phys=12` против 14) |
| `-Out` абсолютный | проба запускается из оснастки: `-Out tools\pie\…` ложится в `wd_app\tools\pie\…`, код 0 |
| `& <файл>`, не `pwsh -File` | массив `-Extra` схлопывается со второго ключа, проба говорит «неизвестный ключ» |
| одна пересохранённая шапка исходника — девять спектров | калибровка фона, отбор линий и модель группы уезжают от одного файла; читатель — `inputs.csv` |
| замер сцены Amber — тем, что видит человек, не корпусной копией | у копии своя шкала: пик рентгена бария уехал на 8 кэВ (23.6 вместо 32) |
| прежде чем искать новому горбу источник — не бок ли это соседней линии | избыток 51.1 кэВ был низким плечом линии 55.786 при ПШПВ 10 кэВ; поскользнулись дважды |
| невязку мерить окном ПО ПШПВ, не фиксированной ширины в каналах | «гребёнка с шагом 46 кэВ» была сеткой самого окна (16 каналов × 2.9 кэВ) |
| абляционная матрица — для сравнения матриц, не для прогона | разбор отвергает её по клейму: ключ пишется в клеймо, парного ключа у пробы нет |
| ключ должен доехать до построителя; проверять на первых двух сценах | старый двоичный файл счёл `--cone=far` «не нулём» и включил конус всем 44 сценам; три часа счёта (`A77`) |
| поле с несколькими видами узла: «удалить свой и дописать» ≠ «заменить» | чужой вид `SqrtFwhmCalibration` переживал подмену и выигрывал молча — ядро поиска 163 канала вместо 243 (`B18`); снимаются все три вида |
| `'<Efficiency>' in text` — не проверка узла; узел — по `<Guid>` за открывающим тегом | подстрока встречается 35 раз в любом файле с кривой |
| пути библиотеки — через `corpus_paths.py` | имена в NFD: `os.path.isfile` отвечает False на существующий файл |
| таблица правды нового спектра — у того же спектра | чароит на RC103 с чужой разметкой (обе цепочки плюс калий) давал промах по торию и калию |
| часть корпуса связана через группу | втягивание трёх Lu-176 сдвинуло `AS80_Cs137_0cm` 5.16 → 14.59 при неизменном составе понятной части |
| фон накопительной серии — последний файл, не сумма | серии `_01…_15` включают предыдущие |
| один прогон, одна сборка, одна оснастка на все плечи | плечи разными сборками сравнивают сборки, а не модели; правка кода во время замера рвёт развёртку |

## 5. Чего корпус не даёт — известные цены и пределы

* **Уровень кривых ближней зоны у G1S завышен** (сосуды +23…+47 %; точечные после
  +7 мм — 25 см +3 %, 5 см +10 %, до 18.09.2026 было +8 % и +34 %; обвязка пресета
  заимствована, `E15` — «не будет»). На разложение со
  свободными амплитудами влияет слабо, на активности — прямо.
* **Близкие точечные постановки `_P5` хуже дальних `_P25`** на ~4 пункта невязки
  модели (14 пар из 15) без названной причины: кандидаты дерева отвергнуты замером,
  данных о держателе/коллимации G1S не добыть; закрыто как известная цена (`S61`,
  решение Amber 12.09.2026 «Закрыть как известную цену»).
* **Волна модель/измерение в полосе 60…450 кэВ** — известная цена (`S91`, то же
  решение 12.09.2026): штатные узлы континуума 4·ПШПВ дают медиану rms ~12 %, узлы
  1·ПШПВ — ~5 %; Хубер — не держатель волны. Мерка для любой правки континуума —
  `wave_shape.py --batch --from=60 --to=450` по дампам `--dump-curves=`: медиана rms
  малой понятной части ниже 5.0 % при не ухудшенном Σχ² и составе 100 % / 0.
* **Непонятная часть почти не разбирается** (гейт `A277`, два спектра из 36): её
  recall 5 % — свойство гейта, а не модели; сравнивать с прежними правилами нельзя.
* **Контакт RC103 — свойство постановки впритык, а не только геометрии** (`E43`, П73/П76):
  зазор 3.5 мм сшивает контакт (изм/ожид 0.443 → 0.995) ценой точки в 50 мм от корпуса
  (`RC103_point50`, с 18.09.2026 в корпусе спектром `RC103_Cs137_50mm`: 1.05 без зазора →
  **1.19** с зазором 3.5 мм, rev29) — на контакте есть ещё положение
  источника у корпуса (боковое смещение/капсула), которого две осевые точки не разводят;
  активности контактных съёмок RC103 читать с этой оговоркой.
* **Малая база не видит физику выше 1.3 МэВ и сосудных сцен** (§1.8).
* **Германий** — 8 спектров вне работы; верх разрешающего диапазона у сцинтилляторов
  беден: CZT, LaBr₃ (кроме двух `LABR_BRIL`), SrI₂ ушли вместе с правилом «без фона не
  держим».
* **Кривая эффективности есть только у понятной части**: активность в приложении
  считается ровно у её 92 спектров; у непонятной и исключённой ни у одной.
* **Абсолютные активности** — только там, где паспорт есть (эталоны G1S, Cs-137,
  KCl); `LaBr3`, `ASN3_Tile`, природные образцы размечены по виду спектра — для
  recall это нормально, для активностей нет.
* **Модель разрешения ниже ~180 кэВ измерена слабо**: линий там мало, степенная форма
  выбрана по 76 точкам четырнадцати групп как лучшая из четырёх; это оценка снизу.
* Сверка по линиям, которые обязаны быть (`--audit`), слепа к РАВНОМЕРНОЙ ошибке
  доли пика (амплитуда свободна) и чувствительна только к ходу по энергии; ошибку
  УРОВНЯ кривой или матрицы ловит только внешний якорь — паспортная активность.
* Пол полосы библиотеки: линии ниже пола выбрасываются до фита, и ~110 линий ниже
  рабочего низа можно впустить или выбросить без сдвига ни одной мерки —
  «эффективность ниже пола» и «континуум» в разложении не разделены (`S103`).

## 6. Кто этим пользуется

* **Приложение через `CorpusFsaProbe`** — основной потребитель: полноспектральный
  разбор корпуса кодом `FsaAnalyzer`/`FsaSampleLibrary`, склад матриц, кривые
  понятной части; числа раздела «✅ ДЕЙСТВУЮЩАЯ БАЗА» — отсюда.
* **Сторожа приёмки** (`tools/check_*.py`, §2.8) — читают манифест, раздел, сводку,
  объявление базы и этот файл.
* **Приложение напрямую** — `FsaStackShot`, `RoiActivityProbe`, `PeakFinderProbe`
  разбирают отдельные спектры корпуса тем же кодом, что видит человек.
* **`tools/pie`** — независимый харнесс: гоняет корпус из `scripts/wd_*`, истину берёт из
  `corpus/manifest.csv`, кривые — из `data/eff_by_spectrum_lsrm.csv`; матрицу не
  читает, с числами приложения не складывается (§3.9).
* **Приложение в поставке** корпус не читает: поставочные `config/NuclideDefinition.xml`,
  `config/device/*.xml`, `config/ROI/*.xml` не трогаются (приказ Amber 05.09.2026), а
  корпусные копии приборов живут в `corpus/devices/`.
