# pie — полноспектральная декомпозиция гамма-спектров (журнал исследования)

**Вопрос исследования:** насколько далеко можно уехать на сцинтилляционных
спектрах (NaI/CsI, 6.6–8.5 % FWHM на 662 кэВ), если отказаться от поиска пиков
вообще и раскладывать спектр целиком на «образы нуклидов» — отклики
спектрометра на распад отдельных нуклидов и цепочек? Подход известен в
литературе как full-spectrum analysis (FSA) и лежит в основе нескольких
промышленных пакетов обработки; здесь проверяется, что из него собирается на
уже имеющихся строительных блоках BecqMoni и где он ломается на нашем корпусе.

Ключевое отличие от рабочего пайплайна BecqMoni (`PeakDetector`): пиковый
подход спрашивает «есть ли в спектре пик на 583 кэВ», FSA спрашивает «какая
смесь откликов Th-232, Ra-226, K-40… и фона лучше всего объясняет весь спектр
сразу». На плохом разрешении второй вопрос в принципе информативнее: он
использует и мультиплеты, которые финдер не разделяет, и относительные
интенсивности линий внутри цепочки.

## Модель

Измеренный спектр моделируется как

    S(i) ≈ Σ_j A_j · F_j(i; a, b) + B(i) + C(i)

- `F_j` — образ j-го компонента: сумма гауссиан единичной площади по таблице
  линий компонента, положение — из энергетической калибровки спектра, ширина —
  из FWHM-калибровки, вес линии — квантовый выход на распад родителя цепочки ×
  эффективность регистрации (если есть кривая). Это «спектр пиков» — образ БЕЗ
  непрерывного рассеяния.
- `a, b` — энергетический дрейф (усиление и ноль шкалы) — общие нелинейные
  параметры модели, перебираются сеткой (по умолчанию ±0.8 % × ±3 кэВ),
  линейная часть решается в каждом узле заново.
- `B` — измеренный фон, нормированный на живое время. По умолчанию вычитается
  с коэффициентом 1 (см. итерацию 5 — почему не подбирается).
- `C` — континуум (комптоновское рассеяние + всё несмоделированное), два
  режима:
  - `snip` — континуум оценивается заранее SNIP-ом (`SpectrumAriphmetics.
    Continuum`) и вычитается; фит идёт по «спектру пиков»;
  - `spline` — континуум входит в общую систему как неотрицательный
    кусочно-линейный базис («шапки») с шагом узлов ≥ 4·FWHM, чтобы шапка не
    могла съесть одиночный пик. Это ближе к канонической постановке
    «сплайн в общей системе уравнений».

Линейная часть — взвешенный NNLS (активное множество на нормальных
уравнениях): веса 1/D_i, D_i = max(S_i,1) + (ξ·C_i)² — пуассоновская
статистика плюс погрешность континуума. Поверх — две итерации хуберовского
перевзвешивания (|r|/σ > m ⇒ вес × mσ/|r|, m = 3): систематические
несоответствия формы не должны утаскивать оценки. Погрешности — из обратной
матрицы нормальных уравнений активного множества, надутые на sqrt(χ²/ndf).
После первого решения — «предварительный анализ состава»: компоненты с z ниже
порога выбрасываются и модель перефитовывается (итерация 4).

Выход — «пирог»: доля каждого компонента в объяснённых пиковых отсчётах,
скорость счёта, z. Отсюда и имя инструмента.

### Библиотека компонентов

- **Цепочки** — из наборов нуклидов рабочего конфига (`NuclideDefinition.xml`,
  сеты `k0.70|i1.00` из исследования нуклидных сетов): Th-232, Th-228, Ra-226,
  U-238, U-235. Сет U-238 разрезается: радиевая ветвь (Ra-226…Pb-210)
  вырезается и представляется компонентом Ra-226, U-238 остаётся «головой
  ряда» (итерация 3).
- **Одиночные нуклиды** — встроенная таблица: K-40, Cs-137, Am-241, Co-60,
  I-131, Eu-152, Ba-133, Lu-176. Экзотика (Eu-152, Ba-133, I-131) оставлена в
  библиотеке по умолчанию сознательно — как ловушки на фантомы.
- **Мешающие образы (nuisance)** — характеристический рентген W (ториевые
  электроды) и Pb (свинцовый домик). В «пирог» не входят (итерация 1).

## Инструмент

`Program.cs` — консольный харнесс: собирается `csc` против готового
`BecquerelMonitor.exe`, работает в рабочем каталоге корпуса
(`tools/CORPUS/scripts/wd_<детектор>` — там конфиг устройства, сеты и спектры
корпуса). Из BecqMoni переиспользуются: загрузка `ResultDataFile`, энергетическая
и FWHM-калибровки, SNIP, менеджеры конфига, наборы нуклидов.

```
pwsh tools/pie/run_corpus.ps1 [-Mode snip|spline|both] [-SkipBuild] [-DumpModels]
python tools/pie/score.py [--mode snip|spline] [--sthr 3] [--zthr 4] [--out-dir …]
```

Ключи харнесса:

| ключ | по умолчанию | что делает |
|---|---|---|
| `--input=<файл\|каталог>` | — | обязателен; каталог — все `*.xml` по алфавиту |
| `--workdir=<dir>` | текущий | рабочий каталог (конфиг устройства + сеты) |
| `--mode=snip\|spline` | `snip` | модель континуума |
| `--components=A,B,…` | 15 компонентов (см. ниже) | состав библиотеки |
| `--split-chain=Th-232` | — | разрезать цепочку на дочерние (итерация 7) |
| `--standard=Имя=файл.xml` | — | заместить расчётный образ измеренным (итерация 6) |
| `--emin/--emax` | 40 / 2800 кэВ | диапазон фита |
| `--eff-curve=<csv>` | — | `spectrum,E_keV,eps`, лог-лог интерполяция |
| `--bg=fixed\|fit` | `fixed` | вычитать фон с β = 1 или подбирать (итерация 5) |
| `--bg-sigma` | 0.15 | ширина прикола на β при `--bg=fit` |
| `--bg-file=<xml>` | — | внешнее фоновое измерение вместо встроенного (итерация 8) |
| `--no-bg` | — | игнорировать фон вовсе |
| `--xi` | 0.03 | доля погрешности континуума в весах |
| `--huber` | 3.0 | порог перевзвешивания в σ (3 прохода = 2 перевзвешивания) |
| `--refit-z` | 3.0 | порог отсева перед вторым проходом; 0 — без отсева |
| `--component-map=<csv>` | — | `спектр,комп1;комп2;…` — свой состав библиотеки на спектр (итерация 15); строится `make_sets.py` |
| `--backscatter` | — | образы обратного рассеяния по найденному составу (итерация 15) |
| `--bs-theta` | 110 | нижний угол задней полусферы для широкой колонки, градусы |
| `--bs-steps` | 24 | шагов по углу; 400 ничего не меняет (проверено) |
| `--bs-mode` | both | `broad`\|`sharp`\|`both` — какие колонки рассеяния заводить |
| `--sum-peaks` | — | образ каскадных сумм-пиков; на корпусе не даёт ничего (итерация 15) |
| `--gain-range/--gain-steps` | 0.008 / 9 | сетка усиления |
| `--offset-range/--offset-steps` | 3 кэВ / 9 | сетка нуля шкалы (в кэВ, переводится в каналы) |
| `--no-drift` | — | сетка 1×1 |
| `--result-index` | 0 | какой `ResultData` брать из файла |
| `--out=<префикс>` / `--dump-model=<dir>` | `pie` | результаты и дамп модели |

Состав библиотеки по умолчанию: Th-232, Ra-226, U-238, U-235, K-40, Cs-137,
Am-241, Co-60, I-131, Eu-152, Ba-133 плюс мешающие Xray-W, Xray-Pb, SE-2614,
DE-2614. **Lu-176 есть во встроенной таблице, но в список по умолчанию не
входит** — при расширении прогона на GS4000 (единственный `176LU` в манифесте)
его надо добавить руками, иначе гарантированный MISS. Компонентов для `88Y` и
`139CE` (смесь на CZT) нет вовсе, `score.py` исключает их из истины.

Что лежит в CSV:

- `<префикс>_runs.csv` — по строке на спектр: дрейф, χ²/ndf, фон, время.
  `ncomp` — число компонентов, **доживших до финального фита**, `nactive` —
  ненулевых колонок вместе с шапками континуума.
- `<префикс>_components.csv` — по строке на колонку финального фита. После
  отсева `--refit-z` выброшенный компонент **исчезает из файла целиком**, а не
  пишется нулём: отсутствие строки ≠ нулевая амплитуда. Строка с `amp_cps=0`
  означает другое — компонент прошёл отсев, но во втором проходе обнулился.
- `share_pct` — доля в «пироге», считается только по не-nuisance компонентам;
  у мешающих образов и фона она всегда 0.

Скорость: 0.1–0.8 с на спектр (сетка дрейфа 9×9, 13 компонентов, 8192 канала).

## Эксперимент

22 спектра корпуса на детекторах с кристаллами NaI/CsI: ASN16 (10, 8192 кан.,
6.66 %), AS80x80 (8, 8192 кан., 7.65 %), RC103/RC103g (4, 1024 кан.,
8.3–8.5 %). Истина — `tools/CORPUS/corpus/manifest.csv`. Для ASN16 и
RC103 есть расчётные кривые эффективности (`data/eff_by_spectrum_lsrm.csv`);
для AS80x80 кривых нет — эта группа сознательно идёт без эффективности, как
контраст.

Критерий «компонент найден» в скоринге: доля ≥ 3 % и z ≥ 4. Взаимозачёт
цепочек: Th-228 ⊂ Th-232; равновесный «U-238» манифеста = U-238 (голова) +
Ra-226. Для спектров без вычтенного фона комнатные Th/Ra/K-40 считаются
«мягкими» фантомами.

## Журнал итераций

### 1. Первый запуск: фантомный Am-241 на ториевом электроде

Первая же декомпозиция ASN16_Th232 (электроды WT-20 — вольфрам с ~2 % тория,
114 М отсчётов): Th-232 83 %, но Am-241 13 % с z = 44. Дамп модели показал
горб на 52–60 кэВ, который не объясняется ни континуумом, ни линиями цепочки.
Это ХРИ вольфрама (Kα 57.98/59.32 кэВ) — характеристический рентген самого
электрода, возбуждаемый излучением цепочки, а 59.5 кэВ Am-241 сидит ровно там
же. Урок канонический для FSA: **у всего, что есть в спектре,
должен быть образ в модели** — иначе NNLS повесит это на ближайший похожий
компонент. Добавлены nuisance-образы рентгена W и Pb → Am-241 упал до z = 1.0,
Xray-W забрал своё (z = 4.3).

### 2. Обратное рассеяние — предел шаблонов «из таблицы линий»

Негатив ASN16_Cs137 (251 М отсчётов): Cs-137 76 %, но U-235 17 % (z = 56) и
I-131 6.5 % (z = 46). Причина видна по энергиям: пик обратного рассеяния
662 кэВ лежит на 184 кэВ — в полуширине от 185.7 кэВ (U-235); полка между ним
и комптоновским краем достаётся I-131 (364.5 кэВ). SNIP считает пик обратного
рассеяния «пиком», а не континуумом, и оставляет его в данных. Режим `spline`
(шапки шире 4·FWHM) снял I-131 (6.5 → 1.4 %), но пик обратного рассеяния
пикоподобен — U-235 не лечится ничем, пока в образах нет рассеянной
составляющей. Это главный структурный предел подхода «пики из таблицы линий +
гибкий континуум»: канонические реализации FSA строят образы из измеренных
эталонных спектров, где обратное рассеяние и комптон входят в образ.

### 3. U-238: полная цепочка ≠ голова ряда

Урановое стекло (ASN16_UGlass, U-238 без радиевой части): фит занулил U-238 и
повесил 63.3 кэВ Th-234 на Am-241 (80 %!). Сет U-238 из конфига несёт всю
цепочку с Bi-214/Pb-214 — такой шаблон не может лечь на спектр головы ряда:
жёсткие внутрицепочечные отношения интенсивностей это и сила FSA (фантому
трудно), и слабость (неравновесную цепочку нельзя фитовать равновесным
образом). Разрез на «U-238 = голова» + «Ra-226 = радиевая ветвь» дал на обоих
UGlass чистый результат: ASN16 — U-238 87–89 % + U-235 11–12 %, ok в обоих
режимах; AS80 (без кривой эффективности) Am-241 остался, но упал 74 → 22–42 %.

### 4. Перефит после отсева (слабый эффект)

Второй проход без компонентов с z < 3 («предварительный анализ состава»)
реализован и включён по умолчанию, но на этом корпусе почти ничего не меняет:
у фантомов, порождённых систематикой формы при большой статистике, z всё равно
десятки. Отсев по z работает против шумовых фантомов, а наши — не шумовые.

### 5. Вырожденность измеренного фона

RC103_K40 (маринелли с KCl, фон встроен) в режиме spline: **все** компоненты
образца нулевые, весь K-40 объяснён фоном с раздутым коэффициентом. Колонка
«K-40 пробы» геометрически лежит внутри колонки «фон с комнатным K-40 +
шапки»; NNLS, взяв фон первым, уже не получает градиента переложить пик на
пробу. Мягкий байесовский прикол β ≈ 1 ± 15 % не помог — при миллионах
отсчётов штраф прикола тонет в данных. Решение: фон измерен и нормирован по
живому времени — по умолчанию **вычитается с β = 1** (`--bg=fixed`), подбор
оставлен опцией. RC103_K40 стал чистым: K-40 100 %, ok.

### 6. Образы из измеренных эталонов

Реализован канонический для FSA путь: `--standard=Имя=файл.xml` замещает
расчётный образ измеренным — из спектра эталона вычитается его собственный
встроенный фон, счёт нормируется на живое время; для режима snip дополнительно
готовится вариант без собственного континуума. Амплитуда такого компонента в
фите — **безразмерное отношение активности пробы к активности эталона**.

Грабли, стоившие первого прогона: у каждого спектра корпуса своя
энергетическая калибровка, и массив эталона нельзя подставлять в шкалу образца
«как есть» — пики разъезжаются сильнее сетки дрейфа, NNLS зануляет эталон
целиком и раздаёт спектр фантомам (χ²/ndf 22.8 против 12.97 у таблицы линий).
Обязательна передискретизация через энергию с сохранением интеграла:
`t(i) = ∫ образ(u) du` по интервалу каналов эталона, соответствующему каналу
образца.

Демонстрация на двухкомпонентном ASN16_Th232_Am241 (электрод WT-20 + источник
Am-241, 32 М отсчётов), режим spline:

| | Th-232 | Am-241 | фантомы | χ²/ndf |
|---|---|---|---|---|
| таблица линий | 56.6 % | 23.8 % | U-238 9.4, Ba-133 5.1, Ra-226 4.1 | 12.97 |
| эталоны (Th, Am) | 76.1 % | 8.4 % | U-238 9.6, Ra-226 3.5, Ba-133 2.4 | 12.22 |

Отношения активностей к эталонам: Th-232 — 0.331, Am-241 — 0.108. Главный
сдвиг — не χ², а перераспределение области 59.5 кэВ: в образе-эталоне Th-232
рентген вольфрама уже сидит внутри (тот же электрод), и Am-241 перестаёт
подкармливаться W-рентгеном — его доля падает втрое. Механизм готов; для
систематического прогона по корпусу не хватает чистых эталонов Ra-226 и K-40
на ASN16/AS80 (у RC103 есть K-40).

### 7. Незаполненные пики: вылет и зажатый Ac-228

На послойной картинке ASN16_Th232 остались «пустоты» — пики данных над
стеком: 338, 911/969, ~1592, ~2103 кэВ. Разбор: 2103 = 2614−511 (одиночный
вылет), 1592 = 2614−1022 (двойной вылет, плюс слабая Ac-228 1587.9) — пиков
вылета в образах не было вовсе (генерируются только пики полного поглощения;
в канонической математике для вылета есть отдельные калибровки EffEsc1/2).
А 338 и 911/969 — линии Ac-228, зажатые жёсткой связкой интенсивностей
внутри единого ториевого образа: NNLS не может поднять их, не переполнив
238/583/2614, и Хубер разрешает «бросить» проигрывающие пики.

Два инструмента:
- мешающие образы `SE-2614` (2103.5) и `DE-2614` (1592.5) со свободными
  амплитудами — доли вылета зависят от кристалла, фитовать их честнее, чем
  зашивать;
- `--split-chain=Th-232` — цепочка разрезается на дочерние нуклиды
  (Ac-228, Pb-212, Tl-208, Bi-212, Th-228), каждый фитуется свободно.

На ASN16_Th232 (spline, известный состав, без декоев): χ²/ndf 26.7 → 14.9,
пустоты закрыты (DE z=87, SE z=47 — горбы действительно были вылетом).
Отношение амплитуд дочерних — встроенная проверка равновесия, и она
показывает величину перекоса образа: Ac-228 : Pb-212 : Tl-208 = 1 : 0.43 :
0.69 при ожидаемом 1 : 1 : 1 (интенсивности в сете — на распад родителя).
Это прямое измерение суммарной ошибки кривой эффективности и каскадного
суммирования по диапазону — то, что в цельном образе оплачивалось хвостом
невязок и фантомами-поглотителями. Оборотная сторона разреза: связка
интенсивностей — главная защита от фантомов, поэтому разрез — режим
диагностики и известного состава, а не корпусное умолчание.

### 8. Внешний фон и происхождение остаточных пустот (RC103)

RC103_Th232WT20 записан на естественном фоне, фон в файле не встроен. Гипотеза
«пустоты — это комната» проверена честно: добавлен ключ `--bg-file=` (внешнее
фоновое измерение, грузится без конфига устройства, передискретизация в шкалу
образца через энергию, дальше обычное вычитание с β = 1) и подключён фон того
же прибора за 848 ks. Попутно закрыт тупик: фон как образ со свободной
амплитудой (`--standard=Room=...`) NNLS зануляет — континуум фона вырожден со
слоем шапок, работает только вычитание.

Результат отрицательный и оттого ценный: карта недоборов после вычитания
комнаты не изменилась (χ²/ndf 13.7 → 14.2). Все пустоты принадлежат отклику
самого образца:
- 45–57 и 137–175 кэВ — **пики обратного рассеяния** собственного излучения:
  ХРИ W 59 → 48, мультиплет 300–340 → ~145, 583 → ~178 кэВ. Пикоподобны,

### 10. Сетка дрейфа упирается в границу, и это не дрейф

Предупреждение «drift optimum on grid edge» срабатывает не в исключительном
случае, а **на 14 спектрах из 22** (в обоих режимах), в группе AS80x80 — на 7
из 8. То есть корпусные числа получены при шаблонах, сдвинутых на край сетки:
дальше подвинуть их нельзя, остаток невязки систематический и его разбирают
фантомы.

Проверка расширением сетки до ±2 % × ±8 кэВ (21×33 узла, spline, весь корпус):

| | recall | фантомов | топ-1 верен |
|---|---|---|---|
| ±0.8 % × ±3 кэВ (умолчание) | 89 % | 31 | 19/22 |
| ±2 % × ±8 кэВ | 92 % | 32 | 20/22 |

Выигрыш адресный: AS80x80 идёт с 92 % на **100 %** — на AS80_Background
проявляется Th-232 (4 %, z = 21), которого при узкой сетке не было вовсе; на
AS80_Charoite главным компонентом становится Ra-226 (52 %) вместо фантомного
I-131 (57 % → 25 %). Цена — один лишний фантом (K-40 11 % там же). χ²/ndf при
этом почти не двигается (AS80_Onyx 4.48 → 4.39, ASN16_Cs137 31.8 → 30.6) и
даже не обязан падать: узлы сетки пересчитываются от диапазона, победитель
выбирается по χ² **до** Хубера и отсева, поэтому широкая сетка — не надмножество
узкой (AS80_Background 8.378 → 8.417).

Но главное — не прибавка, а диагноз. Требуемый сдвиг совпадает по порядку с
остаточной ошибкой энергетической калибровки самих спектров, записанной в
`corpus/manifest.csv`: у ASN16 `ecal_rms_kev` 2.31 — и оптимум упирается в
границу 3 кэВ у 4 спектров из 10; у AS80x80 9.94 — оптимум уходит на 8 кэВ и
**всё ещё стоит на границе** (5 из 8
спектров группы, +23.6 кан. на AS80_Background). Это не дрейф прибора между
калибровкой и измерением: сетка a, b компенсирует ошибку самой калибровки
корпусных спектров, а на AS80x80 — ещё и отсутствие кривой эффективности,
которое фит пытается выкупить сдвигом шкалы. Отсюда два вывода: (1) корпусный
прогон надо вести с сеткой шире ±3 кэВ, иначе группа с плохой калибровкой
измеряется зажатой; (2) само срабатывание предупреждения — дешёвый и честный
признак «этому спектру нельзя верить как якорю», его стоит выводить в отчёт
скоринга.

### 11. Фон как режим: почти статистическая сходимость

Фоновые спектры корпуса раскладываются принципиально лучше источников, и это
самое прямое подтверждение тезиса «невязка систематическая, а не шумовая»
(spline, `--split-chain=Th-232`, тот же код и та же библиотека):

| спектр | отсчётов в диапазоне | χ²/ndf |
|---|---|---|
| ASN16_Background | 14.5 М | **1.88** |
| ASN16_Th232 (электрод WT-20) | 109 М | 14.57 |
| RC103_Background | 2.0 М | **1.80** |
| RC103_Th232WT20 (тот же электрод) | 10.8 М | 13.74 |

Прогон: `--mode=spline --split-chain=Th-232 --eff-curve=…`, библиотека по
умолчанию; на RC103_Th232WT20 из состава исключён Am-241 (вырожденность с ХРИ
W при 8.5 % — см. каталог ошибок). Спектры — корпусные, из `wd_ASN16` и
`wd_RC103`.

Один и тот же прибор, одна кривая эффективности, одна модель: на фоне модель
сходится практически до статистики, на ярком источнике χ² в восемь раз хуже.
Систематика формы (рассеяние, хвосты, суммирование) не исчезает на фоне —
просто при 14 М отсчётов она ещё тонет в пуассоновском шуме, а при 109 М уже
нет. Это и есть причина, по которой гейты по z не работают: с ростом
статистики значимость фантома растёт, а не падает.

Побочно фон закрывает вопрос из итерации 7 — о чём говорит перекос
внутрицепочечных отношений при разрезе. Отношение амплитуд Ac-228 : Pb-212 :
Tl-208 (нормировано на Ac-228, интенсивности в сете — на распад родителя):

| образец | детектор | Ac-228 : Pb-212 : Tl-208 |
|---|---|---|
| электрод WT-20 | ASN16 (8192 кан., 6.66 %) | 1 : 0.43 : 0.70 |
| тот же электрод | RC103 (1024 кан., 8.5 %) | 1 : 0.47 : 0.72 |
| комнатный фон | ASN16 (тот же прибор и кривая) | 1 : 1.49 : 1.07 |

Один образец на двух разных приборах даёт одно и то же отношение; один прибор
на двух разных образцах — отношения, различающиеся втрое и в разные стороны.
Значит, перекос — **не свойство кривой эффективности** (иначе он был бы общим
для обоих образцов на ASN16) и не свойство прибора. Он принадлежит паре
«образец + геометрия»: у электрода верх ториевой цепочки вдвое сильнее низа
(кандидаты — эманация Rn-220 из металла и каскадное суммирование, резкое на
близком точечном источнике и слабое на распределённой комнате), у комнаты
картина обратная. Разделить эманацию и суммирование этими данными нельзя —
это открытый пункт; но использовать отношение как «встроенную проверку
равновесия» можно только после того, как геометрический вклад отделён.

При этом низкий χ² не означает чистого состава: на том же ASN16_Background
Eu-152 берёт 22 % с z = 39. Модель, сошедшаяся почти до статистики, всё равно
держит фантом в пятую часть пирога — многолинейчатый поглотитель собирает
мелкие несоответствия формы по всему диапазону там, где ни одна отдельная
линия не значима. χ²/ndf и чистота пирога — независимые вещи.

## Что показало исследование

1. **Каркас FSA работает** на имеющихся блоках BecqMoni: калибровки + сеты
   нуклидов + SNIP + NNLS достаточно, чтобы главный компонент определялся
   верно в 19/22 спектров, а чистые негативы (Am-241, K-40, Cs-137, Co-60)
   давали 74–100 % своей доли.
2. **Цена — модель полноты**: каждый фантом в таблице выше — это не шум, а
   реальная структура спектра, для которой в модели нет образа (рассеяние,
   рентген, сумм-пики). FSA-подход честно перекладывает всё несмоделированное
   на ближайший компонент, и статистическая значимость этого фантома растёт
   со статистикой спектра. Гейты по z здесь не работают по построению.
3. **Жёсткие внутрицепочечные отношения** — главный источник силы: разрез
   U-238 на голову и радиевую ветвь мгновенно превратил два худших спектра в
   чистые. Следующий кандидат — неравновесие внутри радиевой ветви (эманация
   радона).

### 12. Форма пика в образе, и первый прогон по всему корпусу (03.08.2026)

До этой итерации все числа журнала стояли на 22 спектрах NaI/CsI. `run_corpus.ps1`
расширен на **все 23 группы, 69 спектров** — так требует CLAUDE.md, и результаты
ниже получены только так. Полный прогон обоих режимов — 110–170 с.

**База (spline, 69 спектров):** Σχ²/ndf 596.8, медиана 5.07, recall 83 % (86/104),
фантомов 93, счёт 86 с.

**Образ строится профилем из ПШПВ-калибровки, а не своей гауссианой.**
`BuildTemplate` звал `Math.Exp(-0.5·d²)` напрямую, игнорируя `PeakType`: у ASN16
конфиг объявляет ExpGaussExp 1.5/5, у AS80x80 — 1.15/4, и левого хвоста у образа не
было вовсе. Теперь окно берётся из `PeakShapeModel.GetLeftSupport/GetRightSupport`, а
нормировка — на площадь самого профиля, посчитанную по полному носителю (даже если
часть его вышла за границы фита: иначе линия у края шкалы весит больше своего).
Ради этого `PeakShapeModel` и `PseudoVoigtProfile` стали public — харнесс обязан
строить образ тем же кодом, что и продукт.

Сама правка при гауссовом корпусе почти нейтральна: Σχ² 596.8 → 593.4 (−0.6 %,
весь выигрыш на CZT: −12.6 %), recall и фантомы не шевельнулись, счёт +23 % (окно
8σ против 5σ). Это и есть проверка: код заменён, поведение не поехало.

**Корпус приведён к реальной форме пика.** `tools/CORPUS/scripts/peakshape.py`
проставляет в рабочие каталоги `wd_*` PeakType и хвосты по конфигам устройства
пользователя (ASN16 → 1, 1.5/5; AS80x80 → 1, 1.15/4; у остальных приборов формы не
измерено, и ставить её наугад нельзя). Корпус `corpus/spectra` при этом не трогается
— скрипт правит только рабочие копии, `--restore` возвращает их к эталону.

Форма даёт **Σχ² 167.4 → 164.3 на этих 18 спектрах** (ASN16 −2.3 %, AS80x80 −1.3 %),
recall 84 % → 84 %, фантомов 17 → 18, состав поехал только на AS80_Charoite.

**Низкая точка ПШПВ.** Модель разрешения корпуса намеренно без свободного члена, и
ниже опорных линий (180 кэВ) она не измерена, а экстраполирована. Насколько — видно
по самому корпусу: на 59.5 кэВ десять спектров ASN16 дают **от 3.1 % до 29.4 %**
полуширины при одном и том же детекторе. Это не смещение, это отсутствие модели.

Заданную точку 58.4 кэВ / 16.1 кэВ (27.6 %) проверить не удалось: подгонка профиля
к линии 59.54 кэВ на `ASN16_Am241` даёт **10.4 кэВ (17.5 %)**, на `ASN16_Th232_Am241`
— 9.4 кэВ (15.8 %), и это совпадает с собственной измеренной точкой конфига ASN16
(27 каналов на 182-м = 17.8 %). Прогнаны оба якоря:

| ASN16, 10 спектров, spline | Σχ²/ndf | recall | фантомов |
|---|---|---|---|
| база | 87.62 | 84 % (16/19) | 17 |
| + форма пика | 85.57 (−2.3 %) | 84 % | 18 |
| + якорь 58.4/16.1 (заданный) | 85.75 (+0.2 %) | 89 % (17/19) | 18 |
| + якорь 59.5/10.4 (измеренный) | **82.50 (−3.6 %)** | 84 % | **17** |

Измеренный якорь лучше по χ² и по фантомам, заданный — на одну находку лучше по
recall (одна пара из 19, это шум). Побочно якорь **стабилизирует** низ шкалы: разброс
3.1…29.4 % схлопывается до 18.1…25.0 %. В рабочем состоянии оставлен измеренный.

**Хвост 2614 больше не недобран.** На `ASN16_Th232` в окне 2650–2750 кэВ модель даёт
118 % данных за вычетом фона (было заявлено −18…−30 %), в 2500–2800 — 94 %, выше
2800 — 94 %. Важная поправка к постановке: сравнивать модель надо с спектром **за
вычетом фона**, а не с сырым; приложение так и рисует (`fsaNetSpectrum`), и на
Чароите «модель 33 % от данных» превращается в «модель 139 % от данных над фоном»,
потому что над фоном там 892 отсчёта из 3753.

### 13. Предел шага узлов сплайна: χ² покупается ценой опознания (03.08.2026)

Проверялось предложение ограничить шаг узлов сверху (`--knot-div=N`: шаг ≤
диапазон/N). Прогон по всем 69 спектрам, spline, корпус в состоянии итерации 12:

| предел шага | Σχ²/ndf | Δ | recall | фантомов | счёт |
|---|---|---|---|---|---|
| нет (как сейчас) | 587.2 | — | 82 % (85/104) | 93 | 122 с |
| ≤ диап/8 | 580.6 | −1.1 % | **83 % (86/104)** | **90** | 122 с |
| ≤ диап/16 | 537.3 | −8.5 % | 81 % (84/104) | 92 | 129 с |
| ≤ диап/32 | **451.7** | **−23.1 %** | **73 % (76/104)** | 95 | 163 с |

Предложенный вариант «диапазон/32» действительно даёт лучший χ² из всех — и он же
единственный, который **ломает опознание**: recall 82 % → 73 %, девять попаданий
потеряно. Видно и поимённо: на `OBS_Th232WT20` торий 36.5 % → 0 %, а его место
занимает фантомный Eu-152 0 % → 83.3 %; на `AS80_Background` калий 37.8 % → 0 %.
Механизм ровно тот, от которого шаг «не меньше 4 ПШПВ» и был поставлен: у Obsidian
на 1024 каналах диапазон/32 — это 32 канала при полуширине 40, то есть узел на
каждые 0.8 ПШПВ, и континуум начинает обводить отдельные пики. χ² при этом обязан
падать — модели добавили свободы, — но объясняет спектр уже не состав, а подложка.

Заявленную причину («подложка сваливается к нулю выше 2500 кэВ») предел не лечит: на
`ASN16_Charoite` в 2500–2800 кэВ он меняет 139 % на 144 %, выше 2800 — 0 % на 23 %
при 132 отсчётах над фоном на 1300 каналов. Лечит её итерация 12.

Единственный вариант, улучшающий всё сразу и бесплатно по времени, — **диапазон/8**:
χ² −1.1 %, фантомов 93 → 90, recall +1.

**Решение мейнтейнера (03.08.2026): предел шага не вводится.** Ни в каком виде — ни
диапазон/32, ни диапазон/8. `BuildHatBasis` в приложении остаётся как был:
`max(4·ПШПВ, диапазон/64)`. Ключ `--knot-div` остаётся только в харнессе, как
инструмент измерения; по умолчанию 0 — предела нет.

### 14. Что видно глазами на графике разложения (03.08.2026)

`ASN16_Th232` открыт в приложении, режим «Show FSA», ROI-конфигурация не выбрана
(в легенде так и написано: `χ²/ndf (no eff)` = 31.84). Состав: Ac-228 49.3 %,
Pb-212 20.7 %, Tl-208 11.9 %, Pb-214 9.8 %, Bi-212 4.9 %, DE/SE-2614 2.1 %.

Три невязки, которые видно без всяких чисел:

1. **583 кэВ (Tl-208) сильно недобран.** Модель там заметно ниже данных, при том
   что 2614 кэВ того же Tl-208 описан. Это ровно тот механизм, из-за которого
   нужна кривая: амплитуда компонента почти целиком определяется его самой
   сильной, высокоэнергетичной линией, а при плоской (то есть отсутствующей)
   эффективности низкие линии того же нуклида обязаны оказаться заниженными.
   Первое, что стоит проверить после подстановки кривой из конструктора.
2. **511 кэВ — превышение над моделью, и объяснить его нечем.** Аннигиляционного
   пика в библиотеке нет вовсе: пики вылета от 2614 (SE 2103.5, DE 1592.5) есть,
   а сама линия 511 кэВ — нет. В ториевом спектре она есть всегда.
   Отдельным образом-мешалкой (`Nuisance`), как SE/DE, — но это правка состава
   библиотеки, и она за отдельным решением.
3. **~460 кэВ — превышение поменьше**, происхождение не установлено.

Плюс подтверждение к итерации 12: приложение рисует стек против спектра **за
вычетом фона** (`fsaNetSpectrum`), так что «недобор» на картинке — настоящий
недобор, а не эффект сравнения с сырым спектром.

### 15. Свой нуклидный сет под спектр, и образ обратного рассеяния (03.08.2026)

Две правки, обе по литературе из `Library\Радиация\NEW` (разбор — в памяти
агента, `gamma-lit-new-folder`). Приборы с разрешением лучше 3 % (HPGe, CZT)
из измерения исключены — там пик разрешается сам и задача другая; остаётся
**58 спектров 18 групп**, и `score.py --min-fwhm 3` теперь так и считает.
Он же печатает Σχ²/ndf по тем спектрам, что вошли в скоринг.

**Набор нуклидов — под задачу, а не общий список.** До сих пор корпус гонялся
одной библиотекой из пятнадцати компонентов, и Eu-152 с I-131 сидели в ней
намеренно, как ловушки на фантомы. Так прибор не используют: оператор выбирает
сет под пробу. Правило (`make_sets.py`, ключ `--component-map`): всегда NORM
(Th-232, Ra-226, U-238, U-235, K-40), плюс нуклид источника, если этот источник
действительно ставили; мешающие образы — часть модели отклика, не выбираются.

Одно это меняет картину сильнее любой правки алгоритма:

| | recall | фантомов | Σχ²/ndf |
|---|---|---|---|
| общая библиотека 15 компонентов | 82 % | 90 | 542.8 |
| свой сет под спектр | **86 %** | **46** | 559.4 |

Половина фантомов журнала была не свойством метода, а свойством постановки.
χ² при этом растёт — и правильно: убраны колонки, которые его выкупали.

**Образ обратного рассеяния.** Фотон энергии E, рассеявшийся назад ВНЕ
кристалла, приходит с E/(1+2E/511): 662 → 184 кэВ (ровно U-235 185.7),
583 → 178, мультиплет 300-340 → ~145, ХРИ W 59 → 48. В каталоге ошибок это
причина №1, и «структуры без образа» здесь ровно столько же, сколько было у
ХРИ вольфрама в итерации 1. Образ строится ВТОРЫМ проходом по найденному
составу (у Cs-137 это один пик, у ториевого электрода — блоб из полусотни
линий; общий образ «по всей библиотеке» имел бы чужую форму), вес линии
берётся на энергии исходного фотона, ключ `--backscatter`.

Колонки две. Прогон показал, что они чинят РАЗНЫЕ спектры: узкая (строго
назад) снимает U-235 с `ASN16_Cs137`, широкая (интеграл по задней полусфере с
сечением Клейна — Нишины) — Ba-133 с европиевых G1S; каждая по отдельности
теряет то, что чинит другая. Учащение выборки по углу до 400 шагов ничего не
меняет: реальный пик строго назад сильнее, чем даёт свободное сечение, —
это геометрия рассеивателя, которой модель не знает. Поэтому обе свободны.

| на своём сете | recall | фантомов | Σχ²/ndf |
|---|---|---|---|
| без рассеяния | 86 % | 46 | 559.4 |
| **+ обратное рассеяние** | **89 %** | **45** | **547.1** |

Прибавка адресная: возвращаются U-235 на `ASN16_Granite` (та самая пара
185.7/186.2 из каталога ошибок) и K-40 на `ASN3_Tile`, уходят U-238 с трёх
спектров и U-235 с `LaBr3_Ore`. На `ASN16_Cs137` при общей библиотеке фантом
U-235 падал с 16.5 % до нуля, а Cs-137 рос с 81 до 96.7 %.

Порядок кругов мерен отдельно: образ только до отсева по z даёт recall, но
возвращает фантомов (90 против 85 на общей библиотеке); только после отсева —
наоборот. Оставлены оба круга.

**Перенесено в приложение** (`FsaAnalyzer.Backscatter`, включено по
умолчанию). Состав библиотеки в приложении и так задаётся выбранными сетами
пользователя — то есть протокол «свой сет под задачу» там выполняется сам.

**Отрицательный результат: каскадные сумм-пики (`--sum-peaks`) не дали ничего.**
Образ строится автосвёрткой линий ОДНОГО нуклида (разные дочерние в совпадение
не попадают), вероятность вылета обоих квантов в одном распаде взята как
min(I₁,I₂), вероятность зарегистрировать оба полностью — ε(E₁)·ε(E₂). На
корпусе: recall 86 % (без изменений), фантомов 46 → 47, Σχ² −0.3 %. На
`RC103_Co60`, ради которого всё и делалось, колонка получает ровно ноль, и
механизм виден: при ПШПВ 8.29 % сумм-пик 2505 лежит в полуширине от 2614 кэВ
комнатного Tl-208 — колонки вырождены, и NNLS выбирает торий, который заодно
объясняет линии ниже. Ключ в харнессе оставлен как инструмент измерения, в
приложение не перенесён.

## Что дальше (по убыванию ожидаемого эффекта)

1. **Образы из измеренных эталонов — систематически.** Механизм `--standard`
   работает (итерация 6); чтобы перевести на него корпусный прогон, нужны
   чистые эталоны Ra-226 и K-40 для ASN16/AS80 (у RC103 K-40 есть). Рассеяние
   и сумм-пики войдут в образ сами.
2. **Кривые эффективности для AS80x80** — группа без кривых стабильно хуже по
   низкоэнергетическим фантомам.
3. **Сетка дрейфа по умолчанию шире ±3 кэВ** и вывод предупреждения о границе
   в отчёт скоринга (итерация 10) — правка на один параметр, даёт +3 пункта
   recall и снимает единственный MISS группы AS80x80.
4. **Образ рассеяния как функция энергии основной линии** (обратное рассеяние
   + комптоновский край параметрически) — дешёвая альтернатива п. 1 для
   одиночных нуклидов типа Cs-137.
5. **Совместная обработка группы спектров** одного образца (общие активности,
   индивидуальные дрейфы) — корпус содержит пары/тройки одного источника в
   разных геометриях (G1S, ASN8-лестница) для проверки.
6. **Интеграция в UI**: «пирог» состава как альтернативный режим в
   `DCResultView` поверх той же декомпозиции.

## Грабли реализации (видны только в коде)

- **Потолочный канал АЦП исключён из фита.** В последний канал падает всё, что
  выше шкалы (RC103_Background: 11 k отсчётов при соседях ~5); образа у такой
  структуры нет, и фит объяснял бы её чем попало. Верхняя граница диапазона
  опускается до `nch − 2`, когда дотянулась до края.
- **Шаг узлов сплайна** — `max(4·FWHM, (chHi − chLo)/64)`, то есть узлов не
  больше ~65 при любом разрешении. Узел ближе 2 каналов к верхней границе
  сливается с ней (иначе «шапка-спица» — почти коллинеарная колонка), но
  сливать по более широкому порогу нельзя: 4·FWHM снимает легитимный узел и
  дубит континуум у верхнего края — χ²/ndf RC103-разреза портился 14.2 → 16.0.
- **NNLS банит колонки, давшие сингулярную активную матрицу** (дубликат или
  коллинеарность). Без бана градиент не меняется и внешний цикл выбирал бы тот
  же индекс до исчерпания бюджета итераций.
- **Дубли в `--components` игнорируются** с предупреждением — две одинаковые
  колонки сингулярны по построению.
- **Сеты с `~decoy` в имени пропускаются** при сборке библиотеки: это
  сеты-обманки из исследования нуклидных сетов, лежащие в том же конфиге.
- **Части разрезанной цепочки не кладутся в общий словарь цепочек**: имя
  дочернего нуклида может совпасть с самостоятельной цепочкой (Th-228 внутри
  Th-232), и запись подменяла бы её огрызком.
- **Прикол на коэффициент фона действует только при `--bg=fit`**; при
  умолчании `fixed` фон вычитается до фита и колонки для него нет вовсе.

## Файлы

- `Program.cs` — харнесс (сборка и ключи — выше).
- `run_corpus.ps1` — сборка + прогон четырёх групп корпуса в обоих режимах
  (`-SkipBuild` — прогон готовым `pie.exe`; сборка идёт в `wd_ASN16` и
  копируется в остальные рабочие каталоги).
- `make_sets.py` — карта «спектр -> состав библиотеки» по классу пробы
  (итерация 15); пишет `component_map.csv`, который читает `--component-map`.
- `score.py` — скоринг против манифеста корпуса. `--min-fwhm 3` исключает
  приборы с разрешением лучше 3 % (HPGe, CZT) — они вне предмета; Покрытие групп сверяется
  с манифестом: упавший (ERROR в `*_runs.csv`) или пропущенный спектр
  попадает в таблицу как «НЕТ РЕЗУЛЬТАТА» и целиком считается промахом;
  `--out-dir` — скорить произвольный каталог результатов.
- `plot_decomp.py` — картинка декомпозиции из дампа модели: по умолчанию
  послойная (фон → континуум → компоненты цветными слоями, верх стека —
  модель, измеренный спектр линией сверху), `--style lines` — каждый образ
  отдельной кривой. Шкала по умолчанию — `--scale pow2`, ось в √N: ноль на
  месте, верх сжат, ничего не режется; `--scale log` и `--linear`
  [`--ymax N`] — логарифм и линейная шкала с обрезанным верхом (вид
  классических пакетов декомпозиции). `--lang ru|en` — язык подписей. В
  легенде — доли полного счёта модели. Континуум на картинке разнесён по компонентам: подложка на
  энергии E приписывается компонентам пропорционально их пиковому счёту
  выше E (рассеяние сбрасывает энергию только вниз) — так стек читается как
  у пакетов с полными образами. Это правило отображения, а не фита: в самой
  модели континуум по-прежнему общий слой шапок, и по-нуклидная подложка
  станет частью модели только с образами из измеренных эталонов.
- `out/` — CSV результатов, дампы моделей, картинки (не в git). Корень —
  первый корпусный прогон (числа итерации 9), `rerun/` — он же на текущем
  коде, `wide/` — широкая сетка дрейфа (итерация 10), `eq_*` — разрезы
  ториевой цепочки из итерации 11.
