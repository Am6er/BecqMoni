## 1. Посылка строки сверена счётом, и она разошлась с деревом ДВАЖДЫ

Строка утверждала: **девять** проб считают FSA, отчитываются **две**, молчат **семь**.
Замер на дереве в начале захода (`python tools/check_probe_tuning.py`, перепись
печатается каждый прогон) дал **десять** и **восемь**, а замер образцом БЕЗ скобок —
**одиннадцать** и **девять**. Обе разницы имеют разную природу, и вторая — дефект
самого сторожа:

| посылка | считают FSA | молчат | чем измерено |
|---|---|---|---|
| строка `T243` (утро 06.09) | 9 | 7 | перепись П9 |
| сторож на момент захода | 10 | 8 | `census()` по образцу `new FsaAnalyzer()` |
| ДЕЙСТВИТЕЛЬНОСТЬ | **11** | **9** | образец `new FsaAnalyzer` БЕЗ скобок |
| после захода | 11 | **0** | тот же сторож, порог поднят |

* **+1 честная:** `FsaSumPeakAccountProbe.cs` заведена другой полосой в тот же день,
  строка её застать не успела. В `git status` она до сих пор `??` (незакоммичена).
* **+1 ПРЯТАВШАЯСЯ:** `FsaRobustnessProbe.cs` собирает анализатор ЧЕРЕЗ СПИСОК ПОЛЕЙ —
  `new FsaAnalyzer { ResponseMatrix = …, RefitZ = 0.0, HuberM = 0.0 }`, — без скобок.
  Прежний образец переписи `new\s+FsaAnalyzer\s*\(\s*\)` такую запись НЕ ВИДИТ, и
  проба была молчащей, невидимой сторожу молчания. ⛔ Это класс «сторож считает не
  ту совокупность»: число молчащих печаталось каждый прогон и было НЕПОЛНЫМ, а по
  выводу этого не видно ничем. Образец переписи расширен до `new\s+FsaAnalyzer\b`.

⚠ Отсюда общий вывод, годный не только здесь: **перепись, которая ищет одну ФОРМУ
ЗАПИСИ, меряет форму, а не сущность.** У C# конструктор пишется двумя способами, и
второй способ давал пробе освобождение от правила.

## 2. Что сделано

### Правило вынесено в довесок — `tools/effmaker/probes/FsaTuningReport.cs`

Файл без точки входа; `build_all.ps1` выводит такие сам (по отсутствию образца
объявления `Main` В ТЕКСТЕ) и кладёт довеском КАЖДОЙ пробе. Таблицы «кому какой
довесок» нет нарочно (`T57`). В довеске:

* `Snapshot()` — снимает поставочную полосу (шесть статик `FsaBand.Default*`) ДО
  разбора ключей; первый вызов побеждает;
* `Print(analyzer[, плечо])` — сличает настроенный анализатор с чистым
  `new FsaAnalyzer()` ОТРАЖЕНИЕМ (свойства и поля), плюс полосу — поимённо по
  статике, потому что отражение её не видит;
* печатает одну строку `SETUP\tпротив поставочного разбора изменено[ плечо]: …`.

Необязательное «плечо» заведено потому, что три пробы считают несколькими разборами
за прогон (`FsaDoubleCountProbe`, `TrustFloorProbe`, `FsaSumPeakAccountProbe`): без
пометки две строки отчёта в одном выводе неразличимы, и болезнь ~~`S82`~~ возвращается
внутри одного прогона.

### Зовут все одиннадцать

`FsaBackgroundMarkProbeF48`, `FsaCascadeProbe`, `FsaDoubleCountProbe`, `FsaPaletteProbe`,
`FsaResidualProbeF21`, `FsaRobustnessProbe`, `FsaSelectionProbeF16`,
`FsaSumPeakAccountProbe`, `TrustFloorProbe` — плюс два прежних отчитывавшихся.

⛔ У проб, которые двигают ОДИН анализатор от плеча к плечу (`FsaCascadeProbe`,
`FsaPaletteProbe`), отчёт печатается ОДИН раз и ПЕРЕД первым `Analyze`. Причина —
`T240`: после разбора у анализатора появляется состояние прогона (`RefitZState`,
`RefitZTopZ`, `RefitZJudged` — три открытых свойства с приватной записью), и второй
отчёт называл бы ИСХОДОМ то, что обязан называть настройками. Там, где анализатор у
каждого плеча свой (`NewAnalyzer`, `Run`, цикл порогов), отчёт печатается на каждом.

## 4. Грабля, стоившая двух пересборок: пример в комментарии сделал довесок ПРОБОЙ

`build_all.ps1` отличает довесок от пробы **поиском образца объявления точки входа ПО
ТЕКСТУ ФАЙЛА** (`Select-String -Pattern 'static\s+(int|void)\s+Main\s*\('`), не разбирая
код. В первой редакции довеска пример употребления был написан так:

```
//   static int Main(string[] args)
//   {
//       FsaTuningReport.Snapshot();
```

— и `FsaTuningReport.cs` перестал быть довеском. Последствия разом: сам он падает
`error CS5001` («программа не содержит статического метода Main»), а ВСЕ одиннадцать
проб, которые его зовут, — `CS0103` «имя не существует в текущем контексте». Сборка
честно назвала одиннадцать сломанных файлов, но причина стоит в двенадцатом.

⛔ **Комментарий — не нейтральная область, когда рядом живёт текстовый сторож.**
Правило теперь записано и в самом довеске, и отдельным правилом сторожа
(`judge_companion`: объявление точки входа в довеске = отказ, с этим самым доводом),
чтобы вторая попытка написать пример стоила секунду, а не две пересборки.

  `build_p16` лежит НЕЗАКОММИЧЕННАЯ работа П15 по веществу — для отчёта о настройках это
  безразлично, но числа физики с этого каталога брать нельзя.
* **Рабочий каталог `tools/CORPUS/scripts/wd_p16` НЕ СОЗДАН.** `mk_appwd.ps1` отказал

* **Пятнадцать проб трогают `NumberDecimalSeparator`, двенадцать из них ПРИСВАИВАЮТ его клону культуры** —
  `culture.NumberFormat.NumberDecimalSeparator = …` на клоне
  `Thread.CurrentThread.CurrentCulture`. Часть делает это НАРОЧНО и законно (это их
  предмет: `CultureProbeO14`, `GraphCultureProbeF27`, `RestCultureProbeF28`,
  `RestCultureProbeF47`, `MatrixRefusalProbeP8` ставят ЗАПЯТУЮ, чтобы поймать
  приложение). Остальные ставят ТОЧКУ — то есть лечатся ровно запрещённым способом
  (`A242`: «подменять разделитель в клоне системной культуры НЕЛЬЗЯ»), тогда как соседи
  по каталогу пишут `CultureInfo.CurrentCulture = CultureInfo.InvariantCulture`. В моей
  переписи такой оказалась `FsaRobustnessProbe.cs` (строки 29–31). Правка однострочная,
  но разбор «нарочно или по недосмотру» нужен КАЖДОМУ из пятнадцати поимённо, а
  четырнадцать файлов — чужие; поэтому строка, а не правка на месте. Родитель `A244`
  этого не покрывает: он про 1176 мест ПРИЛОЖЕНИЯ, оснастка в его счёт не входит.
