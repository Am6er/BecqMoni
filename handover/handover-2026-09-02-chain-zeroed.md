# Ряд Th-232 занулён целиком: окно линии под порогом АЦП держит недоверяемый континуум

Заход 02.09.2026, по картинке Amber (`Th232(WT-20).xml`, прибор `Atom Spectra 80x80`,
кривая «Цилиндр Lu», набор `Th-232`, галки «Enable DB lookups for FSA» и «Равновесие»).
Строка задачи — `A49`.

## Что было на экране

Легенда FSA: `Ann-511` 66.89 %, `X-ray W` 5.24 %, `X-ray NaI` 1.49 %, `continuum` 26.37 %,
`Th-232 — chain < 0.0906 %`, невязка `+5.0 / −14.6 %`, строка качества
`χ²/ndf · suppressed · matrix · sum… 31.06`. То есть весь ряд получил НОЛЬ, а состав
пересилен одним приборным образом (`S104`).

## Матрица тут ни при чём — мерено

Вопрос Amber был «почему не подтянулась матрица». Подтянулась:

| проверка | значение |
|---|---|
| файл `config/device/response/57512f8b-….rmx` | формат **7**, физика **12**, 140 узлов, bin 2 кэВ |
| клеймо файла | `phys=12;2e997efe…6c446e27` |
| клеймо геометрии из СНИМКА в файле спектра | то же, `IsValidFor = True` |
| клеймо геометрии из конфига прибора | то же, `IsValidFor = True` |
| `HasGeometry` / `UseResponseMatrix` | True / True в обоих |

Плюс два независимых свидетеля в самой легенде: пометка `· matrix` печатается только при
живой матрице (иначе `· no matrix`, [EnergySpectrumView.Fsa.cs:1339]), а `· sum…` —
каскадное суммирование, которое без матрицы не работает вовсе
([FsaAnalyzer.cs:4569], `BuildSumPeakCurve` возвращает null при `ResponseMatrix == null`).

⚠ Попутно: у той же сборки **6 из 10 матриц формата 6** — они молча отбрасываются
`ResponseMatrix.Load` (проверка `reader.ReadInt32() != FormatVersion` → null). Это
«Цилиндр» у RC-103 и пять файлов, Guid которых не принадлежит ни одной кривой ни в одном
конфиге приборов.

## Разряд: одна линия ниже порога АЦП убивает ВЕСЬ образ

Абляции (проба `ChainCutProbe`, выбрасывает линии ниже порога ИЗ НУКЛИДНЫХ образов,
всё остальное не трогает):

| прогон | χ²/ndf | ряд | `Ann-511` |
|---|---|---|---|
| как есть (95 линий) | 31.061 | **0** | 66.89 % |
| `--drop-below=15.4` (снята 1 линия) | 31.061 | **0** | 66.89 % |
| `--drop-below=15.6` (снято 2) | 31.061 | **0** | 66.89 % |
| `--drop-below=15.9` (снято 3, включая 15.784 с выходом 33.3 %) | 31.061 | **0** | 66.89 % |
| `--drop-below=16.3` (снято 4 — все, что ниже 20 кэВ) | **26.974** | Tl-208 37.4 · Ac-228 37.2 · Pb-212 12.4 · Bi-212 4.7 | 2.06 % |
| `--drop-below=45` (снято 5) | **22.442** | Ac-228 37.3 · Tl-208 35.2 · Pb-212 16.6 · Bi-212 4.3 | 1.21 % |
| снята галка «Равновесие» | 21.684 | Tl-208 70.4 · Ra-224 12.1 · Bi-212 8.3 | 1.53 % |

Переключатель — ровно «есть ли у образа ХОТЬ ОДНА линия ниже 20 кэВ». Интенсивность ни
при чём: снятие линии 15.784 кэВ с выходом 33.3 % не меняет НИЧЕГО (числа побитово те
же), а снятие последней оставшейся — 16.200 кэВ, выход 0.72 % — переворачивает разбор.
Четыре линии: 15.349 / 15.500 / 16.200 (Ra-228) и 15.784 (Ac-228), это L-рентген.

## Почему так — механизм

1. `ResponseContinuumTrustFloorKev = 100` кэВ ([FsaAnalyzer.cs:4114]). Ниже порога
   континуум матричного образа **отвязывается** в отдельную свободную колонку — ровно
   затем, чтобы «жёсткая связка пик+континуум» не зануляла компоненты с найденными
   пиками (в объявлении поля так и написано: на граните NNLS выбрасывал
   Pb-212/Pb-214/Tl-208 целиком).
2. Исключение из отвязки — **пиковые окна линий ±2 ПШПВ**
   (`SplitContinuumBelowTrustFloor`, [FsaAnalyzer.cs:4137]): «пик под порогом обязан
   выжить».
3. У линии 16.2 кэВ на этом приборе ПШПВ ≈ 7.8 кэВ, окно ±15.6 кэВ, то есть
   **[0.6 … 31.8] кэВ**. Вместе с окнами 39.9 / 57.8 / 63.8 / 89.9 … кэВ окна ЗАКРЫВАЮТ
   ВСЮ полосу 0–100 кэВ, и отвязывать становится нечего.
4. Мера (проба `DepositProbe`, доля отклика образа и сколько из неё ПРИВЯЗАНО):

   | полоса | отклик, доля образа | привязано, все 95 линий | привязано, без 4 нижних |
   |---|---|---|---|
   | 0–6 кэВ | 0.240 % | **100 %** | 0 % |
   | 6–11 кэВ | 0.383 % | **100 %** | 0 % |
   | 11–16 кэВ | 0.321 % | **100 %** | 47 % |
   | 16–20 кэВ | 0.537 % | 100 % | 100 % |

5. А в спектре ниже ~11 кэВ **ровно ноль отсчётов** — порог АЦП (первый ненулевой канал
   53, 11.1 кэВ). Модель обязана быть нулём там же, а привязанный образ обязан положить
   туда 0.62 % своей площади при ЛЮБОЙ ненулевой амплитуде. Взвешенный NNLS выбирает
   единственный выход — амплитуду нуль.

То есть это ТОТ ЖЕ отказ, ради которого заведён порог доверия, вернувшийся через
исключение для пиковых окон.

## Что ещё видно и не объяснено

- Даже со снятой связкой разбор плохой: χ²/ndf 21.7, невязка 22.7 %, а состав
  вырожден (Pb-212 и Ac-228 в ноль, 238.6 кэВ забирает Ra-224 своей 241).
- Матрица этой сцены посчитана для пробы **«воздух»** в стакане Ø40×15 мм
  (`<Source>Air, dry</Source>`), а меряется пучок электродов ВТ-20 — вольфрам с 2 % ThO₂.
  Самопоглощения пробы в модели нет вовсе.
- Нижний край сетки у этой матрицы **20 кэВ**, а умолчание после ~~`T49`~~ — 5 кэВ.
  Ниже первого узла `ResponseMatrix.Accumulate` растягивает строку узла 20 кэВ на шкалу
  линии, то есть отдаёт линии 15.8 кэВ эффективность 20 кэВ (мерено: площадь 5.583E-3
  одинакова для 15.349 / 15.5 / 15.784 / 16.2 / 18 / 19.9 / 20.0 кэВ). На занудение это
  не влияет — доля отклика под порогом от нижних линий почти не зависит, — но кривую
  внизу шкалы завышает.

## Пробы захода

Лежат в песочнице сессии, в дерево не клались: `MatrixCheck.cs` (клейма и `IsValidFor`),

## Починено — решение Amber 02.09.2026

Выбран вариант «не пускать в образ линии ниже первого узла матрицы».
Правка одна, в [FsaAnalyzer.cs](../BecquerelMonitor/FullSpectrumAnalysis/FsaAnalyzer.cs),
рядом с гейтом вылетов (`S47`) — там же, где уже решается «через матрицу пойдёт
разбор или из одних пиков», потому что знать это может только анализатор:

* линии с `Energy < ResponseMatrix.Energies[0]` собираются в список и выбрасываются
  из библиотеки **тем же ножом**, что и опора полосы по столбцу (`S103`), — метод
  переименован `NarrowLibraryByShare` → `NarrowLibrary`, заказчиков у него теперь
  двое, второй копии кода не заведено;
* трогаются ТОЛЬКО компоненты, идущие через матрицу: у образа с `WeightsAreFinal`
  (обратное рассеяние) столбец строит `BuildTemplate` по кривой, первого узла у
  него нет;
* сработавший нож называет себя в `BandNote` — «ниже первого узла матрицы (N кэВ)
  выброшено K линий, образов опустело M». Плечо без выброса молчит, но его видно
  по отсутствию строки.

⚠ **И это не «прошло», а «не проверено»**: нож не сработал НИ РАЗУ на 121 спектре —

отсутствия вреда, а не подтверждение пользы. Подтверждение одно: сама сцена.
Значит правка выстреливает только там, где нижний край сетки ПОДНЯТ против
умолчания 5 кэВ, — как у «Цилиндр Lu» с её 20 кэВ.
