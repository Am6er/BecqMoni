## 5. Что именно ломается: механизм назван и посчитан

Правка (`git diff d2523ebd b2ee8207 -- .../FsaSampleLibrary.cs`) добавляет вызов
`AddEscapeImages(spec, result, report)`, который зовёт

```
FsaLibrary.EscapeImages(result, spec.CrystalFractions.Count > 0 ? spec.CrystalFractions : null)
```

а в `FsaLibrary.EscapeImages` отсев по доле рождения пар записан так:

```csharp
double share = PairShare(crystalFractions, line.Energy);
if (!double.IsNaN(share) && !(share >= EscapeMinPairShare))
{
    continue;         // пары рождаться могут, но не рождаются
}
```

⛔ **При `crystalFractions == null` доля равна `NaN`, и отсев ВЫКЛЮЧАЕТСЯ ЦЕЛИКОМ.**
Родителем вылета становится любая линия выше 1022 кэВ с выходом не ниже
`EscapeMinIntensity`, а вес — сырой выход, без доли пар. Поэтому наверх выходит
не Tl-208 2615, а Bi-214 1120 (выход ~15 %), у которого рождение пар всего на
98 кэВ выше порога и физически ничтожно.

**Счёт сущностей — образы вылета появляются РОВНО там, где нет матрицы:**

| плечо | понятная часть (G1S16+G1S24) | непонятная часть (AS80x80+ASN16) |
|---|---|---|
| `D3_lib2` (матрицы на месте, 42 из 42) | **0** образов `SE-*`/`DE-*` | **36** образов |
| `D1_app7` / `b2ee8207` (матрицы потеряны) | **25** образов | 36 образов |

То есть `CrystalFractions` приходят ВМЕСТЕ С МАТРИЦЕЙ, и спектр без матрицы
получает образы вылета без единого физического ограничителя.

### Куда садятся образы

| образ | энергия | что там на самом деле |
|---|---|---|
| `SE-1120` | 1120 − 511 = **609.0** | Bi-214 **609.3** — сильнейшая линия ряда радия |
| `DE-1631` | 1631 − 1022 = **609.0** | она же |
| `SE-1631` | 1631 − 511 = **1120.0** | Bi-214 **1120.3** |
| `DE-1120` | 1120 − 1022 = **98.0** | рядом с Th-234 **92.6/92.8** |
| `DE-1588` | 1588 − 1022 = **566.2** | склон комптона Ac-228 |

Образ вырожден с настоящей линией, NNLS делит отсчёты между ними как угодно, и
амплитуда нуклида уходит под гейт значимости.

## 9. Что делать с `S141` — решение Amber

Правка `S141` сделана по существу верно (SE/DE в модели нужны), но её отсев по
доле рождения пар на спектре **без матрицы молчит целиком**, и там она берёт
76 % отсчётов одним образом и стоит 7 пунктов recall. Три исхода, и выбор не мой:

1. **Отменить `AddEscapeImages` до починки отсева** — непонятная часть
   возвращается к 205.3 / 96 %, база переобъявляется третий раз за сутки.
2. **Оставить и починить отсев:** при `crystalFractions == null` считать долю
   рождения пар по веществу кристалла из конфигурации прибора, а не отключать
   отсев; плюс не брать родителей ближе N кэВ от порога.
3. **Оставить как есть, признав законной ценой** — тогда 89 % и есть recall
   непонятной части, и это надо записать в базу словами, а не молча.
