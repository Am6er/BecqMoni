## AMBER176 — форма прибора теряет старшие коэффициенты

**Было.** `DeviceConfigForm.button1_Click` писал подгонку только в поля; `SaveFormContents` берёт c2…c4
до степени СТАРОЙ шкалы → c2 терялся. Калибровка по одной точке добавляла (0, 0) в сам список.
Попутно `button9_Click`: `num < 0 && num >= Count` (никогда не верно) и `num = 0` без выделения —
«Удалить» без выделения удаляло первую точку, на пустом списке падало.

**Сделано.** `DeviceConfigForm.cs:2080-2087` — точки в локальной копии списка (и степень — по
`points.Count`); `:2181-2190` — после второй `CheckCalibration` `activeDeviceConfig.EnergyCalibration =
energyCalibration` (свой объект обработчика); `:1985-2000` — без выделения `num = −1`, условие `||`.

**Замер (проба, форма без окна, `LoadFormContents` новой конфигурации → `button1_Click` →
`SaveFormContents`).** Три точки на шкале [−2, 0.35, 4e-6]: до — после «Калибровать» в конфигурации
`[0, 1]`, после «Сохранить» степень 1 `[−2.0, 0.35]` (c2 потерян); после — степень 2
`[−1.99999999999999, 0.35, 4.00000000000003E-06]`. Одна точка: до — точек в списке 1 → 2, после — 1 → 1.
«Удалить» без выделения: до — 2 точки → 1, пустой список → `ArgumentOutOfRangeException`; после — 2 → 2,
пустой → без броска.

**Экран.** Новая конфигурация (160 каналов), три точки (25, 86, 152 → 10, 40, 90 кэВ), «Execute
Calibration» → 2nd Coeff 0.00209269668415144, «Save» → в файле копии конфига `PolynomialOrder` 2,
коэффициенты `2.20421590371248, 0.259513946747715, 0.00209269668415144`. ⚠ На 2500 каналах та же
подгонка честно понижается сторожем изгиба до 1 (не дефект — `S42`).
