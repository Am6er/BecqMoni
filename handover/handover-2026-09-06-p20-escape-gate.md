## 1. Что именно правилось

Две половины, обе названы решением Amber, и обе нужны.

### Половина А — вещество кристалла восстанавливается по названным элементам

`FsaSampleLibrary.CrystalFractionsOf(spec)` — новая. Массовые доли кладёт
`DescribeCrystal`, и кладёт **только из геометрии**; у спектра без геометрии их
нет. Но сам кристалл известен и без неё: его элементы называет конфигурация
прибора (в корпусном замере — колонка `crystal` таблицы `materials.csv`), и они
лежат в `FsaSampleSpec.CrystalElements`.

Восстановление — **однозначное совпадение состава**, не догадка: набор элементов
сверяется с составом каждого вещества-кристалла библиотеки
(`GeometryMaterialLibrary.Of(MaterialKind.Crystal)`, порог доли 1 % — тот же, с
каким элементы и отбирались). Подходит ровно одно вещество — берутся его доли;
ни одного или больше одного — пусто.

⚠ **Равными доли не считаются.** У NaI натрий и иод дают по массе 0.153 и 0.847;
«поровну» ошиблось бы в долю рождения пар примерно в полтора раза.

⚠ Имён веществ в коде при этом не появилось (решение Amber 01.09.2026): вещество
опознаётся СОСТАВОМ, а список составов — данные библиотеки, которую правит
человек.

### Половина Б — запас над порогом рождения пар, работающий ВСЕГДА

`FsaLibrary.EscapeParentMarginKev = 124.0`. Родитель обязан стоять не ниже
`PairThresholdKev + EscapeParentMarginKev` = **1146 кэВ**, знаем мы вещество или
нет. Отсев по доле при `NaN` больше не отключает сам себя: он заменяется своим
следствием, посчитанным заранее.

Порядок проверок в `EscapeImages` теперь такой: **сперва запас, потом доля.**
Форма `!double.IsNaN(share) && !(share >= EscapeMinPairShare)` — та, которой
отсев выключал себя, — снята; осталось `!double.IsNaN(share) && share <
EscapeMinPairShare`, и молчать при неизвестном веществе ей уже нечем.

⚠ `Ann-511` (`PairsPossible`) запас **не трогает**: аннигиляционный квант
рождается в защите и обвязке, а не в кристалле, и вещество кристалла о нём
ничего не говорит. Там прежний голый порог 1022 кэВ.

## 2. Откуда взялись 124 кэВ — ЗАМЕР, а не круглое число

`EscapeMarginProbe` считает долю рождения пар в полном ослаблении для **каждого
кристалла библиотеки** и половинным делением ищет энергию, на которой она
пересекает `EscapeMinPairShare` = 0.1 %.

| вещество | 1100 кэВ | 1173 кэВ | 2614 кэВ | пересечение 0.1 % |
|---|---|---|---|---|
| CsI   | 0.0228 % | 0.1353 % | 15.318 % | 1156.7 кэВ |
| NaI   | 0.0190 % | 0.1129 % | 13.266 % | 1166.3 кэВ |
| **BGO** | **0.0277 %** | **0.1685 %** | **17.674 %** | **1146.3 кэВ** |
| LaBr3 | 0.0164 % | 0.0979 % | 12.309 % | 1174.5 кэВ |
| CeBr3 | 0.0167 % | 0.0996 % | 12.447 % | 1173.4 кэВ |
| SrI2  | 0.0199 % | 0.1181 % | 13.982 % | 1163.8 кэВ |
| CdTe  | 0.0204 % | 0.1208 % | 14.230 % | 1162.6 кэВ |
| CZT   | 0.0201 % | 0.1193 % | 14.100 % | 1163.3 кэВ |
| GSO   | 0.0217 % | 0.1290 % | 14.213 % | 1159.1 кэВ |
| HPGe  | 0.0101 % | 0.0611 % |  9.159 % | 1204.8 кэВ |

**Взято НАИМЕНЬШЕЕ пересечение: 1146.3 − 1022 = 124.3, округлено ВНИЗ до 124.0.**

Почему именно наименьшее, а не среднее и не наибольшее. Ниже этой границы
родителя отвергает **любое известное вещество** — значит запас нигде не спорит с
отсевом по доле, а только продолжает его туда, где вещества нет. Возьми я
наибольшее (германий, 1204.8), запас стал бы СТРОЖЕ физического правила у BGO и
CsI и снимал бы законные образы; возьми круглые 100 кэВ — под запас пролезли бы
линии, которые всякий кристалл считает пустыми.

Проба печатает этот замер заново на каждом прогоне и **отказывает**, если правка
библиотеки веществ сдвинет наименьшее пересечение ниже запаса.

### Чем 98 кэВ отличаются от 1593 кэВ — числом, а не словом

`Bi-214` 1120.3 стоит на 98 кэВ выше порога пар: доля рождения пар там **0.023 %
у CsI и 0.019 % у NaI** — впятеро ниже порога отсева. `Tl-208` 2614.5 стоит на
1593 кэВ выше: доля **15.3 % и 13.3 %**, то есть в шестьсот раз больше. Граница
между ними лежит около 1146–1166 кэВ, и запас проводит её там же.

## 7. Находки

### 7.1 ⛔ Потолок непонятной части на `347ab3ab` — 93 %, а не 96 % (СТРОКА)

Плечо «SE/DE сняты вовсе» на дереве `347ab3ab` даёт **217.6 / 93 %**. Замер П18
на дереве `d2523ebd` тем же способом давал **205.3 / 96 %**. Значит между
`d2523ebd` и `347ab3ab` непонятная часть потеряла ещё **три пункта recall**, и
потеряла их НЕ правкой `S141` — та в этом плече выключена.

Числа дня выстраиваются так:

| дерево | непонятная recall |
|---|---|
| `d2523ebd` (П18) | 96 % |
| `b2ee8207` (П18) | 89 % |
| `347ab3ab` как есть | 87 % |
| `347ab3ab` без SE/DE | **93 %** |
| `347ab3ab` с починенным отсевом | **93 %** |

Развёртка по коммитам промежутка мне не по кошельку (плечо = сборка + прогон, и
это не мои файлы) — отсюда строка, а не правка на месте.

### 7.2 Факт без «сделать»: в приложении вещества кристалла БЕЗ ГЕОМЕТРИИ взять негде

`CrystalFractionsOf` восстанавливает вещество по `spec.CrystalElements`, и в
корпусном замере они есть — их даёт `materials.csv`. А в приложении
`FsaCompositionInference` заполняет `CrystalElements` **только из геометрии**,
той же, что даёт и доли. То есть у пользователя без геометрии половина А
работать не с чем, и его защищает одна половина Б (запас 124 кэВ).

Это не дефект починки — это отсутствие источника: назвать кристалл прибора,
не строя геометрию, в конфигурации сейчас негде. Куда его класть — решение
Amber, и оно возвращено вопросом, а не строкой.

### 7.3 Факт без «сделать»: описание пробы врало ровно в ту сторону, куда смотрел дефект

В шапке `EscapeParentsProbe` стояло «без вещества правило обязано остаться
прежним — спектр без геометрии не должен менять поведение». Прежнее правило без
вещества не отсеивало НИЧЕГО, и фраза читалась как договор, которого никто не
собирался соблюдать. Правлено в этой же полосе.
