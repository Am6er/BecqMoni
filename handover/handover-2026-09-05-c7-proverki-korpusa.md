## `T95` — проверка вершины объявлена независимой от фита, а зависела

### Что было

Шапка `gaussfit_check.py` обещала: «Гаусс тут не участвует вовсе, поэтому
проверка не может подтвердить саму себя». А последним условием `bump_ok` шло

```python
if abs(mu - x[k]) > sigma0 * gaussfit.FWHM_SIGMA:
    return False, top, need          # фит сел не на эту вершину
```

где `mu` — ПОДОГНАННЫЙ центр, приходящий аргументом.

### Замер: подменён фит, данные не менялись

Вердикт `bump_ok` считан на одних и тех же окнах при четырёх разных `mu`
(`scratchpad/c7_t95.py`, вход — все линии, принятые гейтом первого прохода):

| часть | линий | штатный `mu` | БЕЗ зажима | `mu` ПРЕЖНЕГО фита | `mu` + 1 ПШПВ |
|---|---:|---:|---:|---:|---:|
| known | 557 | 61.9 % | 61.9 % | 72.3 % | **24.1 %** |
| unknown | 274 | 64.6 % | 64.6 % | 71.7 % | **21.9 %** |
| excluded | 87 | 79.3 % | 79.3 % | 90.4 % | **43.7 %** |

Перевёрнутых вердиктов при НЕИЗМЕННЫХ данных:

* снятие зажима — **0** (0/557, 0/274, 0/87);
* `mu` прежнего фита — 1 из 469 понятной, 0 из 244 непонятной, 0 из 73 германия;
* **заведомо плохой фит (`mu` сдвинут на одну ПШПВ) — 211 из 557, 117 из 274,
  31 из 87.**

Вывод числом: **зависимость от фита была**, и на плохом фите она переворачивает
38…44 % вердиктов. Заявленной независимости не было.

### Что стало

`bump_ok` разведена на два независимо считаемых ответа:

* `ok` — вершина есть; фит не участвует;
* `mu_hit` — фит сел ИМЕННО НА НЕЁ; считается и печатается ОТДЕЛЬНО.

Шапка модуля переписана и несёт эти числа. **Прежние числа перемеряны и
остаются в силе**: снятие зажима не тронуло ни одного вердикта на всём корпусе,
а полный прогон после правки дал ровно те же значения, что до неё —
known 472/557/+88, unknown 246/274/+30, excluded 73/87/+14.

Мерка теперь печатает отдельной строкой: «вершина есть, а фит сел от неё дальше
ПШПВ — 0 случаев из 10 (в вердикт «бугор» это БОЛЬШЕ не входит)».

### Плохой вход, на котором проверка отказала

`mu` = `ch + ПШПВ` (заведомо плохой фит) на неизменных данных: доля с вершиной
61.9 % → 24.1 %, 211 перевёрнутых вердиктов. До правки это молча ехало в число
«доля с вершиной»; после правки такой `mu` меняет только колонку `mu_hit`, а
вердикт `ok` остаётся прежним.

## `V16` — отрицательный контроль «сдвиг на ±5 ПШПВ» не отрицательный

### В чём мерился сдвиг — и в чём должен

⚠ **Посылка задания («может, сдвиг мерится в каналах или кэВ, а надо в ПШПВ
прибора») перевёрнута замером.** Сдвиг УЖЕ мерился в ПШПВ ПРИБОРА:

```python
e2 = e_ref + sign * FAKE_OFFSET * res_a * np.sqrt(max(e_ref, 5.0))
```

где `res_a` берётся из `corpus/detectors.csv`. И это **не лекарство, а
причина**: чем шире прибор, тем дальше прыжок и тем вернее он попадает на
соседнюю настоящую линию.

| группа | ПШПВ(662) | 5 ПШПВ при 200 кэВ | при 1000 кэВ |
|---|---:|---:|---:|
| AS80x80 | 9.21 % | 167.6 кэВ | 374.7 кэВ |
| G1S16 | 6.65 % | 121.0 кэВ | 270.5 кэВ |
| ASN16 | 5.86 % | 106.6 кэВ | 238.4 кэВ |
| OBS | 4.91 % | 89.3 кэВ | 199.7 кэВ |
| HPGE | 0.20 % | 3.6 кэВ | 8.1 кэВ |

### Валит ли сдвиг проверку на сцинтилляторах — числом

Сверка каждой «заведомо ложной» позиции с ПОЛНЫМ списком излучений пробы
(`build_corpus.sample_lines`, I ≥ 0.1 % на распад родителя), в пределах одной
ПШПВ:

| часть | ложных предложено | стоит на НАСТОЯЩЕЙ линии | доля |
|---|---:|---:|---:|
| known | 2546 | 2113 | **83.0 %** |
| unknown | 1214 | 1007 | **82.9 %** |
| excluded (германий) | 420 | 48 | 11.4 % |

**Да, валит.** По группам приборов — от 96.7 % (ASN8_4096) до 9.7 % (HPGE_GEM);
LaBr (2.95 %) сидит ровно посередине на 66.7 %.

### Положительный контроль объяснения: развёртка по разрешению

Разбиение по группам — это признак, а не причина: у германия и сцинтилляторов
разные пробы. Поэтому опыт с заморозкой: те же 82 спектра понятной части, те же
пробы, тот же список излучений, едет ТОЛЬКО множитель при `res_a`.

| `res_a` × | ложных | на настоящей линии | доля |
|---:|---:|---:|---:|
| 0.03 | 2570 | 110 | 4.3 % |
| 0.10 | 2570 | 335 | 13.0 % |
| 0.25 | 2570 | 764 | 29.7 % |
| 0.50 | 2559 | 1453 | 56.8 % |
| 1.00 | 2477 | 2113 | 85.3 % |
| 2.00 | 2128 | 2010 | 94.5 % |

Доля идёт ЗА множителем при замороженном составе — причина в разрешении.

Поимённо (худшие): `AS80_Cs137_0cm` 964.75 → Ac-228 964.77 (I = 0.25 %);
`ASN16_Granite` 205.29 → U-235 205.32 (I = 5.02 %); `G1S16_Na22_P5` 969.02 →
Ac-228 968.97 (I = 0.79 %).

### Что стало

Ложный набор ЧИСТИТСЯ по полному списку излучений — **одним местом**,
`fake_lines(..., forbidden=full_lines(entry), clean=CLEAN_FWHM)`. Колонка
«ЛОЖНЫЕ ВДАЛИ» тоже переведена на полный список (прежде мерила расстояние до
десятка курированных опор — `gate_blind_check:244`, ровно то, что называет
строка).

Цена вопроса — избирательность гейта, и она меняется вдвое:

| часть | ложных принято, БЫЛО | н/л БЫЛО | ложных принято, СТАЛО | н/л СТАЛО |
|---|---|---:|---|---:|
| known | 368 из 2477 = 14.9 % | 2.58 | **24 из 364 = 6.6 %** | **5.80** |
| unknown | 216 из 1200 = 18.0 % | 2.71 | **15 из 193 = 7.8 %** | **6.27** |
| excluded | 9 из 414 = 2.2 % | 16.67 | **4 из 366 = 1.1 %** | **33.15** |

То есть вывод «избирательность гейта на сцинтилляторах низка (2.19 и 2.21)»
действительно рассыпается: она 5.80 и 6.27.

⚖ Ключ `--clean=0` воспроизводит прежнее поведение ПОБИТОВО (2477 / 368 /
14.9 % / 2.58) — значит изменилась именно чистка и ничего больше.

### Плохой вход, на котором проверка отказала

`--clean=0` — ложный набор не чистится:

```
known    2546  2113  83.0%   В РАБОТЕ 2546  из них на линии 2113 83.0%  ⛔ НЕ ОТРИЦАТЕЛЬНЫЙ
⛔ ОТРИЦАТЕЛЬНЫЙ КОНТРОЛЬ ЗАГРЯЗНЁН настоящими линиями в 3 частях. Код возврата 4.
```

Хороший вход (чистка включена): 0 из 433 / 0 из 207 / 0 из 372, код 0.

⛔ **Собственная ловушка, пойманная своим же контролем.** В первой постановке
счётчик загрязнения считался ТОЛЬКО при включённой чистке. `--clean=0` обнулял
и набор, и счётчик: сторож молчал ровно там, где обязан кричать, — код возврата
0 на заведомо плохом входе. Исправлено: загрязнение МЕРЯЕТСЯ всегда, `clean`
управляет только ВЫБРАСЫВАНИЕМ. Без подброшенного плохого входа этот дефект не
был бы виден.

## `V17` — «доля линий с настоящей вершиной» есть величина не корпуса

### Величиной ЧЕГО она оказалась

Ответ: **величиной ПОКАНАЛЬНОЙ ВЫДЕЛЕННОСТИ пика (`top` против `need = 3√N`),
то есть значимости, делённой на корень из ширины пика В КАНАЛАХ** — а не
интегральной значимости z и уж точно не доли настоящих среди опор.

Признак сравнивает высоту НАД ХОРДОЙ В ОДНОМ КАНАЛЕ с 3√N ТОГО ЖЕ КАНАЛА, а z —
величина интегральная. Одна и та же z, размазанная по вдесятеро большему числу
каналов, даёт вчетверо меньшую поканальную выделенность.

**Показано на двух приборах с разным разрешением, всё прочее заморожено** —
та же сцена, та же z = 35, то же зерно, те же 40 мест, едет ТОЛЬКО ширина
подсаженного пика в каналах:

| кан/ПШПВ | `ASN16_Cs137` (5.86 %) | median top | need | `HPGeGEM_Th232` (0.19 %) | median top | need |
|---:|---:|---:|---:|---:|---:|---:|
| 1.5 | 100.0 % | 816 | 86 | 100.0 % | 787 | 85 |
| 8 | 100.0 % | 159 | 42 | 100.0 % | 139 | 40 |
| 25 | 100.0 % | 65 | 30 | 100.0 % | 55 | 27 |
| 60 | 85.0 % | 32 | 24 | 100.0 % | 34 | 22 |
| 120 | **50.0 %** | 25 | 22 | 85.0 % | 30 | 20 |
| 250 | 45.0 % | 19 | 19 | 85.0 % | 43 | 23 |
| 500 | **35.0 %** | 19 | 25 | 92.5 % | 82 | 29 |

`top` падает с 816 до 19, `need` — только с 86 до 25: отношение едет с 9.5 до
0.8, и ровно там доля обваливается. Это причина, а не совпадение: сцена, проба,
z и зерно заморожены.

⚠ **Первая версия этого опыта показала «зависимости нет» (97.5…100 % на всех
ширинах) — потому что развёртка кончалась на 25 каналах на ПШПВ, а реальные
окна корпуса доходят до 187 (ASN16) и 224 (AS1PRO).** Слишком короткая
развёртка сама выглядит как отсутствие эффекта.

И то же на ЗАВЕДОМО НАСТОЯЩИХ подсаженных пиках одной значимости — доля едет от
прибора к прибору, при том что набор опор тут ни при чём:

| группа | ПШПВ(662) | кан/ПШПВ | z = 12 | z = 35 | z = 120 | штатный набор |
|---|---:|---:|---:|---:|---:|---:|
| HPGE_GEM | 0.19 % | 3.6 | **100 %** | 100 % | 100 % | 93.8 % |
| G1S16 | 6.65 % | 6.6 | 8 % | 54 % | 100 % | 71.7 % |
| ASN16 | 5.86 % | 187.0 | **0 %** | 33 % | 100 % | 64.2 % |
| AS1PRO | 7.13 % | 224.2 | 0 % | 0 % | 100 % | 100.0 % (12 линий) |

⚠ Доля на ШТАТНОМ наборе — это свёртка чувствительности признака (таблица
выше) с распределением опор группы по z, поэтому по группам она едет не
монотонно. Цитировать её как «сколько опор настоящие» нельзя ни в каком виде.

### Что стало: признак назван, второй заведён, изгиб подсажен

* Признаков теперь ДВА, оба считаются всегда и печатаются рядом, имя стоит в
  заголовке каждой колонки и в каждой строке с числом:
  `пик-3√N` (прежний) и `пик-3√N+симм` — **поставочный**.
* Симметрия спада: меньший спад не мельче `SYM_MIN = 0.25` от большего.
  Введена НЕ из красоты, а отрицательным контролем: канонический изгиб
  `G1S24_Y88_P5` 198.1 кэВ даёт спад влево 10090, вправо 2295, отношение
  **0.227**.
* Цена признака на штатном наборе мала: known 73.6 % → **72.4 %** (362 → 356 из
  492), unknown 74.3 % → **73.4 %** (226 → 223 из 304), excluded 90.7 % →
  **90.7 %** (68 из 75, ни одной потери). Развёртка порога: при 0.10 — 361/225,
  при 0.30 — 353/219, при 0.50 — 324/184.
* Заведена **стадия C — подсадка НА ИЗГИБ**, ровно как требует строка: широкий
  смещённый горб вместо пика модельной ширины.
* Заведён **именной контроль** `CANON`: вердикт каждого признака на
  `G1S24_Y88_P5` 198.1 кэВ печатается поимённо, расхождение поставочного с
