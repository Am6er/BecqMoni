# `AMBER295`: автомаска фона и нож при красной строке включены умолчанием, откат выше порога снят (06.11.2026, полоса `fixFSA`)

Решения Amber 06.11.2026 вопросником, дословно: «Возможно ли автоматом не брать участки в рассмотрение, где фон больше спектра?», об откате «Замерить через критика (Рекомендую)», по итогам замера «Маска и нож при красной (Рекомендую)». По вердикту `crit295`, вопросником того же дня, дословно: «Сторож маски (Рекомендую)», о витрине «Разобрать, затем решить (Рекомендую)».

## Что сделано

Оба ключа в конструкторе `true`; выключаются для сравнения: `FsaAnalyzer.BackgroundExcessMask`, `FsaAnalyzer.BackgroundBandKnife`, у корпусной пробы `--bg-mask=0`, `--band-knife=0`. Логи и сценарии на диске, не в git; снимок графика на диске, не в git.

**Автомаска.** Судит окно не уже `BackgroundWarningWidthFwhm` (2 FWHM) с суммарным превышением фона над спектром за `BackgroundWarningZ` (5σ): те же разность, дисперсия, порог и ширина, что у красной строки «фон больше спектра» (`JudgeBandWarnings`). Каналы по их знаку не выбираются: `ExcessWindows` снимает только окна целиком. Снятый канал получает дисперсию `MaskedVariance`, вес и слагаемое χ² исчезают, ndf уменьшается на число снятых каналов, медиана Хубера их не считает.

Первая версия судила и на первом проходе, до перекладки фона, и испортила K-40: пик фона стоял мимо пика пробы, окно на крыле было значимо (2519–2805 кэВ, z 182.6, ×11.8), K-40 0.8435 → 0.8409, χ²П 6.61 → 7.32. Поэтому `WithBackgroundMask`: цепочка идёт без маски; красной строки на итоговом фоне нет — результат прежний до бита; есть — один разбор с маской при найденной шкале фона.

**Тёплый старт.** Разбор с маской стартует от привязки разбора без маски (`AnchorWarmOut`). Холодный старт терял вторую опору ширины: `AS80_Th232Medal` усиление 1.015487 → 1.017734, ширина ×0.9734 по 2 опорам → ×0.8052 по 1, χ²П 50.93 → 60.42 (мутант К2 ниже), Th 920 → 808 в замере критика. Тёплый: ×0.9781 по 2, χ²П 35.02.

**Нож при красной строке.** `UntieBelowTrustFloorWhenStrongAbove` включается внутри разбора с маской, только если окно красной строки лежит в коридоре `AnchorGainBrakeZeroMaxKev` (30 кэВ) … `ResponseContinuumTrustFloorKev` (100 кэВ) (`InKnifeCorridor`). Новых чисел нет. Рампа порога — величина спектра, а не константа, поэтому низ коридора взят с тормоза 30 кэВ. Иначе нож не включается. Нож, не отвязавший ни бина (нет матрицы), не значится: первая сборка приёмки показала строку «активность считана выше 100 кэВ» при «отвязано 0 из 0», это была ложь окна, снято (`knifeWorked`).

**Откат выше порога снят из кода целиком** (`AnchorRollbackAboveTrustFloor`, `--rollback-floor`). Причина: торию не помог (выше 100 кэВ разбор без привязки всё равно лучше: по меткам 30.184 против 31.533, «Из NucBase» 46.167 против 55.329), корпус сломал: `G1S16_Am241_P25` 1.069 → 0.286, χ²/ndf 1.21 → 5.67, опора ниже порога доверия судье не видна; вне паспорта 1 → 2, сумма выходов 14.6 → 78.0.

**Сторож маски.** Правило `FsaAnalyzer.MaskRefusal`: при маске опор шкалы меньше, чем без неё, или участок накрывает сильнейшую линию компонента состава (мешающие образы не в счёт). Отказ в любом проходе отправляет весь разбор заново без маски (`Analyze`), горит прежняя красная строка, строки маски нет, причина — в служебной строке и `FsaResult.BackgroundMaskRefused`. Весь разбор, а не один проход: первая версия отказывала только проходу с привязкой, и откат сравнивал его с проходом без привязки, но с маской, то есть χ² на разном числе каналов. Так `ASN16_Radon_filter2` chain_eq прошёл бы мимо сторожа (усиление 1.000, ряд 13.12). Ключ сравнения `BackgroundMaskGuard`, у `FsaStackShot` `--mask-guard=0`.

**Показ.** Красная строка 37–66 кэВ рядом с маской 30–68 кэВ читалась странно, поэтому при маске одна строка вместо красной, с диапазоном маски. При сработавшем ноже — своя строка. Ключи `FSAReport_BackgroundMaskRow*`, `FSAReport_BackgroundKnife*` в `FSAReportView*.resx`.
