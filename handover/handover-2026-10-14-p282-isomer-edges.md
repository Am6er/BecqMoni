## Метод (скрипт `D:\BqMoni_Claude\p282\add_isomer_edges.py`)

**Кто случай.** Родитель P — каждый `nucid` из `decay_chain`; его рёбра берутся ПРАВИЛОМ ПРИЛОЖЕНИЯ
(`DecayParentRule.ChainTable` + `ChainLevelClause` + `ChainPercColumn`; текст читается из `.cs`, как в
`tools/CORPUS/scripts/chains.py`, своей копии нет). Для ребра P → D (основное состояние) изомеры X — строки
`nuclides` того же нуклида с меткой состояния строчными (`99TCm`, `126SBm1`; признак — регистр).

**Набор ENSDF.** `schemedb.ensdf_datasets` с дочерним D и родителем P, мода из `dsid` (`B-`, `EC`/`B+` — одна,
`A`, `IT`; наборы задержанных частиц не берутся), набор ИЗОМЕРА родителя (`parent_l_seqno` ≠ уровня P) — нет
(иначе у `191HG` брался набор `(50.8 M)` изомера уровня 35); из оставшихся — ближайший по периоду родителя,
допуск ln 1.25 (как `import_weak_gammas.py`), а набору основного состояния у родителя в основном состоянии — до
×10: у долгоживущих период переоценён (Sn-126 ENSDF2 1·10⁵ лет против 2.18·10⁵ в `nuclides`, ×0.46).

**Уровень изомера.** Уровень набора, чей период ближе всего к периоду X (`ensdf_levels.half_life_sec`, допуск
ln 1.5; уровни короче 1 мкс — только с меткой метастабильного). Из пары «m»/«m1» одного состояния (периоды до
1 %) берётся то имя, к которому сводит подпись приложение (`NucidOf`: «Tc-99m» → точное `99TCm`). Изомер, у
которого в `nucdb` нет СВОЕГО распада (ни строк `decay_radiations`, ни ветвей `l_decays`), — сквозной: его поток
идёт дальше по переходам набора (у Sn-126 `126SBm2`, 11 с, отдаёт свои 69.2 % в `126SBm1`).

**Доля прохода — ход по схеме набора.** Заселение уровня = питание (`ensdf_feedings`: β⁻ — IB, захват/β⁺ — TI,
иначе IB + IE, α — IA) + приток гамм сверху; уровень делит поток между выходящими переходами пропорционально
полной интенсивности (TI, иначе RI·(1+α)); уровень изомера — конечный. Переход без привязки к нижнему уровню
привязывается вторым, грубым допуском max(3 кэВ, 1 %) — уровни ENSDF2 бывают округлены («345.0» у `110SN`, где
280.46 кэВ иначе повисала и уносила 100 % потока); у уровня с ОДНИМ выходом без записанной интенсивности
(141EU: 1.58 кэВ в основное) весь поток идёт по нему. **f_отн = заселение изомера / Σ питаний** — величина
внутри набора, нормировки `N` (NR, BR — в `schemedb` не импортированы) не нужно. На распад родителя: **f = BR · f_отн**,
BR — доля ветви P в D по правилу приложения.

**Сверка независимым путём** (балансом основного состояния): f_бал = BR − (прямое питание основного + приток к
нему мгновенных гамм) с якорем RI → % по линиям самой поставки (медиана I_nucdb/RI по сильным, как
`import_weak_gammas.py`). Сошлось — |f − f_бал| ≤ max(0.3 п.п., 15 %). Mo-99: f 87.66 %, f_бал 87.96 %.

**Сложено ли.** Опорная линия — СОБСТВЕННАЯ линия изомера: та, что не совпадает ни с одной гаммой мгновенной
части набора (переходы не из уровня изомера) и которую срез поставки NuDat (1 % сильнейшей, `AMBER151`) не убрал
бы (f·I ≥ 1.2 % сильнейшей гаммы P); у Bi-207 это 1063.66, а не 569.70. Нет такой — сильнейшая, и из выхода P
вычитается её мгновенная часть, посчитанная ТЕМ ЖЕ ходом (γ-поток перехода мимо изомера; у Mo-99 140.511 —
4.68 %). Допуск энергии max(1 кэВ, 4·10⁻⁴·E). Избыток выхода у P ≥ 0.5·f·I_X — СЛОЖЕНО, < 0.2·f·I_X — ПОТЕРЯНО.
⚠ Мгновенную часть по RI набора (с якорем) брать нельзя: набор Os-191 несёт и распад изомера, и RI 129.43 — весь
поток, а не мгновенная часть; первая версия метода так объявила потерянными Os-191, Bi-204, Bi-207, Ta-178.

**Как пишется — расщеплением ветви, а не голой вставкой.** P → X с долей f (тот же уровень и канал, что P → D);
доля P → D уменьшается на f (сумма ветвей P в нуклид D прежняя — как у прецедента поставки `234TH → 234PAm1`
100 % без строки в 234PA); изомеру X, которого `decay_chain` родителем не знает, вставляются его ветви своего
уровня из `l_decays` (одна строка на дочь — наибольшая), IT — в D. ⛔ Голая вставка P → X при P → D 100 %
ДВОИТ D: ряд Sn-126 дал бы Sb-126 100 % + Sb-126m 100 % при истине Sb-126 18.6 %, а `CascadeAtomicData`
получил бы ветвей на 100 % + f. Знаков после точки у новой доли P → D — сколько у вычитаемых: 100 − 1.173 =
98.827, не «98.83» (иначе сумма 100.003).

**Что пишется по умолчанию**: ПОТЕРЯНО, f ≥ 0.1 % (= `MinChainBranch`), хоть одна линия изомера ≥ 0.01 % на
распад родителя (порог `AMBER151`), сверка не расходится. Расходящиеся — ключом `--include-diverging`.
**До неподвижной точки**: изомер, ставший родителем, сам может кормить изомер своей дочки (`123INm → 123SNm`
нашёлся вторым проходом), третий проход — пусто. **Повтор — без изменений**: второй `--apply` по записанной копии
— 0 вставок, 0 правок, отпечаток `decay_chain` тот же (`2ab2241378d72e10`). Без `--apply` база открыта `mode=ro`;
`--apply` в файл дерева, каталога сборки или `%AppData%\BecqMoni` отказывает без `--allow-live`.
