## §0. Вердикт

**Исполнено, принято пробой.** Чтение файла раскладки идёт лестницей целевой файл → `.bak` →
поставочный `config\layout\ExpertMode.xml` из каталога приложения → встроенная копия того же
файла → пусто. Без `.bak` человек видит поставочную раскладку (9 панелей поставочного файла),
а не пустое окно; слово после показа называет, откуда взята («Показана поставочная раскладка
…» / «…, встроенная в приложение»). Новая сборка: `LayoutFileProbe` **181 плечо, «ВСЕ
СОШЛИСЬ», код 0**; сборка П89 (`0f738825`) на тех же плечах — **код 1, дефект воспроизведён**
(`Default`, панель пуста при поставочном рядом и без него). `check_headless`, `check_resx`,
`check_resx_designer`, `check_resx_letters`, `check_resx_zorder`, `check_probe_numbers` — 0;
`check_all.py` в основном дереве после переноса — **40 из 41**, красен только `check_registry`
(N8: журналы `AMBER43–45` чужой сессии не закоммичены — не этой полосы). Закрывает Amber

## §1. Лестница чтения — что откуда, в ClickOnce и в портативной

| ступень | ClickOnce (`%AppData%\BecqMoni\config\layout\ExpertMode.xml`) | портативная (`Package.IsStandAlone`; `Package.Layout` = каталог сборки) |
|---|---|---|
| 1. целевой файл | читается; негоден → отложен в `.broken-<yyyyMMdd-HHmmss>` | то же; ⚠ здесь целевой файл И ЕСТЬ поставочный |
| 2. `.bak` | прежняя удачная копия; поднята → скопирована на место целевого (П89) | то же |
| 3. поставочный файл | `<каталог exe>\config\layout\ExpertMode.xml` — лежит в установке (`Content` + `PublishFile` в `.csproj`), это посев первого запуска (`MainForm.cs:107–118`) | **ступени нет**: `SupplyPathFor` вернул `null`, потому что путь совпал с целевым (сравнение полных путей без регистра) — читать «поставочный» после того, как он же отложен ступенью 1, нечего |
| 4. встроенная копия | EmbeddedResource `BecquerelMonitor.config.layout.ExpertMode.xml` — тот же файл ссылкой из `.csproj`, байт в байт = `config/layout/ExpertMode.xml` (8636 байт, измерено плечом 4.2) | **рабочая ступень портативной сборки** — ровно случай Amber (журнал падения: «автономная установка») |
| 5. пусто | панели по одной из меню «Вид»; слово называет причины ВСЕХ отказавших ступеней | то же |

Правила лестницы, измеренные пробой:

* **Файла нет вовсе** — не отказ (слова нет), но и не пустое окно: лестница идёт со ступени 3
  молча (плечи 2.1б, 4.8). ⚠ Это расширение против П89, где «нет файла → `Absent`, читатель не
  звался»: под «Поставочная раскладка как умолчание» умолчание — поставочная, и удалённый рукой
  файл (совет из журнала падения — «пока файл не удалят руками») больше не даёт пустого окна.
  Прежний исход `Absent` остаётся только когда файла нет И ни поставочной, ни встроенной не
  вышло. Отказ поставочной/встроенной при отсутствующем файле не молчит: строка в поток ошибок
  без окон (`LayoutFile.DescribeAbsent` → `AppUi.Note`, плечо 2.1в).
* **Битый поставочный лестницу не рвёт** — идёт дальше ко встроенной (плечи 2.8/4.5б); битая
  встроенная (или ресурса нет в сборке — `null`) — отказ с причиной, не тишина (2.10).
* **Поставочная и встроенная на место целевого НЕ кладутся** (2.6, 4.3) — `.bak` из них не
  создаётся, запись как была (П89): закрытие запишет то, что человек расставил.
* **До поставочной не доходит, если поднялся `.bak`** — слово его не называет (2.3).
* ⚠ **Прежнее плечо 3.3 П89 изменило исход по замыслу:** обрезанный файл без `.bak` на
  настоящей панели теперь `LoadedFromBuiltin`, а не `Default` (поставочного рядом с пробой
  нет → встроенная); с десериализатором-пустышкой панель остаётся пустой (пустышки библиотека
  снимает), годный файл после этого читается. Остальные плечи П89 — зелены как были.

## §6. Находки (в строки не заводятся — цена и почему)

* **Расширение лестницы на отсутствующий файл** (§1) — решение полосы под слова Amber
  «Поставочная раскладка как умолчание», не отдельное решение Amber; откат — одно условие в
  `LayoutFile.Read` (`if (outcome.TargetExisted)` → лестница только при отказе) и плечи 2.1б/2.1в/4.8
  пробы. Если распорядитель сочтёт, что П89-исход «нет файла → пусто» надо вернуть, — это
  минуты, не строка.
* `DescribeAbsent` пишет по-английски — как остальные `AppUi.Note` (поток ошибок без окон,
  человек за экраном этого не видит). Ресурсов на него не заводилось: читатель — проба.
* После `LoadFromXml` поставочной раскладки с содержимым-пустышками библиотека держит
  `FloatWindows = 5` при двух `FloatWindow` в файле — поведение DockPanelSuite на скрытых
  плавающих панелях, приложения не касается (в П95 экран показал раскладку верно); мерится
  только `Contents`.
* `build_all.ps1` в свежем `-Out` печатает «нет заверенной записи набора — свежесть судится
  ВРЕМЕНЕМ (T41)» — ожидаемо для первого заверения, не отказ.
* `check_build_recipe.py` покраснел на первой копии `build_wt.ps1` в `handover/`: сторож ищет
  ключ `/p:GenerateManifests=false` в окне восьми строк после `MSBuild.exe`, а в моём скрипте
  между `$msb = …` и вызовом лежало девять строк переменных. Скрипт переупорядочен (переменные
  выше `$msb`, ход и ключи те же), сторож — 0; прогоны §4 шли исходной редакцией с тем же
