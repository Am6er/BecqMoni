# AMBER224 — гипотеза ускорения FSA на GPU

## Постановка

Amber 14.10.2026, консоль, дословно:

> Запиши задачу - проверить гипотезу ускорения расчёта FSA для выбранного спектра на GPU. Пока
> привяжись ко включённой галке "Use GPU" в расчёте матрицы отклика.
> Нужно сравнение было/стало отношением на сценах: точка, цилиндр, маринелли. Критерий сходимости -
> бит-в-бит.

Разобрано навыком аналитика: вопросов к Amber не осталось — ответы ниже взяты из дерева.

## Что значит каждое слово постановки

* **«Расчёт FSA для выбранного спектра»** — разбор в окне приложения: сеанс FSA документа
  (`FsaAnalysisSession.Compute` → `FsaAnalyzer`).
* **Галка «Use GPU»** — `GlobalConfigInfo.UseGpuForResponseMatrix`, галка «Use Nvidia GPU» окна
  матрицы отклика (`AMBER219`, П245; по умолчанию ВЫКЛ). Галка включена — разбор идёт GPU-путём,
  выключена — прежним путём, побайтно как сейчас.
* **«Было/стало отношением»** — время разбора одного спектра:
  * «было» — нынешний путь на ЦП (N−1 потоков, `AMBER213`);
  * «стало» — GPU-путь на той же машине;
  * отношение «было/стало» — по тёплой медиане и отдельно по холодному прогону, как в журнале П241.
* **Сцены «точка, цилиндр, маринелли»** — по спектру с живой матрицей на каждую сцену. Спектры берутся
  из спектров Amber и из понятной части корпуса; полоса называет их в журнале. Без матрицы разбор другой —
  это отдельная строка таблицы, не подмена.
* **«Бит-в-бит»** — снимок результата разбора с GPU и без него совпадает побайтно, числа сверяются
  битами. Мерило есть: проба `FsaSpeedProbeP241`, ≈230 тыс. строк снимка на спектр. Положительный
  контроль — `--flip=…`: снимок обязан разойтись.

## Что известно о цене разбора

Журнал [П241 / AMBER213](handover-2026-10-07-p241-amber213-fsa-speed.md).

Почти всё время уходит на построение образов компонентов:
* `BuildFitColumns` / `BuildTemplate` — уширение гистограмм поглощения;
* строка Грам и решатель NNLS (`SolveFitColumns`);
* опоры привязки шкалы;
* связка членов ряда.

После распараллеливания (15 потоков) разбор занимает:

| спектр | матрица | время разбора |
|---|---|---|
| Th232 | есть | 3.0 с |
| «Cs 137 в домике» | есть | 1.4 с |
| Lu176 | есть | 0.65 с |
| AS80 Cs-137 | есть | 1.4 с |
| «Радон деревня» | нет | 1.9 с |

С матрицей ускорение упирается в ПОСЛЕДОВАТЕЛЬНУЮ часть:
* гистограммы поглощения (`DepositOf` → `BuildResponseDeposit`);
* суммирователь каскадов;
* кэш переноса `ResponseMatrix.TransferCache` — изменяемое состояние без защиты.

## Что следует из «бит-в-бит» (известно заранее, не догадка)

* **FMA.** nvcc по умолчанию сливает `a·b + c` в FMA (`--fmad=true`), и это меняет округление против
  .NET. Поэтому ядра собираются с `--fmad=false` или явными `__dmul_rn` / `__dadd_rn`.
* **Порядок сумм.** Суммы идут в том же порядке, что на ЦП: одна нить — один выходной элемент,
  последовательный цикл по тем же индексам. Параллельные свёртки и атомарные сложения бит-в-бит не дают.
* **Трансцендентные функции.** `exp`, `log`, `erf` не округляются корректно, и CUDA libm отличается от
  CRT, которую зовёт .NET. Поэтому веса ядер, профили линий и всё, где есть эти функции, считаются на ЦП
  и передаются на GPU. Другой путь — перенести саму функцию побитно. `sqrt` и четыре действия
  округляются корректно в обоих мирах.
* **Значит, на GPU — только арифметика.** Это уширение по готовым весам, строки Грам, сложение образов.
  Выигрыш ограничен их долей в профиле.

## Где живёт GPU

* Родная DLL `BecquerelMonitor/rmgpu_f.dll` собрана из `tools/effmaker/gpu/*.cu`. Она лежит в git
  с паспортом и сторожем (П245).
* Обёртки:
  * `EfficiencyMaker/GpuMatrixRun.cs`;
  * `EfficiencyMaker/GpuPack*.cs`;
  * `RmGpu.Probe` — поиск устройства.
* Новые ядра FSA — в той же DLL или в соседней. Паспорт и сторож обновляются тем же движением.
* GPU-порт ведёт распорядитель (решение 05.10.2026).

## Приёмка

1. Галка ВЫКЛ — снимок `FsaSpeedProbeP241` побайтно прежний на всех спектрах замера.
2. Галка ВКЛ — снимок побайтно равен снимку ВЫКЛ на трёх сценах (точка, цилиндр, маринелли) и на
   спектре без матрицы. Положительный контроль расходится.
3. Таблица «было/стало» по сценам: тёплая медиана, холодный прогон, мс и отношение.
4. Витрина FSA (`check_fsa_showcase`) и малая база против `out_rev46_*` — побайтно; `check_all` — 0.
5. Ускорения нет или бит-в-бит недостижим — гипотеза отвергнута числом. Код не остаётся, итог — в журнал.
