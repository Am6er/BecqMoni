## 1. Как сделаны веса по модели (`FsaAnalyzer.cs`)

Веса решателя до правки: `variance[i] = max(raw[i], 1) [+ (ξ·continuum)²] [+ шум вычтенного фона] [+ γ²N² + β²B²]`,
`baseWeights = 1/variance`; `FitHuber` три прохода (при `HuberM > 0`): `weights = 1/variance`, после прохода —
`× m·σ/|r|` у каналов с `|r| > m·σ`, `σ = √variance`. Смещение (П46): `E[(y − μ)/y] ≈ −1/μ`, градиент по колонке
несёт `−Σφ/μ`.

**Правка** (`patch_analyzer.py` + переворот умолчания, +167/−5 строк):

1. `ModelWeights { get; set; }` — свойство по образцу соседей (`RefitZRelative`, `CascadeSumPhotonLight`),
   описание без копий чисел/полярности (`check_fsa_docs.py` код 0); полярность — у присваивания в конструкторе.
2. В `Analyze`, там же, где строятся `baseWeights` (после ВСЕХ слагаемых дисперсии), при ключе запоминаются
   `NoiseTerms`: `Subtracted[i] = raw[i] − y[i]` (континуум SNIP + фон — то, что вычтено из сырого отсчёта) и
   `Extra[i] = variance[i] − max(raw[i], 1)` (всё сверх пуассона). Плечо ВЫКЛ этим не касается вовсе.
3. `FitResult` получил `Model` (модель фита, ставится в `FitOnce` — массив уже был) и `Variance` (дисперсия,
   от которой построены `Weights` финального прохода).
4. `FitHuber` — один IRLS для обоих перевзвешиваний:

   ```
   scale = variance                      // по данным — как прежде
   passes = HuberM > 0 ? 3 : 1;  при ModelWeights и passes < 2 → passes = 2
   for pass:
       best = FitOnce(weights)
       if ModelWeights: scale = max(Model + Subtracted, 1) + Extra     // модель ЭТОГО прохода
       w = 1/scale;  if HuberM > 0 && |r| > HuberM·√scale: w *= HuberM·√scale/|r|
   best.Variance = scale
   ```

   **Сочетание с Хубером — обоснование.** Оба перевзвешивания — множители одного веса
   `w_i = ψ(r_i/σ_i)/(r_i/σ_i) · 1/σ_i²`; Пирсон меняет σ_i (от модели вместо данных), Хубер — ψ. Считать их
   одним проходом естественно и дешевле, чем две вложенные итерации; и порог Хубера `m·σ` при σ по модели
   ПРАВИЛЬНЕЕ, чем по данным: канал с провалом вниз при σ по данным выглядел выбросом только потому, что его σ
   схлопывалась вместе с отсчётом (σ² = y), а σ модели от одного отсчёта не зависит. Первый проход остаётся по
   данным (затравка; модели ещё нет), проходов при Хубере по-прежнему три, то есть два перевзвешивания по модели;
   без Хубера (`--huber=0`) проходов два. Сетка дрейфа (`FitOnce` по узлам усиление×ноль) сравнивает узлы
   ОДНИМИ весами по данным — общей меркой, не зависящей от модели узла, — и это держит цену: 81 узел без
   лишних проходов. Тот же `FitHuber` служит и всем последующим фитам (привязка, отсев, гейт, обратное
   рассеяние): каждый сам пересобирает веса от своей модели.
5. `ComputeCharacteristicLimits`: `V = fit.Variance ?? variance`, нулевая гипотеза `v0 = V[i] − a·φ[i]` — при весах
   по модели это ровно `μ̂ − a·φ` (модель без компонента), при весах по данным — прежняя `variance` (тот же массив,
   побитово). Это и есть «одинаково для нулевого прохода МК-поверки»: копия МК разбирается тем же `Analyze`,
   её пределы — той же формулой от дисперсии того же оценщика.
6. `AnchorScale` (центроиды опор) оставлен на дисперсии по данным — он не оценщик состава; отчётные веса
   (`reportWeights`, `Chi2NdfPoisson`, ε, `ReportNdf`) не тронуты.

**Ключ и печать.** `CorpusFsaProbe --weights=data|model` → `Options.Weights` (null — умолчание анализатора) →
`analyzer.ModelWeights` в `NewAnalyzer`; `KEYS` печатает `Weights нет → model`, `SETUP` — `ModelWeights False → True`
отражением (`FsaTuningReport`), `APPLIED` — свидетельства прежних точек (ключ уходит в анализатор, точка применения —
`SETUP`). Строка сдвига «−Σφ/μ (П46)» в сводке `--limits-mc` при весах по модели помечается
«НЕ ДЕЙСТВУЕТ … справочно». `FsaP42ArmProbe --weights=data|model` — тот же ключ хуком `ProbeSetup` для
`FsaStackShot --infer` (файл `FsaStackShot.cs` правит П48 — не тронут, запускался как есть).
