# Полоса G11 (06.09.2026): `A240`, восьмое место — `DocumentManager.CheckDocument`

Довесок к `A240` (родня ~~`A234`~~, ~~`A235`~~). Семь мест-читателей причины
отказа `FwhmCalibration.DefaultCalibration(cfg, energyCalibration, out string refusal)`
чинит полоса F62; здесь — восьмое, `BecquerelMonitor/DocumentManager.cs`,
`CheckDocument` (второй вызов старой подписью). Реестр не правился (по заданию).

Артефакты: `handover/g11-a240/` — `build_g11.ps1` (сборка приложения и двух проб
вручную тем же `csc`; `build_all.ps1` в момент полосы падал на чужих пробах F62),
`before/` и `after/` (замеры на дереве ДО правки — `bin\Debug_G11ref` — и ПОСЛЕ —
`bin\Debug_G11`), `diff-*.patch` (⚠ `diff-DocumentManager.patch` содержит и
незакоммиченные строки полосы G10 — ключи `ERRChannelEdge*`, они не мои),
`check_all.txt` (12 из 12 сторожей, код 0).

## Что сделано

1. **`CheckDocument` переведён на перегрузку с причиной.** Точка служебная:
   `bool`, сюда ведут семь методов (`CreateDocument`, `OpenDocument`, `LoadDocument`,
   `ImportDocumentAtomSpectra`, `ImportDocumentN42`, `LoadBackgroundSpectrum`,
   `ImportCsvEnergyToDocument`). Голоса у неё НЕТ и быть не должно — иначе он
   удвоил бы голос двери. **Читатель причины — `ReportMissingFwhmCalibration` →
   `WhyNoFwhmCalibration`** (тот же метод, которым говорят обе двери ввоза и, с
   F54, открытие/создание). Причина уходит наверх ПОЛЕМ: слабая таблица
   `ConditionalWeakTable<ResultData, string> fwhmRefusals` рядом со спектром,
   пишется `RememberFwhmRefusal` (снимается, если кривая построилась), читается
   `WhyNoFwhmCalibration` первой; переспрос `DefaultCalibration` остался только для
   спектров, которые `CheckDocument` не проходили (дверь SpecUtils).

2. **Найден и закрыт на месте дефект в том же месте: открытие выдумывало прибор.**
   `ResultData.PeakDetectionMethodConfig` помечен `[XmlIgnore]` и в файл не пишется;
   после разбора у каждого спектра стоят ВСТРОЕННЫЕ умолчания
   `new FWHMPeakDetectionMethodConfig()` = 15/3756/103. В `OpenDocument` и
   `LoadDocument` `CheckDocument` шёл ДО `PrepareDeviceConfig`, то есть кривую
   разрешения для документа без сохранённой кривой строил по встроенным числам, и
   лишь потом подставлялись настройки прибора. Итог — «кривая есть
   `[0:15 3756:103]`», 0 голосов, при конфигурации прибора, у которой умолчание не
   строится вовсе. Это `A239` («модель разрешения выдуманного прибора»), но на
   пути ОТКРЫТИЯ, а не ввоза. Правка: `PrepareDeviceConfig` перенесён перед
   `CheckDocument` в обоих методах (в `ImportDocument093b` `CheckDocument` не
   зовётся — не трогал). Затрагивает только файлы БЕЗ элемента `FwhmCalibration`:
   у 129 из 129 корпусных спектров он есть (`grep -L` = 0), их кривые не
   меняются.

3. **Новое плечо пробы `N42RoundTripProbe --mode=onevoice`** — ровно один голос
   на событие у трёх путей к `CheckDocument`, достижимых без ввоза: создание
   (`CreateDocument`), открытие сохранённого (`SaveDocument` → `CloseDocument` →
   `OpenDocument`), фон (`LoadBackgroundSpectrum` тем же файлом). Голос = строка
   `BecqMoni:` в потоке ошибок (`AppUi.Report` без окон пишет ровно одну).
   Прогрев менеджеров перед замером: без него первое обращение давало «создание 3»
   (библиотека нуклидов, главный конфиг, каталог ROI — не голоса двери).
   Положительный контроль ложной тревоги — исправная конфигурация, 0/0/0.

## Находки по §9

1. **Закрыто на месте** — порядок `PrepareDeviceConfig`/`CheckDocument` при
   открытии (п. 2 выше). Цена: 6 строк в своём файле + замер.
2. **Факт в журнал, не строка:** два пути к `CheckDocument` без читателя —
   `ImportDocumentAtomSpectra` (после `CheckDocument` нет
   `ReportMissingFwhmCalibration`) и `ImportCsvEnergyToDocument` (то же). Состояние
   туда доходит по коду (`ResetSpectrumConfig` кривую не трогает, `CheckDocument`
   строит по настройкам документа), но человек его УЖЕ слышал при создании
   документа, в который ввозит (`CreateDocument` говорит), и дверь N42 в том же
   положении говорит второй раз — соглашение дверей (`A160`/`A175`) здесь
   расходится: две двери говорят, две молчат. Не правил: по заданию — «только
   этот вызов и его читатель», и без файла Atom Spectra / CSV в пробе замера нет.
   Дописка в `A240`, а не строка: правка — по одной строке в каждой двери, тем же
   методом; решение о голосе дверей ввоза — за распорядителем.
3. **Факт:** `noconfig` в исправном плече «документ пробы | SpecUtils» показывает
   «дверь сказала слово: 1» — это строки первого обращения к менеджерам
   (библиотека нуклидов, главный конфиг), не голос двери; те же строки давали
   «создание 3» в `onevoice` до прогрева. У `noconfig` прогрева нет — числа его
   первого плеча на единицу завышены. Не правил: чужое плечо, на выводы `A234`
   не влияет.
4. **Факт:** текст `ERRNoFwhmCalibrationImport` говорит «ввезённых спектров» и
   при создании нового документа, и при открытии сохранённого — ключ общий (так
   решено в F54: «тот же ключ, если суть та же»). Нового ключа не заводил.
5. **Факт:** `LoadBackgroundSpectrum` строит кривую фону через `CheckDocument`,
   и при отказе она у фона null — читателя у неё нет и не нужен: фон вычитается
   по отсчётам, `BackgroundEnergySpectrum` с ПШПВ нигде не связан (grep пуст).
   Голосов 0 в обоих плечах — правильно.

## Готовая дописка в `A240`

➕ **06.09.2026 (G11): восьмое место — `DocumentManager.CheckDocument` — переведено
на перегрузку с причиной; читатель — `ReportMissingFwhmCalibration` →

строило её по ВСТРОЕННЫМ 15/3756/103 (`PeakDetectionMethodConfig` в файл не
пишется, `CheckDocument` шёл до `PrepareDeviceConfig`) — «кривая есть
`[0:15 3756:103]`, голосов 0» при приборе, у которого умолчание не строится
(`A239` на пути открытия); `PrepareDeviceConfig` перенесён перед `CheckDocument`
в `OpenDocument` и `LoadDocument`, корпус (129, все с кривой в файле) не сдвинулся.
Без читателя остались два пути к `CheckDocument`: `ImportDocumentAtomSpectra` и
`ImportCsvEnergyToDocument` — не зовут `ReportMissingFwhmCalibration` после
проверки; по одной строке тем же методом, замера нет (нужен файл Atom Spectra /
CSV в пробе). Журнал:
