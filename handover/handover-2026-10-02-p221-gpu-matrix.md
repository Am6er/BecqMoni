## Архитектура порта (`tools/effmaker/gpu/README.md`)

* Физика — построчный перенос горячего пути C# (≈ 4100–4400 строк на историю при
  умолчаниях, карта `map_history.md` §6) в CUDA C++, те же имена функций; данные собирает
  тот же C#-код приложения, упаковщик пробы (`GpuMatrix.cs`, `GpuPackTables.cs`,
  `GpuPackScene.cs`) снимает их ОТРАЖЕНИЕМ и шлёт одним позиционным потоком с контрольным
  словом после каждой записи (`host.h`).
* Настройки — все открытые простые поля `EfficiencySimulator` по имени (`cfg.h`, 69 полей,
  сгенерировано отражением); незнакомое имя или неустановленное поле — отказ.
* Постобработка узла (нормировка, перенос шкалы света, свёртка шума, κ, клеймо, запись)
  остаётся C#-кодом приложения: GPU возвращает сырые суммы узла, проба кладёт их в
  симулятор и зовёт его закрытые методы отражением — вторая копия обвязки не пишется.
* Две ступени приёмки: (1) `real = double` + xorshift64* с состоянием CPU на начало
  истории — сверка ПО ИСТОРИЯМ (занос, канал, свет), допустимы лишь редкие развилки на
  последнем разряде `log`/`exp`; (2) `real = float` + Philox по (узел, история) — матрица
  узел к узлу против склада rev41 статистикой, затем корпус FSA.

## Ступень 1 приёмки — сверка переноса по историям (02.10.2026)

`CorpusMatrixProbe --gpu-check=N` (`GpuMatrixCheck.cs`): CPU гонит историю отражением
(`source.NextWeighted` + `OneHistory` либо `AnalogHistory`) и запоминает состояние
xorshift64* на её начало; GPU (`rmgpu.dll`, `real = double`, `-fmad=false`) повторяет ту же
историю. Сравниваются возврат, вес, занос, свет, косинус, бин, канал, признаки и
СОСТОЯНИЕ ГСЧ ПОСЛЕ истории (число выдач).

* Три сцены (цилиндр G1S24, точка RC-103, маринелли G1S16), узлы 0/48/96/143, обе ветви,
  по 20 000 историй: **0 расходящихся из 480 000**, гистограмма взвешенной ветви
  сходится до 7e-15 (`D:\BqMoni_Claude\p221\t0\check1.txt`).
* ⛔ Положительный контроль (`BQ_GPU_CHECK_POISON=1` портит бит состояния чётных историй):
  сверка называет расходящимися **ровно 10 000 из 20 000** в обеих ветвях — она меряет.
* Весь корпус, 49 сцен × 4 узла × 2 ветви × 5000 историй = **1.96 млн историй: 4 с
  развилкой** (`D:\BqMoni_Claude\p221\t1\check_all.txt`):
  * 2 — `ASN16_point0_house`, узел 48 (37.878 кэВ), взвешенная: то же число выдач, другое
    ослабление. Опытом на GPU (`BQ_GPU_LAUNCH=1,1` — одна нить подряд, как CPU;
    `BQ_GPU_RESET=1|2` — сброс кэшей μ / кэша луча перед историей): подряд — 0 развилок,
    сброс кэша луча — развилка воспроизводится, сброс кэшей μ — нет. Значит, **на CPU кэш
    луча не прозрачен**: история #2300 даёт 0.9004 по лучу, оставленному #2299, а с чистым
    кэшем 0.6066 → строка `A315`.
  * 2 — аналоговая ветвь, 3000 кэВ (`G1S_denta120_oisn16_166_p24`, `G1S_petri60_oisn06_064_p24`),
    по одной истории: держатся и одной нитью подряд → не перенос состояния, а развилка на
    последнем разряде `log`/`exp` CUDA против .NET на длинной истории; допустимы по
    определению ступени.
* Итог: **перенос горячего пути верен** (ступень 1 пройдена). Найдено попутно и заведено
  строками: `A313` (состав зазора не упорядочен по Z), `A314` (вложенный каскад затирает
  общий стек), `A315` (кэш луча не прозрачен); GPU-порт повторяет все три КАК ЕСТЬ.

### «Взрыв» float на 6–7 кэВ — разбор и правка

Сверкой по историям во float (`BQ_GPU_CHECK_FLOAT=1`, узел 4, 6.011 кэВ, 300 тыс.): пик узла
на CPU РОВНО НОЛЬ (квант не проходит отражатель и корпус, τ > 60 — обрезка), а во float у
253 историй τ ≈ 44 и вклад ≈ 1e-19 — луч ПРОСКАКИВАЛ тонкий слой: подталкивание через
границу 1e-7 см меньше шага представления float (≈ 1e-6 см на 10 см), точка не сходила с
границы, и порог «позади точки» той же величины терял отрезок. Правка — макросы
`RM_NUDGE`/`RM_BEHIND`/`RM_RAY_BACK`/`RM_ON_RAY2` (`common.cuh`, 21 место в пяти файлах):
в double — РОВНО прежние константы C# (сверка double после правки — 0 развилок на трёх
сценах), во float — 2e-5 / 1e-5 / 1e-5 см / 1e-9 см². После: развилок на узле 4 — 1 из
300 000 (было 253), пик снова ноль; float против double — медиана пика 0.014 % (было 0.141 %),
худший шум Q_k 0.048 (как у double; было 0.37).

Оставшийся «выброс» узла 6 (6.59 кэВ, 5·10⁹ %) — деление на ноль: пик узла 9.8e-21 у CPU и
9.9e-21 у GPU, вклады историй ~1e-27 у самой обрезки τ = 60. Мерка относительного
расхождения на таких узлах бессмысленна, поэтому `MatrixDiffProbe --min-sum=` (П221)
выводит из мерки узлы с Σ строки A ниже порога и печатает их число.

| пара, `--min-sum=1e-6` (18 узлов вне мерки) | пик, медиана / худший % | смещение пика, % |
|---|---|---|
| CPU зерно 0 / CPU зерно 777 | 0.448 / 5.3 (14 кэВ) | −0.148 ± 0.108 |
| CPU зерно 0 / GPU double | 0.516 / 14.1 (13 кэВ) | +0.091 ± 0.150 |
| CPU зерно 0 / GPU float | 0.507 / 14.9 (13 кэВ) | +0.126 ± 0.155 |
| CPU зерно 777 / GPU float | 0.461 / 20.3 (13 кэВ) | +0.291 ± 0.204 |

Худший узел GPU один и тот же у double и float — они берут ОДНИ потоки Philox, это одна
флуктуация на краю пропускания корпуса (13 кэВ, тяжёлый хвост). Скорость после правки и
`-maxrregcount=64`: ядра 15.7 с против 72 с CPU на 15 потоках — **4.6×**.

Профилировщик ядер (Nsight Compute 2025.1) в этой среде падает с `0xC0000409` даже на
пробной программе — замеры делаются прогонами, без профиля.

## `A315` — кэш луча переживает историю: разбор, цена, решение Amber (02.10.2026, вечер)

Корпусный счёт GPU (`t6`) на `AS80_point0` против склада дал смещение пика −3.9 ± 1.2 %:
ниже ~20 кэВ расхождение ПЛАВНОЕ (на 9–14 кэВ GPU ниже склада на 35–60 %). Разбор:

* сверка по историям в double, узлы 14 и 20: раскрой — 3 и 1 развилка, и именно они держат
  пик узла (0.0253 против 0.0069; 0.126 против 0.0045); одна нить подряд — 0 развилок;
* `BQ_GPU_RESET=2` (сброс `rayCount`/`rayValid`) воспроизводит развилку, `=4` (снимок
  `SaveRay`) — нет; `--recollect` CPU её не снимает;
* АРБИТР — свежий CPU-симулятор на той же истории (`GpuMatrixCheck`): #703, #3171, #13515 —
  CPU в потоке 0.0099 / 0.0154 / 0.1218, свежий CPU = GPU ≈ 1e-16…1e-9; #10942 — наоборот,
  загрязнена история GPU (нить несла кэш своей прошлой истории). То есть дефект в ОБОИХ
  счётах, на разных историях, и совпасть они не могли;
* цена (GPU, 3 млн, одни потоки Philox, разница — только сброс кэша перед историей),
  `AS80_point0`: ниже 10 кэВ ложное «дно» 1e-7…1e-6 при настоящем ≤ 1e-11; 12.3 кэВ ×28;
  13.4 +68 %; 14.7 +9.7 %; 16.1 +0.71 %; 17.6 +0.20 %; ≥ 21 кэВ ≤ 0.01 %. Затронуты три
  точечные сцены «на грани»: `AS80_point0`, `RC103_point0`, `ASN16_point0_house`.

Решения Amber 02.10.2026 вопросником, дословно: GPU — **«Сброс на GPU (Рекомендую)»**;
приложение — **«Чинить сейчас (Рекомендую)»**. Сделано: `EfficiencySimulator.ForgetRay()`
(`rayValid = false`) в начале `OneHistory`, `AnalogHistory`, `OutsideNextEvent` и цикла
`TotalEfficiency`; тот же `ForgetRay()` в GPU-порте (`OneHistory`, `AnalogHistory`). Номер
физики не поднимается: по решению пересчитываются три матрицы, у остальных 46 сцен сверка
1.96 млн историй этого класса не нашла.
