## Что было в дереве

Дверь «SpectraLine GBS» — `MainForm.GBSFileToolStripMenuItem_Click` →
`DocumentManager.ImportDocumentGBS` (заведена 17.12.2024, `a8048c10` «Add SpectraLine SPE
spectrum file import», затем `6418c108` «SPE -> GBS rename»). Разбирает формат GBS-Elektronik
(`Ritecdat`): первая строка `$SPEC_ID:` / `$APPLICATION_ID:` / `$DEVICE_ID:`, вторая — пометка
спектра, `$DATE_MEA:` (`MM/dd/yyyy H:mm:ss`), `$MEAS_TIM:` (живое и полное через ДВА пробела),
`$DATA:`, отсчёты, `$ENER_DATA_X:` (точки «канал энергия», кривая — сторожем `S42`), `$COUNTS:`.
Ссылка на описание формата в коде (`gbs-elektronik.de/…/Ritecdat_e.pdf`) ведёт теперь на
паспорт детекторов CdZnTe, описания формата там нет.

SpecUtils (исходник `sandialabs/SpecUtils`, `src/SpecFile_spe.cpp`) читает этот же формат как
IAEA SPE, но точки калибровки берёт только из `$ENER_DATA:` / `$MCA_CAL_DATA:` /
`$ENER_TABLE:` (и полином из `$ENER_FIT:` / `$MCA_CAL:`); `$ENER_DATA_X:` упомянут лишь в
комментарии-перечне разделов.
