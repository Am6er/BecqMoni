Постановка Amber 13.10.2026, дословно: «ищи ошибки в приложении. Особенно — физика и FSA. Если
надо открыть экран и поискать UI баги — без проблем, делай.» Участок полосы — файлы спектров.
Экран не открывался: всё мерилось пробой без окон настоящими дверями приложения.

## Чем мерилось

Проба `tools/effmaker/probes/SpectrumFilesProbeP263.cs` (режимы `xml`, `n42`, `export`, `amp`,
`devcfg`, `csvdate`, `atomic`; описание — в шапке файла). Каталог прогона — копия
`build_p263` с КОПИЕЙ конфигурации Amber (`%AppData%\BecqMoni\config` → `D:\BqMoni_Claude\p263\run\config`);
оригиналы только читались. Входы: корпус `tools/CORPUS/corpus/spectra` (136 файлов
ResultDataFile) и `YandexDisk\Спектры` (683) — 819 файлов. «До правки» — та же проба против
сборки `HEAD` (`48FAF168…`, `D:\BqMoni_Claude\p263\run_before`); новые методы проба зовёт
отражением, поэтому один и тот же exe работает на обеих сборках. Выводы — `D:\BqMoni_Claude\p263\final\*.txt`
(на диске, не в git), «до» — `xml_before.u8.txt`, `keep_before.txt`.

Положительные контроли: отсчёт +1 в копии — расхождение видно; «3600,5» в `MeasurementTime` —
открытие ОТКАЗЫВАЕТ; `<Address>abc</Address>` в конфиге AmplitudaSerial — отказ; механизм
`StreamWriter(имя)` + отказ посреди записи — файл испорчен (на старом коде).

## Находки и сделанное

### 1. ⛔ Времена, которых нет в файле, открытие ставило «сейчас» — Бк в окне результата (сделано)

`ResultData.StartTime`/`EndTime` и `SampleInfoData.Time` по умолчанию — `DateTime.Now`, и файл
без этих элементов открывался с моментом ОТКРЫТИЯ. Такие файлы пишут чужие программы и
конвертеры. Счёт: у Amber 149 из 683 без `<EndTime>` (104 поверочных ЛСРМ — начало есть, конца
нет), 45 без начала и времени пробы (выгрузки RadiaCode, SpectraVibe), 9 без карточки пробы;
в корпусе 89 без `<EndTime>`. Цена — поправка на распад окна результата
(`MeasurementResultManager.DecayToSamplingFactor`): «набор» от начала до сегодняшнего дня.

| | до | после |
|---|---|---|
| файлов без времени с множителем Co-60 ≠ 1 (> 0.1 %) | 192 из 236 | 0 |
| худший такой множитель | Co-60 ×2.8081, Cs-137 ×1.2450 (`SpectraVibe\HPGe GMX\Фон.xml`) | 1 |
| файлов с временами, множитель ≠ 1 (настоящая задержка пробы) | 61 | 50 (−11: файлы с началом и концом, но без времени пробы) |

Поверочный файл ЛСРМ 2024 года (начало 22.10.2024, конца нет) давал Co-60 ×1.135, файл 2016 года — ×1.8.

Правка: признаки присутствия — члены `…Specified` сериализатора (`ResultData.StartTimeSpecified`,
`EndTimeSpecified`, `SampleInfoData.TimeSpecified`: при чтении ставятся, только если элемент
был; геттер всегда true — запись не меняется). `DocumentManager.FillAbsentTimes` в
`OpenDocument` и `LoadDocument` (не на путях 0.93b/0.97b): конца нет — начало + полное время
(`A177`); времени пробы нет — начало; начала нет, а проба есть — время пробы (задержка ноль);
нет ни того, ни другого — `UnknownStartTime` и голос `ERRMissingStartDateTime` один раз на
файл (`A207`).

Формат записи не изменился: все 785 открываемых файлов сохранены обеими сборками —
538 побайтно одинаковы, 247 отличаются ТОЛЬКО элементами времени, ровно у файлов без них
(192 — `<EndTime>`, 44 — `<EndTime>`+`<StartTime>`+`<Time>`, 11 — `<Time>`).

### 2. Импорт CSV ставил дату набора «сейчас» (сделано)

Обе двери CSV (со счётом и с энергиями) оставляли `StartTime`/`EndTime`/`SampleInfo.Time`
моментом создания документа — днём импорта, молча; тот же CSV дверью SpecUtils давал
1970-01-01 с голосом (`AMBER169`). Теперь — соглашение `A207`: `UnknownStartTime` в оба поля,
конец = начало + время, голос `ERRMissingStartDateTime` один раз. Замер `csvdate`: до —
Start/Sample 2026-10-14 02:41 («сейчас»); после — 1970-01-01, End 00:20:34.5 (T = 1234.5 с),
голос есть. Поправка на распад не меняется (проба и начало равны и до, и после).

### 3. Экспорт Atom Spectra, CSV, CSV с энергиями — неатомарная запись (сделано)

`new StreamWriter(имя)` обрезает файл до нуля при открытии: отказ посреди записи поверх файла
человека оставлял обрезок. Теперь — `Utils.AtomicFileWriter`, как у «Сохранить» и N42. Запись
вынесена в методы без диалога `WriteAtomSpectraFile`, `WriteCsvFile`, `WriteEnergyCsvFile`,
`WriteN42File` (пункты меню зовут их; проба тоже). Замер `atomic` (отказ впрыснут: массив короче
числа каналов): до (механизм) — файл «ИСПОРЧЕН»; после — у всех трёх экспортов отказ
`IndexOutOfRangeException`, файл человека ЦЕЛ, `.tmp` не остаётся. Байты прежние: .txt — UTF-8
без BOM, CSV — с BOM (`ef bb bf`).

### 4. CSV округлял время набора до 0.1 с (сделано)

Шапка `TotalTime={0:0.0}` → `{0:0.0#######}`: 3600.25 → было 3600.3, стало 3600.25; вид «3600.0»
сохранён. Свой импорт CSV читает это число в знаменатель.

## Остаток (не чинилось)

* **Экспорт .txt и CSV теряет живое время** (формат несёт одно время). После круга знаменатель
  растёт на долю мёртвого времени: из 313 файлов с живым временем медиана 0.06 %, у 35 больше
  1 %, у 15 больше 5 %, `Detector overload\Cs137-2100cps.xml` — ×3.33 (Бк ÷3.33);
  AmplitudaSerial (живое 3240.5 при полном 3600.25) — Бк ×0.900. Свой ECSV дверью SpecUtils
  время не читает вовсе — подставляется уставка панели. Вопрос Amber 1.
* **N42 пишет «KB Radar / ATOM Spectra» для любого прибора** (785 из 785; Amplituda,
  RadiaCode, Obsidian). Вопрос Amber 2.
* **N42 не несёт карточку пробы**: имя (873 спектра), примечание (873, заменяется описанием
  прибора), время пробы (625), объём (109), масса (62), место (53). Вопрос Amber 3.
* **Время пробы с вкладки — без пояса** (`DateTimePicker` даёт `Unspecified`), начало набора —
  с поясом: на ПК в другом поясе задержка «проба → начало» сдвигается на разницу поясов.
  У Amber 34 файла с разным видом записи. Вопрос Amber 4.
* Файл чужого конвертера с пустым `<Time />` (`SpectraVibe\CZT TeCd\Смесь Am-Ce-Cs-Co-Y.xml`)
  не открывается целиком («Строка "" не является допустимым значением AllXsd») — отказ
  словами; один файл, правка — разбор времени строкой, формат записи трогать.
* Не мой файл: `MainForm.cs:667` — `AutosavePeriod * 60 * 1000` в `int`: при периоде 35792–71582
  мин порог отрицательный, автосохранение на каждом такте (100 мс) во время набора; `(int)` в
  `GlobalConfigForm` при значении больше `int.MaxValue` — `OverflowException`. Замер
  `D:\BqMoni_Claude\p263\autosave_overflow.cs`: 35792 → −2147447296, срабатывает на первом такте.
