## Как строились плечи

Копии моих шести файлов приложения сняты ДО первой правки; плечо «до» собрано
возвратом этих копий (сверка sha256 после возврата — все шесть совпали), плечо
«после» — возвратом правленых. **Обе сборки шли подряд, одна за другой.**

Между сборками обойдено дерево `BecquerelMonitor\**\*.cs|*.resx|*.csproj`
(618 файлов) по времени правки и размеру: **ни один файл не менялся** — ни мой,
ни чужой. Это существенно: в дереве прямо сейчас лежат незакоммиченные правки
соседних полос (`GlobalConfigManager.cs`, `EfficiencyMaker/GeometryModel.cs`,
семь `*.resx` форм), и они одинаковы в обоих плечах.

```powershell
# оба плеча, подряд, отдельными процессами
/p:OutputPath='bin\Debug_A154_before\' /p:IntermediateOutputPath='obj\A154_before\'   # код 0
/p:OutputPath='bin\Debug_A154\'        /p:IntermediateOutputPath='obj\A154\'          # код 0
# в каждый каталог: config\device <- tools\CORPUS\corpus\devices (24 файла),
# N42RoundTripProbe.exe.config <- BecquerelMonitor.exe.config, затем csc пробы
```

⚠ Свежесть пробы проверена СОДЕРЖИМЫМ вывода (новое поле `StartTime` в слепке,
раздел ГОЛОСА со сказанным вслух), а не датой файла.

## `A154`. Заголовок столбца называет ВЕЛИЧИНУ, а не «Score»

Что это за столбец: `PeakFitComparisonItem.Score` считается
`GetPeakShapeAicScore(peakType, chi2)` — **относительный критерий Акаике**:
гауссиана берётся за основу и платит `chi2`, а `ExpGaussExp` и `Voigt` платят
`chi2 + 4`, потому что несут по два добавочных параметра формы. По этой величине
таблица СОРТИРУЕТСЯ и по ней же выбирается форма пика
(`DCFwhmCalibrationView.cs:545-568`). Слово «Score» не называет ничего.

| | английский (первичный) | русский |
|---|---|---|
| `PeakFitChiTableScoreColumn` | `AIC (chi2 + parameter penalty)` | `AIC (chi2 + штраф за параметры)` |

Латиница `AIC` и `chi2` в русском значении — не небрежность: соседние ключи той
же таблицы (`chi2`, `ndp`, `chi2/ndp`) уже стоят латиницей в обеих культурах, и
сторож букв это пропускает (смешанных слов нет).

## `A156`. Один конец круга и другой смотрят в одно поле

Ввоз кладёт прочитанное И в `SampleInfo.Time`, И в `ResultData.StartTime` —
соглашение взято у соседа целиком: `DocumentManager` при ввозе формата GBS
делает ровно это (`info.Time = …; StartTime = info.Time`), а ввоз через SpecUtils
заполняет `StartTime`. То же добавлено в разбор 2006 года, чтобы в одном файле не
осталось двух соглашений.

⚠ **Мерка исправлена вместе с дефектом.** Проба сравнивала `SampleInfo.Time`, то
есть поле, которого вывоз не читает: первый оборот сходился, а второй терял дату,
и мерка этого не видела. Теперь мерится `StartTime`, и печатаются оба поля.
Поэтому число «начало потеряно у 12 из 12» на старом плече не спорит с прошлым
заходом, где было «0»: мерили разное.

| | плечо «до» | «после» |
|---|---|---|
| первый оборот, `StartTime` у 12 файлов | **ПОТЕРЯНО (сейчас) у 12 из 12** | настоящая дата у **12 из 12** |
| **ВТОРОЙ оборот** (вывоз → ввоз → вывоз → ввоз) | гнался у 12, **потерял начало у 12**, сдвиги 3.2·10⁷…3.2·10⁸ с | гнался у 12, **потерял у 0**, сдвиг **0 с ровно** |

Пример строки положительного контроля со старого плеча:
`ВТОРОЙ КРУГ: начало 2022-11-28 10:07:57 → 2026-09-04 22:08:07, сдвиг 118929610.055 с ⛔`.

Второй оборот гоняется ключом `--round2=<каталог>` и файлы кладёт ОТДЕЛЬНО:
иначе перевыгрузка дерева удвоила бы `tools/CORPUS/n42`.

### ⛔ ЧЕСТНО: у пяти мест из шести цена НУЛЕВАЯ, и положительного контроля им НЕ БЫВАЕТ

Замер по ВСЕМ культурам в **среде приложения** (.NET Framework 4.8, 915 культур):

| выражение | отказ | иное значение |
|---|---|---|
| `int.Parse("-3")` без культуры | **0** | **0** |
| `int.Parse("12345")` без культуры | **0** | **0** |
| `double.Parse("3.5")` без культуры | **234** | **179** |

с иным знаком минуса `int.Parse` принимает обычный дефис. Пять мест `int.Parse` —
это ПРАВИЛО («в файле число записано по спецификации — читаем инвариантно»), а не
исправление числа. Единственное место с настоящей ценой — `double.Parse` в
`EnergyCalibration` (413 культур из 915), и у него нет читателей.

⛔ **Первый замер этого же был сделан в PowerShell 7 и дал «57 культур
отказывают».** PowerShell 7 — это .NET 8 с ICU, а приложение — .NET Framework 4.8
с NLS; таблицы культур у них разные, и число оттуда качественно ложное. Проверено

## Новые находки, измеренные по ходу (строк в `TODO.md` не заводил — запрет полосы)

1. ⚠ **`AppUi.Report` печатает «BecqMoni: : текст»** — двойное двоеточие, потому
   что все места `N42/Util.cs` (и соседи в других файлах) зовут её с пустым
   заголовком. Видно в безоконном выводе каждого нового голоса `A157`/`A160`.

2. ⚠ **Разбор 2006 года отказывает во ввозе из-за даты, а разбор 2012 — нет.**
   `ImportFromN42(N42InstrumentData…)` зовёт `XmlConvert.ToDateTime(starttime, …)`
   без всякой обёртки: файл без `<StartTime>` или с негодной записью роняет ввоз
   ЦЕЛИКОМ, тогда как после `A157` соседний разбор в том же файле ввозит и
   говорит вслух. Опять два соглашения об одном положении. Не правил нарочно:
   правка изменила бы список ввозимого, а строки на это нет.

3. ⚠ **Ввоз N42 не заполняет `ResultData.EndTime`** — остаётся «сейчас», тогда
   как соседние ввозы (GBS, SpecUtils) ставят `StartTime + MeasurementTime`.
   `A156` свела время НАЧАЛА, конец остался несведённым.

4. ⚠ **Файл из одних только `Calibration` ввозится ПУСТЫМ документом** (8192
   канала, сумма 0) — это соглашение соседа, `ImportDocumentSpecUtils` ведёт себя
   так же. Человеку теперь говорится «Спектров ввезено: 0», но пустой документ
   всё равно открывается, и дальше по нему считают. Чинить надо У ОБОИХ разом,
   иначе снова разъедутся.

5. ⛔ **Замер культур в PowerShell 7 не отвечает за среду приложения.**
   PowerShell 7 — .NET 8 с ICU, приложение — .NET Framework 4.8 с NLS. Одно и то
   же выражение `int.Parse("-3")` даёт «57 культур отказывают» в первом и «0» во
   втором. Мерить культурные свойства приложения нужно ПРОБОЙ на .NET Framework.

6. ⚠ **Питон снял CRLF у файла пробы, несмотря на `newline=''` в обоих концах.**
   Поймано побайтовой проверкой сразу после правки (`CR=1` при `LF=1121`),
   восстановлено. Файлы, правленные тем же приёмом с `encoding='utf-8-sig'`,
   остались CRLF — то есть дело не в очевидном месте. Проверять байты после
   КАЖДОЙ питон-правки, а не после подозрительной.

7. ⚠ **Настоящих файлов с классом `Calibration` и настоящего
   `RadiologicalInstrumentData` в дереве по-прежнему нет** — `A160` и `A152`
   закрыты сочинёнными входами. Как и в `A143`, круг «мы → мы» о совместимости с
   чужими приборами не говорит ничего.
