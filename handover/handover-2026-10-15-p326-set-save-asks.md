## Форма вопроса и довод

**Три ответа — «Да» / «Нет» / «Отмена», и «Нет» честно пишет только наборы.** Разделить при общем файле оказалось
можно, потому что заведение и удаление линий редактор нуклидов пишет в файл СРАЗУ (`CommitDefinitions`):
несохранёнными бывают только поля СУЩЕСТВУЮЩИХ линий (ячейки таблицы — имя, энергия, период; галка «Видимый»; поля
справа после неудачной записи), и у каждой такой линии с П318 есть снимок «до правки». «Нет» на время записи ставит
линиям значения до правок окна нуклидов, пишет файл и возвращает правки на место (пометка окна не трогается). Двух
кнопок («Записать вместе» / «Отмена») хватило бы, если бы честного разделения не было; оно есть — и третий ответ
оставляет человеку возможность не записывать недоделанную правку библиотеки ради записи наборов.

* **Да** — правки окна нуклидов записываются ровно как его собственной кнопкой «Сохранить» (поля справа переносятся
  в линию, файл пишется), окно нуклидов становится «сохранено»; при нечисле в поле — его окно «Введите число», не
  пишется ничего, наборы остаются «изменено».
* **Нет** — в файле наборы и линии ДО правок окна нуклидов; правки остаются в окне несохранёнными, его «Нет» потом
  сводит память с файлом, его «Да» допишет их.
* **Отмена** — не пишется ничего, обе пометки «изменено» остаются.

Тонкость, найденная при разделении: линию правит не только окно нуклидов — редактор наборов красит линии своего
набора («Назначить цвет»). Откат по одному снимку «до» вернул бы и чужую покраску (в файле — покраска, в памяти —
прежний цвет). Поэтому снимок окна нуклидов теперь двойной: «до правки» и «как окно её оставило»
(`NoteEdited` после каждой записи окна в линию), и откат/запись «без правок окна» возвращают поле к «до» только если
оно всё ещё держит то, что туда положило окно. Это же чинит «Нет» самого окна нуклидов после покраски набора
(мера C, ДО — `FFFFA500` в памяти против `FFFF00FF` в файле).

**«Несохранённое» — то же, о чём само окно нуклидов спросит «Сохранить?»**: правки линий в памяти ИЛИ правки полей
справа, ещё не перенесённые в линию (`HasUnsavedEdits` = `definitionsDirty || activeNuclide.Dirty`). Правки полей
запись наборов в файл не уносит, но «Да» их записывает — иначе окно нуклидов после «Да» оставалось бы «изменено».

**Где спрашивается** — в обоих путях записи редактора наборов: кнопка «Сохранить» и «Закрыть → Сохранить? → Да».
Второй путь пишет тот же файл тем же вызовом; «Отмена» там оставляет окно наборов открытым с правками (как отказ
записи по `AMBER201`).

Текст ресурса `MSGSavingNuclideSetUnsavedNuclides` (заголовок — `ConfirmationDialogTitle`, кнопки YesNoCancel,
значок Exclamation; оформление «Yes - …» / «Да — …» — по образцу `EfficiencyMakerKeepUnsavedCurve`; названия окон —
их заголовки в ресурсах форм):

* en: `The "Edit Nuclide Definition" window has unsaved changes to the nuclide library. The library and the nuclide sets
  are stored in one file.` ⏎⏎ `Yes - save those changes together with the sets (nothing will be left unsaved in the
  "Edit Nuclide Definition" window).` ⏎ `No - save only the sets; the library changes stay unsaved in the "Edit Nuclide
  Definition" window.` ⏎ `Cancel - save nothing.`
* ru: `В окне «Редактировать изотоп» есть несохранённые правки библиотеки изотопов. Библиотека и наборы изотопов
  хранятся в одном файле.` ⏎⏎ `Да — записать эти правки вместе с наборами (в окне «Редактировать изотоп»
  несохранённого не останется).` ⏎ `Нет — записать только наборы; правки библиотеки останутся несохранёнными в окне
  «Редактировать изотоп».` ⏎ `Отмена — ничего не записывать.`

⚠ Подписи кнопок `MessageBox` даёт Windows на языке системы, не приложения (как у всех вопросов приложения): при
английском интерфейсе на русской Windows текст говорит «Yes», кнопка — «Да».
