# Полоса П7 (12.09.2026): остаток `AMBER18` — геометрия при ввозе ЛСРМ

**Решение Amber 12.09.2026, вопросником, дословно: «Привязать геометрию при ввозе ЛСРМ».**
Вопрос стоял в журнале П1 §8(а): с 12.09 мощность дозы считается от кривой панели
(`DoseRateManager.Calculate(ResultData)`), и у кривой БЕЗ геометрии дозы нет вовсе —
«у кривой «X» нет геометрии — у дозы нет масштаба». Единственный ввоз, дававший такую кривую,
— экспорт ЛСРМ на вкладке Efficiency (`DeviceConfigForm.ImportLsrmEfficiency`, полоса П21
10.09.2026). Теперь ввоз вторым шагом берёт `.in` той же геометрии.

Сборка: `bin\Debug_P7`, пробы `build_p7` (каталог заверен: приложение `c86fdc62cb03`,
пробы `e60d6d73d07b`, 180). Артефакты прогонов — `handover/p7-lsrm-geometry/probe*.txt`.

## 0. Посылка против дерева — что нашлось до правки

| посылка | в дереве |
|---|---|
| «автоподбор: одноимённый `.in` рядом с экспортом» | у поставочных пар `LSRM Geometries/` имена РАЗНЫЕ: `Exported Curves/Obsidian - marinelli 0.5.txt` ↔ `Models/Obsidian Marinelli 0.5.in`, `RadiaCode - marinelli 0.5.txt` ↔ `RadiaCode_Marinelli0.5.in`. Автоподбор по имени на поставке не сработает ни разу; он оставлен (дёшев, чужие пары бывают одноимёнными), а диалог открывается в каталоге экспорта |
| «кривая ЛСРМ той же геометрии для корпусного спектра» | экспорта ЛСРМ ни для одной сцены корпуса нет (`tools/CORPUS/data/eff_by_spectrum_lsrm.csv` — точки по линиям, не экспорт). Пара для дозы взята УСЛОВНАЯ (см. §2(а)) плюс строгий контроль на AS80 (§2(б)) |
| «прочитать тем же читателем, что конструктор» | читатель один — `GeometryModel.Load` (`EfficiencyMakerForm.ImportGeometryClick:489`). ⚠ Он — разбор `ключ = значение` и на чужом тексте НЕ падает: любой файл даёт модель с нулевым кристаллом, и дефект всплыл бы в дозе («кристалл нулевой глубины»). Поэтому у ввоза своя проверка после чтения (§1) |
| «перегрузить `ImportLsrmEfficiency`» | нельзя: проба П21 (`tools/p21_view/DoseRateCleanupP21Probe.cs:279`) зовёт её отражением `GetMethod("ImportLsrmEfficiency", flags)` БЕЗ списка параметров — перегрузка дала бы `AmbiguousMatchException`. Прежний вход оставлен с прежней подписью, новый назван иначе |
| «подписи — `Properties/Resources`» | сегодня туда писали П1 и П2; строки положены в пару САМОЙ ФОРМЫ `DeviceConfigForm.resx`/`.ru.resx` по образцу `crystalMaterialNotSet` (`DeviceConfigForm.cs:1146`) |

## 1. Что сделано (`BecquerelMonitor/DeviceConfigForm.Efficiency.cs`)

* `ImportLsrmEfficiencyWithGeometry(device, path, geometryPath, out problem, out geometryProblem)`
  — public static, зовут кнопка и проба. `geometryPath == null` (Cancel) — кривая ввозится как
  раньше, без геометрии. `.in` негоден — кривая ВСЁ РАВНО ввозится без геометрии, причина в
  `geometryProblem` (точки кривой негодный `.in` не портит). `Origin = Lsrm`, `ComputeStamp`
  ПУСТОЙ — клеймо значит «чем посчитана», а считал ЛСРМ; кривая с геометрией и пустым клеймом не
  «посчитанная из геометрии», матрицы у неё нет по построению, доза идёт «≈». Откуда кривая и
  геометрия — в `Note`: `LSRM export: X.txt; geometry: Y.in` (+ предупреждения разбора `.in`
  строками).
* `ImportLsrmEfficiency(device, path, out problem)` — прежняя подпись, делегирует с
  `geometryPath = null` (для П21).
* `ReadLsrmGeometry(path, out problem)` — `GeometryModel.Load` + проверка: файл читается;
  `Raw.Count > 0` и кристалл ненулевой (Ø×h либо X×Y×Z бруска) — иначе «не найдены размеры
  сцинтилляционного кристалла» (сюда же попадает коаксиальный `.in` ЛСРМ: `DC_*` читатель не
  берёт, германий вне работы); сцена поля `DS_Scene = ISO` — отказ «эффективность ЛСРМ нормирована
  на испущенный квант, не на флюенс» (иначе в дозе вышел бы отказ «пересчитайте кривую из
  геометрии», для кривой ЛСРМ невыполнимый).
* `SuggestLsrmGeometryPath(exportPath)` — `X.txt → X.in` рядом, если есть.
* `FormText(key, fallback)` — строка из `ComponentResourceManager(typeof(DeviceConfigForm))` с
  запасным английским.
* Кнопка `efficiencyImportButton_Click`: первый диалог как был; второй —
  `OpenFileDialog` с заголовком `lsrmGeometryDialogTitle`, фильтром
  `Resources.EfficiencyMakerGeometryFilter` (общий, уже есть), предзаполненный автоподбором либо
  открытый в каталоге экспорта; Cancel → без геометрии. Негодный `.in` → `MessageBox`
  `lsrmGeometryProblem` («кривая ввезена без геометрии; у дозы нет масштаба, пока геометрия не
  задана «Изменить…»») — про геометрию, не про ввоз, чтобы человек не повторял ввоз.
* Resx: четыре ключа `lsrmGeometryDialogTitle`, `lsrmGeometryProblem`, `lsrmGeometryNoCrystal`,
  `lsrmGeometryFieldScene` в `DeviceConfigForm.resx` + `.ru.resx` (BOM+CRLF сохранены);
  `check_resx*` — код 0. Designer и контролы не тронуты.

## 2. Приёмка — `tools/effmaker/probes/LsrmGeometryImportProbe.cs`, 45/0

**§1 ввоз пары ЛСРМ** `RadiaCode - marinelli 0.5.txt` + `RadiaCode_Marinelli0.5.in`: точек 149;
`Origin = Lsrm`; клеймо пустое; `Geometry != null`; Note называет оба файла. Числа сцены против
текста `.in`, разобранного пробой независимо (см → мм): кристалл **Ø 11.284 × 10.0 мм**
(`DS_CrystalDiameter = 1.1284 cm`), маринелли **Ø 114.0**, колодец **Ø 61.0**, высота пробы
**85.0 мм**, до торца **8.0 мм** — все шесть сошлись. Текст `.in` от геометрии кривой
(`GeometryWriter.Render`) = тексту от прямого `GeometryModel.Load` (8050 знаков). XML
туда-обратно (`XmlSerializer(DeviceConfigInfo)`): кривая найдена по Guid, `Origin = Lsrm`,
геометрия НАЙДЕНА, точек 149, текст `.in` тот же, размеры те же.

**§2(а) доза, пара условная**: `RC103_K40Village` (RadiaCode-103, K-40 в маринелли 0.5 л) ×
кривая §1 → строка состояния **«≈ 0.711 ±0.002 (0.2%) мкЗв/ч (покрыто 94 % отсчётов)»**
вместо отказа; `Approximate = true`, матрицы нет (`NoFile`). ⚠ Модель ЛСРМ — RadiaCode
Ø11.28×10 мм / маринелли 0.5 л, спектр — RC-103 в маринелли 0.5 л; паспортной связи «эта кривая
считана для этого прибора» нет — число проверяет механику, а не измеряет дозу.

**§2(б) строгий контроль**: точки узла `Efficiency` спектра `AS80_Cs137_0cm` (38 точек,
`phys=16`) записаны экспортом ЛСРМ (формат `R`) и ввезены с `corpus/geometries/AS80_point0.in`:
**≈ 0.195380 (ввезённая) = ≈ 0.195380 (родная по пиковой) мкЗв/ч, разность 0.00e+000**;
против журнала П1 (≈ 0.195) +0.2 % (округление П1). Те же точки, та же геометрия, тот же путь —
привязка `.in` даёт кривой ЛСРМ ровно тот масштаб, что у посчитанной. ⚠ Первый заход писал
экспорт шестью значащими (`E5`, как настоящий ЛСРМ) и дал 7.4e-9 относительных — это была
точность ЗАПИСИ пробы, не путь приложения; формат сменён на `R`, допуск 1e-12.

**§3 отказы**: Cancel (`null`) → `Geometry == null`, сообщения нет, `Origin = Lsrm`, доза —
прежний отказ словами «у кривой … нет геометрии — … у дозы нет масштаба»; `.in` которого нет →
кривая ввезена, причина «Файл … не найден»; `.in` сцены поля (`DS_Scene = ISO` дописан к
настоящей модели) → кривая ввезена без геометрии, причина «сцена поля … не может быть геометрией
кривой ЛСРМ»; мусорный файл → `ReadLsrmGeometry` = null, «не найдены размеры … кристалла».

**§4 автоподбор**: без `Pair.in` — null; с `Pair.in` рядом — найден; у настоящего экспорта
поставки — null (имена разные).

**§5 подписи**: четыре ключа читаются по `en-US` и `ru-RU`, русский отличается от английского
(сторож `check_resx_designer.py` обращений через `ComponentResourceManager` не видит — только
`Resources.ResourceManager.GetString`, — эта дыра закрыта пробой, а не сторожем).

**Положительные контроли** (коды перевёрнуты, 0 = отказ получен): `--sabotage=badin` — вместо
`.in` текст экспорта → ввоз положил кривую БЕЗ геометрии, причина «не найдены размеры …
кристалла», проба отказала (28 проверок, 1 провал — «Geometry != null») → **код 0**;
`--sabotage=stamp` — `Origin = Simulation` + клеймо `phys=16; …` → проба отказала на трёх
проверках (Origin, клеймо, Origin после XML) → **код 0**.

**Регрессия**: проба П21 (`DoseRateCleanupP21Probe`, собрана `csc` против `build_p7`) —

## 3. Находки — все в журнал, строк не заведено

1. **Битый `.in` читателем не отвергается** (`GeometryModel.Load` — разбор `ключ = значение`):
   закрыто в той же полосе проверкой `ReadLsrmGeometry` (кристалл ненулевой). Конструктор кривой
   (`EfficiencyMakerForm.ImportGeometryClick`) той же проверки не имеет — мусорный файл заедет
   в поля заготовкой с нулями; там человек ВИДИТ поля и правит их, цена другая — факт, не строка.
2. **Кнопка «Матрица отклика» доступна кривой ЛСРМ с геометрией** (`efficiencyMatrixButton.Enabled
   = config.HasGeometry`): человек может посчитать матрицу нашей физикой к пиковой кривой ЛСРМ,
   и доза пойдёт по матрице без «≈». Ровно то же уже возможно у кривой «по измерениям» с
   дописанной геометрией — поведение не новое. Вопрос Amber (§4), не строка.
3. **Происхождение кривой на вкладке не видно**: сводка показывает точки и клеймо; у кривой ЛСРМ
   клеймо пустое, `Note` с именами файлов на вкладке не печатается. Сводка — подпись 466×30 с
   `AutoSize = false`, третья строка ушла бы за край молча (`A119`-грабля); строку ресурсов
   сегодня класть некуда (`Properties/Resources` заняты). Факт; если понадобится — отдельной
   подписью, как `efficiencyGenerationLabel`.
4. **`DoseRateManager.LastMatrixNote` после отказа `InputOf`** остаётся от прежнего входа
   (исключение бросается до записи кэша). Читателей в приложении нет — только пробы; на экране
   ничего. Факт (файл П6, не мой).
5. **`build_p7` нёс `DosePointsProbeF9.exe`** снятой 12.09 пробы — сторож `T88` отказал, файл убран
   рукой из своего же каталога (в gitignore). Стороне приложения не касается.
6. **Сторож `check_resx_designer.py` не видит `ComponentResourceManager(typeof(Form)).GetString`**
   — прежний `crystalMaterialNotSet` в той же дыре. Закрыто пробой §5 для четырёх новых ключей;
   общий сторож — обслуга, по правилу 3 не вперёд приложения.

## 4. Вопрос Amber (координатору, вопросником)

**Матрицу отклика кривой ЛСРМ — разрешать?** Сейчас (находка 2) кнопка активна, матрица считается
нашей физикой к чужой пиковой кривой; доза тогда идёт по матрице без «≈». Варианты: (1)
*(рекомендую, сделано)* оставить как есть — ровно как у кривой «по измерениям» с геометрией,
человек сам решает; (2) запереть кнопку при `Origin = Lsrm` — кривая ЛСРМ навсегда «≈»; (3)
запереть и подписать причину.
