## AMBER49 — образ случайных наложений вынимает из спектра ОДИН отсчёт на пару вместо ДВУХ

**Где.** `FsaAnalyzer.BuildPileUpComponent`,
`BecquerelMonitor/FullSpectrumAnalysis/FsaAnalyzer.cs:10435-10438`:

```
for (int k = 0; k < bins; k++)
{
    pile[k] = (pile[k] - byEnergy[k]) / total;
}
```

`pile` — автосвёртка спектра `(s ⊗ s)/N` (строится как `Σ_a Σ_b (s_a/N)·s_b`,
масса ровно `N`), `byEnergy` — сам спектр `s` массой `N`. Колонка образа
∝ `(s ⊗ s)/N − s`, интеграл ноль; комментарий над циклом утверждает «пара ушла с
обеих своих энергий», а вычитается ОДНА масса `N`.

**Что должно быть.** Случайное наложение двух импульсов убирает ОБА с их
энергий и приносит ОДИН на сумму: первый порядок по `Rτ`
`s'(E) = s(E)·(1 − 2Rτ) + Rτ·(s ⊗ s)(E)/N`, то есть колонка
∝ `(s ⊗ s)/N − 2·s` с интегралом `−N·Rτ` (счёт при наложениях ТЕРЯЕТСЯ, а не
переносится). Источники: Wielopolski, Gardner, NIM 133 (1976) 303; Gardner,
Wielopolski, NIM 140 (1977) 289; Knoll, Radiation Detection and Measurement,
гл. 17 (pulse pile-up). Пересчёт на моноэнергетическом спектре: `N` событий,
`N_пар` наложившихся пар → в пике `N − 2·N_пар`, в сумм-пике `+N_пар`; код даёт
`−1 : +1`, физика `−2 : +1`. Тракт с режекцией наложений дал бы `−2 : 0`, то
есть ещё дальше от `−1 : +1`.

**Следствие для числа.** Амплитуду колонки закрепляет сумм-пик (убыль вырождена
с образами нуклидов), поэтому из фотопиков модель вынимает ВДВОЕ меньше, чем
надо, и недостающую убыль забирают на себя образы нуклидов: активности ВСЕХ
нуклидов загруженного спектра занижены примерно на долю наложений `Rτ` —
при 10 kcps и `τ ≈ 1.4 мкс` порядка 1.4 %, на «Cs 137 в домике» — доли
процента (по числам ~~`S22`~~, DONE). Ключ `PileUp` включён по умолчанию
(`FsaAnalyzer.cs:4622`, `FsaCalculationOptions.cs:68`), так что действует на
каждый разбор. ⚠ Сверка ~~`S22`~~ «τ из фита 1.400 против 1.424 по площадям
1324/662» этого не ловит: обе величины снимаются с сумм-пика, а дефект — в
убыли.

**Уверенность.** ТОЧНО: вывод из кода плюс источник; величина у конкретного
спектра — по `Rτ` этого спектра. Чем доказать до правки: спектр с заметным
сумм-пиком (`Cs 137 в домике`), образ с множителем 2 у убыли, сравнить
амплитуду Cs-137 и χ²; ожидаемый сдвиг активности `+Rτ`.

## AMBER50 — аналоговый обход ТЕРЯЕТ истории, округлившиеся в бин пика, но не попавшие в допуск

**Где.** `EfficiencySimulator.cs`: `BinOf` (`:7881-7897`) кладёт историю с
`bin ≥ peak`, не прошедшую `InPeak`, в бин `peak − 1` — так делает
взвешенная ветвь (`OneHistory` → `Deposit`, `:8331`). Аналоговый обход
`AnalogContinuumRun` (`:8762-8777`) ту же историю ОТБРАСЫВАЕТ:

```
int bin = (int)(deposited / binKev + 0.5);
if (bin >= peak)
{
    this.CountPeakBinDropped++;
    ...
    continue;               // бин пика — за взвешенной оценкой
}
```

а затем (`:8811-8813`) `histogram[b] = hist[b]` для всех `b < peak`
ПЕРЕЗАПИСЫВАЕТ бин `peak − 1` аналоговым значением, в котором этих историй нет.
Бин пика (за взвешенной оценкой) их тоже не содержит — они не в допуске.
Одна история обязана лечь ровно в один бин; здесь она не ложится ни в один.

**Когда класс непуст.** При действующем полубинном допуске (`peakb=1`, бин
2 кэВ, допуск 1 кэВ) потерянная полоса — `E − dep ∈ (tol, tol + δ]`, где
`δ = E_узла − peak·bin` — насколько узел лёг ВЫШЕ центра своего бина. На
логарифмической сетке 140 узлов это примерно половина узлов. Содержимое полосы
— рассеяние ДО кристалла на малый угол с последующим полным поглощением
(θ ≈ 60–88° при 32 кэВ, 31–45° при 60, 15–22° при 122, 2.8–3.9° при 662) и
мелкие вылеты.

**Подтверждение, уже лежащее в дереве.** Замер 11.09.2026 (`AS80_point0`,
3 млн историй на узел, `ResponseRowDumpProbe --peakw=both`, таблица в
`ResponseMatrix.cs:3747-3766`): Σ строки на 32.194 кэВ — допуск ноль 0.083916,
полубин 0.087764, ПШПВ/2 0.088324 (**−0.64 %** у полубина); на 661.657 кэВ
полубин и ПШПВ/2 ПОБИТОВО равны. Знак `δ` сходится с выводом: 32.194 − 32 =
+0.194 (класс непуст), 661.657 − 662 = −0.343 (пуст). Комментарий там
объясняет разницу «зачётом рассеянного в пик» — но Σ строки допуском двигаться
не может, допуск лишь переносит между бинами; разница — это потерянный класс.

**Следствие для числа.** Строки склада на узлах с `δ > 0` недосчитывают
примерно `(δ/0.194)·0.64 %` площади у пика — до ~3 % у 30 кэВ при `δ ≈ 0.9`,
убывает с энергией; между соседними узлами «пила», интерполяция по узлам
даёт артефакты. Активности низкоэнергетических линий (Am-241 59.5, Ba-133
31/35/81, Co-57 122) завышены на ту же долю. Правка меняет склад матриц и
действующую базу `out_rev32_*` — решение Amber.

**Уверенность.** ТОЧНО по коду и по замеру 11.09; величина на других узлах —
ВЕРОЯТНО, точно даст `ResponseRowDumpProbe --peakw=both` на узле с `δ ≈ +0.9`
(например 32.9 кэВ при бине 2). Родня в реестре: ~~`A267`~~ (класс назван
непустым для света, для веса аналоговой ветви записано «округляет — факт»),
~~`A58`~~/~~`A68`~~, ~~`E34`~~ — тёзки нет.

## AMBER55 — связка равновесия ряда без множителя переходного равновесия

**Где.** `FsaSampleLibrary.Build`, `FsaSampleLibrary.cs:974`:
`AddLine(component, self, line[0], line[1] * member.Value)` — линии члена
ряда входят в образ корня с долей `member.Value` = накопленное ветвление
(`ChainBranches`, `:1437`); члены отбираются `EquilibriumMembers` (`:1285`)
по условию «период дочери короче периода корня».

**Что должно быть.** В равновесии `A_д/A_р = BR·λ_д/(λ_д − λ_р)`
(переходное равновесие; Gilmore 2008, гл. 1; Knoll, гл. 1). Код берёт
`A_д/A_р = BR` — «равновесную единицу», верную лишь при `λ_д ≫ λ_р`.

**Число (периоды из `nucdb`).** Природные ряды — не больше 1.4 %
(Ra-226 → Pb-210: 22.2 г против 1600 г); подряды с коротким корнем
(~~`T259`~~, «Xx-NNN как корень»): Pb-214 → Bi-214 **×3.68**, Zr-95 → Nb-95
**×2.21**, Ba-140 → La-140 **×1.15** — дочерний недооценён, корень и его предел
переоценены, остаток уходит в невязку.

**Уверенность.** ВЕРОЯТНО (физика точна; цена на обычных для Amber рядах — до
1.4 %). Точно даст плечо `--chain=Pb-214` с множителем и без. Родня:
~~`AMBER27`~~/~~`AMBER29`~~ считали Бейтмана только при равновесии ВЫКЛ.

## AMBER56 — правило Брэгга для Z < 10 берёт элементный потенциал вместо потенциала «в соединении»

**Где.** `EstarCalculator.BraggPotential`, `EstarCalculator.cs:500`:

(`EstarCalculator.cs:445`) называет «523.5 против 534.1» необъяснённой
разницей — это ровно этот дефект. Вода: с 106 → 75.3 (таблица 75.0), с 95 →

элементов не содержат.

## AMBER57 — розыгрыш рэлея: наклон F² в последнем отрезке считается по неверной ширине

**Где.** `ScatteringData.Atom.SampleMomentumTransferSq`,
`ScatteringData.cs:184-200`:

```
double t1 = i + 1 < n ? t[i + 1] : tMax;
if (i == last) { t1 = tMax; }
double a = f2[i];
double b = i + 1 < n ? f2[i + 1] : f2[i];
double dt = t1 - t0;
...
double slope = (b - a) / dt;
```

При `i == last` берётся `dt = tMax − t[last]`, но `b = f2[last + 1]` — значение
в узле ДАЛЬШЕ `tMax`. Наклон завышен по модулю в
`(t[last+1] − t[last])/(tMax − t[last])` раз (по базе 1.1…11×). Вес того же
отрезка `head` (`:161`, `PartialIntegral`) считан с ПРАВИЛЬНЫМ наклоном — две
формулы одного отрезка несогласованы; квадратное уравнение решается не для той
плотности, часть розыгрышей упирается в зажим `delta > dt` и садится ровно на
θ = 180°.

**Что должно быть.** `slope = (f2[last+1] − f2[last])/(t[last+1] − t[last])`,
`tMax` ограничивает только верхний предел Δ (сверено пересчётом против
трапеций `ffCum`, `:446-451`).

**Число (оценка по базе, Z = 53, 20 000 розыгрышей на энергию).** В последний
отрезок попадает 2.1 % когерентных на 20 кэВ (θ > 151°), 0.47 % на 60 кэВ
(θ > 158°), 0.01 % на 662; из них 2–18 % зажаты на 180°, средний сдвиг 1–6 %
ширины отрезка. Итого искажено ≤ 0.03 % когерентных (Na — до 0.1 %), на
отклик < 1e-4 — ниже шума склада.

**Уверенность.** ТОЧНО как ошибка формулы; следствие пренебрежимо. P3: правка
одной строки, склад пересобирать не за что.
