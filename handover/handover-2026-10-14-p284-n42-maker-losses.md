# П284 (14.10.2026) — экспорт N42: производитель по прибору и предупреждение, называющее потери

**Решение Amber 14.10.2026 вопросником, дословно:** «Производитель по прибору + назвать потери
(Рекомендую)». Вопрос был: «N42-экспорт: пишет «KB Radar / ATOM Spectra» для любого прибора (785 из
785) и не несёт карточку пробы (масса, объём, время пробы, примечание). Что делать?» Описание
выбранного: «Производитель/модель по типу прибора, иначе «BecqMoni / имя конфигурации» (1–2 ч, нужны
точные названия), и в предупреждении MSGN42ExportLosesEfficiency перечислить, что не уходит в N42
(правка ресурса).» Находка — полоса П263, журнал
[`handover-2026-10-14-p263-spectrum-files.md`](handover-2026-10-14-p263-spectrum-files.md) (остаток, вопросы
Amber 2 и 3).

**Второе решение Amber 14.10.2026 вопросником, дословно: «Как раньше — только при кривой»** — о том, что
первая редакция П284 показывала окно N42 при каждом экспорте (794 из 794, было 110). Итог: условие
показа прежнее, текст — новый полный перечень (раздел 2).

## Где писатель и кто его зовёт

Писатель свой, не SpecUtils: `N42.Util.ExportToN42` (`BecquerelMonitor/N42/Util.cs`). Зовут его
`DocumentManager.WriteN42File` (пункт меню `MainForm` → `ExportDocumentN42` → `WriteN42File`) и пробы
круга N42 (`N42RoundTripProbe`, `N42ChannelCenterProbe`, `N42PolynomialCentreProbe`,
`AtomSpectraN42ProbeP151`, `SpectrumFilesProbeP263`). Читают изготовителя из файла: импорт N42 — только
в текст заметок (`SampleInfo.Note`); признак «файл записан AtomSpectra» (`AMBER87`,
`Util.IsWrittenByAtomSpectra`) судит по `SoftwareName`, а не по изготовителю — поэтому смена
изготовителя круг «мы → файл → мы» не трогает (замерено ниже обеими дверями импорта).

## 1. Производитель и модель — по типу прибора

`Util.InstrumentMakerAndModel(ResultData)`: тип — по классу `InputDeviceConfig` конфигурации прибора
спектра (`DeviceConfig`), если прибор найден в конфигурации (у `DeviceConfig` есть `Guid`). Названия —
только из дерева:

| тип (`DeviceType.Id`) | производитель | модель | откуда название |
|---|---|---|---|
| `AtomSpectraVCP` | KB Radar | ATOM Spectra | прежняя запись `Util.cs` (одна на всех); свои N42 программа AtomSpectra подписывает изготовителем «KB Radar» (журналы П137 — модель «Nano», П151); исходники `github.com/Am6er/AtomSpectra`, «AtomSpectra KB Radar» (П146) |
| `AmplitudaUSB` | Amplituda | Progress spectrometer | PR #34 (EN: «the Amplituda "Progress spectrometer" USB HID block (SBDB-02 …)»; RU: «СБДБ-02 (НПЦ «Амплитуда»)», «По USB он представляется HID-устройством `Progress  spectrometer`»); шапки `AmplitudaUsbDeviceConfig.cs:3`, `AmplitudaUsbProtocol.cs:3`. ⚠ В строке USB два пробела; пишется с одним, как в коде и в EN-описании PR |
| `AmplitudaSerial` | BecqMoni | имя конфигурации | PR #35 и `AmplitudaSerialProtocol.cs:3–4`: «NPP Doza BDEG-3-2 and relatives» — блоки комплекта «Прогресс», изготовитель типом не определён |
| `RadiaCode` | BecqMoni | имя конфигурации | изготовителя в дереве нет (есть лишь имена моделей по BLE «RadiaCode-101/102/103/110», `RadiaCodeDeviceForm.cs:194–197`) |
| `Obsidian` | BecqMoni | имя конфигурации | ни изготовителя, ни модели в дереве нет (ресурсы, форма, PR — только «Obsidian») |
| `AudioInputDevice` | BecqMoni | имя конфигурации | звуковой вход: прибора за ним тип не знает (у Amber так заведены «Atom Spectra Nano 8 …») |

формат не расширялся. Элемент `Hardware` (имя конфигурации) не тронут.

## 2. Предупреждение называет все потери

Список снят с кода: члены `ResultData`, которые пишет «Сохранить», против того, что пишет
`ExportToN42` (`RadInstrumentInformation`, `EnergyCalibration`, `RadMeasurement`: начало, полное и
живое время, отсчёты, сумма; фон — отдельным измерением). **Не уходят:** кривая эффективности с
геометрией и привязкой к матрице (и встроенная матрица `EmbeddedResponseMatrix`); калибровка
разрешения `FwhmCalibration` (импортированный спектр её не несёт — голос импорта «no resolution model,
peak search cannot run»); привязка к конфигурации прибора (`DeviceConfigReference.Guid`; уходит лишь
имя в `Hardware`); серийный номер прибора `EnergySpectrum.SerialNumber` (у RadiaCode, например
`RC-103-000282`); информация об образце — имя, место отбора, дата отбора, вес, объём, заметки (импорт
ставит дату отбора равной началу набора, и поправка на распад к дате отбора
`MeasurementResultManager.DecayToSamplingFactor` пропадает). **Не считаются потерей** — импорт
восстанавливает их из того, что уходит: конец набора (= начало + полное время; расходится лишь при
паузах), уставка времени (= полное время), число годных импульсов (= всех), сам фон (уходит спектром,
теряется только имя его файла).

Новый текст (`Resources.resx` / `Resources.ru.resx`, строки через CRLF, как у соседних
многострочных ключей; `Resources.Designer.cs` — комментарий):

> Not everything a spectrum file holds can be written to N42. NOT exported:
> - the efficiency curve, the detector geometry and the link to the response matrix (spectra with a curve: {0} of {1});
> - the resolution (FWHM) calibration;
> - the link to the device configuration (only its name is written) and the instrument serial number;
> - the sample information: name, location, sampling date, weight, volume, notes.
>
> A file re-imported into a NEW document therefore has no activity of the selection, no full-spectrum analysis (FSA), no normalization by efficiency and no decay correction to the sampling date, and peak search does not run on it until a resolution calibration is set. Exported in full: the spectra and the background, the energy calibration, the start of acquisition, the live and real times.

> В N42 уходит не всё, что хранит файл спектра. НЕ экспортируются:
> - кривая эффективности, геометрия детектора и привязка к матрице отклика (спектров с кривой: {0} из {1});
> - калибровка разрешения (ПШПВ);
> - привязка к конфигурации прибора (пишется только её имя) и серийный номер прибора;
> - информация об образце: имя, место отбора, дата отбора, вес, объём, заметки.
>
> Поэтому у файла, импортированного в НОВЫЙ документ, не будет ни активности выделения, ни полноспектрального разбора (FSA), ни нормировки по эффективности, ни поправки на распад к дате отбора, а поиск пиков на нём не пойдёт, пока не задана калибровка разрешения. Полностью экспортируются: спектры и фон, энергетическая калибровка, начало набора, живое и полное время.

(В ресурсе абзацного пропуска нет — последняя строка идёт сразу за списком.) Имена полей карточки —
те же, что на панели «Sample Information» / «Информация об образце».

### Условие показа — прежнее: есть кривая эффективности

**Решение Amber 14.10.2026 вопросником, дословно: «Как раньше — только при кривой».** Вопрос был о том,
что после первой редакции П284 окно N42 показывается при каждом экспорте — 794 из 794, было 110.

Первая редакция (снята) говорила, если хоть один спектр теряет что-либо: кривую, калибровку разрешения,
ссылку на прибор, серийный номер, непустые поля карточки, вес/объём ≠ 1, дату отбора ≠ начала набора
(метод `N42ExportLosesBeyondCurve`). Калибровку разрешения открытие достраивает каждому спектру, поэтому
окно вставало всегда. Из 676 документов замера без кривой у 234 заполнена карточка (имя / место /
заметки / вес / объём) — эти потери текст называет, но окна при них по решению Amber нет.

Сейчас `DocumentManager.N42ExportWarning` — тело как до П284 (говорит при `withCurve > 0`, числа
`{0} из {1}` — спектры с кривой), изменён лишь комментарий. Текст остаётся новым полным перечнем.
`N42ExportLosesBeyondCurve` **снят**: текст — постоянный ресурс без подстановки перечня по документу,
поэтому тексту метод не нужен, а условию он больше не нужен; оставленный, он был бы признаком без
читателя.
