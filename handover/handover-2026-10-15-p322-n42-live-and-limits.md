| то же с обнулённым живым у всех спектров и фонов (так выглядят 585 из 907 спектров Amber, П311): измерений 270 | `PT0S` у 270, живое = полному у 0 | `PT0S` у 0, живое = полному у 270 |
| то же, файл без значений `LiveTimeDuration` | — | 136 из 136 побайтно как ДО |

**Круг экспорт → импорт → разбор** (`--mode=fsa`): спектр корпуса с обнулённым живым (спектр и фон) выгружается,
импортируется дверью N42, получает прибор, кривую эффективности (с геометрией) и кривую ПШПВ исходного (N42 их не
несёт), поиск пиков, разбор FSA. Числа — формат R.

| спектр | ДО ↔ ПОСЛЕ | внутри сборки: живое = полное ↔ живое 0 |
|---|---|---|
| `AS80_Cs137_0cm` (8192 кан., фон) | пики `26a3f0001a3997f6`, разбор `feb53710a2f7322a` — все 8 строк чисел ДО = ПОСЛЕ (χ²/ndf 4.5316604862397591, Cs-137 доля 93.645145136040981 %, скорость 5301.7685550053857) | `feb53710…` = `feb53710…` |
| `AS80_Th232Medal` (8192 кан., фон) | пики `414f901d5f5d36c1`, разбор `37fcb153c4f9acdd` — все 19 строк чисел ДО = ПОСЛЕ (χ²/ndf 31.612921449989557) | `37fcb153…` = `37fcb153…` |

Знаменатель после круга = полное после круга (то, что давал импорт до правки: `Effective(0, полное)`), побитово, у
спектра и у фона; к исходному — остаток 0 с (у времён не на сетке 100 нс остаток сетки `A147` есть и ДО: пример
`ASN8_Th232_2048` 55470.709087999996 → 55470.709088, у ОБОИХ времён).

Почему числа разбора не сдвигаются: всё деление идёт через `EffectiveLiveTime`; два прямых читателя `LiveTime` в
FSA (`FsaAnalyzer.PileUpLossFor`, `PileUpCapFor`) различают «живое < полного», а живое = полному и живое 0 оба
идут ветвью «живого нет» — замер выше это подтверждает. Что МЕНЯЕТСЯ на экране у повторно импортированного
спектра: поле «Время без МВ» панели измерения показывает полное вместо 0.00 (мёртвое время 0 % в обоих случаях —
`DCControlPanel`, `CountsRateManager.SpectrumDeadTimePercent`).

**`N42RoundTripProbe` перемерена** (`--mode=export` по корпусу, 136 спектров): с правкой ожидания ДО и ПОСЛЕ
печатают одно и то же — «ЖИВОЕ ВРЕМЯ ФОНА потеряно у 14 (наибольший остаток 2.858E-008 с)», «ВРЕМЕНА разошлись у
13 (4.290E-008 с)», «ШКАЛА разошлась у 87» (остатки сетки `A147` и центров/краёв `AMBER73`, прежние), список
происхождения одинаков кроме размера файлов трёх ASN16 (+4…5 байт). Положительный контроль: ПРЕЖНЯЯ проба
(`git show HEAD:`) на сборке ПОСЛЕ — «ЖИВОЕ ВРЕМЯ ФОНА потеряно у 17 (наибольший остаток 4.978E+005 с)»: те же

`N42DoorsProbeF54` не затронута: она меряет только импорт сочинённых входов, экспорта не зовёт.

## 2. Число каналов 64…65536 — ЗАКРЫТО

Места ввода числа каналов человеком (grep `NumberOfChannels =` и форм): **два** — конфигурация прибора
(`DeviceConfigForm.integerTextBox1`, «Кол-во каналов») и «Спектр → Изменить число каналов»
(`ChanNumberChangeDialog.textBox1`). Прочие записи `NumberOfChannels` — из файла (импорт N42/CSV/SpecUtils, длина
массива) или константы смены типа прибора (1024/4096). Формы приборов (`AmplitudaUsb/Serial`, `AudioInput`,
`AtomSpectra`, `RadiaCode`) числа каналов не вводят (у Amplituda — своя проверка при наборе, `ERRAmplituda*Channels`).
`SpectrumCutOffDialog` вводит НОМЕР канала, не их число.

`P322ChannelLimitsProbe` (форма — `SaveFormContents` отражением; диалог — настоящий `ShowDialog`, нажатие «Ввод»
или Enter, затем проверка «окно открыто?» и «Закрыть»):

| вход | ДО | ПОСЛЕ |
|---|---|---|
| форма: 63 / 65537 / 2000000000 | принято, записано в конфигурацию | отказ словами, конфигурация прежняя |
| форма: 64 / 4096 / 65536 | принято | принято |
| форма: 0 / −5 (контроль П316) | отказ | отказ |
| диалог: 63 / 65537 / 2000000000 / −5 + «Ввод»; 2000000000 + Enter | окно закрыто, `SendData` = введённое | отказ словами, окно открыто, `SendData` = 0 |
| диалог: «abc» / пусто + «Ввод» | окно закрыто молча, `SendData` = 0 | отказ словами, окно открыто |
| диалог: 64 / 4096 / 65536 + «Ввод»; 8192 + Enter | закрыто, отдано число | то же |
| итог | **11 дефектов, код 4** | **0, код 0** |

Документ при отказе не создаётся: окно остаётся открытым, «Закрыть» даёт `SendData` = 0, и `MainForm` выходит на
`newChan == 0` до `ConcatSpectrums`.

## 3. Лимит времени 0 — ЗАКРЫТО

Форма: лимит «0» — ДО принят и записан (0 с в конфигурации), ПОСЛЕ — отказ словами, конфигурация прежняя; «1» и
прежнее значение — принимаются; «−100» — отказ (контроль П316). Путь набора не тронут. `P316ScreenPassProbe` с
перемеренными ожиданиями: ДО — 1 дефект (Н12, лимит «0» принят), ПОСЛЕ — 0 (код 0).

Существующие конфигурации: у Amber (`%AppData%\BecqMoni\config\device`, 9 приборов), в поставке и у приборов корпуса
каналы 1024…16384, лимит 3600…360000000 с — ни одна не попадает под новый отказ.

  en «Preset time must be a whole number of seconds greater than zero.↵Entered: {0}»;
