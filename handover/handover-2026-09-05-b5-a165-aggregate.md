## 1. Посылка строки — сверена, верна и ШИРЕ

* `AggregateException.InnerException` действительно отдаёт **только первую**
  из `InnerExceptions` (конструктор кладёт `innerExceptions[0]` в базовый
  класс), и прежний обход `while (link != null) link = link.InnerException`
  шёл по ней одной. Плечо `ветвление` старой сборки: три ветви → **93 знака,
  приписка одна**, вторая и третья ветви не названы.
* `Flatten()` и `InnerExceptions` в дереве **нигде не звались**
  (`grep` по `BecquerelMonitor/` и `tools/effmaker/` — совпадений ноль, кроме
  самой двери и пробы).
* Шире, чем в строке: в .NET Framework 4.8 **`AggregateException.Message`
  соседние сообщения в себя НЕ включает** (в .NET Core 2.1+ включает в
  скобках). Установлено плечом `одна ветвь`: текст «`AggregateException: одна
  беда`» чистый. То есть на этой платформе потерянная ветвь не всплывала
  даже через `Message` — терялась целиком.

## 2. Что сделано (`BecquerelMonitor/GlobalConfigManager.cs`)

Обход переписан со «списка» на «дерево», состояние обхода — во внутреннем
классе `AppUi.ReasonWalk` (текст, массив «встречено» по ссылке, счётчик
названных, признак «остановлен»). Сигнатура `AppUi.Reason(Exception)` не
менялась — соседняя полоса, правящая `NucBase/DataBase.cs`, её читает.

* У обычного звена вложенное одно — `InnerException`. У `AggregateException`
  обходятся **все `InnerExceptions`**, а `InnerException` для него отдельно не
  берётся (это та же первая ветвь; второй раз она ложно взвела бы сторож петли).
* Каждая ветвь — своя приписка с безъязыкой пометкой **`(i/n)`**:
  `Agg: m <- (1/2) A: m <- B: m <- (2/2) C: m`. Цепочка под ветвью идёт тем
  же «`<-`» до следующей ветви. **Единственная ветвь пометки не получает** —
  текст байт в байт прежний (это самый частый живой случай: `Task.Run` с одним
  упавшим делегатом).
* `Flatten()` **не зовётся нарочно**: он строит новый объект (сторож петли по
  ссылке его не узнал бы), сам ходит по вложенным `AggregateException` без
  сторожа (на испорченном дереве повис бы раньше нашего обхода) и теряет
  сообщения вложенных узлов. Вложенный `AggregateException` — обычное звено с
  несколькими вложенными.
* Сторожа `A144` — **общие на всё дерево**: один массив «встречено» на все
  ветви, `ReasonChainLimit = 16` считает звенья всех ветвей. Предел
  останавливает обход целиком (называть больше нечего) с хвостовым «`<- …`».
  Петля через ветвь (ветвь → предок или ветвь → сосед) останавливает **ту
  ветвь**, ставит «`<- …`» и отдаёт ход следующей: соседняя ветвь в чужой петле
  не виновата и терять её молча нельзя.
* Правило `A129` — дословное `Ordinal`-совпадение «Тип: сообщение» — без
  изменений; пометка ветви в сверку не входит (сверяется само звено).

⚠ Свойство, которое стоит знать читателю текста: если две ветви дошли до
одного и того же уже названного звена, хвост получает **два** знака сторожа
подряд («`<- … <- …`») — по одному на каждый под-обход, упёршийся во
встреченное. Это честно (каждый сторож говорит о себе), но выглядит
непривычно; см. плечо `петля через ветвь` ниже.
