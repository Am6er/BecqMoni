# A145: разбиение групп управления FSA

## Решение, которое предлагается принять

Не смешивать в группе «Отображение» переключатели представления готового
результата с параметрами, меняющими сам расчёт. Разделить правую/верхнюю часть
`FSAReportView` на четыре смысловых блока.

### 1. Источник состава

- `По меткам найденных пиков`
- `Из NucBase`

Это один выбор из двух, поэтому в новом окне лучше две радиокнопки, а не
отрицательная галка `Nucbase lookup`. При выборе первого пути недоступны
«Родительские нуклиды» и «Равновесие»: прежний путь строит свободные компоненты
по подписям пиков и структуры ряда не несёт.

### 2. Группировка результата

- `Родительские нуклиды`
- `Дочерние нуклиды`

Этот блок отвечает только за строки XPTable и слои графика. Переключение не
должно запускать FSA заново.

Для такого устройства результат обязан сохранять корень ряда отдельно от
признака связанной амплитуды. Нынешнее `FsaComponentResult.ChainRoot` несёт
именно признак равновесной связки и при свободных амплитудах дочерних пусто.
Одного этого поля недостаточно, чтобы без пересчёта собрать дочерние строки в
родительскую. Нужен отдельный идентификатор происхождения, например
`DecayChainRoot`, у всех членов ряда.

В родительском режиме суммируются кривые и доли дочерних одного корня. Пределы
обнаружения свободных дочерних складывать нельзя: это не предел родителя. Если
родительский режим разрешён при выключенном равновесии, для родительской строки
предел должен считаться отдельно; более простое и честное правило — разрешать
родительский режим только при связанном ряде.

### 3. Модель цепочек

- `Равновесие ряда`

Это не настройка отображения: она превращает несколько свободных амплитуд в
одну и требует полного пересчёта. Галка доступна только при источнике
`Из NucBase`. При погашении сохраняет выбранное значение, как это уже делает
`DCPeakDetectionView`.

### 4. Дополнительные компоненты модели

- `Атомный рентген`
- `Каскадное суммирование`
- `Обратное рассеяние`
- `Пики вылета и аннигиляция 511 кэВ`
- `Наложение импульсов (pile-up)`

Все пять флажков стоят вне выбора «родители/дочерние»: физические компоненты не
перестают существовать из-за группировки строк. Каждый меняет библиотеку или
матрицу задачи и потому запускает пересчёт. Внутри блока можно визуально
отделить атомный рентген от четырёх аппаратурных эффектов, но не делать его
дочерним элементом одной из радиокнопок.

## Предлагаемая раскладка

```text
┌ Источник состава ───────────────────────────────┐
│ ( ) По меткам найденных пиков  (•) Из NucBase │
└────────────────────────────────────────────────┘

┌ Группировка результата ────────────────────────┐
│ (•) Родительские нуклиды  ( ) Дочерние        │
└────────────────────────────────────────────────┘

┌ Модель цепочек ────────────────────────────────┐
│ [x] Равновесие ряда                            │
└────────────────────────────────────────────────┘

┌ Дополнительные компоненты модели ─────────────┐
│ [x] Атомный рентген                            │
│ [x] Каскадное суммирование                     │
│ [x] Обратное рассеяние                         │
│ [x] Пики вылета и аннигиляция 511 кэВ          │
│ [x] Наложение импульсов (pile-up)              │
└────────────────────────────────────────────────┘
```

Таблица XPTable занимает всё оставшееся место и не получает собственных
фильтров, дублирующих эти переключатели. Строки состояния, невязка, качество,
необнаруженные кандидаты и предупреждения остаются строками таблицы при обоих
режимах группировки.

## Важная поправка к A145: `EscapeGate`

Фраза A145 «`EscapeGate` включает вылет как класс» неверна. При матрице отклика
`EscapeGate = true` удаляет отдельные SE/DE-компоненты, потому что матричный
образ нуклида уже содержит вылеты; без матрицы эта ветка фильтра не работает и
отдельные образы остаются. Поэтому пользовательский флажок «Пики вылета и
аннигиляция 511 кэВ» нельзя напрямую привязать к `EscapeGate`.

Нужен один положительно названный параметр уровня конфигурации, а сборка
библиотеки и анализатор должны интерпретировать его с учётом наличия матрицы:
не допускать ни двойного счёта вылетов, ни их полного исчезновения.

## Остальные внутренние ключи — не готовый контракт UI

Один пользовательский флажок `Каскадное суммирование` не должен механически
писать одинаковое значение во все четыре имени из A145:

- `CascadeSumming` включает поправку площадей и сам расчёт совпадений;
- `CascadeSumPeaks` включает только добавление сумм-пиков;
- `SumPeakCurve` — результат расчёта, а не настройка;
- `SumLayerIncludesContinuum` меняет состав штрихованного подслоя на графике,
  причём комментарий в коде прямо оставляет его ручкой проб, не UI.

Для формы нужен один заранее сформулированный пользовательский контракт:
например, включённый флажок означает обе физические половины
(`CascadeSumming` + `CascadeSumPeaks`), а вид штриховки остаётся внутренним
постоянным решением.

Так же нельзя одним кликом поднимать одновременно `Backscatter` и
`BackscatterWithMatrix`. Первый разрешает отдельный приближённый образ там, где
матрицы нет. Второй возвращает этот же свободный образ поверх матрицы, которая
уже несёт обратное рассеяние, то есть намеренно возвращает старый двойной счёт
для A/B-пробы. Пользовательский флажок должен управлять `Backscatter`, сохраняя
защитное правило `BackscatterWithMatrix = false`.

## Поведение переключателей

| переключатель | меняет расчёт | меняет только показ | условие доступности |
|---|---:|---:|---|
| источник состава | да | нет | всегда |
| родители / дочерние | нет | да | родители — только когда известен корень ряда |
| равновесие | да | нет | только `Из NucBase` |
| атомный рентген | да | нет | всегда |
| четыре аппаратурных эффекта | да | нет | всегда; недействующий при текущей матрице эффект объяснять подсказкой |

## Почему не предлагается исходная вложенность A145

Вложенность «Дочерние → равновесие и аппаратурные эффекты» связывает независимые
оси. Она создаёт два неясных положения: что происходит с уже включёнными
эффектами при переходе к родителям и почему один и тот же спектр должен
считаться с разной физикой только из-за способа назвать строки. Раздельные
группы оставляют поведение явным и позволяют менять представление мгновенно,
не трогая проверенный результат FSA.

## Дополненные требования к A145

### Граница задачи

A145 заменяет графическую таблицу-накладку отдельным инструментальным окном,
но не убирает само полноспектральное разложение с графика. После выполнения:

- кривые компонентов, сумма модели, сумм-пики и ленты невязки по-прежнему
  рисуются поверх спектра в режиме `ShowFSA`;
- перечень компонентов, пределы обнаружения, предупреждения, невязка и качество
  живут в `FSAReportView`;
- прежней узкой таблицы, нарисованной вручную внутри графика, больше нет;
- класс `FsaOverlay` и файл `FullSpectrumAnalysis/FsaOverlay.cs` удалены. Его
  вычислительная часть не теряется, а переносится в класс без обязанностей UI;
- A145 не меняет математические формулы FSA, пороги значимости, число именованных
  слоёв и правило свёртки «прочих», кроме явно перечисленных новых флагов модели.

«Все позиции `FsaOverlay`» означает все **смысловые строки**, которые прежняя
накладка могла показать, а не все сырые столбцы матрицы и не возвращение ранее
снятой строки `SuppressedImages`. Вертикального бюджета больше нет: таблица
имеет полосу прокрутки, поэтому строка `FSARowsDidNotFit` становится ненужной.

### Состав `FSAReportView`

Новый тип — `FSAReportView : ToolWindow`, оформленный как соседние DockPanel-виды.
Имя класса оставляется именно с прописным `FSA`. Закрытие скрывает окно
(`HideOnClose = true`), а не уничтожает его.

Сверху вниз окно содержит:

1. группу `Источник состава` с двумя радиокнопками;
2. группу `Группировка результата` с двумя радиокнопками;
3. группу `Модель цепочек` с флажком равновесия;
4. группу `Дополнительные компоненты модели` с пятью флажками;
5. `XPTable`, занимающую всё оставшееся место.

Группы параметров должны сохранять естественную высоту на обеих культурах,
а таблица — получать остаток. Русский текст не должен обрезаться при штатной
минимальной ширине dock-панели. Английские строки лежат в основном `.resx`,
русские — в `.ru.resx`; компоновка и текст задаются ресурсами. По правилам
здоровых WinForms-видов репозитория Designer использует `ApplyResources`, шрифт
формы берётся из `$this.Font`, свойства XPTable с enum задаются кодом Designer,
а шрифт заголовка таблицы устанавливается безопасно в коде, не сериализуется
как тип XPTable в `.resx`.

### Таблица отчёта

Таблица не редактируется и не сортируется: порядок строк несёт смысл. В ней три
колонки:

| колонка | назначение |
|---|---|
| образец | узкая фиксированная колонка: сплошной цвет, штрих сумм-пиков, клетка невязки либо пусто |
| компонент | локализованное имя строки |
| значение | доля, предел, невязка или `chi2/ndf`, выровненные вправо |

Заголовок колонки-образца пустой. Заголовки двух остальных колонок:
`Component` / `Компонент` и `Value` / `Значение`. Числа форматируются текущей
культурой ровно по прежним правилам.

Порядок строк после успешного расчёта фиксирован:

1. обнаруженные слои состава, с цветом и долей;
2. по строке штриховки сумм-пиков для каждого слоя, у которого они есть, без
   второй доли;
3. именованные необнаруженные кандидаты серым, со значением `< ... %`;
4. одна серая строка свёрнутых низковыходных необнаруженных кандидатов, если
   они есть;
5. красная строка `Без фона`, если фон фактически не применён;
6. строка невязки с тем же клетчатым образцом, что на графике, и значением
   `+избыток / -недостаток %`;
7. строка качества: полный текст всех пометок в колонке `Компонент`, значение
   `chi2/ndf` в правой колонке.

Обратное рассеяние сохраняет прежнее правило значения `есть`, а не ложную долю.
Строки `подавлено: ...` не восстанавливаются. Свёртка обнаруженных сверх
`FsaResult.DefaultMaxNamedLayers` в слой «прочие» сохраняется: отдельное окно
снимает ограничение высоты, но не меняет принятую семантику состава.

Для заполнения вводится типизированная модель строки, например
`FsaReportRow { Kind, Name, Value, Color, SwatchKind }`. Проверки и рендерер не
должны определять смысл строки обратным разбором локализованного текста ячеек.

### Состояния таблицы

Таблица обязана явно различать следующие состояния:

| состояние | требуемое поведение |
|---|---|
| нет активного спектра | элементы управления и таблица выключены, одна строка `Спектр не выбран` |
| нет калибровки FWHM или эффективности | окно остаётся доступным, одна строка с точной причиной невозможности FSA |
| первый расчёт идёт | одна строка `Выполняется расчёт...` |
| пересчёт идёт, старый результат есть | старые строки остаются видимыми и получают заметную строку `Пересчёт...`; нельзя выдавать их за уже актуальные |
| расчёт успешен | строка состояния убирается, показывается полный отчёт |
| расчёт завершился ошибкой без старого результата | одна строка с полной цепочкой причины через `AppUi.Reason` |
| пересчёт завершился ошибкой при старом результате | старые строки сохраняются, перед ними показывается красная строка ошибки |

Предупреждение о старом формате матрицы показывается один раз тем же способом,
что сейчас, но его показ не должен зависеть от видимости `FSAReportView` и не
должен происходить из `Paint`/рендерера таблицы.

### Связь окна с главным интерфейсом

`MainForm` создаёт `FSAReportView` вместе с другими tool-view, знает его
persist-string и обновляет его при смене активного документа и активного
`ResultData`. В меню `Вид` добавляется команда `Отчёт FSA`.

Правила открытия и закрытия:

- команда `Вид -> Отчёт FSA` показывает и активирует окно независимо от текущего
  режима графика;
- явная команда документа `Показать полноспектральное разложение` включает
  `ShowFSA` и показывает отчёт;
- вход в `ShowFSA` циклической кнопкой также показывает окно, но не должен
  отбирать клавиатурный фокус у графика;
- закрытие/скрытие отчёта не выключает `ShowFSA`, не сбрасывает результат и не
  отменяет расчёт;
- выход графика из `ShowFSA` не закрывает уже открытый отчёт;
- открытый отчёт сам является потребителем FSA: он запускает расчёт для
  активного спектра даже тогда, когда график не находится в `ShowFSA`;
- если и отчёт скрыт, и график не в `ShowFSA`, изменение параметров только
  инвалидирует кэш; тяжёлый пересчёт откладывается до появления потребителя.

При входе в `ShowFSA` график больше не рисует старую легенду. Пока результата
нет, на графике допускается только короткая строка состояния
`расчёт / невозможно / ошибка`; полный отчёт и строка качества не дублируются.

### Владение расчётом и данными

`FSAReportView` не должен владеть анализатором, задачей, кэшем или результатом.
Иначе скрытие окна оборвёт работу, а график и таблица смогут разойтись. Один
объект сеанса анализа, условно `FsaAnalysisSession`, принадлежит
`DocEnergySpectrum` и обслуживает его активный `ResultData`.

Минимальный контракт сеанса:

- текущее `Result`, `Status`, `IsRunning`, `ResponseMatrixOldFormat`;
- событие завершения/смены состояния;
- `EnsureUpToDate(ResultData, backgroundAvailable, calculationOptions)`;
- `Invalidate()` и `Reset()`;
- одноразовое получение уведомления о матрице.

И график, и отчёт подписываются на один сеанс и строят представление из одного
снимка результата. Двойного запуска FSA и второго кэша быть не должно. При
смене спектра, закрытии документа и завершении старой фоновой задачи сохраняется
нынешняя защита поколением: устаревший результат игнорируется. Если параметры
поменялись во время расчёта, после его завершения обязательно запускается
расчёт последнего снимка параметров; промежуточное значение не должно остаться
«актуальным».

Класс `FsaOverlay` нельзя просто переименовать и оставить полускрытым UI-объектом.
Из него выделяются две независимые части:

- `FsaAnalysisSession` — запуск, штамп, кэш, защита поколений, матрица и статусы;
- `FsaPresentationBuilder` — чистое построение слоёв графика и строк отчёта из
  готового `FsaResult` и режима группировки.

`EnergySpectrumView.Fsa.cs` после переноса отвечает только за рисование кривых,
лент и короткого статуса. Ручные методы таблицы, её бюджет высоты и обрезание
строки качества удаляются.

### Единая модель представления

`FsaPresentationBuilder` возвращает один снимок представления, условно
`FsaPresentation { Layers, SumPeakLayers, ReportRows }`. Один и тот же список
слоёв определяет:

- цвет компонента на графике;
- образец цвета в XPTable;
- порядок строк;
- свёртку «прочие»;
- родительскую или дочернюю группировку.

Это обязательное условие: отдельно собирать легенду и отдельно график нельзя,
иначе после переключения родителей/дочерних цвет, имя или доля разойдутся.

### Семантика группировки родителей и дочерних

Умолчание — `Дочерние нуклиды`, потому что оно сохраняет нынешний вид результата.
Выбор хранится только как настройка представления текущего окна на время работы
приложения: он не попадает в файл измерения и конфигурацию прибора и не входит
в штамп расчёта.

В дочернем режиме показываются нынешние строки членов ряда. В родительском
режиме до выбора верхних N компонентов:

- кривые членов одного `DecayChainRoot` суммируются;
- `SumPeakCurve` тех же членов суммируются отдельно;
- доли складываются;
- цвет и подпись определяются корнем ряда;
- одиночные нуклиды и аппаратурные компоненты остаются отдельными;
- строки пределов обнаружения берутся из рассчитанной родительской компоненты,
  а не складываются из дочерних пределов.

В текущей модели корректный родительский предел существует только при связанном
равновесном ряде. Поэтому для A145 принимается безопасное правило:
`Родительские нуклиды` разрешены только при источнике `Из NucBase` и включённом
`Равновесии ряда`. При других сочетаниях радиокнопка родителей выключена,
автоматически показываются дочерние, а прежний выбор родителей запоминается и
восстанавливается, когда сочетание снова допустимо. Отдельный расчёт предела
свободного родителя в A145 не входит.

Для будущего расширения результат всё равно получает отдельное поле
`DecayChainRoot`. Оно означает происхождение в ряду и не смешивается с нынешним
`ChainRoot`, означающим общую связанную амплитуду. Это закрывает неоднозначность
`A169` и не меняет численный результат.

### Контракт настроек расчёта

Параметры расчёта берутся из активной копии
`FWHMPeakDetectionMethodConfig`, как нынешние `DbLookupsForFsa` и
`ChainEquilibrium`. Изменение:

1. меняет только конфигурацию активного спектра;
2. записывает то же значение как умолчание конфигурации прибора для следующих
   открываемых спектров;
3. не переписывает уже открытые соседние документы;
4. инвалидирует только FSA, не запускает повторный поиск пиков;
5. немедленно пересчитывает FSA только при наличии видимого потребителя.

Для минимальной миграции существующие XML-имена `DbLookupsForFsa` и
`ChainEquilibrium` сохраняются. Добавляются положительно названные поля с
умолчанием `true`: `AtomicXrayForFsa`, `CascadeSummingForFsa`,
`BackscatterForFsa`, `EscapeAndAnnihilationForFsa`, `PileUpForFsa`. Их нужно
провести через конструктор, `Clone`, `AdoptFrom`, сериализацию конфигурации
прибора и штамп FSA. Старые два флажка и их обработчики удаляются из
`DCPeakDetectionView`; общая логика записи конфигурации переносится без
изменения области действия.

Значения по умолчанию специально сохраняют сегодняшний расчёт:

- источник — метки найденных пиков (`DbLookupsForFsa = false`);
- равновесие — включено;
- все пять дополнительных компонентов — включены;
- группировка — дочерние.

### Точная привязка пользовательских флажков

| UI | контракт вычисления |
|---|---|
| атомный рентген | управляет добавлением `AtomicXray` в спецификацию/библиотеку |
| каскадное суммирование | одним значением управляет `CascadeSumming` и `CascadeSumPeaks`; `SumPeakCurve` остаётся результатом, `SumLayerIncludesContinuum` остаётся внутренним `false` |
| обратное рассеяние | разрешает отдельную приближённую компоненту только без матрицы; `BackscatterWithMatrix` всегда `false` |
| вылеты SE/DE и аннигиляция 511 | положительный флаг библиотеки; `EscapeGate` остаётся внутренней защитой от двойного счёта при матрице и не равен значению флажка |
| pile-up | управляет генерацией/добавлением `PileUpComponent` |

Флажок не вправе обещать отключение физики, уже зашитой в матрицу отклика.
Поэтому при наличии матрицы подсказка для обратного рассеяния и вылетов явно
говорит, что переключатель управляет только **отдельной дополнительной
компонентой**, а вклад матрицы остаётся. Если эффект неприменим к текущему пути,
флажок остаётся видимым и хранит выбор, но становится недоступным с объясняющей
подсказкой. В частности, каскадное суммирование без необходимых данных не
выдаётся за сработавшее: строка качества отмечает его только по факту
`CascadeSummingUsed`.

Внутренние `Cascade*Partners`, `CascadeApplied`, `SumPeakCurve`,
`SumLayerIncludesContinuum` и `BackscatterWithMatrix` не являются отдельными
элементами формы. Это граница A145 и уточнение `A170`.

### Доступность элементов управления

| условие | источник | родители | дочерние | равновесие | доп. компоненты |
|---|---|---|---|---|---|
| нет активного спектра | выкл. | выкл. | выкл. | выкл. | выкл. |
| источник `По меткам пиков` | вкл. | выкл. | выбраны | выкл., значение помнится | по фактической применимости |
| `NucBase`, равновесие выкл. | вкл. | выкл. | выбраны | вкл. | по фактической применимости |
| `NucBase`, равновесие вкл. | вкл. | вкл. | вкл. | вкл. | по фактической применимости |

Переключение источника или равновесия, которое делает родительский режим
невозможным, не стирает предпочтение пользователя: визуально выбираются
дочерние, но при возврате допустимых условий родители восстанавливаются.

### Локализация и доступность

У каждого флажка и радиокнопки есть осмысленный локализованный текст и tooltip,
объясняющий, меняет ли действие расчёт либо только группировку. Tab-order идёт
сверху вниз по группам, затем в таблицу. Радиокнопки работают с клавиатуры как
две отдельные группы. Цвет никогда не остаётся единственным носителем смысла:
у сплошного слоя есть имя и доля, у штрихованного — текст `сумм-пики`, у невязки
— текст и знаковые числа, у предупреждений — текст.

### Критерии приёмки

A145 можно считать выполненной только если одновременно доказано следующее:

1. `FsaOverlay` отсутствует в исходниках и проекте; старой ручной таблицы на
   графике нет.
2. `FSAReportView` создаётся, открывается из меню, восстанавливается из layout,
   переживает hide/show и отслеживает активный документ.
3. Явный и циклический вход в `ShowFSA` показывают отчёт по правилам выше;
   закрытие отчёта не меняет режим графика.
4. График и XPTable используют один результат и одну модель слоёв; второго
   анализа нет.
5. Все семь категорий строк представлены, таблица прокручивается и ничего не
   отбрасывает по высоте.
6. Полная строка качества, включая сочетание `подавлен`, `старая матрица`,
   `суммирование`, `без эффективности` и край дрейфа, доступна без усечения в
   английской и русской культурах.
7. Переключение дочерние/родители не меняет штамп расчёта и не запускает FSA;
   переключение любого расчётного флага меняет штамп и приводит к одному
   актуальному пересчёту.
8. Родительский режим недоступен без NucBase+равновесия; при допустимом режиме
   сумма кривых и долей совпадает с суммой показанных дочерних с машинным
   допуском.
9. При матрице и без неё флаги вылетов и обратного рассеяния не создают двойной
   образ и не меняют скрытые защитные ключи на опасные значения.
10. Смена спектра во время фонового расчёта не подмешивает старый результат;
    быстрая серия изменений заканчивается результатом для последнего набора
    параметров.
11. Клонирование и сохранение конфигурации проверено для всех новых флагов;
    другой уже открытый документ не меняется.
12. Форма и таблица отрендерены и просмотрены в `en` и `ru`: нет обрезанных
    подписей, наложений, сериализованных XPTable-enum и замены шрифта.
13. Существующие численные corpus/probe-проверки FSA не изменились там, где
    соответствующий новый флаг оставлен во включённом состоянии по умолчанию.

До явного решения Amber «брать A145 в работу» этот документ является только
проектом реализации и дополнением требований. Он не разрешает менять код.
