## 2. Чего не хватало оценщику кривой

Взвешенная ветвь (`OneHistory`) — прямой квант `exp(−τ)` плюс ОДНО рассеяние на луче к кристаллу
(`ScatteredRun`); вылетевший из кристалла квант не ведётся (`escapeCollect` у неё выключен),
сквозной пролёт с возвратом из-за кристалла — ноль, флуоресценция пробы — ноль. Аналоговая ветвь
(`AnalogTransport`) ведёт всё: очередь квантов, возврат из обвязки (`A55`), многократное
рассеяние, флуоресценцию вне кристалла (`F27`). На 45…60 кэВ любое комптоновское рассеяние
уносит ≤ 6.7 кэВ, K-рентген иода, отражённый корпусом, возвращается с недобором 0…2.8 кэВ —
всё это в окне ПШПВ/2.

Встречная проверка ветвей в ТЕСНОМ допуске 1 кэВ (`CurveWindowP216`, `AS80_point0`, 1.6 млн
историй): аналог/взвешенная 1.0098 / 1.0037 / 1.0045 / 1.0022 / 1.0001 на 32.19 / 45 / 59.54 /
80 / 122 кэВ — в тесном допуске ветви согласны до 0.2…1 %, расходятся в полосе.

## 3. Правка — окно полной строки (решение Amber к `AMBER145` 01.10.2026 «Окно полной строки матрицы»)

`EfficiencySimulator.Run`, путь кривой (без гистограммы), при допуске кривой больше тесного:

* взвешенная ветвь считает пик **тесным допуском** `CurveTightPeakHalfWidthKev` = `BinKev`/2
  умолчания склада (1 кэВ — допуск бина пика матрицы); допуск меняется только на время
  взвешенного цикла, `InPeak` случайных чисел не тянет;
* полоса «1 кэВ < недобор ≤ ПШПВ/2» — **аналоговая ветвь** `AnalogInConeBandRun`: n историй тем
  же розыгрышем точки, направление В КОНУСЕ взвешенной ветви с весом конуса (точка внутри
  объемлющей сферы — полная сфера), полный `AnalogTransport`;
* класс вне конуса (`AMBER79`, оценка следующего события) — как был, допуском ПШПВ/2.

Это ровно разбиение ε_p по разрешению склада (EPRS: «бин пика» взвешенной + «прочие бины с
недобором ≤ ПШПВ/2» аналоговой). Рычаг проб `CurvePeakResolutionWindow` (ВЫКЛ — прежняя кривая
побитово). Геометрия без разрешения (допуск 0) и узлы с ПШПВ/2 ≤ 1 кэВ — окна нет, прежний счёт.
Выходы прогона для проб: `LastCurveBand`, `LastCurveBandErrorPercent`, `LastCurveWeightedTight`,
`LastCurveAnalogTight`.

Клеймо кривой (`EfficiencyCalculation.Run`): кусок **`; peps=fwhm`** (то же имя и значение, что
определение ε_p в клейме матрицы) — только у геометрии с разрешением, перед `mdb=` (последним
остаётся отпечаток, `check_matdb_fingerprint` зелёный). `CorpusEffProbe.CurveIsCurrent` требует
`peps=fwhm` у геометрии с разрешением: прежние кривые корпуса (физика 26 без куска) считаются
устаревшими. Положительный контроль: `--only=AS80_point0 --n=400000 --dry` — новая проба
«посчитано 1, пропущено 0», старая — «пропущено 1».

`check_matrix_keys.py`: два поля симулятора внесены в реестр SIM («неприменимо»: рычаг проб и
тесный допуск от умолчания склада) — «СОСТАВ КЛЮЧЕЙ СОШЁЛСЯ».

## 5. Остаток и решения

* **Остаток −0.2…−0.9 % к полному аналоговому переносу** — класс с недобором ≤ 1 кэВ, который
  взвешенная ветвь не рождает (возврат и многократное с нулевой потерей): аналог/взвешенная в
  тесном допуске 1.0098 / 1.0037 / 1.0045 / 1.0022 / 1.0001 (`AS80_point0`). Тот же остаток у
  ε_p склада (разбиение одно). К Geant4 новая кривая ближе аналоговой на 32 кэВ (0.998 против
  1.007), так что «долечивать» его полным аналоговым пиком нет оснований; в допуск приёмки
  входит. Строкой не заводится — факт.
* ⛔ **Поколение кривой.** Отдельного номера поколения кривой в коде НЕТ: `phys=` кривой — это
  `ResponseMatrix.PhysicsVersion`, общий с матрицей; `check_curve_generation.py` сравнивает только
  его. Поднять 26 → 27 значит отказать всем 49 матрицам склада и рабочим матрицам Amber, чьё
  содержимое правка не трогает (ночной пересчёт ≈ 8.5 ч), и это `ResponseMatrix.cs` — не файл
  полосы. Сделано: кусок `peps=fwhm` в клейме кривой (виден человеку в строке клейма вкладки
  «Эффективность») и гвард `CorpusEffProbe`. Сторож `check_curve_generation` и подпись вкладки
  (`GenerationNotes`) прежнюю кривую физики 26 без `peps=fwhm` НЕ называют — по построению (код
  сторожа, правила 1–11, читает только `phys=`). Варианты — для распорядителя (§6 отчёта).
* **Кривые корпуса и поставочные/ROI — НЕ пересчитаны** (по заданию). Команда пересчёта
  корпуса из корня слитого дерева после `build_all.ps1` с кодом 0:
  `tools\effmaker\probes\build_<полоса>\CorpusEffProbe.exe --n=400000` (без `--force`: гвард
  `peps=fwhm` сам признаёт все 49 геометрий с разрешением устаревшими). Время: 36 мин × 1.43…1.66
  ≈ **52…60 мин**. Меняет `<Efficiency>` 92 понятных спектров (на 32…122 кэВ +0.5…+3 %, у сцен
  с K-краем пробы в шкале — до +61 % в узле сразу выше края) → корпус и база (rev39 → новая).
