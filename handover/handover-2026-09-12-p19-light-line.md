## 1. Что сделано и почему именно там

### 1.1 Где применяется форма — в построении образов, не в привязке

Задание давало два места: (а) в построении образов, (б) в привязке (опоры сравнивать с E + s(E), образ не
трогать). Сделано (а), и (б) тоже — плечом замера `anchor`, чтобы цену (б) назвать числом, а не доводом.
Довод за (а) — из кода: `RemapLightScale` (`EfficiencySimulator`) при счёте матрицы ставит КАЖДЫЙ бин
строки линии E на `L̄_бина / (L̄_пика / E)` — то есть нормирует всю строку на свет её пика полного поглощения.
На шкале прибора, линейной по свету и откалиброванной по E₀, та же строка стоит с множителем
`k = r(E)/r(E₀)` ЦЕЛИКОМ — пик, комптон, вылеты; чужие линии, подложка, сплайн и фон не двигаются вовсе.
Это и есть точная карта, о которой писала П16 §3.1. Сдвиг по бину (П18) двигал вместе с пиком всё, что в
бине стоит, — отсюда плата Cs-137 (континуум 100…477 кэВ ехал на +1.5…+3.9 кэВ при множителе 1 у 662).
Форма (б) оставляет модельный пик на E, а шкалу тянет к E + s(E) — модель пика заведомо не там, где
данные; измерено: +40 % корпусу.

### 1.2 Код (копия, патч `light-line.patch`)

| место | что |
|---|---|
| `ResponseMatrix` | `AccumulateLight(target, E, w, channel, shiftKev, lightScale)` — множитель положения на ВЫХОД переноса; протянут через `Accumulate` → `Place` → `Stretch`/`Transfer` (после правила канала, до `shiftBins`): `b·scale·k`, `(b+shift)·k`, `mapped/bin·k`. Узлы сетки выбираются по E (физика отклика — у кванта E), множитель — к выходу. Единица не меняет ни бита (`x·1.0 == x`) — контроль §2 это подтвердил |
| `FsaAnalyzer.AnchorLightForm` | слово `bin` / `line` / `peak` / `anchor`; разбирается в `Analyze` (`ParseLightForm`, незнакомое слово — отказ, не подмена); умолчание в конструкторе — `line`; описание у объявления, `check_fsa_docs.py` код 0 |
| `FsaAnalyzer.AccumulateLine` | ОДНА точка сбора отклика линии для всех трёх построителей (`BuildResponseDeposit`, `BuildLineBlue`, `BuildLineColumn`): без координаты — прежние `AccumulateChannel`/`Accumulate` до бита; `line` — `AccumulateLight(…, k = (E + s)/E)` на все каналы; `peak` — `AccumulateShifted` на канал `Peak`, прочие как были (у матрицы без каналов сдвинуть один пик нельзя — строка как есть) |
| сумм-пики | по видимой энергии суммы (`ApparentSum`, ~~`S20`~~) и той же координатой s(E_вид) ОДИН раз, как одиночная линия той же видимой энергии (в форме `bin` они получали её автоматически — бином); сумм-континуум (`AccumulateSumContinuum`): в `line` отклик третьего кванта своим множителем, приподнятый на видимую сумму пары с её сдвигом; в прочих формах — прежний `AccumulateShifted` |
| длина гистограмм | `lightMarginBins` = ⌈max s⁺/бин⌉ + 1 (по узлам таблицы, `FsaLightScale.MaxShiftKev`) — иначе пик верхней линии ниже E₀, уехав вверх на 4 кэВ, лёг бы зажимом `Add` в последний бин; нуль без координаты |
| привязка | у форм `line`/`peak` таблица S(p) по бинам не строится; `DriftPosition` — сдвиг по бину ТОЛЬКО у `bin`; поиск линии ядра опоры — на E + s(E) (`LinePositionKev`); координата опоры S — s(E) линии ядра в каналах на модельном центре; МНК на первом проходе, как у П18: Y′ = Y − S, потом β = 1 → **кэш гистограмм `deposits` сбрасывается** (сдвиг живёт в образах), перефит; дальше β⁺ = 0. Форма `anchor`: β⁺ = 1 на каждом проходе, наружу β = 0, модель не трогается |
| `SplitContinuumBelowTrustFloor` | окно пика — вокруг E + s(E) |
| `FsaResult.AnchorLightForm`, `CorpusFsaProbe` | `--anchor-light=0\|1\|bin\|line\|peak\|anchor\|NaI:Tl\|CsI:Tl` (`1` — форма умолчания анализатора), `--anchor-form=` отдельно (к кривой поимённо); колонка `anchor_form` В КОНЕЦ `runs.csv`; в сводку «положение по свету … форма X»; `anchor_note` — «свет NaI:Tl: β 1.000, форма line» |

Координата у всех форм действует только после первой принятой опоры (β = 1), как у П18; без опор шкала и
образы — как без ключа (в понятной части спектров без опор нет: 26 / 29 / 29 по 1 / 2 / ≥ 3).

### 1.3 Что точная форма предполагает — и чего у сегодняшнего склада нет

Множитель `k = r(E)/r(E₀)` точен, когда кривая света, которой `RemapLightScale` нормировал строку (склад),
и кривая, по которой ставится пик (таблица `FsaLightScale`), — ОДНА. Сегодняшний штатный склад считан БЕЗ
K-провала (П18 §1.2), таблица NaI — С провалом (П17, `--kdip=1`); ниже ~100 кэВ они расходятся на величину
провала (1…3 %), то есть континуум и вылеты низких линий множитель по таблице ставит не совсем туда, куда
поставил бы склад с провалом. Склад П20 (`store_a17_run.cmd`: `--peakb=1 --xrkl=1 --kdip=1`) это расхождение
снимает — на нём `line` обязана быть не хуже `peak`, и это надо измерить прежде, чем выбирать форму.
