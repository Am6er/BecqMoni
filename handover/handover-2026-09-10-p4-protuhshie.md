## `T21` — закрывается: ключ мёртв, правило шапки найдено, цена измерена

**Что осталось по строке:** «цена зануления `calc_scattered` НЕ ИЗМЕРЕНА НИ НА
ОДНОЙ энергии, и измерить её опубликованным API нечем — ни `.in`, ни json до
ключа не доносят».

**Первая половина посылки подтвердилась, вторая ОКАЗАЛАСЬ НЕВЕРНОЙ.**

### Ключ действительно мёртв — и это теперь замер, а не вывод

Путь `.in` даёт фиксированное зерно, значит два прогона обязаны совпасть
ПОБИТОВО. Сравнение по отчёту без строк `Date:`/`Time:` — только они и
различают повторы:

| в файле | шапка | sha1 отчёта |
|---|---|---|
| `calc_scattered = true` (опора) | true | `fb841de9…` |
| `calc_scattered = false` | **true** | `fb841de9…` — тот же |
| повтор опоры | true | `fb841de9…` |
| **контроль** `calc_electron_ttb = false` | false | `9bfd6e53…`, 7.3 → 4.3 с |

Проверено, что в САМ ФАЙЛ попадает то, что просили (`calc_scattered = false`
дословно в `tccfcalc.in`) — иначе мерился бы мой генератор входа, а не DLL.
То же на второй геометрии (маринелли 0.5 л, `29a251b8…` в обеих ветвях) и на
json-пути (шапка `true` в обеих ветвях, 7.3 / 7.2 с).

### Правило шапки: она печатает НЕ ЭТОТ ключ

Перебором соседей по одному ключу за прогон:

    печатаемое cp.calc_scattered = calc_coincidence ИЛИ calc_full_eff

Девять наблюдений — пять прежних из README и четыре новых — ложатся без
исключений, включая обе «противоречивые»: Co-60 с `calc_coincidence = false`
печатает `false`; Scale (A = 290) с `calc_full_eff = true` печатает `true`.
Заодно поймано, что `calc_effc` тоже мёртв: `true` в файле, `false` в шапке,
отчёт побитово тот же.

### Цена — измерена, вопреки «измерить нечем»

Раз действующий признак есть `coincidence ИЛИ full_eff`, выключенное состояние
ДОСТИЖИМО: выключить оба. Co-60, 5 млн распадов, по два зерна на ветвь:

| линия | ВЫКЛ | ВКЛ | ВЫКЛ/ВКЛ | разброс повторов |
|---|---|---|---|---|
| 1173.2 кэВ | 5.419e-3 / 5.438e-3 | 5.384e-3 / 5.383e-3 | 1.0084 | 0.35 % / 0.02 % |
| 1332.5 кэВ | 4.541e-3 / 4.524e-3 | 4.544e-3 / 4.492e-3 | 1.0032 | 0.38 % / 1.15 % |

Второй, независимый подход — сравнение ВЕТВЕЙ на Be-7 (у настоящего нуклида
признак включён, у поддельной сетки Scale выключен), 20 млн распадов, по два
зерна: отношение Scale / Be-7 = **0.9985 (−0.15 %)** на 477.6 кэВ при разбросе
повторов 0.15 % и 0.05 %.

⚠ **Чего замер НЕ даёт — сказано вслух: чистого разделения.** Пары,
отличающейся ТОЛЬКО рассеянием, у опубликованного API нет; признак всегда
переключается вместе с тем ключом, которым его включают. Числа выше — ВЕРХНЯЯ
ГРАНИЦА, и она годится ровно потому, что мала: будь она велика, две правки в
разные стороны могли бы погасить друг друга.

Записано: README §13.3 (новый подраздел вместо двух отозванных абзацев), §13.7
(две строки таблицы «что сломано»), шапки `run_tccf2.py` и `scale_set.py`.
