## 2. Что сделано

### `appwd_plan.ps1`
* `Get-AppWdProbeSources -Repo` — единственный перебор `tools\effmaker\*.cs` +
  `tools\effmaker\probes\*.cs` (`-File -Force`); `Get-AppWdPlan` берёт `$probeSrc` из неё.
  Взято из патча оборванной полосы `handover/aborted-2026-09-05/…appwd_plan.ps1.patch`
  ТОЛЬКО это (без `Resolve-AppWdPath` и прочего — не `T89`).
* Ключ `-ProbeCatalog` у `Get-AppWdPlan` и `New-AppWdPlanOrDie`: шаг 4а кладёт поставочные
  `BecquerelMonitor\config\device\*.xml` (9) и `config\ROI\*.xml` (12) родами
  `поставочный конфиг\device` / `поставочный конфиг\ROI`. **Ключ, а не общее правило,
  нарочно:** оснастке корпуса их класть нельзя — `config\device` у неё строится из
  приборов КОРПУСА целиком (`Exclusive`), а поставочный `AtomSpectraVCP.xml` несёт ТОТ ЖЕ
  GUID, что корпусный `1.Atom Spectra Nano 16 Pro RadiaScan 701A.xml` (сверено скриптом по
  `<Guid>`): два GUID = модальное окно = зависание (`B6`). Без ключа план побайтно прежний —
  `mk_appwd.ps1`/`run_appwd.ps1`/`check_appwd.ps1` не тронуты и поведения не меняют.
  Источник — репозиторный `BecquerelMonitor\config\`, как у шага 4 (в `$Bin\config\device`
  csproj кладёт ОДИН прибор из девяти). Дублей GUID среди девяти поставочных нет.

## 4. Грабли захода

* ⛔ **`pwsh -Command "& 'build_all.ps1' …"` ТЕРЯЕТ код возврата:** при первом прогоне
  контроля `T89` сборка вернула «1» при печатном отказе кода 3 — `-Command` отдаёт 0/1 по
  `$?`, а не `exit N` скрипта. С `-File` — честные 3. Рецепт `CLAUDE.md`
  (`pwsh tools\effmaker\probes\build_all.ps1`) это `-File`, он верен; ловушка — у обёрток.
* ⚠ `Start-Process -ArgumentList` режет путь с пробелами (известно по `CLAUDE.md`):
  `--spectrum=C:\…\BQ Eng res…` ушёл как «неизвестный ключ: Eng». Аргумент — в кавычках.
* ⚠ Имя параметра `$args` у функции PowerShell перебивается автоматической переменной:
  массив аргументов дошёл пустым. Не называть параметры `$args`.
