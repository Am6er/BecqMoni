## 2. `A59` — соседние зёрна давали один поток

`ResetStream(seed)` ставил `state = seed | 1`, то есть младший бит зерна
выбрасывался: **20260902 и 20260903 — одно и то же зерно**. Схлопывались не
только соседи: номер узла входит в зерно слагаемым (`ResponseMatrixBuilder`
складывает зерно с кратным золотого множителя), и половина узлов попадала в ту же
пару. Вторая половина строки: ленивая инициализация из `Seed` шла мимо
`ResetStream` — без перемешивания и без 16 холостых розыгрышей.

**Правка.** `MixSeed` = SplitMix64 (полная лавинность: один бит зерна меняет
половину битов состояния), ленивый путь идёт через `ResetStream`.

**Приёмка** (`AS80_point0`, 662 кэВ, 200 тыс. историй):

| плечо | пик | полная |
|---|---|---|
| зерно 20260902 | 1.407161e-1 | 2.884061e-1 |
| зерно 20260903 | 1.398315e-1 | 2.873965e-1 |
| **расхождение** | **0.63 %** | 0.35 % |
| то же зерно повторно | бит в бит | бит в бит |
| зёрна 100 / 101 | 0.14 % | 0.10 % |

Ожидаемый шум взвешенной ветви на этой статистике 0.51 %, то есть σ разности
0.72 % — расхождения ложатся в него. Прежде плечо давало 3e-7.

## 5. `A57` — конус на габарит СЦЕНЫ, а не детектора

Строка предлагала «навести тем же конусом, каким пользуется взвешенная ветвь».
⛔ **Так делать нельзя, и это уже измерено:** конус на объемлющую сферу ДЕТЕКТОРА
однажды занизил ε_полную на 4 % (см. `TotalFullSphere`, «ложь была в оценщике, не
в физике») — он режет истории «мимо узла, рассеялся в пробе, вернулся». У
маринелли сосуд доходит до r = 6.76 см при радиусе детектора 3.45.

**Правка.** Габарит копится по ВСЕМ областям сцены (`SceneBounds`), конус
наводится на него, вес — доля телесного угла. Вне габарита вещества нет вовсе,
поэтому не отсекается ни одна история, способная дать отсчёт. Ключ
`AnalogConeSampling`, умолчание ВЫКЛЮЧЕНО, проведён до построителя и клейма
(`--cone=1` у `CorpusMatrixProbe`, проверка в `MatrixStampProbe`).

**Заодно починена мерка шума.** `SmearedContinuumError` считала дисперсию бина
равной его содержимому (пуассон с весом 1) и при взвешенных историях завышала бы
шум ровно во столько раз, во сколько конус его снизил. Теперь копится сумма
квадратов весов; при полной сфере она равна сумме весов, и числа прежние.

**Приёмка** (`G1S_point25`, 662 кэВ, 500 тыс. историй):

| | полная сфера | конус |
|---|---|---|
| шум континуума | 11.26 % | **0.95 %** |
| историй в пике аналоговой ветви | 642 | **90834** |
| согласие ветвей (взвеш./аналог.) | 1.0429 | **1.0046** |

**Несмещённость против Geant4** (наш 4 млн, арбитр 40 млн): вся сумма — конус
**+0.30 %**, полная сфера +0.54 %; низ — −0.46 % против +0.97 %.

**Контроль на ближней сцене:** `AS80_point0` даёт с ключом и без него
**бит в бит** одно и то же — точка запуска внутри габарита, конус не применяется.

## 9а. `A63` — причина найдена: вылет электрона включается порогом 350 кэВ

`t_eff = 0.4·max(0, T − 350 кэВ)/1000·R(T)` (`ElectronEscapeSlope`,
`ElectronEscapeT0Kev`). При 59.5 кэВ фотоэлектрон несёт 26 кэВ (K-оболочка) или
54 (L) — **вылета нет вовсе по построению**. Форма калибровалась по ε_пик на
662–2614 кэВ, то есть ВВЕРХУ шкалы.

**Абляция порогом** (`--esc-t0=0`, голый кристалл, 59.541 кэВ, 2 млн):

| полоса | порог 350 | порог 0 | Geant4 |
|---|---|---|---|
| 1…12 | −63.97 % | −60.14 % | — |
| 13…25 | −87.99 % | **−79.73 %** | — |
| 32…54 | −86.89 % | **−82.00 %** | — |
| 55…59 | −100 % | −98.45 % | — |
| пик | +1.85 % | +1.74 % | — |
| сумма | −0.03 % | −0.03 % | — |

То есть порог держит лишь ДЕСЯТУЮ часть недобора; остальное — сама линейная
форма: при T = 26 кэВ множитель `0.4·T/1000` даёт `t_eff` в 1 % пробега.

**Цена снятия порога наверху шкалы мала** (662 кэВ с обвязкой, 2 млн против 5 млн
арбитра): пик +1.06 → **+0.91 %**, прочие полосы в пределах 0.2 пункта, сумма
+0.03 % в обоих случаях. То есть перекалибровка формы внизу шкалы верхнюю
калибровку, скорее всего, не ломает — но проверять это обязательно развёрткой,
а не одной точкой.

**Следующий шаг:** развёртка `t_eff` по энергиям против Geant4 на ГОЛОМ кристалле
(там причина одна) с обязательной сверкой ε_пик на 662/1461/2614.

## 9б. Ревизия правок: три находки, все три починены

Разбор чужой ревизии по коду, а не на слово. Все три подтвердились.

### `A67` (был P0) — версия физики не поднималась

`PhysicsVersion` осталась **12**, хотя `A52`–`A57`, `A59` и `A61` меняют отклик
ВСЕГДА (это не ключи, их не выключить). Старая матрица самосогласована — её
клеймо отвечает её же настройкам, — поэтому `IsValidFor` отвечал «годна», а гвард
пересчёта «пересчитывать не надо». Проверено на `AS80_point0.rmx` от 31.08:
клеймо по настройкам файла сходилось.

**Починено:** версия поднята до **13**, перечень правок записан в самом поле.
Та же матрица теперь даёт `phys=13` против `phys=12` в файле:

```
клеймо при умолчаниях : phys=13;48d37ef0…
клеймо в файле        : phys=12;f3d585d6…
клеймо по НАСТРОЙКАМ ФАЙЛА: phys=13;e24e06c3…
  НЕ СОШЛОСЬ — изменился сам состав клейма или версия физики
```

⚠ Следствие, которое надо знать: **до этой правки склад не пересчитался бы даже
по прямому приказу** — гвард отдавал бы старые матрицы как годные.

### `A66` (был P1) — ключи в клейме, но не в файле

`XcomPairThreshold`, `PositronTransport`, `PositronOffset`, `RayleighToCrystal`
(`S130`) и `AnalogConeSampling` (`A57`) учитываются в `ComputeStamp`, но
`WriteOptions`/`ReadOptions` их не несли. После чтения флаг становился `false`,
клеймо пересчитывалось без него и не сходилось САМО С СОБОЙ — `IsValidFor` «нет»
навсегда. ⚠ Это ровно та дыра, которую `T114` уже закрывала для ЗЕРНА, и она
повторилась дважды за один день.

**Починено вторым хвостом `OPTF`, а не подъёмом формата:** плюс один к
`FormatVersion` объявил бы нечитаемыми все 44 посчитанные матрицы, а хвост
совместим в обе стороны (у старого файла его нет, флаги `false` — он и правда
считался без ключей).

**Приёмка прогоном** (крошечная матрица, 3 узла):

| прогон | ожидание | вышло |
|---|---|---|
| посчитать с `--cone=1` | файл создан | создан |
| повторить с `--cone=1` | ПРОПУСТИТЬ | «посчитано 0, пропущено 1 (клеймо сошлось)» |
| повторить без ключа | пересчитать | «посчитано 1» |

### `A65` (был P2) — тихий отброс при переполнении очередей

Замечание справедливо по сути, но **величина измерена и она ничтожна**:

## 9в. `A63` починена: мягкий вылет электрона

**Приказ Amber: «Чини A63».** Починено, версия физики 13 → **14**.

### Что мешало и как отделялось

Начал не с калибровки, а с атрибуции — и правильно сделал: **абляция каналов**
на голом кристалле (59.541 кэВ, 2 млн) показала, что шельф 32…54 держится у нас
рентгеном (−29 % при `--no-xray`) и тормозным (−27 % при `--no-brem`), а вылет
электронов не даёт **ничего**: `--no-esc` шельф даже поднимает на 5 % (шум).
Причина — порог: `t_eff = 0.4·max(0, T − 350)/1000·R(T)`, а фотоэлектрон при
59.5 кэВ несёт 26 кэВ.

⚠ **Моя прикидка «канал не может дать больше 0.26 %» была НЕВЕРНОЙ** — ошибся в
длине поглощения. Развёртка по `--esc-slope` при пороге 0 показала обратное: при
доле пробега f = 1 шельф даёт 6.9e-3 (1.4 % полной) против недобора в 3.5e-3.
Гипотеза устояла только потому, что её проверили замером, а не арифметикой.

### Почему не «другой наклон»

Единый наклон, чинящий низ, **ломает верх** (голый + зазор, пик окном ±3):

| | 59.5 кэВ | 661.7 | 2614.5 |
|---|---|---|---|
| умолчание 0.4/350 | +0.65 % | +0.66 % | −1.04 % |
| наклон 5, порог 0 | +0.18 % | −0.62 % | −3.37 % |
| наклон 12, порог 0 | −0.46 % | −0.64 % | −3.38 % |
| наклон 20, порог 0 | −0.96 % | −0.64 % | −3.38 % |

Наверху доля пробега упирается в единицу, поэтому наклоны 5…20 неразличимы, а
пик уходит втрое дальше от арбитра.

### Правка

К порогово-линейной части добавлен член **`0.5·exp(−T/100 кэВ)`**. Он гаснет к
сотням кэВ: на 477 кэВ добавляет 4 % к величине, на 2.4 МэВ — ничего.

**Приёмка** (наш 2 млн / арбитр 5 млн, шкала энерговыделения, мир пустой):

| сцена, полоса | было | стало |
|---|---|---|
| голый ВПЛОТНУЮ, 13…25 кэВ | −88.0 % | **−1.5 %** |
| голый ВПЛОТНУЮ, шельф 32…54 | −86.9 % | **−18.3 %** |
| голый ВПЛОТНУЮ, пик ±3 | +1.84 % | **+0.49 %** |
| голый + зазор, 13…25 | −81.6 % | **+3.6 %** |
| голый + зазор, шельф | −75.8 % | **−7.0 %** |
| голый + зазор, пик | +0.66 % | **+0.01 %** |
| **с обвязкой, 662 кэВ, пик** | +1.13 % | +1.03 % |
| **с обвязкой, 2614.5, пик** | −1.04 % | −1.06 % |

### Чего эта правка НЕ закрывает — и не должна

Полоса 55…59 кэВ — **вылет L-рентгена** (`A60`), у нас его нет вовсе. Проверено
на своих числах: бины 55 и 56 у арбитра дают 2.66e-4 и 2.61e-4 против фона
2.5e-5 — это линия с резким краем, а не хвост шельфа. Подгонять `t_eff` по полосе
целиком значило бы возложить на неё чужой канал; полоса приёмки резана 32…54.
Указал на это `bq-eng-res-net-a9` встречной проверкой — до того я считал полосу
одним шельфом.

Остаток — строка `A70`: параметров два, а подобраны они по двум полосам ОДНОЙ
энергии; развёртки по энергиям нет, устойчивость `T_мяг` = 60/100/150 кэВ даёт
шельф −21/−7/+3 %.
