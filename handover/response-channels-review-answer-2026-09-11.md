## 2. Запрещённый `EscapeXray` на 32.194 кэВ: трассировка

Ваш довод принят полностью, и вы попросили именно то доказательство, которое
разделяет две версии. Оно снято: в `EfficiencySimulator` заведена трассировка
выбора канала (элемент, оболочка вакансии, энергия рентгена, метки перед
`ChannelOf`). Прогон на узле **32.194 кэВ**, один поток, первые 22 истории
канала — приложение В. Выдержка:

```
канал=EscapeXray вылетело=3.9252 метка_рентген=3.9252 метка_аннигиляция=0.0000
                 остаток=0.0000 допуск=0.0000 | Z=53 оболочка=3 рентген=3.9252
канал=EscapeXray вылетело=4.6155 метка_рентген=4.6155 метка_аннигиляция=0.0000
                 остаток=0.0000 допуск=0.0000 | Z=55 оболочка=2 рентген=4.6155
канал=EscapeXray вылетело=5.0164 метка_рентген=5.0164 метка_аннигиляция=0.0000
                 остаток=0.0000 допуск=0.0000 | Z=53 оболочка=1 рентген=5.0164
```

**Все до одной истории — L-серия** иода (Z = 53) и цезия (Z = 55), энергии
**2.68…5.02 кэВ**, подоболочки L1 / L2 / L3. Ни одной K-линии (они были бы
28…35 кэВ). Метка `lossXray` равна энергии ушедшего кванта, остаток нулевой —
то есть **вторая ваша версия (несброшенные или унаследованные метки)
опровергается**: метки набраны в этой самой истории и именно L-квантом.

Причина в коде одна и она видна сразу: розыгрыш характеристического кванта
ведёт обе серии — K-линия при `u < kFraction·ω_K`, иначе L-подоболочки, — а
метка у них **общая**:

```csharp
double gone = this.InCrystal(x, y, z, kx, ky, kz, xray, depth + 1);
double markedInside = this.lossAnnihilation + this.lossXray - markedBefore;
this.lossXray += Math.Max(0.0, gone - markedInside);   // K и L в одну метку
```

а `ChannelOf` выбирает канал по величине метки, не по тому, какая оболочка
ответила. Значит **канал следует читать как «ушёл характеристический рентген
кристалла», а не «K-рентген»**; на 32.194 кэВ он населён законно, но именем
обещает невозможное. Физика при этом верна: L-край иода 4.56 / цезия 5.01 кэВ,
падающие 32.194 выше их, и L-флуоресценция разрешена.

Числа, подтверждающие, что канал держится целиком L-серией (Σ по строке отклика
на один испущенный фотон):

| плечо | Σ `esc_xray` на 32.194 |
|---|---|
| `direct_peakw0` | 5.654551e-05 |
| `direct_peakw1` | 6.529154e-06 |
| `direct_no_lx` (L-вылет выключен) | **0.000000e+00** |

## 3. Допуск в полуширину и правило бина

**Про подмену смысла — согласны, и это уже заведено у нас отдельной строкой**
(`A306`, заведена по итогам первой выдачи): при включённом допуске «полное
поглощение» в ленте и «канал полного поглощения» перестают быть одним
множеством. Ваша формулировка точнее нашей: следует различать физическое
полное поглощение и попадание в аппаратное окно фотопика, и вторая величина не
должна незаметно занимать место первой — тем более что каскадная поправка
применяется только к каналу `Peak`.

**Оба ваших контрпримера к `BinOf` воспроизводятся арифметически.**

* `E₀ = 661.657`, `E_dep = 650`: `bin = (int)(650/2 + 0.5) = 325`, `peak = 331`;
  условие `bin >= peak` ложно, событие остаётся в бине 325. При этом `InPeak`
  возвращает `true` (недобор 11.657 ≤ 22.039). То есть **счёт считает историю
  пиком, а гистограмма кладёт её в континуум** — правило едино только для тех
  историй, которые уже округлились в последний бин.
* `E₀ = 32.194`, `E_dep = 31.8`, допуск 0: `bin = (int)(31.8/2 + 0.5) = 16 = peak`,
  `InPeak` ложно (недобор 0.394 > 0), и событие принудительно сдвигается в бин
  15, то есть **на 30 кэВ — смещение на 1.8 кэВ вниз**.

Замечание «энергетический бин и физический канал должны быть независимыми
признаками» принимаем как формулировку задачи; у нас это теперь пункт (3) общей
строки `AMBER16`.

## 4. Перенос строки между узлами

Подтверждаем: `Stretch` масштабирует **всю строку** множителем
`E_линии / E_узла`, поэтому особенность, стоящая на фиксированном расстоянии от
линии (escape-пик `E − E_X`), переносится в `E − E_X·(E/E_узла)`, а не в
`E − E_X`. Для наших узлов 636.2533 и 678.7224 и линии 661.657 ваши числа по
комптоновскому краю (472.083 и 480.701 против точного 477.334) воспроизводятся.

Наблюдаемое следствие — размазывание края: у перенесённой строки
(`store_interp`) доля канала `esc_xray`, попавшая в окно 620…640 кэВ, равна
**92.67 %**, у прямого счёта того же узла — **98.11 %** (`direct_peakw1`) и
**97.92 %** (`direct_peakw0`, ваша цифра 97.9 % воспроизведена точно).

Ваш расчёт центра тяжести пикового канала тоже воспроизведён:

| плечо | линия | центр канала `peak` | сдвиг |
|---|---|---|---|
| `store_interp` | 32.194 | **31.634** | −0.560 кэВ |
| `store_interp` | 661.657 | **661.139** | −0.518 кэВ |
| `direct_peakw1` | 32.194 | 32.000 | −0.194 кэВ (дискретизация бина) |
| `direct_peakw1` | 661.657 | 662.000 | +0.343 кэВ (дискретизация бина) |

То есть **сдвиг около полукэВ вносит сама интерполяция**, а не прибор: у
пересчитанного узла его нет. Ваш вывод — «до того как приписывать
низкоэнергетический сдвиг прибору, проверьте вклад матрицы и отображения» —
принят; в первой выдаче (§7.6) весь сдвиг низа был отнесён к калибровке, и это
было сказано слишком уверенно.

## 5. Про «41 %» и про сумму отклика

**Поправка принята.** Правильное сравнение — по абсолютным величинам:

```
C_on  = 0.01655155   (direct_peakw1)
C_off = 0.00932089   (ablation --ablate=scat)
(C_on − C_off) / C_on = 43.69 %
```

В первой выдаче сравнивались доли, нормированные на разные суммы (4.157 п.п. от
10.104 %), и получилось 41 %. Ваше число верное.

**Про сумму отклика — расхождение реальное, и механизм у него назван в коде.**
Измерено (Σ строки на один испущенный фотон, 32.194 кэВ):

| плечо | Σ | отн. к `peakw0` |
|---|---|---|
| `direct_peakw0` | 0.156718 | — |
| `direct_peakw1` | 0.163807 | **+4.524 %** |
| `direct_no_scat` | 0.156722 | +0.003 % |
| на 661.657: `peakw0` → `peakw1` | 0.098727 → 0.098578 | −0.151 % |

Причина не в переклассификации: **вместе с нулевым допуском гасится вся ветвь
однократного рассеяния до кристалла.** Это сделано намеренно и записано в коде:
при нулевом допуске её вклад в пик тождественно нулевой, а всё, что она кладёт
ниже пика, всё равно перезаписывается аналоговым счётом континуума (он
переписывает бины `0…peak−1` целиком), — а стоит ветвь 1.45…1.96× времени узла.
Поэтому `peakw0` и `--ablate=scat` дают почти одно и то же (0.156718 против
0.156722), а весь прирост при `peakw1` — это рассеянные кванты, попавшие в
**бин пика**: в нём канал «неполное поглощение» вырос с 2.135e-04 до 7.633e-03,
то есть на 7.4e-03 при полном приросте суммы 7.1e-03.

⚠ Отсюда важное для чтения первой выдачи: **абляция `--ablate=scat` при
включённом допуске и старая складская матрица (`peakw0`) — это, с точностью до
шума, одно и то же состояние.** Значит «41 % (43.69 %) канала — внешнее
рассеяние» относится к НОВОМУ расчёту; на прежней жёлтой картинке этой добавки
не было вовсе, и переносить долю туда количественно нельзя. Ваша оговорка верна.

⚠ И следствие, которое стоит назвать прямо: **полная эффективность регистрации
в модели зависит от заявленного разрешения прибора** — на 32 кэВ на 4.5 %. Для
площади фотопика это ожидаемо (окно), для суммы по всем бинам — нет.

## 8. Найдено по дороге: лента образа одной линии имеет шесть максимумов

Это не было ни в одном из шести пунктов, но прямо относится к вашему вопросу об
артефактах восстановления.

**Факт.** Образ `Ba-131` состоит из одной линии 30.973 кэВ. Отклик матрицы на
неё занимает **16 бинов и обрывается на 30 кэВ** (приложение Б — весь отклик
целиком). После уширения и подгонки лента этого компонента простирается
**от −5.7 до 909.5 кэВ** и имеет локальные максимумы:

| энергия | величина | доля вершины |
|---|---|---|
| 30.1 кэВ | 956 040.6 | 100 % |
| **159.1** | 44 179.9 | 4.62 % |
| **251.6** | 15 373.3 | 1.61 % |
| **405.1** | 4 192.2 | 0.44 % |
| **530.8** | 8 399.8 | 0.88 % |
| **622.9** | 4 482.5 | 0.47 % |

Это именно те четыре «синих максимума», о которых вы писали. Форма каждого —
нормальный пик: у максимума 159.5 кэВ ширина на полувысоте около 21 кэВ, что
равно ПШПВ прибора в этой точке (6.66 % · √(662·159) = 21.6 кэВ). То есть в
источник свёртки попал вклад, стоящий при 159.5 кэВ, — а в образе компонента
такой энергии нет.

**Что проверено и что исключено:**

* библиотека не менялась разбором — список линий образа до и после разбора
  одинаков (одна линия);
* подпороговый нож ни при чём — при `--floor=0` максимумы остаются (41 219.6
  против 44 041.4 при 160 кэВ);
* это не подложка сплайна: она в ленты компонентов не входит и учитывается
  отдельной кривой; сумма лент плюс континуум даёт модель;
* энергетическая шкала спектра монотонна (0 немонотонных переходов на 8192
  каналах), то есть обращение «энергия → канал» однозначно;
* явление воспроизводится в двух независимых пробах (`FsaComponentDumpProbe` и
  `FsaStackShot`), то есть не является ошибкой одной выписки.

**Механизм не установлен.** Мы не называем его, пока он не измерен: это ровно
тот разряд ошибки, о котором вы предупреждали, и гадать здесь хуже, чем сказать
«не знаем». Явление заведено пунктом (5) внутренней задачи и будет разобрано
отдельно.

## Приложение Г. Участки кода, о которых спрашивали

**Где меняется `lossXray`** (`EfficiencySimulator`, фотопоглощение в кристалле):

```csharp
double xray = this.SampleFluorescence(this.geometry.Crystal, e);   // K ИЛИ L
double casc = this.pendingCascadeKev;                              // второй квант K→L
this.pendingCascadeKev = 0.0;
if (xray > 0.0)
{
    double kx, ky, kz;
    this.Isotropic(out kx, out ky, out kz);
    double electron = this.ElectronLoss(x, y, z, e - xray - casc, depth);
    double markedBefore = this.lossAnnihilation + this.lossXray;
    double gone = this.InCrystal(x, y, z, kx, ky, kz, xray, depth + 1);
    double markedInside = this.lossAnnihilation + this.lossXray - markedBefore;
    this.lossXray += Math.Max(0.0, gone - markedInside);
    // ... то же для каскадного L-кванта `casc`
    return lost + electron + gone + goneC;
}
```

Метка пополняется только **непомеченным остатком** вылета: вложенная рекурсия
свои вылеты уже пометила, и прибавка полного `gone` считала бы их дважды.

**Выбор серии внутри `SampleFluorescence`** (то самое место, где K и L
расходятся, а метка остаётся общей):

```csharp
double omega = f.Omega(this.MeasuredFluorescenceYield);
double u = this.Uniform();
if (u < kFraction * omega)          // K-серия
{
    this.CountKXray++;
    double kev = PickLineAt(this.Uniform(), f.LineKev, f.LineWeight, out line);
    if (this.KLCascade) this.CascadeAfterK(f, f0.Shells[k], line, energyKev);
    return kev;
}
if (!this.LXrayEscape || !f.HasL || f0.Shells[k] == null) return 0.0;   // оже
double[] lFrac = f0.Shells[k].LFractions(energyKev);
double edge = kFraction * omega;
for (int li = 0; li < f.OmegaL.Length && li < lFrac.Length; li++)
{
    if (!(f.OmegaL[li] > 0.0) || f.LineKevL[li] == null
        || energyKev <= f.LEdgeKev[li]) continue;   // подоболочка закрыта
    edge += lFrac[li] * f.OmegaL[li];
    if (u < edge)
    {
        this.CountLXray++;
        return PickLine(this.Uniform(), f.LineKevL[li], f.LineWeightL[li]);
    }
}
return 0.0;                                          // оже-электрон
```

**Где берётся `PeakHalfWidthKev`** — ровно два места. Модель геометрии:

```csharp
public double PeakHalfWidthKev(double energyKev)
{
    if (!(this.FwhmAt662Percent > 0.0) || !(energyKev > 0.0)) return 0.0;
    return 0.5 * this.FwhmAt662Percent / 100.0 * Math.Sqrt(662.0 * energyKev);
}
```

и сборщик матрицы, где решается, брать его или нет:

```csharp
PeakHalfWidthKev = options.PeakToleranceFromGeometry
    ? geometry.PeakHalfWidthKev(energyKev)
    : 0.0
```

Там же гасится ветвь однократного рассеяния (§5):

```csharp
SingleScatter = options.SingleScatter
                && !ResponseMatrix.SingleScatterErased(geometry, options),

public static bool SingleScatterErased(GeometryModel geometry, ResponseMatrixOptions options)
{
    if (geometry == null || options == null || !options.AnalogContinuum) return false;
```
