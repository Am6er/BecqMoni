Сделано как прототип по слову Amber: «Сделай пробную реализацию, ничего не коммитить и не пушить!»;
закоммичено и выпущено тегом 2026.10.26.01 по следующему слову, дословно: «делай коммит всего и

## Постановка и решения Amber

- «когда у нас так сжата ось энергий (0.116 коэфф), как бкмони определяет, какое именно значение отобразить в текущий пиксель?»
- «Нужно сохранять площадь пика. Сумма по пикселю выглядит правильным решением.»
- Вопросник 26.10.2026, дословно: граница группы — «Долями по перекрытию (Recommended)»; панель курсора — «Диапазон и сумма группы (Recommended)»; снимки — «До / после / контроль 1024 (Recommended)».

## Как было

`DrawBarChart`, `ChannelAtPixel`, карта `EnsurePixelChannelMap` брали на столбец ОДИН канал —
`NearestChannel` под левой кромкой. При 0.116 пкс/канал (8.6 канала на столбец) остальные
7–8 каналов не рисовались: высота столбца = один канал, площадь видимого = 0.118 от суммы
отсчётов, хвост спектра — шум одного канала (до единиц на лог-шкале).

## Что сделано

`BecquerelMonitor/EnergySpectrumView.PixelBins.cs` (новый partial):

- канал i занимает [i − ½, i + ½) (как рисует график, `AMBER88`); края столбца [x, x+1) — в
  дробные каналы теми же формулами, что прежняя карта (`EdgeChannel`, `PixelSpan`);
- столбец сжат, если накрывает > 1 канала (допуск 1e-9: ровно 1:1 не сжат) — тогда значение =
  `OverlapSum`, сумма с долями по перекрытию; иначе путь прежний, побитово;
- переведены все потребители: `DrawBarChart` (спектр, фон, континуум), `DrawLineChart`
  (точка на столбец), `DrawPeakBarChart`/`DrawPeakLineChart` (подложка по столбцу + пик по
  своим каналам), `DrawFsaBand`/`DrawFsaCurve` (через карту кадра), `TryFsaPeakTopY`,
  `DrawFsaAnchors`, `PeakTopY`, `ShowCalibrationPeaks`, заливка выделения, подгонка вертикали
  (`CalculateDrawingDataBoundaries`, `ExtendBoundariesWithFsaModel` — окно шириной в
  «каналов на столбец»);
- панель курсора при сжатии: «Канал: a - b», «Энергия: E(a) - E(b)», «Всего импульсов» и
  «Фоновых» — сумма с теми же долями.

## Дефект выпуска 2026.10.26.01: жёлтые линии ПШПВ (26.10.2026)

Amber, консоль, со снимком (`n15-beads-small-denta`, X 0.216, лог): «Баг с отрисовкой FWHM
(жёлтая линия) при масштабировании». Причина: `DrawFWHM` — единственная отрисовка вида,
которую прототип не перевёл; база выделения, вершина `MaxValue` и полувысота в
`EnergyResolutionResult` — отсчёты НА КАНАЛ, а столбцы стали суммами ~4.6 каналов, и
жёлтая вертикаль кончалась в разы ниже нарисованного пика. Прочие отрисовки по значениям
каналов просмотрены поиском (`this.height - …valueRange…`): остальные либо уже переведены,
либо не берут значений спектра (оси, линии интенсивностей библиотеки).

Правка: `CompressionScaleAt(k)` (`EnergySpectrumView.PixelBins.cs`) — «каналов на столбец»
при сжатии, иначе ровно 1; им умножаются база (по каждому каналу), вершина и база под ней,
концы линии полувысоты. Числа панели (ПШПВ, отсчёты) не тронуты — правится только рисунок.

Замер — `CompressedAxisShot --select-kev=a..b` (новый ключ: выделение вместо курсора, печать
верха жёлтой вертикали против верха нарисованного столбца под ней, пкс), `ASN8_Th232_8192`,
сборка выпуска (`1f8fa673`) против правки:

| выделение, шкала | hs 0.216 | hs 0.116 | hs 1.0 | перегруппировка ×2, hs 0.432 |
|---|---|---|---|---|
| 220–260 кэВ, лог | 44 → 0 | 61 → 0 | 0 → 0 | 24 → 0 |
| 220–260 кэВ, лин | 126 → −2 | 143 → −1 | 0 → 0 | 92 → −1 |
| 560–610 кэВ, лог | 44 → 0 | 61 → 0 | 2 → 2 | 23 → 0 |
| 560–610 кэВ, лин | 16 → 0 | 18 → 0 | 1 → 1 | 11 → 0 |

При hs 1.0 кадры обеих сборок побайтно равны (4 из 4). Остаток в 1–2 пкс — вершина
`MaxValue` подогнана параболой (`AMBER231`), а не взята с шумного канала. Снимки —
