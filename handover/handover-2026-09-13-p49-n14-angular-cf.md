## 1. Механизм

### 1.1 Что такое Q_k и как считается

Теорема сложения полиномов Лежандра для W(θ₁₂) = 1 + Σ A_kk·P_k(cos θ₁₂): при осевой симметрии
(член m = 0) вероятность поглотить в пике оба кванта из одной точки —

    ε_пары = ε_p(1)·ε_p(2)·(1 + A₂₂·Q₂(1)·Q₂(2) + A₄₄·Q₄(1)·Q₄(2)),
    Q_k(E) = ∫ ε_p(E,θ)·P_k(cos θ) dΩ / ∫ ε_p(E,θ) dΩ.

θ — угол вылета к оси «точка вылета → центр кристалла» (сфера габарита `sphereZ`, та же, по которой
`OneHistory` наводит конус). Для протяжённой пробы — среднее по точкам розыгрыша. Для ВЫНОСА (партнёр
уносит событие любым заносом) те же моменты берутся по ПОЛНОЙ эффективности — Q_k^T(E); файл несёт
обе пары столбцов.

**Приближения названы** (в шапке `AngularAttenuation`): (а) члены m ≠ 0 у точек вне оси отброшены —
ось на центр кристалла, где они наименьшие; (б) среднее по точкам берётся порознь для двух энергий
(Q_k(1)·Q_k(2) вместо ⟨q_k(r,1)·q_k(r,2)⟩) — связь точек двух квантов уже несёт κ; (в) пара с
ненаблюдаемым промежуточным переходом считается изотропной (`ForPair`) — занижает, не завышает;
(г) ε_T для Q_k^T — взвешенная оценка (занижена по уровню на 12…15 %, `TotalEfficiency` аналоговый),
нужна лишь её угловая форма.

### 1.2 Проба `AngularQkProbe` — без правки `EfficiencyMaker`

`EfficiencyMaker` не тронут (ночной счёт склада идёт из HEAD). Направление история разыгрывает
внутри `OneHistory`, поэтому оно **подсматривается отражением**: симулятор собирается ШТАТНЫМ
`ResponseMatrixBuilder.MakeSimulator` по `Options` лежащей `.rmx` (рецепт склада, допуск пика узла,
зерно узла); точка — `source.NextWeighted`; сохраняется `state` ГСЧ; зовётся тот же `InCone`/`Isotropic`
той же веткой, что в `OneHistory`; состояние возвращается; `OneHistory(E, x, y, z, hist[3], E/2, w)`
разыгрывает ТО ЖЕ направление и даёт пиковый счёт (возврат) и полный (сумма трёх бинов).

⛔ **Положительный контроль на каждой сцене:** узел 0 гонится штатным `Efficiency(E)` с тем же зерном
и тем же n — средний счёт моего обхода обязан совпасть ДО БИТА. Совпал на всех 9 сценах (шесть малой
базы, далёкая точка, два маринелли), в том числе с гистограммой — то есть подсмотр и гистограмма не
сдвигают поток. Второй контроль — далёкая точка (§2.2).

Сетка: 24 узла log-равномерно 30…3000 кэВ, интерполяция линейная по ln E, за краями — крайний узел.
Q_k гладки по E (таблица ниже), 24 узлов достаточно: между соседними узлами Q₂ меняется на < 0.01.
Историй на узел 300 000 (ASN16_lu_side — 1 500 000): шум Q₂ ≤ 0.0075 у всех (§2.1), у точечных
0.0002…0.002. Цена — 7…11 с на сцену (36 с у ASN16) на 12 потоках.

### 1.3 Сайдкар `<ключ>.qk` — где и почему

Текст UTF-8, ~2.5 КБ: шапка `format=1`, `scene=`, `geomsha=` (SHA-256 `GeometryWriter.Render(геометрия)`),
`matrix=` (клеймо `.rmx`, справочно), `histories=`, `seed=`, `built=`; строки
`E Q2 Q4 dQ2 dQ4 eps_peak Q2T Q4T dQ2T dQ4T eps_total`. Формат `.rmx` не тронут.

Решения: (1) **в git, рядом с `.in`** — файл малый, воспроизводимый за секунды, и сцена без `.qk` видна
в `git status`; (2) ключ соответствия — **отпечаток геометрии, не клеймо матрицы**: Q_k — свойство
формы сцены, смена физики склада меняет его на доли процента, а клеймо меняется каждым единым счётом
(ночью `phys=17 → 18`) — привязка к клейму обесценила бы все сайдкары к утру; (3) в оснастку они едут
вместе с матрицами в `config\device\response` (`appwd_plan.ps1`, источник — `<склад>\*.qk`), и разбор
ищет их **там же, где матрицу** (`ResponseMatrixStore.Directory`), перебирая `*.qk` по отпечатку —
имя файла склада приложения — guid кривой, а таблица считается на сцену; (4) для приложения Amber:
положить `<что угодно>.qk` в `config\device\response` рядом с `.rmx` — найдётся по отпечатку.

### 1.4 Ядерная половина — как пара получает A_kk

`AngularCorrelation.ForPair(ключ, E₁, E₂)`: `CascadeAtomicData.Of(ключ)` → у обеих линий строка
`GammaIntensity` (сильнейшая в 0.3 кэВ) с `Transition` → одна ветвь (Z, A дочернего; линии разных
ветвей — Eu-152 Sm/Gd — изотропны) → `SchemeOf(Z, A).FindSeq(from, to)` по номерам уровней (не по
энергии — самозванец `W26` не грозит) → `Cascade(a, b)` либо `(b, a)`; смежность концов обязательна.
Кэш на экземпляре сумматора по (ключ, E_min, E_max).

Попутно: коды мультипольности **8 и 9 (E4, M4)** прежде молча давали изотропию — добавлены
(`OrderOf`); у Bi-207 1063.7 (13/2⁺ → 5/2⁻, M4) — сильнейший каскад нуклида. `AngularProbe` не тронут,
`check_all` зелёный.

### 2.3 Контроль «4π → 0» — ⚠ ПОСЫЛКА ПОСТАНОВКИ НЕВЕРНА для маринелли и поля

Посчитано (`qk_marinelli.log`): маринелли 1 л на Ø63 (`G1S_mar1l_oisn06_057_p16`) — Q₂ = 0.60…0.75;
маринелли 0.5 л на кубике 10 мм (`RC103_marinelli05_kcl`) — Q₂ = 0.93…0.98. Не ноль, и это верно:
Q_k = 0 требует, чтобы из ТОЧКИ ВЫЛЕТА кристалл был виден во все стороны (ε(θ) = const) — это
источник ВНУТРИ кристалла или колодец. Из точки маринелли кристалл виден в конусе, и чем он меньше,
тем ближе к «далёкой точке» (RC103 → 0.95). Полевая сцена — каждая точка далеко → Q_k → 1, корреляция
входит целиком. Предел «→ 0» получается только у усреднения момента m = 0 по точкам с ФИКСИРОВАННОЙ
осью — там Q_k гасится геометрически, а члены m ≠ 0, несущие физику, выброшены; ось на центр
кристалла из каждой точки этого артефакта не имеет. Предел «→ 0» показан аналитически: точка на торце
(d = 0) у чёрного диска даёт Q₂ = Q₄ = 0; перенос на `AS80_point0` даёт 0.45/−0.06 при 60 кэВ, потому
что окно и оправа гасят скользящие направления — ε(θ) не ступенька.
