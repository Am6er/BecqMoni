## 4. Правка (`tools/effmaker/probes/FsaReportViewProbe.cs`, +163/−7)

1. **Каталог снимков — до всего.** В `Main` после разбора ключей `Directory.CreateDirectory(outDir)`; не
   создался — «⛔ МЕРИТЬ НЕЧЕМ: каталог снимков --out=… не создаётся: …», код 2 (как у гейта геометрии `A277`).
2. **Ожидание строк привязки — ПО РЕЗУЛЬТАТУ сцены, а не числом.** Новая `AnchorMarks(marks, scene, count,
   gain, zero)`: без матрицы не добавляет ничего; при матрице и `ScaleAnchorsUsed == 0` — одну строку
   «`FSAReport_AnchorRow` | `FSAReport_AnchorNone`»; при опорах — три (`AnchorRow`, `AnchorGainRow`,
   `AnchorZeroRow`) с числами, записанными рукой по сцене. Подписи — из `.resx` окна тем же
   `ComponentResourceManager`, как у остальных пометок. Метка цвета `Plain` — чёрный (строка числа, `A281`);
   `BlockProblems` её понимает.
3. **Три сцены матрицы в разделе 6** (обе культуры): без матрицы (5 пометок, строки опор нет — теперь это
   утверждается явно), с матрицей без опор («раздутый» и «всё учтено» — четвёртая строка «none»), и НОВАЯ
   «шкала привязана»: `ScaleAnchorsUsed = 2, Gain = 1.0123, AnchorOffsetKev = −0.5`, три кандидата (два
   принятых, один отвергнутый) → ждём «2», «+1.23», «-0.50» и подсказку из заголовка и трёх строк
   (`+`, `+`, `-`).
4. **Положительные контроли** (все печатают «отказал, как и должен»): блок с матрицей БЕЗ строки опор —
   ровно то, что проба принимала до 18.09; ожидание «опор нет» на привязанной сцене; потерянная строка
   усиления; «1» опора вместо двух.
5. **Раздел 5:** `ExpectedKinds` считает строки опор по результату (`ResponseMatrixUsed` → +1, при опорах +3);
   сцена всех родов `SceneAllKinds` получает живую матрицу с двумя опорами, чтобы ветка мерилась
   (таблица 40 → 43 строки: «черта, заголовок и 7 пометки блока» вместо 4). Прежний контроль «потерянная
   строка блока» действует и на неё.

Имён нуклидов в правке нет (компоненты кандидатов — `L1`/`L2`/`L3`).
