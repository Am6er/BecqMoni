## Что сделано

### 1. Новый помощник `BecquerelMonitor/LayoutFile.cs` (статический класс)

Один путь записи и один путь чтения на все места; `MainForm` — тонкие вызовы.

**Запись `LayoutFile.Save(DockPanel, string)` → `Write(string, Action<Stream>)`:**

1. раскладка сериализуется В ПАМЯТЬ — `panel.SaveAsXml(MemoryStream, Encoding.Unicode)`;
   отказ сериализации файла не касается вовсе;
2. байты → `ExpertMode.xml.tmp` рядом, `Flush(true)`;
3. `File.Replace(tmp, target, target + ".bak", true)` — подмена одним вызовом ОС
   (`ReplaceFile`), прежняя удачная копия остаётся `.bak`; целевого файла ещё
   нет — `File.Move`.

Отказ любого шага убирает `.tmp` и бросает — читатели отказа прежние (~~`A13`~~:
окно из меню, записка при закрытии). Сериализатор, не давший ни байта, —
отказ, а не пустой файл (ровно тот файл, от которого чинимся). Каталог при
отсутствии создаётся.

⚠ **Кодировка и перегрузка — измерено пробой, а не выведено.** Прежний
`SaveAsXml(имя)` пишет `Encoding.Unicode` (IL: `call Encoding.get_Unicode`).
Первая редакция брала перегрузку `SaveAsXml(Stream, Encoding, upstream: true)`
(«не закрывать поток») — и файл вышел на 82 байта (41 знак UTF-16) короче
библиотечного: `upstream` значит «часть большого документа», и объявление
`<?xml version="1.0" encoding="utf-16"?>` не пишется. Взята двухаргументная
перегрузка (`upstream: false`): она закрывает поток, но `MemoryStream.ToArray()`
работает и после закрытия. Итог — файл БАЙТ В БАЙТ тот же, что писала
библиотека (плечо 3.1 пробы).

**Чтение `LayoutFile.Load(DockPanel, string, DeserializeDockContent)` → `Read(string, Action<string>)`:**

файла нет → `Absent` (не отказ, как и было) · прочитан → `Loaded` · отказ разбора
→ сломанный переименовывается в `ExpertMode.xml.broken-<yyyyMMdd-HHmmss>` (улика
остаётся, следующий запуск на неё не наткнётся) → читается `.bak` →
`LoadedFromBackup`, копия возвращается на место основного файла (чтобы запуск,
оборванный до закрытия, не пришёл к умолчанию) → негоден и он / его нет →
`Default`. Сам `Read` не бросает; итог — `LoadOutcome` (что читалось, причины
через `AppUi.Reason`, куда отложен), слово за экраном собирает `Describe`.

⚠ **Почему `.bak` можно поднимать после отказа на той же панели** — измерено по
IL `Persistor.LoadFromXml`: сперва весь XML разбирается в структуры
(`LoadContents` → `LoadPanes` → `LoadDockWindows` → `LoadFloatWindows` →
`XmlReader.Close`), и только затем `DockPanel.SuspendLayout` и построение.
Отказ разбора панели не касается; сторож библиотеки «панель уже заполнена» на
втором чтении не срабатывает (плечо 3.3: после обрезанного файла годный
читается). Поток файла открывается своим `FileStream` (`FileShare.Read`) в
`using`, чтобы после отказа файл можно было переименовать.
