## 1. Кто читает и пишет поле (опись до правки)

* `DeviceConfigInfo.CrystalMaterialName` — поле; пишет только `DeviceConfigForm.SaveFormContents`
  (`CrystalMaterialFromForm`), показывает `LoadCrystalMaterial` (зовёт `LoadFormContents`).
* Читатели — запасной источник при спектре без геометрии, порядок не менялся:
  `DCFwhmCalibrationView.ScintillatorOf` (кривая света вкладки FWHM), `FsaSampleLibrary` / `FsaSampleSpec`
  (`OfSpectrum`, `CrystalFractionsOf`), `FsaAnalysisSession` (снимок прибора, клеймо).
* Загрузку формы `LoadFormContents` зовут: выбор строки списка, «Новый», «Дубль», освежение после записи мимо
  формы (`UpdateModifiedConfigFile`), перестройка списка после «Сохранить»/«Нет»; отражением — пробы
  `TractCurvatureFieldProbe`, `CultureProbeO14`, `DeviceCalibrationTabProbeA280` (безоконный путь, `S100`).
* Геометрия кривой ложится в прибор в ОДНОМ месте — `EfficiencyMakerForm.SaveIntoConfig`
  (`boundConfig.Geometry = geometryPanel.Model.Clone()`), затем событие `SavedIntoConfig`, на которое
  подписана форма прибора (`OpenEfficiencyMaker`). Других присваиваний `.Geometry` в приложении нет
  («Дублировать» копирует кривую целиком — кристалл тот же, вопроса не требует).
* `SetActiveDeviceConfigDirty` при `contentsLoading` ничего не делает — поэтому подстановка идёт ПОСЛЕ
  снятия флага загрузки.

## 2. Что сделано

**Загрузка прибора в окно** (`DeviceConfigForm.OfferCrystalFromGeometry`, конец `LoadFormContents`). Поле
прибора пустое, а у кривых `EfficiencyConfigs` есть геометрия с названным кристаллом:
* кристалл один (по имени без учёта регистра) — окно ставит его в «Вещество кристалла» и помечает прибор
  изменённым; в файл значение уходит только «Сохранить» (или «Да» на «Сохранить изменения?»);
* кристаллы разные — **решение полосы: спросить окном выбора**, как велит решение Amber «тоже спрашиваем»:
  по строке на кристалл (имя — как в списке, в скобках — кривые с ним), кнопки «Взять выбранный» /
  «Оставить не заданным». Вопрос ставится в очередь окна (`BeginInvoke`), а не посреди загрузки — загрузку
  зовёт и событие `Load`, когда окно ещё не на экране; к моменту вопроса прибор перечитывается по Guid;
* геометрии с кристаллом нет — поле не трогается;
* только у прибора, который правит окно (`activeDeviceConfig`): проба, зовущая загрузку отражением на чужом
  объекте, поля не получает.

Сопоставление имени со строкой списка — общим `CrystalComboItem` (вынесен из `LoadCrystalMaterial`, поведение
то же: первая строка-кристалл с тем же именем; нет — вещество с этим именем из библиотеки; нет и его — само
имя строкой, чтобы сохранение его не потеряло).

**«Нет» держится до закрытия окна** (`crystalDefaultDeclined`). Ответ «Нет» на «Сохранить изменения?»
перечитывает прибор из файла; без памяти отказа загрузка снова подставила бы кристалл и пометила прибор
изменённым, и вопрос вставал бы на каждой смене вкладки. Теперь «Нет» при подставленном окном кристалле и
«Оставить не заданным» запоминаются для этого прибора, пока окно открыто; открытое заново предлагает снова.

**Сохранение геометрии** (`OfferCrystalOfSavedGeometry` в обработчике `SavedIntoConfig`). Когда «Сохранить
кривую» конструктора приносит в кривую НОВЫЙ кристалл X (кривая была без геометрии или вещество кристалла
сменилось — `EfficiencyMakerForm.SavedCrystalIsNew`):
* поле прибора пустое — X ставится без вопроса;
* поле Y непустое и не X — вопрос над окном конструктора «У геометрии кристалл X, у прибора — Y. Сделать X
  веществом прибора?»; «Да» ставит X и помечает прибор изменённым, «Нет» поле не меняет;
* поле уже X — ничего.
Пересохранение той же геометрии (кривая, размеры) вопроса не повторяет — это «изменённая геометрия» без
другого кристалла; спрашивать снова после «Нет» на тот же кристалл было бы назойливо.

**Без окон** (`S100`, память `headless-run-blocks-on-dialog`): оба вопроса гейтятся `AppUi.HasWindows` и
видимостью окна; вопрос «да/нет» идёт дверью `AppUi.AskYesNo` (шов стенда `AppUi.Probe` его видит), окно
выбора при шве стенда не поднимается — поле остаётся пустым. `check_headless.py` — «ЧИСТО».

**Строки** — в `DeviceConfigForm.resx` / `.ru.resx` (шесть ключей `crystalFromGeometry*`), английский
первичен; разбор `string.Format` — `InvariantCulture`.

**Проба** `tools/effmaker/probes/CrystalDefaultProbeA285.cs` — девять плеч без окон: разбор кристаллов кривых;
загрузка с одним кристаллом (показ, «изменён», поле конфигурации до записи пустое, запись кладёт имя);
положительный контроль без геометрии; заданное поле; разные кристаллы без окон; чужой объект; память «Нет»
(с контролем); сохранённая геометрия при пустом/другом/том же поле; признак нового кристалла у конструктора
(без геометрии — да, пересохранение — нет, смена вещества — да).

## 4. Следствия и находки

* **Следствие решения Amber, не дефект:** прибор с геометрией и пустым полем при выборе в окне сразу
  «изменён» — первая же смена вкладки или закрытие окна спрашивают «Сохранить?». Так и задумано
  («помечает прибор изменённым»); «Нет» больше не повторяется (см. §2).
* На снимке `tw1113` ДО правки красны две пробы (A/B: вывод совпадает с `wt_base`, кроме пути склада):
  `CurveGenerationProbe` — «РАСХОЖДЕНИЙ: 6» (ждёт сообщений поколения 16 при нынешней физике), и
  `FsaCrystalMixFallbackProbe` — «НЕ СОШЛОСЬ: 8». Не мои файлы и не моя область; в `check_all` их не зовёт ни
  один сторож. Переданы распорядителю отчётом.
* Экранная проверка шла параллельно с полосой `a284` на той же машине: её приложение поднималось поверх
  моего, и один ввод полосы `a285` (щелчок по графику и набор имени кривой) ушёл в её окно. Дальше управление
  шло сообщениями окнам своего процесса (WM_SETTEXT / BM_CLICK / WM_COMMAND) с проверкой переднего окна по
  PID. Урок для распорядителя — экранные полосы на одной машине разводить по времени.
