## Находки и что сделано

### Окна, ресурсы, тесты (полоса окон)

- **Консоль платы** слала `-rst`/`-sto`/`-sta`/`-cal …` одним Enter, в том числе в идущее измерение;

  значений), — через вопрос с «Нет» по умолчанию; «Только наблюдение» запрещает и в TCP.
- Один счётчик поколений на три фоновые операции страницы — кнопки оставались серыми; у каждой свой.
- Уровень gzip и поздние ответы переезжали к другой конфигурации; сброс при загрузке страницы,
  ответы чужой конфигурации отбрасываются, вопрос называет плату.
- Отказ сохранения давал два окна подряд — `DeviceSaveRefusedException`, форма ставит
  `saveRefusalReported`.
- «Прочитать из прибора» (TCP) брал адрес из сохранённого профиля, а не из полей страницы; результат
  пропадал при возврате к тому же профилю (сравнение ссылкой клона → по Guid).
- Окно журнала закрывалось вместе с окном настроек — теперь без владельца, одно на программу.
- Окна вывода росли без предела — 2000 строк / 200 КБ; статус «плата не найдена» обрезался —
  многоточие и подсказка.
- Подсказки — `AppUi.WrapTip`, `ToolTip(components)`.
- Перевод: «вкладка «Калибровка энергии»», «Показать журнал», «Авторизация» без «(прокси)» (уходит

### REST (полоса REST)

- **Набор с лимитом платы всегда кончался аварией застоя:** уставка ставилась в
  `board + limit + 2·период + 5`, плата вставала на `limit`, документ до уставки не доходил — окно
  «плата встала», без автосохранения и звука. Теперь уставка `board + limit`, по достижении лимита
  застой не объявляется, конец отдаёт `MeasurementController.OnTimer`.
- **«Продолжить» подменяло спектр документа чужим набором** (плату сбросили, она набрала больше) —
  теперь каналы платы, свёрнутые до N документа, сверяются поканально.
- Профиль с N > 8192 или N, не делящим 8192, — отказ до любой команды плате (было: 16384 → плата
  считала дальше; 3000 → верхние каналы молча терялись).
- Разбор JSON был квадратичен (`Substring` остатка на каждом значении) — без копий; предел глубины
  вложенности 64 (иначе `StackOverflowException` роняет процесс).
- «Отключиться» держало поток окон до 9–18 с — отсоединение без ожидания; `GET /api/device`
  на «Старте» — за окном ожидания.
- `Expect: 100-continue` выключен на POST; `nan` в `time`/`lost` — ошибка разбора; «только
  наблюдение» отказывает на «Старте», если плата позади документа; «Стоп» присоединённого набора
  говорит, что плата считает дальше; окна при закрытии программы не поднимаются.
- Все тексты ошибок обмена, причин сброса, калибровки, сжатия и состояний — ресурсами; ветвление по
  тексту `"calib_set is false"` → код причины.

### TCP и встройка (полоса TCP)

- **Сброс платы извне не распознавался, документ молча затирался** (минута набора вместо десяти
  часов, обрезок на диск при автосохранении). Сеанс сверяет каждый снимок с последним отданным
  (время, сумма, каналы); свой `-rst` распознаётся по отметке; чужой — остановка и сообщение.
- Молчащий мост на пробе давал слепой `-sta` в новый документ; одна выборка считалась «плата
  считает», и «Продолжить» не слало `-sta`. Теперь «считает» — только по росту времени, «стоит» —
  ≥ 1.5 с без изменения, иначе вопрос (без окон — отказ).
- «Стоп» без ответа на `-sto` при живом сокете говорил «Остановлено» — повтор по новому
  подключению или отложенный стоп с сообщением; 10 с без полного цикла — потеря связи.
- Вопрос «Старта» не знал документа (спектр из файла затирался) — передаются время и счёт документа.
- Присоединение раздувало порог времени, «Очистить» на чужом наборе слало `-rst` без вопроса — вопрос
  и возврат порога.
- `-inf`/`-cal` на «Старте» — за окном ожидания (было до 4 с замирания); свой `try/catch` у TCP-Пуска
  (было чужое «Bluetooth не поддержан»); свёртка каналов на потоке окон; окна при закрытии программы
  не поднимаются; тексты связи — ресурсами (`AtomSpectraTcpLinkException`).

## Остаток — строка `A340`

- TCP-«Стоп» при потерянной связи держит поток окон до ~3 с (до 1 с ответа `-sto` + до 1.9 с
  `WaitExit`); за окно ожидания не убран — из `OnTimer` (стоп по уставке) грозит повторным входом.
- Сторож сброса TCP: счётчик канала 27-битный; канал выше 134 М отсчётов перевалит маску и будет
  принят за сброс (измерение остановится с сообщением).
- Проверка всех исправлений на живой плате — автору.
- Решение Amber «Оставить как у автора» (калибровка) — не остаток, а решение; не переоткрывать.
