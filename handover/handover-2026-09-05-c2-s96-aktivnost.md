## 2. Формула: число к числу

Сцена: 4096 каналов, 1 кэВ = 1 канал, гауссов пик на 662 кэВ, выделение
622–702 кан., фон вдвое дольше измерения.

```
N(gross) = 1 218 490 ; N(фон) = 24 300 ; t = 1000 с ; t(фон) = 2000 с
N(net)   = 1 206 340 ; ε(662) = 1.000e-3 ; I = 85.1 %
приложение  A = 1.41755e+06 Бк
вручную     A = (N/t)·100/(ε·I) = 1.41755e+06 Бк
расхождение −1.64e−16
K = 1175.09 (ждали 100/(ε·I) = 1175.09) ; dK = 58.7544 (δ = 5 %)
```

⛔ Меряет НЕ копия формулы: `EnergySpectrumView` поднимается **без окна**
(`FormatterServices.GetUninitializedObject`), поля ставятся отражением, зовётся
приватный `EnsureSelectionAnalytics` — та самая ветка, что рисует панель.

⚠ **Заголовок строки `S96` записывает формулу НЕВЕРНО.** В строке стоит
`A = N·100/(ε(E)·I%)`, без времени; на деле `ROIAriphmetics.CalculateActivity`
считает от **cps**, то есть `A = (N/t)·100/(ε·I%)`. На этой сцене разница —
ровно множитель t = 1000: 1.42e+09 против 1.42e+06 Бк. На выводы `S96` это не
влияет (подмена подписи меняет только 1/I%), но запись в строке чинить надо.

## 5. Положительный контроль

⛔ Проверка, которая проходит всегда, ничего не меряет. Двенадцать заведомо
плохих входов и один заведомо хороший — все через настоящую ветку вида.

| плохой вход | что случилось | видно человеку |
|---|---|---|
| выход `I = 0` | ветка не начата | нет |
| выход `I < 0` | ветка не начата | нет |
| кривой эффективности нет | ветка не начата | нет |
| **энергия ниже первой точки кривой** | **⚠ ветка НАЧАТА, числа нет, причина НЕ НАЗВАНА** | **нет** |
| **энергия выше последней точки** | **⚠ то же** | **нет** |
| пик без подписи | ветка не начата | нет |
| два пика в выделении | ветка не начата | нет |
| подпись — рентген элемента | ОТКАЗ вслух | да |
| выход ниже порога 1 % | ОТКАЗ вслух | да |
| фонового спектра нет | ветка не начата | нет |
| спектр снят с показа | ветка не начата | нет |
| режим пиков `Invisible` | ветка не начата | нет |
| **всё на месте (отрицательный контроль)** | **число со спором, 1.41755e+06 Бк** | **да** |

**Молчаливых ЧИСЕЛ — ноль.** Ни на одном плохом входе приложение не показало
активность. Это главный результат проверки: тот класс дефекта, ради которого
заведена `S96`, на этих входах не воспроизводится.

⛔ **Молчаливых ОТСУТСТВИЙ — два, и это находка.** Энергия за краем кривой:
подпись поставлена (значит, и кривая есть, и пик один), но `TryForLine`
возвращает голый `false`, отказ не заводится, и на панели не появляется ничего —
состояние, неотличимое от «кривой нет вовсе». Рядом, на пути ЗОНЫ,
`BecquerelCoefficient.Resolve` эту же беду называет отдельной причиной
(`BqCoeffOutOfRange`, с энергией и границами кривой). Одна формула, два пути,
и говорит только один.

⚠ Признак «видно человеку» считается по правилу самой отрисовки
(`activityLabelShown = подпись непуста И (число > 0 ИЛИ есть отказ)`), а не по
догадке пробы.

## 6. Спор соседей опирается на линии, по которым сам же отказывает

Найдено при разборе CSV. `ScanActivityRivals` считает соперником ЛЮБУЮ видимую
линию набора с выходом > 0 — включая рентген элемента и линии с выходом ниже
порога, по которым приложение активность ПОКАЗЫВАТЬ ОТКАЗЫВАЕТСЯ. Такая линия не
может дать другого числа, а множитель по ней считается — и у рентгена он вообще
бессмыслен: `Intencity` у него значит долю внутри K-серии, а не выход на распад.

Мерено по 628 пикам с показанной активностью:

* **16** пиков из 134 «со спором» имеют ТОЛЬКО отказные соперники: предупреждение
  висит там, где неверного числа быть не может;
* на **8** пиках показанный множитель ЗАВЫШЕН; худший —
  `AS80_Cs137_0cm` @ 130.554 кэВ, подпись «Ac-228»: панель говорит «до ×2688.89»,
  а по настоящим соперникам ×11.79, то есть **завышение в 228 раз**.

Правка не сделана нарочно: у неё две постановки с разной ценой (исключить такие
линии из спора совсем — теряется предупреждение «подпись может быть рентгеном»;
считать их соперниками, но не пускать в множитель — остаётся «1 соперник, до
×1.0»), и выбор между ними — решение Amber, а не догадка полосы.

5. `S96` ссылается на `PeakDetector.cs:136` как на вызов `MatchNuclide` — верно;

## 8. Что осталось открытым

* мелочь строки: формула `S96` без времени (см. §7.1);
* молчаливое отсутствие при энергии за краем кривой (§5) — нужна СВОЯ строка
  ресурса, `BqCoeffOutOfRange` не годится дословно: она кончается словами «Взято
  сохранённое значение», а на пути выделения сохранённого значения нет вовсе;
* спор по отказным линиям (§6) — ждёт решения Amber о постановке;
* окно спора (0.5 ПШПВ) уже поймало 118 пиков корпуса, но у **100** из 494 голых
  чисел есть линия-нуклид в полосе 0.5…1.0 ПШПВ — краем в тот же пик, спутать
  правдоподобно, худшее отношение выходов там те же 58.5×. Порог окна — тоже
  решение, а не догадка.
