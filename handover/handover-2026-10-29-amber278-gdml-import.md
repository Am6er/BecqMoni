«Этот формат» — GDML: перед этим Amber дала ссылку на папку геометрии
<https://github.com/VibeEngineering-LLC/geant4-detector-models/tree/main/detectors/Atom-GS2020-PRO-MAX/geometry> и
спросила, родной ли это формат Geant4. Да: GDML (Geometry Description Markup Language) — XML-формат файла геометрии,
сделан в CERN для Geant4; читается и пишется штатным `G4GDMLParser` (модуль `persistency/gdml`, сборка с
`GEANT4_USE_GDML=ON` и Xerces-C). Приложение Geant4 этого набора (`geant4/run_marinelli/main.cc`) геометрию в коде не
строит, а читает GDML по переменной `GS2020_GDML`, кристалл ищет по имени тома `LV_NaI_crystal`.

Ссылки задачи:

* GDML набора GS2020 — <https://github.com/VibeEngineering-LLC/geant4-detector-models/tree/main/detectors/Atom-GS2020-PRO-MAX/geometry>
* cadmesh — <https://github.com/christopherpoole/cadmesh>: библиотека C++ для Geant4, грузит сетки CAD (STL, OBJ, PLY)
  телами Geant4; GDML сама не читает. По решению Amber — только справка (см. ниже).

Разобрано навыком аналитика (правило 4 `CLAUDE.md`) до записи строки. Задача записана, не начата.

## Что есть в дереве (29.10.2026)

* **GDML в приложении нет нигде** — ни читателя, ни упоминания в коде. Единственный разбор GDML в дереве —
  питоновский `handover/p338-amber234/gdml_summary.py` (П338, `AMBER234`): им геометрия GS2020 переписывалась в сцены
  `.in` руками.
* **Импорт редактора** — `EfficiencyMakerForm.ImportGeometryClick` (`EfficiencyMakerForm.cs:547`), кнопка «Импорт из
  LSRM…» (ресурс `EfficiencyTabImport`). Различает расширение: `.in` — геометрия в поля, `.txt`/`.efa`/`.efr` — кривая
  окна (`AMBER226`). Фильтр — `EfficiencyMakerLsrmImportFilter` (`:554–558`). ⚠ Всё прочее («Все файлы») сейчас
  читается как `.in`, то есть выбранный так `.gdml` был бы прочитан не тем читателем.
* **Модель геометрии параметрическая** (`EfficiencyMaker/GeometryModel.cs`): кристалл — цилиндр или параллелепипед
  (`CrystalShape`), слои отражателя, зазора, корпуса, оправы — толщинами; проба — цилиндр, Маринелли, коробка
  (`GeometrySourceType`). Произвольных тел, булевых операций и сеток модель не выражает. Значит, импортированный GDML
  в эту модель не ложится, и ни поля, ни расчёт из него сейчас не строятся. Это и есть часть «остальное обсудим позже».
* **Область 2** — `GeometrySketch` в режиме `Detector` (`GeometryEditorPanel.cs:430`, `AddSketch` `:873`): осевой
  разрез с размерными стрелками; у вкладки «Источник» — свой чертёж (`:905`).

**GS2020 (`GS2020_marinelli_th232.gdml`, разбор `gdml_summary.py`):** 50 томов без мира —

* 7 `genericPolycone` (тела вращения, точки r–z): корпуса `LV_Al_housing_1/2`, отражатель `LV_Reflector` (MgO 1.8),
  кристалл `LV_NaI_crystal` (r 25.4, z −17.25…33.55), окно `LV_Silica_window`, два эпоксидных уплотнения;
* 2 `polycone`: сосуд `LV_VesselWall` (PP 0.905) и проба `LV_SourceMatrix` вложенным томом;
* 41 `tessellated` (сетки STL из Blender): оболочка `LV_Shell_1_00` (Al, 30.9 см³), дно `LV_Component301_1_34`
  (Al, 19.3 см³), кольцо прижима (Al, 5.8 см³), пена (5.6 см³), две платы FR4 (4.3 и 3.8 см³), 8 корпусов SiPM
  (Si, по 0.11 см³), пины Cu, пайка Sn, винты из нержавейки — ~25 томов объёмом меньше 0.01 см³;
* `box` 500 мм — мир.

Вещества: 7 своих (`MgO_powder`, `Fused_silica`, `Epoxy`, `Epoxy_crumb`, `Vessel_PP`, `FR4`, `PE_foam`) с долями,
и имена базы NIST Geant4 — `G4_Al`, `G4_SODIUM_IODIDE`, `G4_Si`, `G4_Cu`, `G4_Sn`, `G4_STAINLESS-STEEL`, `G4_AIR`;
свои вещества тоже ссылаются на `G4_*` (`G4_Mg`, `G4_O`, `G4_C`, `G4_H`, `G4_POLYPROPYLENE`, `G4_SILICON_DIOXIDE`,
`G4_POLYETHYLENE`). ⛔ **Состава и плотности веществ `G4_*` в файле НЕТ** — Geant4 берёт их из своей таблицы
(`G4NistMaterialBuilder`). Сводка «с хим. составом» поэтому требует своей таблицы соответствия «имя `G4_*` → состав,
плотность». Простые элементы `G4_<символ>` тривиальны; соединения — из засева NIST нашей библиотеки веществ
(`GeometryMaterialSeed`, имена там другие — сопоставление проверить построчно).

**RC-103 / RC-110:** 19 / 18 томов, все `box`, плюс 2 / 3 `subtraction` (булево вычитание); 11 / 9 своих веществ с
долями по элементам `G4_*`; кристалл `G4_CESIUM_IODIDE`.

Итого читатель обязан знать: `box`, `subtraction`, `polycone`, `genericPolycone`, `tessellated`, позиции из
`define`, единицы `lunit`/`aunit`/`unit`, вложенные тома (`physvol` → `volumeref`), свои вещества с `fraction`/`D`.
Файлы GS2020 по 11.8 МБ (~100 тыс. треугольников) — читать потоком (`XmlReader`), не деревом целиком.

## Сделать

1. Читатель GDML (новый класс рядом с `LsrmEfficiencyFile`): тела и вещества из списка выше; незнакомое тело или
   вещество без состава — строкой сводки с названием («не поддержано: `<тег>`», «состав `G4_…` неизвестен»), без
   молчаливой подмены и без падения.
2. Таблица «имя `G4_*` → состав, плотность» — на все имена восьми файлов набора, не на один GS2020.
3. Кнопка «Импорт из LSRM…» → «Импорт…» (`EfficiencyTabImport`, en + ru), фильтр диалога — `.gdml` вместе с `.in`,
   `.txt`, `.efa`, `.efr`; ветвление `ImportGeometryClick` по расширению.
4. После импорта на вкладке «Детектор»: поля области 1 (выбор формы, толщины, вещества слоёв) убираются, на их месте —
   текстовое поле только для чтения со сводкой («TextView» в словах Amber; в WinForms — многострочный `TextBox`
   `ReadOnly`). Строки сводки — крупные тома (имя, вещество, состав по элементам, габарит, объём, масса), затем
   «прочее» по веществам. Числа — инвариантной культурой с точкой, без группировки разрядов.
5. Область 2 — два чертежа: разрез плоскостью через ось и поперечное сечение; тела залиты цветом вещества,
   сетки STL — линией пересечения треугольников с плоскостью; кадр — по габариту тел без мира.
6. Приёмка — все восемь GDML набора: сводка сходится с `gdml_summary.py` по томам, объёмам и веществам; окно экраном
   ru/en на копии конфигурации (снимки в git не идут); `python tools/check_all.py` — код 0.

## Не решено — «остальное обсудим позже» (слова Amber)

* Что делают вкладки «Источник» и «Расчёт из геометрии» при импортированном GDML (в файлах GS2020 проба и сосуд
  уже внутри, а параметрическая модель их не выражает).
* Сохранение: «Сохранить» / «Готовый детектор» / конфигурация прибора для геометрии из GDML.
* Расчёт кривой и матрицы отклика по такой геометрии — перенос частиц у нас знает только параметрические тела.
* Детали чертежа, которые станут видны на реализации: на какой высоте брать поперечное сечение (через кристалл или
  через плату SiPM) и какая ось — ось прибора (`z` мира у GS2020; у RC-103/110 проверить); порог «крупного тома».
