## 1. Мерка: синтетический спектр линии (`DoseGridProbe`)

Спектр линии E строится из ТОЙ ЖЕ матрицы, по которой считает доза: N квантов/с дают `N·T·строка(E)`
отсчётов, бин `b` строки — отрезок `[(b−½)·шаг, (b+½)·шаг)` с равномерной плотностью, раскиданный по
каналам настоящего спектра корпуса (номер канала — центр, `AMBER73`), без разрешения и с гауссом (FWHM на
662 из `manifest.csv`, ∝ √E). Ответ руками — `Ḣ = N·G·Ḣ*(10)/φ̇ (E_линии)`. Путь «≈» — только пик площади
`N·T·ε_пик(E)` (континуум путь «≈» заведомо принимает за кванты, и доля представительной энергии видна
только без него). Сцены: `AS80_point0` (8192 кан., шкала −5…2829), `G1S_point5` (1024, −11…3023),
`RC103_point0` (1024, 2…2837), `ASN16_point10_house` (8192, −7…3343). Линии: 59.54, 88.03, 122.06, 356.01,

### 2.2 Лечение — и почему не «центр тяжести отсчётов» как есть

Предложенное ревизией «центр тяжести отсчётов» в чистом виде неверно для пути с матрицей: у линии в своём
диапазоне лежит не только пик, но и её собственный комптон/вылеты, и центр тяжести ниже линии. Поэтому:

1. цель — центр тяжести ПРИПИСАННЫХ отсчётов: первый момент отсчётов диапазона (по центрам каналов) минус
   первый момент континуума линий выше (он известен из тех же строк, которыми континуум вычитается);
2. энергия линии подбирается так, чтобы центр тяжести ЕЁ строки в диапазоне совпал с целью (секущая,
   не больше 8 шагов, допуск 0.001 кэВ); на этой энергии — ε, Ḣ/φ̇ и строка, вычитающая континуум ниже;
3. у пути «≈» (пиковая кривая) строки нет — энергия есть центр тяжести отсчётов как есть;
4. диапазон, где приписанное меньше пятой части отсчётов (`RepresentativeMinShare = 0.2`), и диапазон, у
   которого на подобранной энергии своя доля ниже пола, остаются на середине. Первое — потому что центр
   тяжести разности двух больших чисел есть шум вычитания; второе поймано пробой: остаток 3 % отсчётов в
   13…17 кэВ уехал к низу 13.12 с долей в 18 раз меньше середины и дал +2.6 % показания (ASN16, 662).
   Пол судится по-прежнему на середине — пропускать ли диапазон, свойство сетки, а не спектра.

**Почему ПЕРВЫЙ момент, а не пик или квантиль.** Строка матрицы — без разрешения прибора, спектр — с ним.
Из всех мер положения только среднее не меняется от симметричного размытия; «верхняя половина», квантиль,
мода на разрешении смещаются, и спектр с моделью без разрешения уже не сравнить.

**Отвергнутый вариант — мелкая внутренняя сетка** (отношение узлов 1.05 вместо 1.325, энергия — середина):
замер на той же синтетике — путь матрицы +2…+42 % (обрезание отрицательных остатков в нуль на сотне узких
диапазонов копит положительное смещение). Сборка с этим вариантом была пробной и откачена.

### 2.3 Названная цена

* У линии, чей собственный комптон заходит в её диапазон, центр тяжести строки почти не растёт с энергией

* Цена счёта: одно `Calculate` с матрицей — 3.2…4.1 мс → 6.6…19.5 мс (Debug, 1024…8192 канала): строка

## 5. `AMBER93` — полевые сцены: мерка и отказ

`DoseFieldProbe` строит обе сцены генератором (`GeometryScenes.Ground`/`Borehole`, верх расчёта 3000 кэВ)
на каждом пресете и считает `I(μ) = ∫dV e^{−μl}/(4πr²)` по направлениям из центра кристалла:
`I = ½∫dcosθ (1 − e^{−μL(θ)})/μ`, L — хорда грунта по лучу. Положительные контроли: при μ = 0 это `G·V`
приложения до бита шести знаков (+0.0000 % у обеих сцен), и при конечной сцене не больше предела
бесконечной — `1/(2μ)` над грунтом, `1/μ` в лунке — и не ниже 95 % его (98.6 % и 99.0 % у G1S).

Gamma-1S 63×63, грунт `Soil` 1.50 г/см³:

| | 662 | 1460.8 | 2614.5 |
|---|---|---|---|
| на земле: I(μ), см / без ослабления ×… | 4.240 / ×17.14 | 6.228 / ×11.67 | 8.396 / ×8.66 |
| в лунке: I(μ), см / без ослабления ×… | 8.553 / ×8.36 | 12.501 / ×5.72 | 16.667 / ×4.29 |

Все 8 пресетов: на земле ×12.8…×20.1 на 662, в лунке ×8.2…×8.6. **K-40, 1 Бк/кг, воздушная керма
нерассеянных: честная 0.0216 нГр/ч, как считало приложение 0.2519, UNSCEAR 2000 (с рассеянными) 0.0417** —
честная/UNSCEAR = 0.518 (на всех пресетах 0.517…0.522), приложение/UNSCEAR = 6.04 (4.5…7.1). В лунке мерка —
UNSCEAR ×2 (геометрия 4π): 0.519, приложение ×2.97.

**Не сошлось в 10 %**, и причина одна на всех пресетах: вторую половину поля несут кванты, рассеянные в
грунте, а метод «N·G·Ḣ/φ̇ на линию» их не видит — с матрицей их отсчёты объяснены континуумом линии (перенос
сцены ведёт кванты через грунт, `EfficiencySimulator.AnalogContinuum`), по пиковой кривой они шли бы
квантами своих энергий с тем же G. Два пути разошлись бы вдвое, и ни один не был бы дозой. По решению Amber —
**отказ словами**: `DoseRateGeometry.FluencePerPhoton` для `Scene = Ground | Borehole` бросает
`DoseRateRefusalException` с ключом `DoseRateFieldScene` (en/ru; ru при русском интерфейсе проверен пробой:
«Мощность дозы: кривая посчитана для полевой сцены (на земле или в лунке). … Считайте дозу сценой поля

## 6. Находки

1. **Строка матрицы дозы — без разрешения прибора.** Линия у границы диапазона в спектре делится между
   соседями, строкой — нет; с этим связан весь остаток пути матрицы с разрешением: AS80 59.5 +9.74 %, RC-103
   1173.2 +6.24 % и 1460.8 +5.06 %, ASN16 2614.5 +4.43 % (было +16.41 / +5.25 / +5.73 / +4.57). Лечение —
   свёртка строки с FWHM спектра (`ResultData.FwhmCalibration`), но у дозы своего перевода FWHM в кэВ нет, он
   живёт в разборе FSA (занятые файлы), и число меняется у всех — строкой реестра.
2. **Пол эффективности снимает ВЕРХ шкалы у малых кристаллов.** `MinOwnEfficiencyFraction` = 1 % от
   наибольшей по сетке задумывался против низа (ε → 0 ниже 15 кэВ), но у RC-103 по пиковой кривой снимает
   1657…2837 кэВ (своя 5.2e-4 и 8.1e-4 против максимума 0.118): линия 2614.5 не даёт дозы вовсе (путь «≈»
   −100 % в `DoseGridProbe`); по полной — держится на 1.15 %, у самой границы. Правило пола — политика
   показания, строкой реестра с вопросом Amber.
3. **Сторож `check_declared_base.py` не находит коммит объявления, если объявление внесено слиянием.**
   `declaration_commit` ищет `git log -S 'sources=…' -- tools/CORPUS/README.md` без `-m`, а `3ea9889d`
   (объявление rev33) — слияние: поиск пуст, сторож сверяет отпечаток с РАБОЧИМ деревом («строка ещё не
   закоммичена»), и ЛЮБАЯ правка кода приложения краснит его — и до коммита, и после. Замер: на чистом HEAD в
   worktree — код 0; тот же worktree + только правки П145 — код 1; `git log -m --first-parent -S …` находит
   `3ea9889d`. Файл не полосы — строкой реестра.
