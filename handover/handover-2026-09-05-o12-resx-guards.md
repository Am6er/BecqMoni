## 1. `T230` — формат: BOM + CRLF побайтово

**Посылка сверена байтами и подтвердилась по существу, но НЕ по числам.**
Задание называло «93 перевода строки» у `EfficiencyMakerForm.resx` и «91» у
`.ru.resx`; счёт байтами даёт **109 и 109**. Строка `TODO.md` для английского
файла («CRLF 0, LF 109») верна, число для русского в ней не стояло. Пример
нормального файла в задании — «`DeviceConfigForm.resx` CRLF 80 из 80» — на деле
7596 из 7596.

По всему дереву 77 файлов `.resx`, не по правилу были ровно эти два; BOM
(`efbbbf`) стоял у обоих — сбиты были только переводы строк.

Приведены к BOM+CRLF побайтово скриптом с приёмкой внутри: содержимое,
нормализованное к «без BOM, LF», обязано совпасть до и после — `assert` по
sha256, у обоих файлов совпало (`4c0cc029c5bd9b82`, `329d9803f6b9e8a5`).

**Стало:**

| сторож | код до | код после |
|---|---|---|
| `check_resx.py` | 1 | **0** |
| `check_resx_letters.py` | 1 | **0** |
| `check_resx_zorder.py` | 1 | **0** |
| `check_resx_designer.py` | 1 | 1 — *законно*, 26 ключей (§2) |

Сборка `Debug_O12` — код возврата **0**; ресурсы формы читаются обратно из
собранного вида на обеих культурах (`$this.Text`: `Efficiency maker` /
`Конструктор кривой эффективности`), сателлит `ru` на месте.

### ⛔ Правка в коммит НЕ уедет, и это не оплошность, а устройство

`.gitattributes` в дереве есть и держит `*.resx text eol=crlf`; в индексе все
`.resx` лежат с LF (`git ls-files --eol` → `i/lf`). Значит перевод строк в
рабочем дереве **git не хранит вовсе**: после правки `git diff` пуст,
`git diff --numstat` пуст, а `git status` показывает файлы изменёнными только
потому, что у них поменялся размер. Отсюда:

* приёмка «четыре сторожа 0» верна **на этой рабочей копии** и восстанавливается
  сама на любой свежей выкладке;
* но и **сломать её заново может любой инструмент**, записавший `.resx`
  текстовым режимом, и `git diff` этого не покажет. Отдельная строка — §4.

## 2. `T228` — разбор вызовов обёрток по тексту ЦЕЛИКОМ

Было: в `one_step` текст резался на строки, а аргументы отрезались выражением
`\(([^()]*)\)`. Значит вызов, разнесённый на две строки, был невидим ВОВСЕ, как
и вызов с вложенными скобками. А в дереве обёртка `DoseRateCoefficients.Text`
почти везде записана так:

```csharp
throw new InvalidOperationException(string.Format(
    DoseRateCoefficients.Text("DoseRateOutsideXcom", "…{0}…"),
    energy));
```

Стало: выражение находит только имя вызова и открывающую скобку, аргументы
отрезает новый `balanced_args` — по парной скобке, с пропуском строковых и
символьных литералов (обычных, `@"…"` и `'x'`); `split_args` тоже перестал
резать по запятой внутри строки; номер строки считается по смещению.

**Числа на дереве:**

| | до | после |
|---|---|---|
| обращений с литеральным именем проверено | 744 | **772** |
| из них через ОДИН шаг | 19 | **47** |
| ключей, которых нет в нейтральном resx | **2** | **30 мест / 26 имён** |
| обращений с вычисляемым именем недоступных | 0 | 0 |

Прибавка ровно та, что ожидалась: 19 = 10 `GetResourceText()` + 7 `.Resource` +
2 `Text()`; 47 = те же 10 + 7 + **30** `Text()`. Ни одна прежняя находка не
потерялась, ложных не появилось: все 30 совпадений `Text(` — обращения к
`DoseRateCoefficients`.

**26 имён** (30 мест; `DoseRateCurveTooShort`, `DoseRateEmptySpectrum`,
`DoseRateNoCalibration`, `DoseRateNoTime` встречаются дважды) — файл
`handover/o12-resx-guards/t228-missing-keys.txt`. Ни одного из 26 нет ни в
`Properties/Resources.resx`, ни в `Resources.ru.resx` (счётом: есть в en 0, есть
в ru 0). Это ровно список строки `A237`; заводить ключи полоса не имела права —

## 5. Найдено попутно (строки — в отчёте полосы, `TODO.md` полосе править нельзя)

1. **`check_resx_zorder.py` смотрит формат только у ПАРНЫХ resx.** Плечо формата
   получает `[r for _d, r in pairs]` — 43 файла, у которых есть

   шапке `check_resx_designer.py` записано «чтобы четыре сверки называли одно и
   то же число».
2. **Формат `.resx` в рабочем дереве git не хранит** — правка не видна ни в
   `git diff`, ни в коммите (§1). Сломать заново может любой инструмент,
   пишущий `.resx` текстовым режимом, и следа не останется.
3. **Обёртка опознаётся по ИМЕНИ МЕТОДА, без разбора получателя.** `wrappers()`
   возвращает `{Text: 0}`, и выражение `\bText\s*\(` бьёт по всему дереву.
   Замер сегодня: 40 вызовов вида `Text(`, из них 30 с первым аргументом-
   литералом — и все 30 это `DoseRateCoefficients.Text`, то есть ложных
   срабатываний **ноль**. Но первый же чужой `X.Text("литерал", …)` будет
   осуждён как ключ ресурса.
