### Правка

`BecquerelMonitor/EfficiencyMaker/GeometryMaterialStore.cs`:

* `CurrentSeedVersion` 7 → **8** (строка поколения — воздух и стекло по NIST);
* постоянная `AirGlassSeedVersion = 8` — порог переноса отдельным словом, чтобы
  следующее поколение засева не заставляло перенос повторяться;
* `EnsureLoaded`: после сведения по именам — `MigrateAirGlass(list, seed)` при
  `SeedVersion < 8`. Три движения, и все три дают ровно то, что видит новый
  пользователь:
  1. `Air, dry` формулой `N2 O1` → составом NIST (N/O/Ar/C);
  2. `Glass` (кварц 2.32) — СНИМАЕТСЯ: в засеве поколения 8 его нет вовсе;
  3. `Glass, plate` строкой таблицы (вид `Other`) → тем же составом, но видом
     `BeakerWall` и сокращением «Glass».
* `Migrate` трогает запись, ТОЛЬКО если она побитово равна прежнему засеву
  (`SameEntry`: имя, сокращение, формула, плотность, вид, доли, смесь — точным
  сравнением). Прежние записи стоят строками (`PreviousAir`, `PreviousGlass`), а
  прежняя `Glass, plate` ВЫВОДИТСЯ из нынешней записи засева (сокращение снять, вид
  `Other`) — вторая копия четырёх долей молча разошлась бы с таблицей;
* `MigrateGeometry(GeometryModel)` / `MigrateSlot` — перенос вещества СЛОТОВ:
  вещество в геометрии лежит СНИМКОМ, и правка засева до него сама не доезжает.
  Трогается только снимок «`Air, dry`, ρ 0.001205, ровно два элемента с долями,
  посчитанными из формулы `N2 O1`»; эталон прежнего состава считается один раз и
  только после дешёвой проверки имени, плотности и числа элементов — у того, кто уже
  на новом засеве, до базы `matdb` дело не доходит.
* ⚠ Запись файла НЕ делается: перенос живёт в памяти ровно так же, как сведение по
  именам, а файл переписывает только редактор (`Save`) — по движению человека.

`BecquerelMonitor/EfficiencyConfigData.cs` — одна строка в сеттере `Geometry`, рядом с
`ApplyGapDefault()`: `GeometryMaterialStore.MigrateGeometry(value)`. Это и есть вход
геометрии из конфигурации прибора и из спектра, несущего свою кривую.

## `S181` — НЕ ЗАКРЫТА: замер невозможен, основное дерево не собирается

### Что удалось установить чтением

Разбор ревизии подтверждается по коду: `FsaLineAudit.Group` (`FsaLineAudit.cs:383`,
`:397-400`) ставит окно линии по `calibration.EnergyToChannel(E)` плюс усиление и ноль
опор, а анализатор кладёт каждый бин образа через `LightToChannel`
(`FsaAnalyzer.cs:2374-2384`) — карту `E(0) + (x − z₀)·s`. Читателей сверки ровно два, и
оба — обслуга: `tools/effmaker/probes/CorpusFsaProbe.cs:3287` и
`tools/effmaker/probes/LineAuditScaleProbe.cs`; приложение `FsaLineAudit` не зовёт
нигде (проверено `grep` по всему дереву).

⚠ **Важное уточнение к постановке, которого в разборе нет: карта включается ТОЛЬКО при
живой матрице.** `FsaAnalyzer.Analyze` ставит растяжение при
`adcZeroMode == Fixed && AnchorScale && ResponseMatrix != null` (`:4862`), а у «adc» —
после разведочного прохода, в блоке привязки. Значит дефект живёт на спектрах
ПОНЯТНОЙ части корпуса (матрица есть) и не живёт там, где матрицы нет; синтетический
стенд без матрицы его не показывает вовсе.

⚠ **И вторая находка, которая решает судьбу правки: карты в `FsaResult` НЕТ.** Поля
`adcScale`, `adcE0`, `adcZeroKev` — закрытые поля `FsaAnalyzer`, наружу уходит только
ТЕКСТ служебной строки `AnchorNote` («нуль adc: кан 0 = … кэВ калибровки, свет … кэВ,
растяжение … по … кэВ», точность F2/F5/F1). Починить `FsaLineAudit` «в одном файле»
нечем: нужен либо экспорт трёх чисел в `FsaResult` (а заполняются они в
`FsaAnalyzer.cs`), либо передача карты параметрами от читателя. Оба пути упираются в
`FsaAnalyzer.cs`, который в этом заходе держит полоса П130.

### Почему замера нет

⛔ **Основное дерево не собирается**, и не из-за правок по существу: файл
`BecquerelMonitor/FullSpectrumAnalysis/FsaAnalyzer.cs` лежит на диске БЕЗ ЕДИНОГО
ПЕРЕВОДА СТРОКИ. Замер (`handover/p133-migration/s181-fsaanalyzer-mangled.txt`):

* 782 528 байт, **CR 0, LF 0, CRLF 0** (счёт байтами, как велит правило);
* BOM записан ДВАЖДЫ: `ef bb bf ef bb bf`;
* в `HEAD` (`231378bf`) у файла 13 242 строки;
* MSBuild Debug → **exit 1**, `FsaAnalyzer.cs(1,610143): error CS1513: Требуется "}"` —
  всё, что стоит после первого `//`, съедено однострочным комментарием;
* ⚠ сравнение с `HEAD` ПОСЛЕ снятия всех пробельных символов: 384 384 символа с обеих
  сторон, **совпали посимвольно** — содержательных правок в файле нет, потерять нечего,
  и `git checkout -- <файл>` возвращает его без потерь.

Файл чужой (П130), и полоса его НЕ ТРОГАЛА и НЕ ВОССТАНАВЛИВАЛА: `git checkout` полосе
запрещён, а восстановление посреди чужой работы — ровно тот случай, когда починка губит
работу соседа. Остальные три файла этой области целы (`FsaLibrary.cs` 726 строк,
`FsaSampleLibrary.cs` 3719, `FsaResult.cs` 2241, `FsaLineAudit.cs` 567).

Без сборки основного дерева ни «ДО», ни «ПОСЛЕ» по `S181` не меряется, а по
распоряжению Amber того же дня чинить без воспроизведения нельзя. Замерить в worktree
`p122` тоже нельзя, и это измерено доводом, а не догадкой: там `PhysicsVersion = 23`,
все складские матрицы несут `phys=22`, матрица не подхватывается — а без матрицы карта
`adc` не включается, то есть дефект в том дереве не воспроизводится в принципе.
