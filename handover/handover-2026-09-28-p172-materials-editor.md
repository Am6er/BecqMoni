## AMBER104 — гидрат через точку и регистр после обновления

**ДО (подтвердилась, числа ревизии повторились).** «CaSO4.2H2O» → Ca S O5.2 H2 (μ ×1.072 на 30 кэВ,
×1.037 на 60), «CuSO4.5H2O» → ×1.306 / ×1.222, «Na2SO4.10H2O» → ×1.369 / ×1.087 — без отказа.
Однозначные записи гидрата («C6H12O6.H2O», «NaCl.2H2O», «CaSO4*2H2O», «CaSO4·2H2O») — отказ.
Файл библиотеки поколения 8 с формулами «CS1 I1», «NI1», «PB1», «SI1 O2», «CO2» читался молча как
C S I, N I, B P, S I O2, C O2 — прежний разбор (до 24.09.2026) читал их Cs I, Ni, Pb, Si O2, Co2.

**Правка.** `GeometryMaterialLibrary.TryParseFormula`: формула режется на части аддукта (IUPAC
IR-4.4.3.5) знаками «*», «·» (и типографскими братьями) и точкой, у которой по обе стороны НЕ
цифры; у второй и дальше части — множитель впереди. Точка между цифрами — дробная часть
(«Cd0.9Zn0.1Te1», «Si1.5 O3», «CaSO4.2» = 4.2 атома O), кроме вида «n.m» + заглавная при n ≥ 1
(«CaSO4.2H2O»): читается двояко, и ей — отказ словами (`GeometryMaterialsErrorFormulaDot`) с
подсказкой «гидрат — через * или ·, дробь — с пробелом после». Регистр: при чтении файла
поколения < 9 (`GeometryMaterialStore.CaseSeedVersion`) у формулы, которую прежний разбор читал
ЦЕЛИКОМ и иначе, ставится `Entry.LegacyFormula`; такое вещество теряет состав, причина с обоими
прочтениями — `LegacyFormulaProblem` (`GeometryMaterialsErrorFormulaCase`), редактор веществ не
сохранит библиотеку, пока формулу не наберут заново (иначе пометка ушла бы с поколением). Формулы,
которые прежний разбор и сам читал не целиком («H2O» — водородом), не помечаются. Выбранное в
редакторе геометрии вещество без состава — отказ `GeometryEditorErrorMaterialEmpty` (не вакуум
молча). ⚠ Ожидание П150 «H2.O — отказ» заменено: точка перед заглавной — аддукт, H2·O = H2O.

**ПОСЛЕ.** Все однозначные гидраты — верный состав («CaSO4*2H2O» → H 0.0234, как у ревизии);
три двусмысленных — отказ словами; пять формул заглавными из файла поколения 8 — отказ с обоими
прочтениями; «CO2» в файле поколения 9 — C O2 без отказа; «Cs1 I1», «H2O», «Bi4 Ge3 O12», «Ge1» —
прежний состав. Библиотека Amber через склад: отказов по регистру 0.

## AMBER105 — плотность ≤ 0 в поле вещества

**ДО (подтвердилась).** RC103_point0: «−1.5» и «0» у кристалла, «0» у отражателя, «−2.7» у корпуса,
«0» у пробы — в модели библиотечная плотность (4.51 / 2.25 / 2.7 / 0.001205), поле не краснеет,
`Validate` молчит (5 из 5).

**Правка.** `GeometryEditorPanel.MaterialProblem`: у показанной строки с выбранным веществом
плотность ≤ 0 — отказ словами `GeometryEditorErrorDensityField` («“Кристалл”: плотность −1.5 г/см³ —
плотность должна быть больше нуля»), поле красным (`MarkBadValues`), полевая сцена по такой
плотности не пересчитывается. Снятые строки (проба у ISO, стенка у съёмок в поле) и пустой список
(«вещество не задано», `A303`) не судятся.

**ПОСЛЕ.** 5 из 5 — отказ и красное поле; контроли: RC103_point0 как есть — молчит; ISO с нулём в
снятой строке пробы — молчит.

## AMBER106 — правка вещества пробы через «…» и полевая сцена

**ДО (подтвердилась).** Цилиндр «на земле», грунт; в библиотеке грунт → свинец по пути
`EditMaterials` HEAD (повторён пробой дословно): глубина осталась 638.6 мм (4.06 λ), по формуле
551.1 / Ø 2963.6 мм.

**Правка.** Хвост `EditMaterials` вынесен в `ApplyLibraryEdit` и, если правка задела состав
вещества пробы, зовёт `RecomputeScene` (у обычной пробы он молчит сам).

**ПОСЛЕ.** Глубина 551.1 мм = 3.50 λ, Ø 2963.6 — сходится с формулой. Экраном: вода → «Pb1» в
библиотеке, сцена «на земле» пересчиталась 881.9 → 826.6 мм, пробег 25.2 → 23.6 см.

## AMBER107 — «Freon-13ii» и «Lanthanum oxysulfide» в засеве

**ДО (подтвердилась).** Фреон Z 55 вместо 53: μ засева/NIST 34.5 кэВ ×0.207, 60 кэВ ×1.088, 100 кэВ
×1.090; оксисульфид (доли La2OS): ×1.047 / ×1.048 / ×1.045. Где используются: в сценах корпуса
(`tools/CORPUS/corpus/geometries`), моделях (`tools/effmaker/models`), `config/` и конфигах приборов
Amber — нигде; в библиотеке Amber (поколение 2) обе записи есть и побитово равны засеву.

**Правка.** Засев — генерируемый файл, правлен ГЕНЕРАТОРОМ: `tools/effmaker/import_lsrm_materials.py`
получил `ERRATA` — доли двух строк берутся из `matdb.star_material_composition` (FREON-13I1, id 165;
LANTHANUM OXYSULFIDE, id 181; база только читается). Перед правкой генератор воспроизвёл
`GeometryMaterialSeed.cs` побайтно; после — в файле ровно две строки данных и две строки шапки.
Поколение засева 8 → 9; перенос `MigrateSeedErrata` — только записи, побитово равные прежнему засеву
(правило Amber 22.09.2026 для `AMBER67`), и `MigrateErratumSlot` — слоты геометрии с прежними долями
(в конфигах Amber таких нет). Файл: `GeometryMaterialStore.cs` (вне списка полосы, но перенос живёт
там же, где у `AMBER67`; других правок этого файла в дереве не было).

**ПОСЛЕ.** Засев = NIST (μ ×1.000); в файле поколения 8 прежний фреон перенесён, оксисульфид с
правленой рукой плотностью 5.9 не тронут.

## Остаток AMBER102 — подсказка ISO в редакторе геометрии

**ДО.** У видов пробы (точка, цилиндр, маринелли, кювета) строка под списком вида источника пуста.

**Правка.** `UpdateSceneHint`: у вида пробы строка `GeometryEditorSceneIsoHint` — «Мощность дозы по
этой кривой — для пробы в этой геометрии. Для фона (излучение со всех сторон) заведите отдельную
кривую со сценой «Изотропное поле (ISO)».»; та же — подсказкой при наведении на список. У полевых
сцен строка прежняя (пробег / эффективная площадь).

**ПОСЛЕ.** 4 вида пробы — подсказка, 3 полевые сцены — прежний текст; экраном — две строки, поля
не наезжают.

  так задумано (пометка иначе теряется с поколением); отказ называет вещество и оба прочтения.
