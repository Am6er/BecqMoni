## Форма вопроса и довод

Место — `NucBase.buttonImportDef_Click` (по журналу П326 — `NucBase.cs:1177`, `defManager.SaveDefinitionFile()`;
место подтвердилось). Вопрос задаётся, если открыто окно «Редактировать изотоп» с несохранённым
(`NuclideDefinitionForm.OpenWithUnsavedEdits()`, признак П326 `HasUnsavedEdits`) и импорту есть что записать; три
кнопки — смысл П326, только про импорт:

* **Да** — правки окна нуклидов записываются ровно как его кнопкой «Сохранить» (`SaveTogether()`: поля справа
  переносятся в линию, файл пишется, окно становится «сохранено»), затем импорт составляется заново по записанному и
  пишется. Порядок «сперва окно, потом импорт» — порядок действий человека: правки он сделал до нажатия «Импорт».
  Файл пишется дважды, каждый раз целым. Отказ окна (нечисло в поле — его «Введите число»; файл занят — окно
  менеджера) — импорта нет, как при «Отмене».
* **Нет** — импорт записывается так, будто правок окна нуклидов нет: **составлен** он по линиям до правок окна и
  **записан** с ними (`WriteWithoutUnsavedEdits(...)`, по очереди для каждого окна — тем же порядком, что «только
  наборы» у П326). Правки остаются в окне несохранёнными; его «Нет» потом сводит память с файлом, его «Да» допишет их.
* **Отмена** — импорта нет: ни память, ни файл не тронуты, окно нуклидов остаётся «изменено».

**Что импорт делает с памятью и почему он теперь сперва составляется.** Прежде импорт сразу менял список менеджера:
дописывал новые линии и (с галкой «перезаписать») переписывал имя, выход, период и ряд существующих, — а потом писал
файл. «Отмена» после этого означала бы откат памяти задним числом. Теперь `PlanImport()` составляет импорт, не трогая
библиотеку (новые линии — отдельным списком, видны следующим строкам того же импорта, как прежде; правки существующих
— отдельно), `ImportPlan.Apply()` кладёт его в память только после ответа, `ImportPlan.Revert()` снимает.

**Почему «Нет» составляет импорт по линиям ДО правок окна.** Правка ячейки окна лежит в линии сразу, и ключ импорта
(нуклид + энергия, `AMBER197`) читается по ней. Переименованная окном «Cs-137» → «Cs-137-P328» линия ключ теряет
(`N:CS-137-P328` вместо `N:137CS`), и импорт той же строки без «перезаписать» заводил её второй раз: в файл уходили
и правленая линия, и копия «Cs137» (мера R ниже, ДО — две линии на 662 кэВ при одной было). «Будто правок окна нет» —
значит и узнавание линий без них.

**Импорт перезаписывает линию, которую правило окно.** Откат и запись «без правок окна» (П326) возвращают поле к «до
правки» только если оно ещё держит то, что туда положило окно: поле, переписанное импортом, остаётся за импортом. Мера
E: окно сняло галку «Видимый» у Cs-137, импорт переписал его выход — в файле выход импорта и галка до правки; «Нет»
окна снимает только галку, выход импорта цел в памяти и в файле.

Текст ресурса `MSGNucBaseImportUnsavedNuclides` (заголовок — `ConfirmationDialogTitle`, кнопки YesNoCancel, значок
Exclamation; оформление и название окна — как у `MSGSavingNuclideSetUnsavedNuclides` П326):

* en: `The "Edit Nuclide Definition" window has unsaved changes to the nuclide library. The import saves the whole
  library file.` ⏎⏎ `Yes - save those changes together with the imported lines (nothing will be left unsaved in the
  "Edit Nuclide Definition" window).` ⏎ `No - save only the imported lines; the library changes stay unsaved in the
  "Edit Nuclide Definition" window.` ⏎ `Cancel - do not import.`
* ru: `В окне «Редактировать изотоп» есть несохранённые правки библиотеки изотопов. Импорт записывает файл библиотеки
  целиком.` ⏎⏎ `Да — записать эти правки вместе с импортированными линиями (в окне «Редактировать изотоп»
  несохранённого не останется).` ⏎ `Нет — записать только импортированные линии; правки библиотеки останутся
  несохранёнными в окне «Редактировать изотоп».` ⏎ `Отмена — не импортировать.`

⚠ Подписи кнопок `MessageBox` даёт Windows на языке системы (как у всех вопросов приложения).

## Вне поручения — найдено при разборе и починено в своём файле (`NucBase.cs`)

* **F. Отказ записи оставлял импорт в памяти** (`A9`: «список в памяти обязан сходиться с файлом»; комментарий
  `AMBER201` прямо называл это «линии лишь в памяти»). Новые линии и перезаписанные выходы жили в памяти до
  перезапуска — разметка пиков и FSA видели их, — а ближайшая запись библиотеки любым окном уносила их в файл молча.
  Теперь отказ записи снимает импорт (`ImportPlan.Revert`); ДО — N в памяти, 153 линии, выход O 9.52; ПОСЛЕ — как
  было, 152, 2.27.
