## 1. Где в коде проходит граница «привязано / свободно»

Разобрано чтением `FsaAnalyzer.cs` (правка решателя не потребовалась — отвязанная часть ОТДЕЛИМА):

| место | что происходит |
|---|---|
| `DepositOf` → `SplitContinuumBelowTrustFloor` (≈10400) | гистограмма поглощения образа (сумма откликов матрицы по линиям) режется ОДНИМ ножом: бины ниже `ResponseContinuumTrustFloorKev` = 100 кэВ, НЕ попавшие в пиковые окна линий (±2 ПШПВ, не меньше ±3 бинов; окна считаются для ВСЕХ линий, и левое плечо линии чуть выше порога тоже остаётся), вынимаются в `Deposit.Tail`; в основной гистограмме, в подслое сумм и в четырёх каналах исхода (`S3`) эти бины обнуляются. Пик под порогом (рентген Bi/Pb 75–90 кэВ у Pb-212) остаётся ПРИВЯЗАННЫМ |
| `BuildTemplateFromResponse` (≈10520) | обе гистограммы уширяются одним ядром: `template` (привязанная часть) и `lowTail` (хвост) |
| `FitOnce` (≈9483–9517) | на каждый матричный образ с непустым хвостом в решатель уходят **ДВЕ колонки**: `{Component = образ, Values = template}` и `{Component = null, Values = lowTail}` — у хвоста своя свободная амплитуда NNLS, без имени, как у шапок сплайна; отсев по z, пределы, парциальные невязки хвост не видят (`Component == null` пропускается везде: `TopZ`, `RefitZ`, `PartialResidualGate`, `ComputePartialResiduals`) |
| `CollectScaleAnchors` (≈3471) | привязка шкалы складывает ВСЕ безымянные колонки (шапки + хвосты) в свой «континуум» — это часть фита, не тронуто |
| `BuildResult` (≈8200) — **до правки** | все `Component == null` колонки с положительной амплитудой складывались в `result.Continuum`; `Model = Continuum + Σ кривых` |
| `FsaResult.DistributeContinuum` (≈1666) | подложка `Continuum` разносится по слоям нуклидов пропорционально их пиковому счёту ВЫШЕ канала — так хвост Pb-212 (и сплайн) попадал в ленту и долю Pb-212 |

Итак, граница «привязано / свободно» — в `SplitContinuumBelowTrustFloor`: **привязано** = пиковые окна
всех линий образа (везде по шкале) + весь образ выше 100 кэВ; **свободно** = континуум образа ниже 100 кэВ
вне окон. В решателе это две колонки, и свободная — отделима без правки решателя: до `BuildResult`
она доходит безымянной колонкой, и потерять её имя она успевала только там.

## 2. Правка (приложение)

Фит не тронут ни строкой: `FitOnce`, гейты, отсев, пределы, привязка — те же (приёмка побитово, §3).

* `FsaAnalyzer.FitColumn` — поле **`TailOf`** (компонент, чей хвост); ставится в `FitOnce` при создании
  колонки хвоста. `Component` у колонки остаётся `null` — для решателя и всех гейтов она по-прежнему
  безымянная.
* `FsaAnalyzer.BuildResult` — колонка с `TailOf != null` **НЕ складывается в `Continuum`**: амплитуда ×
  образ копится в **`FsaResult.UntiedTail`** (по каналам) и в **`FsaResult.UntiedTails`** (чей, сколько
  отсчётов в полосе фита). `Model` (верх стека) = `Continuum` + Σ кривых — БЕЗ хвоста; невязка в
  отсчётах (`ResidualMissingShare`/`ResidualExcessShare`) считается против неё — хвост входит в «не
  описано». Разнос подложки, слои, доли, лента на экране, строки отчёта — всё ниже по течению читает
  `Continuum`/`Model`/`Components` и меняется само: **в `EnergySpectrumView.Fsa.cs`, `FsaResult.SpreadContinuum`,
  `FsaPresentationBuilder`, `FSAReportView` ни одной строки кода не тронуто** (в виде — только
  комментарий у ленты невязки). Новой строки на экране нет, resx не тронуты.
* `FsaResult` — сущность **`FsaUntiedTail`** (компонент, отсчёты), поля `UntiedTail`/`UntiedTails`, два
  читателя МОДЕЛИ ФИТА: `FitContinuum()` = `Continuum + UntiedTail`, `FitModel()` = `Model + UntiedTail`.
* `FsaLineAudit` (кросс-сверка линий, читатель — только `CorpusFsaProbe`) берёт `FitModel()`/`FitContinuum()`:
  сверка судит МАТРИЦУ по высотам линий, и то, что под окном забрала свободная колонка, — описание
  подложки фитом, а не промах матрицы; с `Continuum` без хвоста сверка внизу шкалы врала бы ровно на
  хвост. Числа сверки — те же (проверено малой базой с `--audit`, §3.8).
* `CorpusFsaProbe --limits-mc` (розыгрыш копии спектра пуассоном) — среднее берётся `FitModel()`: копия
  без хвоста лишилась бы низа шкалы, которого у измерения не убавилось. В штатный прогон корпуса этот
  режим не входит.

Оснастка: `FsaStackShot` — строка `отвязанный хвост (в невязке, не в слоях): Pb-212 N, …; всего T отсч.`,
столбец `untied_tail` в `--dump=`, раздел `untied_tail` в `--rates=` (ПОСЛЕ прежних строк, шапка та
же), ключ **`--plant-tail`** (подсадка «хвост снова в слой» — только для пробы, §3.4);
`FsaDoubleCountProbe` — раздел 6 `S173` (договор результата + подсадка); `CorpusFsaProbe` — файл
`*_tails.csv` (свой файл, шапки `runs`/`components` не тронуты) и столбец `untied_tail` в `--dump-curves`.
