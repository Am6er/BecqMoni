## AMBER110 — стабилизатор по одной опоре: прямая через (0 кан, 0 кэВ)

**ДО** (`10-before.log`, спектр сочинён по калибровке корпусного `RC103_Th232WT20`
[−3.258, 2.4647, 3.42E-04], пик опоры — гаусс, усиление g = 1.000 и 1.020):

| опоры | g | 59.54 | 661.66 | 1460.82 | 2614.51 |
|---|---|---|---|---|---|
| 661.66 | 1.000 | +5.07 | +0.97 | **−56.55** | **−223.15** |
| 1460.82 | 1.000 | **+7.65** | **+27.41** | −0.51 | −127.71 |
| 661.66 + 1460.82 | 1.000 | **−39.97** | +1.04 | −0.52 | **−92.65** |

Числа ревизии (−56.6, −223, +27.4, +7.7) воспроизведены. У ASN16 (`ASN16_Th232`, 8192 кан.)
опора 661.66 даёт 1460.82 −38.8, 2614.51 −130.7 кэВ.

**Находка сверх строки, закрыта здесь же:** при ДВУХ опорах стабилизатор подгонял прямую
через две точки (порядок = число точек − 1) — та же потеря кривизны: RC-103 59.54 −40 кэВ,
2614.51 −93 кэВ. Файл свой, правка — та же функция, поэтому не строкой.

**Правка** (`PeakStabilizer.cs`, `RemapChannels`): уход усиления растягивает номер канала, уход
нуля АЦП его сдвигает, поэтому новая шкала — ПРЕЖНИЙ полином, прочитанный в канале a + b·ch
(коэффициенты — биномиальным разложением, степень прежняя). Одна опора: a = 0, b = C(E)/ch
(E(0) прежний); две опоры: a и b по двум точкам. Три и больше — прежняя подгонка полинома
(код не тронут).

**ПОСЛЕ** (`11-after.log`): RC-103 одна опора 661.66 — 59.54 +0.09, 1460.82 +2.29,
2614.51 +4.27 кэВ (остаток — целый канал опоры, стабилизатор ищет максимум сглаженного спектра
на целом канале: 260 вместо 259.6); опора 1460.82 — не хуже ±1.0 кэВ; две опоры — не хуже
±3.0 кэВ; при g = 1.020 то же. ASN16: не хуже ±0.73 кэВ везде. Положительный контроль —
сама проба: на сборке ДО те же плечи дают −56…−223 кэВ.

## AMBER127 — AtomSpectra по умолчанию не возмещает мёртвое время

**ДО:** `new AtomSpectraDeviceConfig().DeadTime()` = 0 → `LiveTime.Calculate` отдаёт LT = T.
Конфиг Amber (`OneDrive\Desktop\Debug\config\device`, только чтение): у трёх её конфигураций
ASN16 элемента `DeadTimeValue` нет вовсе (= 0), у «Atom Spectra 80x80» — 1.357 мкс (кнопкой).
Корпус (`--corpus-lt`): из 32 спектров AtomSpectra LT = T ровно у 10 приборов с τ-кнопкой
(AS1Pro_Ra226 6824 имп/с, AS80_Th232WT20 1948, ASN16 ×7, ASN3_Tile) плюс 7 ASN8 (звуковой
вход). `ASN16_Cs137` (LT/T = 0.99025 при 696.6 имп/с) даёт τ = 14.0 мкс — так ASN16 и
настроен. Цена LT = T: τ = 14 мкс — 608 имп/с −0.85 %, 1948 −2.73 %, 6824 −9.55 %, 10 кимп/с
−14 %; τ = 7 мкс — вдвое меньше.

**Что знает сам прибор/программа** (github.com/Am6er/AtomSpectra, только чтение, файлы
`AtomSpectraService.java`, `SpectrumFileN42.java`, `SpectrumFileBqMoni.java`): программа
AtomSpectra мёртвого времени НЕ возмещает — пишет `LiveTimeDuration` = `RealTimeDuration`, из
ответа `-inf` берёт только `VERSION`. Прибор отдаёт в `-inf` пары «ИМЯ значение» (`RISE`,
`FALL` — отсчёты АЦП фронта и спада, `F` — частота оцифровки, Гц; пример ответа и поля —
PROTOCOL.md проекта atomspectra-waterfall-esp32). Формула τ = (RISE + FALL + 1)/F — прежней
кнопки BecqMoni; её слова [3], [5], [9] совпадают с RISE, FALL, F примера.

**Правка:**
* `AtomSpectraDeviceConfig.DeadTimeFromInfo(ответ, out причина)` — разбор `-inf` ПО ИМЕНАМ
  (лишние пробелы и переводы строк не сдвигают), отказ — NaN и причина словами, не ноль.
* Кнопка «Обновить мёртвое время» (`AtomSpectraVCPDeviceForm`) — тем же разбором; отказ —
  окно `ERRReadDataFromPort` (порт) + причина; временный порт закрывается в `finally` (раньше
  при броске оставался открытым).
* Контроллер (`AtomSpectraDeviceController.RefreshDeadTimeFromDevice`) — после принятого
  старта/подключения спрашивает `-inf` и ставит τ конфигурации документа; отказ τ не трогает
  (Trace). Живое время пересчитывается от начала набора, так что поправка ложится на всё
  измерение.

**ПОСЛЕ:** разбор (`--dt`): ответ примера → 7.0000 мкс; с двойным пробелом и переводом
строки → 7.0000; пустой, «-ok», «FALL x», «F 0» → отказ словами (4 из 4). Путь с живым
прибором НЕ проверен — прибора у полосы нет, и к COM-порту Amber полоса не подключалась
нарочно (мог идти её набор).

⚠ **Цена для живых измерений Amber** (умолчание меняет числа): после правки каждое новое
измерение ASN16 получит LT < T: при её 608 имп/с (`ASN16_Th232`) активности, дозы и скорости
вырастут на +0.86 %, при фоне ~60 имп/с — на +0.08 %, у AS1Pro при 6824 имп/с — примерно на
+10 %. Прежние сохранённые спектры не меняются (LT лежит в файле). τ в памяти ложится в
объект конфигурации прибора; в файл конфигурации попадёт, только если человек сохранит
конфигурацию прибора.

Наблюдение, не строка: по PROTOCOL.md «эталонная» программа считает мёртвое время по
(ValidPulseCount + InvalidPulses)·τ, а BecqMoni — по `TotalPulseCount`·τ; поле
`invalid_pulses` пакет AtomSpectra несёт (`AtomSpectraVCPIn`), в живое время оно не идёт. Замера
нет, какой из двух счётчиков прав для Nano — не установлено.
