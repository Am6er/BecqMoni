# Ревизия FullSpectrumAnalysis, 07.09.2026

## Область

Статическая ревизия `BecquerelMonitor/FullSpectrumAnalysis/*.cs` с упором на
математическую корректность, физические размерности, статистические допущения,
граничные случаи и сохранность метаданных между вычислительными проходами.

## A287 — теряется происхождение члена ряда при сужении библиотеки

`FsaAnalyzer.NarrowLibrary` создаёт новый `FsaComponent`, когда из компонента
удалена только часть линий. Копируются `WeightsAreFinal`, `Derived`,
`FixedTemplate` и `TotalYieldPercent`, но не копируется `DecayChainRoot`.

Это проявляется в режиме `FsaBandMode.LibraryToFitByShare`: первый проход
оценивает вырожденность подпороговых линий, `NarrowLibrary` удаляет часть из них,
после чего рекурсивный второй проход работает уже с копией компонента без
происхождения в ряду. Сам спектральный столбец и амплитуда при этом остаются,
поэтому дефект не виден по невязке, но `FsaComponentResult.DecayChainRoot`,
родительская группировка и сопоставление связанных характеристических пределов
получают другую семантику, чем у необрезанных членов того же ряда.

Адрес: `BecquerelMonitor/FullSpectrumAnalysis/FsaAnalyzer.cs`, метод
`NarrowLibrary`, инициализатор копии около строки 3013.

Исправление локальное: переносить `DecayChainRoot = component.DecayChainRoot`
вместе с остальными метаданными. Нужна проверка с компонентом ряда, у которого
одна подпороговая линия выброшена, а хотя бы одна линия остаётся: после второго
прохода корень должен сохраниться и в компоненте результата, и в родительской
группировке.

## A288 — парциальные невязки обрываются после связанной цепочки

`BuildResult` разворачивает одну колонку `FsaComponentKind.Chain` в несколько
`FsaComponentResult` через `SplitChainMembers`. `ComputePartialResiduals`,
напротив, идёт по колонкам фита и берёт очередную строку результата через общий
счётчик `row++`. Для обычного компонента это совпадает; для цепочки — нет.

После первой цепочки следующий столбец сравнивается не со своей строкой, а со
вторым членом уже развёрнутой цепочки. Проверка имени не сходится и выполняется
`break`, поэтому `ZoneChi2Ndf` и `ZoneDeltaD` не рассчитываются ни для этого, ни
для всех следующих компонентов. Значения остаются исходными `NaN`. Сам
`PartialResidualGate` использует отдельный цикл до `BuildResult` и этим дефектом
не затронут; повреждены диагностические величины и вся внешняя мерка, которая
читает их как результат анализа.

Дефект воспроизведён поставочной сборкой `build_p31` на одном спектре
`AS1Pro_Ra226` с ключом `--partial`. Фит сообщил 10 компонентов, а после
развёртки цепочки CSV содержал 11 строк: конечные зонные величины получил только
первый член цепочки `Ra-226`; у остальных шести членов цепочки и у всех четырёх
следующих nuisance-компонентов осталось `zone_n = 0`. Итого рассчитана **1
строка из 11**. Для сравнения старый артефакт `out_p6`, созданный до связанной
цепочки, содержит зонные величины у 381 строки из 385 — сам расчёт работал, пока
число колонок совпадало с числом строк результата.

Адрес: `BecquerelMonitor/FullSpectrumAnalysis/FsaAnalyzer.cs`, строки около
3734–3754. Исправление должно сопоставлять строку результата с колонкой по
устойчивому ключу или явно заполнять одинаковую зонную мерку всем членам
развёрнутой цепочки. Нужен тест: цепочка из двух членов, затем одиночный
компонент; у одиночного после расчёта обе зонные величины должны быть конечны.

## A289 — период полураспада превращён в фиксированную задержку

`CascadeAtomicData.Delays` читает `g4_level.half_life_sec`, складывает эти
значения вдоль пути уровней и записывает сумму в `Transition.EmitDelaySec`.
`FsaCascadeSummer.VacancyGiven` и ветка аннигиляции затем используют жёсткие
условия `delay < windowSec` и
`abs(delay_other - delay) < windowSec`: совпадение либо учитывается полностью,
либо не учитывается вовсе.

Это неверная физическая модель времени распада. Период полураспада не является
задержкой события: время жизни уровня экспоненциально распределено. Уже для
одного уровня вероятность уложиться в окно `t` равна
`P = 1 - exp(-ln(2) t / T1/2) = 1 - 2^(-t/T1/2)`. Например, при
`T1/2 = t` верная доля равна 50 %, а код даёт 0 % из-за строгого `<`; чуть ниже
границы он скачком даст 100 %. Для цепочки уровней нужна свёртка экспоненциальных
распределений (гипоэкспоненциальное распределение), а не сумма периодов.

Дефект не равен уже записанному в `S58` приближению о смешанном населении уровня:
он действует и для единственного пути. В `schemedb.sqlite` есть множество
излучающих уровней с `T1/2` порядка поставочного окна 1 мкс; влияние именно на
действующий корпус ещё следует измерить по нуклидам и фактическим окнам приборов,
поэтому приоритет оставлен P2.

Адреса: `CascadeAtomicData.cs:477-520`, `FsaCascadeSummer.cs:1584-1597` и
`:1651-1684`. Приёмка должна включать аналитический одноуровневый случай
`T1/2 = window` (ожидается 0.5), пределы `T1/2 << window` и
`T1/2 >> window`, затем хотя бы двухуровневую цепочку.

ожидаемых ссылок на новый, ещё не добавленный в git журнал он выдал четыре

  малую базы таблицей ниже.

Это не дефект FSA, но по обязательному правилу реестра он зарегистрирован
строкой `T250`. Остальные сообщения проверки о путях-шаблонах печатаются
справочно и в итог `НАХОДОК` не входят.
