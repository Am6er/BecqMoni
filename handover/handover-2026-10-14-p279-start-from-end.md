# П279 (14.10.2026) — начало набора из конца у файла без начала и без времени пробы

Решение Amber 14.10.2026 вопросником, дословно: **«Конец − полное время (Рекомендую)»**. Вопрос был:
«Файл без начала набора и без времени пробы, но с концом (у тебя 45 таких — поверки ЛСРМ, выгрузки
RadiaCode): по правилу A207 начало = 1970-01-01. При включённой поправке на распад набор выглядит
длиной 54 года (Co-60 ×7.12, Cs-137 ×1.75), а продолжение набора такого файла даёт «56 лет» (Cs-137
×1.78). Как брать начало?» Вариант: «Начало выводится из конца и реального времени — множитель
распада верный, продолжение набора тоже. Голос A207 и метка 1970 для таких файлов пропадают.»

Корни: П263 (`FillAbsentTimes`), П268 (пустой элемент времени), П269 (остаток F6), ревизия П270 №4
(журнал `handover-2026-10-14-night-coordinator.md`, вопрос 21).

## Правка

`BecquerelMonitor/DocumentManager.cs`:

* `FillAbsentTimes` — в ветке «нет ни начала, ни времени пробы»: если конец в файле есть и полное
  (реальное) время набора `EnergySpectrum.MeasurementTime` > 0 — начало = конец − полное время,
  время пробы = начало (правило П263 «времени пробы нет — время начала»), голоса `A207` нет, счёт
  «неизвестных начал» не растёт. Иначе — прежнее `A207`: 1970-01-01 в оба поля и голос.
* новый `StartFromEnd(end, seconds)` — null при времени 0, отрицательном, ∞, NaN и когда
  `end − seconds` выходит за календарь (тогда в силе `A207`).

Двери: `OpenDocument`, `LoadDocument` и `EfficiencyCurveIo.LoadResultData` идут через
`FillAbsentTimes` — правка доезжает до всех трёх (измерено пробой). Загрузка фона
(`LoadBackgroundSpectrum`) `FillAbsentTimes` не зовёт и времена фона не читает — от фона берётся
только спектр (П268), там менять нечего. Путь 0.97b — без правил П263, как был. Формат записи не
тронут: признаки `…Specified` прежние, элементы пишутся те же.

## ⚠ Посылка вопроса шире данных: правка не трогает ни одного файла Amber

Сканер (`D:\BqMoni_Claude\p279\scan_before.txt`, сканер П269) по 683 файлам Amber и 136 корпусным:
расклада «начала и пробы нет, конец есть» — **0**. Те 45 файлов без начала и времени пробы — **без
конца тоже**: 44 — выгрузки RadiaCode-101 (формат 120920, ни одного времени, карточки пробы нет;
одна папка `YandexDisk\Спектры\…`, список — `D:\BqMoni_Claude\p279\list45.txt`), 1 — SpectraVibe CZT с
пустым `<Time />`. Выводить начало им не из чего: они открываются, как и прежде, с 1970 и голосом
`A207`, и продолжение набора такого файла по правилу «начало то же, конец по часам» по-прежнему даёт
56.78 года (Cs-137 ×1.79). Это подтверждает круг Amber: 1300 из 1300 сохранений побайтно прежние.

Чтением кода, где «продолжение» сохраняет начало загруженного файла: AmplitudaSerial и AmplitudaUSB
ставят `StartTime = Now` только у пустого спектра (`AmplitudaSerialDeviceController.cs:302`,
`AmplitudaUsbDeviceController.cs:179`); AtomSpectra, RadiaCode, Obsidian — контроллер прибора
заводится на первый «Пуск» открытого документа заново (`new_document_created = true` в
конструкторе) и ставит `StartTime = Now`; звуковой вход — `Now` всегда. Путь продолжения без прибора
недоступен — продолжение измерено подражанием (арифметика двери), не дверью прибора. У 7 из 44
выгрузок RadiaCode дата есть в имени файла (`Spectrum_2021-08-10  14-37-05_86628s.xml`) — это не
время из файла, и решение Amber его не касается. **Для распорядителя:** что делать с файлами без
всех трёх времён (продолжение набора «56 лет» у Amplituda) — вне этого решения.
