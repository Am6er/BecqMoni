### Измеренный механизм — чем полоса вообще может двигать матрицу

Полоса не трогает матрицу. Она двигает **список линий компонента**: пол библиотеки
уезжает с 20.0 кэВ (1 % от максимума кривой) на 30.0 кэВ, и у `Cd-109` из пяти линий
остаётся одна — 88.03 кэВ, а рентген серебра K (22…25 кэВ) отсекается. Если после
этого компонент не переживает отсева по значимости, в отчётном фите остаются одни
производные образы, а они матрицу не трогают по построению
(`FsaAnalyzer.FitOnce`: `fromMatrix |= template != null` только для компонентов без
`FixedTemplate` и без `WeightsAreFinal`). Тогда `ResponseMatrixUsed = false` при
живой и исправной матрице.

Наблюдение в подтверждение: на дереве БЕЗ матрицы (`wd_p3`, физика 16, отпечаток не
сошёлся) `Cd-109` у этого спектра как раз ОТСЕИВАЕТСЯ (`CUT Cd-109 Single 0.00`), и в
отчёте остаются одни производные. То есть путь, по которому пометка расходилась,
существует и виден; сегодня, с матрицей, компонент отсев переживает.

### Правка отчёта — ДОБАВЛЕНИЕМ, ничего не переименовано

Новая колонка **`matrix_images`** дописана В КОНЕЦ строки `runs.csv`. Порядок и имена
всех прежних колонок (`matrix_applied` на десятом месте, `matrix_found`,
`matrix_note`) не тронуты — сегодня на этом отчёте объявляется база, и менять смысл
старых колонок посреди этого нельзя.

Что она считает: сколько образов ОТЧЁТНОГО фита матрица имела право строить —
компонент предъявленной библиотеки, у которого нет `FixedTemplate` и не выставлен
`WeightsAreFinal`. Правило то же, по которому судит сам `FitOnce`. Компоненты,
заведённые анализатором самим (наложения, обратное рассеяние), сюда не идут: они
матрицу не трогают по построению.

## 4. Попутная находка: `--refit-z` с большим значением ОТКЛЮЧАЕТ отсев, а не ужесточает его

Найдено при поиске плеча «найдена, но не применена». Замер на `G1S16_Cd109_P25`
(склад физики 15, значимости `Cd-109` z = 7.76, `Esc-NaI` z = 0.57):

| ключ | что в отчёте | `matrix_images` |
|---|---|---|
| поставочный (`RefitZ` = 3.0) | `Cd-109` | 1 |
| `--refit-z=8` | `Cd-109` + `Esc-NaI` | 2 |
| `--refit-z=20` | `Cd-109` + `Esc-NaI` | 2 |
| `--refit-z=1000` | `Cd-109` + `Esc-NaI` | 2 |

Подняли порог — компонентов в отчёте стало БОЛЬШЕ. Причина прочитана в коде,
`FsaAnalyzer.cs:1886`:

```csharp
if (keep.Count > 0 && keep.Count < total)
{
    ... FitHuber(..., keep); ...
}
```

Когда порог выше значимости ВСЕХ компонентов, `keep` пуст, условие ложно, и
второго прохода не происходит вовсе — отсев просто НЕ ПРИМЕНЯЕТСЯ, молча. То есть
плечо развёртки `--refit-z=<большое>` читается как «самый строгий отсев», а на деле
это «отсева нет». Ни отказа, ни предупреждения; в шапке прогона ключ печатается как
принятый.

⚠ Ветка сама по себе разумна (пустой фит бесполезен), беда в МОЛЧАНИИ: у признака нет
читателя. Чинится в приложении (`FsaAnalyzer`), не в моих файлах.
